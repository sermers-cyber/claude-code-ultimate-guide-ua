# Довідник налаштувань Claude Code

> Повний довідник для конфігурації `settings.json` та змінних оточення. Охоплює підтверджені налаштування до Claude Code v2.1.310 включно (востаннє переглянуто 27 жовтня 2026). Авторитетним залишається [офіційний довідник налаштувань](https://code.claude.com/docs/en/settings-reference).

**Джерела:** [Офіційна документація з налаштувань](https://code.claude.com/docs/en/settings) · [Офіційна документація зі змінних оточення](https://code.claude.com/docs/en/env-vars) · [JSON-схема](https://json.schemastore.org/claude-code-settings.json)

**Легенда:**
- Без позначки = підтверджено в офіційній документації
- `📋 Тільки схема` = присутнє в JSON-схемі, але не на офіційній сторінці налаштувань (все одно дієве)
- `⚠️ Неперевірено` = не підтверджено в офіційних джерелах

## Область дії та пріоритетність (Scope and Precedence)

Claude Code використовує п'ять рівнів (Scopes) налаштувань, які застосовуються від найвищого до найнижчого пріоритету:

| Пріоритет | Область дії | Розташування | Чи спільне? | Призначення |
|----------|-------|----------|---------|---------|
| 1 | **Managed** | Сервер, MDM-профіль, реєстр або системний `managed-settings.json` | Так (під розгортання IT) | Політики масштабу організації, не можуть бути перевизначені |
| 2 | **Командний рядок** | `--` прапорці при запуску | Ні | Тимчасові сесійні перевизначення |
| 3 | **Local** | `.claude/settings.local.json` | Ні (в `.gitignore`) | Особисті налаштування під конкретний проект |
| 4 | **Project** | `.claude/settings.json` | Так (комітиться в Git) | Спільні налаштування для команди |
| 5 | **User** | `~/.claude/settings.json` | Ні | Глобальні особисті налаштування за замовчуванням |

**Об'єднання масивів:** Такі налаштування, як `permissions.allow`, `sandbox.filesystem.allowWrite` та `allowedHttpHookUrls`, конкатенуються та дедуплікуються на всіх рівнях дії — вони не замінюються повністю.

**Пріоритет заборони:** Правила `permissions.deny` завжди мають найвищий пріоритет, незалежно від наявності правил `allow` чи `ask` на будь-якому іншому рівні.

**Методи доставки керованих налаштувань (Managed Settings):**
- Керовані сервером (через консоль адміністрування Claude.ai)
- macOS MDM: plist-файл `com.anthropic.claudecode`
- Windows Registry (Реєстр): `HKLM\SOFTWARE\Policies\ClaudeCode`
- Файл: `managed-settings.json` за шляхом `/Library/Application Support/ClaudeCode/` (macOS), `/etc/claude-code/` (Linux/WSL), `C:\Program Files\ClaudeCode\` (Windows)
- Директорія динамічного підвантаження: `managed-settings.d/*.json` поруч із `managed-settings.json`, об'єднуються в алфавітному порядку

**Інші конфігураційні файли:** Файл `~/.claude.json` зберігає OAuth-сесію, конфігурації серверів MCP, статус довіри до проектів та загальні інтерфейсні вподобання, такі як `editorMode`. Не намагайтеся вносити ключі з `~/.claude.json` у `settings.json` : це призведе до помилок валідації схеми.

## Ключі налаштувань (Settings Keys)

### Основна конфігурація (Core Configuration)

#### `$schema`
**Тип:** string | **Область дії:** всі | **Типово:** немає

URL JSON-схеми для валідації в IDE та автодоповнення. Додайте `"https://json.schemastore.org/claude-code-settings.json"`, щоб увімкнути вбудовану валідацію у VS Code, Cursor та інших редакторах.

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json"
}
```

#### `model`
**Тип:** string | **Область дії:** всі | **Типово:** `"default"`

Перевизначення моделі за замовчуванням для всіх сесій. Приймає аліаси (`"sonnet"`, `"opus"`, `"haiku"`, `"opusplan"`) або повні ідентифікатори моделей, такі як `"claude-sonnet-4-6"`. Змінна оточення `ANTHROPIC_MODEL` має вищий пріоритет.

```json
{ "model": "opus" }
```

#### `agent`
**Тип:** string | **Область дії:** всі | **Типово:** немає

Запуск основного потоку виконання як іменованого субагента. Застосовує системний промпт цього агента, обмеження на інструменти та модель. Значення має збігатися з ім'ям агента, визначеного в `.claude/agents/`. Також доступно через прапорець командного рядка `--agent`.

```json
{ "agent": "code-reviewer" }
```

#### `language`
**Тип:** string | **Область дії:** всі | **Типово:** `"english"`

Бажана мова відповідей Claude. Також встановлює мову для розпізнавання голосового диктування. Приклади: `"ukrainian"`, `"japanese"`, `"spanish"`, `"french"`.

#### `cleanupPeriodDays`
**Тип:** number | **Область дії:** всі | **Типово:** `30`

Сесії, які є неактивними довше цієї кількості днів, автоматично видаляються при запуску. Встановлення значення `0` призведе до видалення всіх існуючих транскриптів при запуску та повного вимкнення збереження сесій: файли `.jsonl` не записуватимуться, команда `/resume` не показуватиме розмов, а хуки отримуватимуть порожній `transcript_path`.

#### `autoUpdatesChannel`
**Тип:** string | **Область дії:** всі | **Типово:** `"latest"`  
**Значення:** `"latest"` | `"stable"`

Канал випуску оновлень, якого слід дотримуватися. Канал `"stable"` зазвичай відстає від `"latest"` приблизно на один тиждень і пропускає версії з серйозними виявленими регресіями.

#### `alwaysThinkingEnabled`
**Тип:** boolean | **Область дії:** всі | **Типово:** `false`

Увімкнути розширене міркування (extended thinking) за замовчуванням для всіх сесій. Зазвичай конфігурується через інтерфейсну команду `/config`, а не прямим редагуванням файлу.

#### `includeGitInstructions`
**Тип:** boolean | **Область дії:** всі | **Типово:** `true`

Включає вбудовані інструкції щодо робочого процесу комітів та PR, а також моментальний знімок стану git (git status snapshot) в системний промпт. Встановіть `false`, якщо ви використовуєте кастомний скіл для роботи з git. Змінна оточення `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS` має вищий пріоритет.

#### `voiceEnabled`
**Тип:** boolean | **Область дії:** user | **Типово:** немає

Увімкнути голосове диктування в режимі push-to-talk. Записується автоматично, коли ви запускаєте команду `/voice`. Вимагає наявності акаунту на Claude.ai.

#### `companyAnnouncements`
**Тип:** array of strings | **Область дії:** всі | **Типово:** немає

Оголошення компанії, що показуються користувачам при запуску. Кілька оголошень циклічно змінюються у випадковому порядку.

```json
{
  "companyAnnouncements": [
    "Welcome to Acme Corp! Review code guidelines at docs.acme.com",
    "All PRs require code review before merge"
  ]
}
```

#### `availableModels`
**Тип:** array of strings | **Область дії:** всі | **Типово:** немає

Обмежує список моделей, які користувачі можуть обрати за допомогою команди `/model`, прапорця `--model`, інтерфейсу налаштування Config або змінної `ANTHROPIC_MODEL`. Не впливає на опцію "Default", якщо не ввімкнено `enforceAvailableModels`.

```json
{ "availableModels": ["sonnet", "haiku"] }
```

#### `fastModePerSessionOptIn`
**Тип:** boolean | **Область дії:** всі | **Типово:** `false`

Коли встановлено `true`, швидкий режим (fast mode) не зберігається між сесіями. Кожна сесія починається з вимкненим швидким режимом, вимагаючи від користувачів увімкнути його за допомогою `/fast`. Вибір користувача все одно зберігається.

#### `teammateMode`
**Тип:** string | **Область дії:** всі | **Типово:** `"auto"`  
**Значення:** `"auto"` | `"in-process"` | `"tmux"`

Спосіб відображення напарників (teammates) в агентних командах. Значення `"auto"` використовує розділені панелі (split panes) у tmux або iTerm2, інакше використовується `"in-process"`.

#### `showClearContextOnPlanAccept`
**Тип:** boolean | **Область дії:** всі | **Типово:** `false`

Показувати опцію "очистити контекст" (clear context) на екрані прийняття плану. Встановіть `true`, щоб повернути цю опцію, яка була прихована за замовчуванням, починаючи з версії v2.1.81.

#### `feedbackSurveyRate`
**Тип:** number | **Область дії:** всі | **Типово:** немає

Ймовірність (від 0 до 1), з якою опитування про якість сесії з'являтиметься при завершенні. Встановіть `0`, щоб повністю вимкнути його. Корисно при використанні Bedrock, Vertex або Foundry.

#### `disableAutoMode`
**Тип:** string | **Область дії:** всі | **Типово:** немає  
**Значення:** `"disable"`

Встановіть значення `"disable"`, щоб запобігти активації автоматичного режиму (auto mode). Видаляє варіант `auto` з циклу перемикання `Shift+Tab` та відхиляє прапорець запуску `--permission-mode auto`.

#### `useAutoModeDuringPlan`
**Тип:** boolean | **Область дії:** user / local | **Типово:** `true`

Чи використовує режим планування (plan mode) семантику автоматичного режиму, коли останній є доступним. Не зчитується зі спільних налаштувань проекту.

#### `autoMode`
**Тип:** object | **Область дії:** user / local | **Типово:** немає

Костомізація класифікатора автоматичного режиму. Містить масиви текстових правил `environment`, `allow` та `soft_deny`. Не зчитується зі спільних налаштувань проекту.

#### `defaultShell`
**Тип:** string | **Область дії:** всі | **Типово:** `"bash"`  
**Значення:** `"bash"` | `"powershell"`

Оболонка за замовчуванням для виконання команд `!`. Використання `"powershell"` вимагає встановленої змінної оточення `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`.

#### `skipWebFetchPreflight` `📋 Тільки схема`
**Тип:** boolean | **Область дії:** всі | **Типово:** `false`

Пропускати перевірку чорного списку (blocklist check) перед викликом інструменту WebFetch для завантаження URL.

#### `env`
**Тип:** object | **Область дії:** всі | **Типово:** немає

Змінні оточення, які застосовуються до кожної сесії. Використовуйте цей ключ замість обгорткових скриптів для встановлення змінних. Усі підтримувані ключі дивіться в розділі [Змінні оточення](#змінні-оточення-environment-variables).

```json
{
  "env": {
    "NODE_ENV": "development",
    "CLAUDE_CODE_EFFORT_LEVEL": "medium"
  }
}
```

### Плани та Пам'ять (Plans and Memory)

#### `plansDirectory`
**Тип:** string | **Область дії:** всі | **Типово:** `"~/.claude/plans"`

Директорія, де зберігаються результати роботи команди `/plan`. Шлях вказується відносно кореня проекту.

#### `autoMemoryEnabled`
**Тип:** boolean | **Область дії:** всі | **Типово:** `true`

Увімкнути або вимкнути функцію автоматичної пам'яті, яка автоматично накопичує та зберігає контекст між сесіями.

#### `autoMemoryDirectory`
**Тип:** string | **Область дії:** user / local / managed | **Типово:** немає

Кастомна директорія для збереження файлів автоматичної пам'яті. Приймає шляхи з розширенням символу `~/`. Не дозволяється до використання в проектних налаштуваннях (`.claude/settings.json`) з міркувань безпеки, щоб запобігти перенаправленню записів пам'яті спільними репозиторіями у чутливі місця на диску.

### Дозволи (Permissions)

Керування тим, які інструменти та операції Claude може виконувати.

#### `permissions.allow`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Правила дозволів, які дозволяють запуск інструментів без запиту підтвердження користувача. Масиви об'єднуються на всіх рівнях конфігу. Дивіться розділ [Синтаксис правил дозволів](#синтаксис-правил-дозволів-permission-rule-syntax) нижче.

#### `permissions.ask`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Правила дозволів, які вимагають обов'язкового підтвердження користувача перед викликом інструменту.

#### `permissions.deny`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Правила дозволів, які повністю блокують використання інструментів. Мають найвищий пріоритет безпеки — не можуть бути змінені чи обійдені правилами allow або ask на будь-якому рівні.

#### `permissions.additionalDirectories`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Додаткові робочі директорії, до яких Claude має доступ, окрім поточного кореня проекту.

```json
{ "permissions": { "additionalDirectories": ["../shared-libs/"] } }
```

#### `permissions.defaultMode`
**Тип:** string | **Область дії:** всі | **Типово:** не задано (вбудований початковий режим для поверхні: `auto` в інтерактивних сесіях термінала та VS Code з v2.1.283)  
**Значення:** `"default"` (псевдонім `"manual"`) | `"acceptEdits"` | `"plan"` | `"auto"` | `"dontAsk"` | `"bypassPermissions"`

Режим дозволів за замовчуванням при запуску Claude Code. `auto` та `bypassPermissions` діють лише з налаштувань користувача чи managed (або через `--permission-mode`), а не з налаштувань проєкту чи локальних. У віддалених (Remote) середовищах підтримуються та виконуються лише режими `"acceptEdits"` та `"plan"`.

#### `permissions.disableBypassPermissionsMode`
**Тип:** string | **Область дії:** всі | **Типово:** немає  
**Значення:** `"disable"`

Встановіть значення `"disable"`, щоб запобігти активації режиму `bypassPermissions` (обхід дозволів). Вимикає дію прапорця командного рядка `--dangerously-skip-permissions`. Найбільш корисно в керованих (managed) налаштуваннях організації.

#### `allowManagedPermissionRulesOnly`
**Тип:** boolean | **Область дії:** managed only | **Типово:** `false`

Коли встановлено `true`, користувацькі та проектні правила `allow`, `ask` та `deny` повністю ігноруються. Застосовуються виключно правила дозволів з керованого рівня (managed settings).

### Синтаксис правил дозволів (Permission Rule Syntax)

Правила записуються у форматі `Tool` або `Tool(specifier)`. Порядок оцінки: спочатку перевіряються правила `deny`, потім `ask`, потім `allow`. Перше правило, яке збіглося, перемагає.

| Інструмент | Патерн | Приклад |
|------|---------|---------|
| `Bash` | Патерн команди з вайлдкардами | `Bash(npm run *)`, `Bash(git *)` |
| `Read` | Патерн шляху до файлу | `Read(.env)`, `Read(./secrets/**)` |
| `Edit` | Патерн шляху до файлу | `Edit(src/**)`, `Edit(*.ts)` |
| `Write` | Патерн шляху до файлу | `Write(*.md)` |
| `WebFetch` | `domain:hostname` | `WebFetch(domain:example.com)` |
| `WebSearch` | Без специфікатора | `WebSearch` |
| `Task` | Назва агента | `Task(Explore)` |
| `Agent` | Назва субагента | `Agent(researcher)` |
| `MCP` | `mcp__server__tool` або `MCP(server:tool)` | `mcp__memory__*` |

**Префікси шляхів для правил Read/Edit/Write:**

| Префікс | Значення |
|--------|---------|
| `//` | Абсолютний шлях від кореня файлової системи |
| `~/` | Шлях відносно домашньої директорії користувача |
| `/` | Шлях відносно кореня поточного проекту |
| `./` або без префікса | Відносний шлях (від поточної робочої директорії) |

**Примітки щодо вайлдкардів для Bash:** Символ `*` збігається з будь-якою позицією. Запис `Bash(ls *)` (з пробілом перед зірочкою) збігається з `ls -la`, але НЕ збігається з командою `lsof`. Запис `Bash(*)` еквівалентний простому `Bash` (збігається абсолютно з усіма командами). Застарілий формат суфікса `:` (наприклад, `Bash(npm:*)`) оголошений deprecated.

```json
{
  "permissions": {
    "allow": ["Edit(*)", "Bash(npm run *)", "Bash(git *)"],
    "ask": ["Bash(git push *)"],
    "deny": ["Read(.env)", "Read(./secrets/**)"],
    "defaultMode": "acceptEdits"
  }
}
```

### Хуки (Hooks)

#### `hooks`
**Тип:** object | **Область дії:** всі | **Типово:** немає

Конфігурація кастомних команд для запуску на різні події життєвого циклу сесії. Зверніться до [документації з хуків](https://code.claude.com/docs/en/hooks) для ознайомлення з форматом, повним набором із 33 подій хуків, кодами виходу та доступними змінними оточення, а також до [розділу 7.1 посібника](../ultimate-guide.uk.md#71-система-подій).

#### `disableAllHooks`
**Тип:** boolean | **Область дії:** всі | **Типово:** `false`

Повністю вимкнути запуск усіх хуків та відображення будь-якого кастомного рядка стану (status line).

#### `allowManagedHooksOnly`
**Тип:** boolean | **Область дії:** managed only | **Типово:** `false`

Коли встановлено `true`, завантажуються виключно керовані (managed) хуки та SDK-хуки. Хуки користувача, проекту та плагінів повністю блокуються.

#### `allowedHttpHookUrls`
**Тип:** array of strings | **Область дії:** всі | **Типово:** немає (без обмежень)

Список дозволених URL-патернів, які можуть викликати HTTP-хуки. Підтримує символ `*` як вайлдкард. Якщо визначено, хуки з невідповідними URL будуть мовчки заблоковані. Порожній масив блокує запуск абсолютно всіх HTTP-хуків. Масиви об'єднуються на всіх рівнях налаштувань.

```json
{ "allowedHttpHookUrls": ["https://hooks.example.com/*"] }
```

#### `httpHookAllowedEnvVars`
**Тип:** array of strings | **Область дії:** всі | **Типово:** немає (без обмежень)

Список дозволених імен змінних оточення, які HTTP-хуки можуть інтерполювати в значення заголовків запитів. Результуючий список `allowedEnvVars` для кожного хука є перетином з цим глобальним списком. Масиви об'єднуються на всіх рівнях налаштувань.

### Сервери MCP (MCP Servers)

#### `enableAllProjectMcpServers`
**Тип:** boolean | **Область дії:** всі | **Типово:** `false`

Автоматично схвалювати запуск усіх серверів MCP, які визначені у файлах `.mcp.json` проекту. Запобігає появі діалогових вікон підтвердження для кожного окремого сервера.

#### `enabledMcpjsonServers`
**Тип:** array of strings | **Область дії:** всі | **Типово:** немає

Список дозволених імен конкретних серверів з файлів `.mcp.json` для схвалення.

#### `disabledMcpjsonServers`
**Тип:** array of strings | **Область дії:** всі | **Типово:** немає

Список заблокованих імен конкретних серверів з файлів `.mcp.json` для відхилення.

#### `allowedMcpServers`
**Тип:** array | **Область дії:** managed only | **Типово:** немає (без обмежень)

Список дозволених серверів MCP, які користувачі можуть конфігурувати. Кожен запис перевіряється на збіг за параметрами `serverName`, `serverCommand` або `serverUrl`. Значення undefined знімає обмеження, порожній масив — режим повної заборони.

```json
{
  "allowedMcpServers": [
    { "serverName": "github" },
    { "serverCommand": "npx @modelcontextprotocol/*" },
    { "serverUrl": "https://mcp.company.com/*" }
  ]
}
```

#### `deniedMcpServers`
**Тип:** array | **Область дії:** managed only | **Типово:** немає

Список серверів MCP, які є явно заблокованими. Застосовується на всіх рівнях, включаючи керовані сервери. Має вищий пріоритет перед списком `allowedMcpServers`.

#### `allowManagedMcpServersOnly`
**Тип:** boolean | **Область дії:** managed only | **Типово:** `false`

Коли встановлено `true`, виконуються виключно сервери з масиву `allowedMcpServers` керованих налаштувань. Користувачі все ще можуть додавати сервери MCP, але працюватимуть лише сервери, визначені адміністратором. Список `deniedMcpServers` продовжує об'єднуватися з усіх джерел.

#### `channelsEnabled`
**Тип:** boolean | **Область дії:** managed only | **Типово:** `false`

Дозволити використання каналів (channels) для користувачів планів claude.ai Team та Enterprise. Якщо не встановлено або дорівнює `false`, доставка повідомлень каналів блокується, незалежно від параметрів, які користувачі передають у `--channels`. Розгортання з API-ключами Console використовують типові значення Console та керовані засоби контролю; не робіть висновків про їхню політику з цього налаштування, що стосується лише Team/Enterprise.

#### `allowedChannelPlugins`
**Тип:** array | **Область дії:** managed only | **Типово:** немає (використовує дефолтний білий список Anthropic)

Список дозволених плагінів каналів, які можуть надсилати повідомлення. Перевизначає стандартний список дозволених плагінів Anthropic. Вимагає увімкненого параметра `channelsEnabled: true`. Порожній масив блокує всі плагіни каналів.

> **Межа безпеки**: цей список дозволених визначає, які плагіни каналів можуть доставляти повідомлення. Він не надає доставленому повідомленню, його відправникові чи плагіну жодних дозволів на Bash, файлову систему, GitHub чи інші інструменти. Обмежуйте відправників і ставтеся до вмісту каналу як до недовіреного вводу, зокрема коли плагін може передавати запит на дозвіл.

### Пісочниця (Sandbox)

Налаштування ізоляції для команд bash з міркувань безпеки. Працює на macOS, Linux та WSL2.

#### `sandbox.enabled`
**Тип:** boolean | **Область дії:** всі | **Типово:** `false`

Увімкнути ізоляцію команд у пісочниці. Повністю ізолює команди bash від вашої локальної файлової системи та мережі.

#### `sandbox.failIfUnavailable`
**Тип:** boolean | **Область дії:** всі | **Типово:** `false`

Завершити роботу з помилкою при запуску, якщо параметр `sandbox.enabled` дорівнює `true`, але пісочниця не може бути ініціалізована (через відсутність системних залежностей або непідтримувану платформу). Якщо встановлено `false`, показується попередження, а команди виконуються без ізоляції. Дуже корисно для корпоративних середовищ, де використання пісочниці є жорсткою безпековою вимогою.

#### `sandbox.autoAllowBashIfSandboxed`
**Тип:** boolean | **Область дії:** всі | **Типово:** `true`

Автоматично дозволяти виконання команд bash, якщо вони ізольовані у пісочниці. Коли пісочниця активна, команди bash, які зазвичай вимагали б ручного підтвердження користувача, схвалюються автоматично.

#### `sandbox.excludedCommands`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Список команд, які виконуються без пісочниці безпосередньо у вашому локальному оточенні (наприклад, `git push *` або `docker *`).

> **Використовуйте форму з glob, а не голе ім'я.** Голий запис на кшталт `"git"` збігається лише з рядком `git` без аргументів, тож ніколи не спрацьовує на справжній виклик, і команда лишається в пісочниці. Пишіть `"git *"`. Опублікована JSON-схема підказує саме голу форму, тому тут так легко помилитися: ви налаштовуєте щось недієве, помічаєте, що команда все ще в пісочниці, і лише тоді знаходите форму з glob ([anthropics/claude-code#10524](https://github.com/anthropics/claude-code/issues/10524)). Перевірено на 2.1.220: `"git"` не мав ефекту, `"git *"` спрацював одразу.

> **Кожна команда у виклику має збігатися (v2.1.277+).** Claude Code звіряє записи з усім командним рядком, який надсилає. `npm ci && docker compose build` лишається в пісочниці, якщо інший запис не охоплює `npm ci`, а перенаправлення у файл, `cd`, цикл чи підстановка `$(...)` залишають усю команду в пісочниці. До v2.1.277 одна відповідна команда знімала пісочницю з усього виклику, зокрема з команд, що виконувалися перед нею ([anthropics/claude-code#81157](https://github.com/anthropics/claude-code/issues/81157)). Записи збігаються з текстом виклику: `git -C <path> push`, `/usr/local/bin/docker` і скрипт, що викликає інструмент усередині, не збігаються.
>
> Виключена команда виконується без обмежень файлової системи й без проксі, тож може дістатися будь-якого хоста, а не лише `allowedDomains`. Обмежуйте записи підкомандами, яким справді потрібно вийти з пісочниці, а не цілим бінарним файлом. Git поверх SSH на macOS є поширеним випадком (на Linux і WSL2 він працює в пісочниці, щойно хост дозволено): виняток потрібен лише для мережевих операцій, тож перелічіть їх і залиште локальний git обмеженим.
>
> Коли пісочниця admin-required (`allowUnsandboxedCommands: false` із managed-налаштувань або `--settings`, або managed `allowManagedDomainsOnly`), записи в `.claude/settings.json` і `.claude/settings.local.json` репозиторію ігноруються (v2.1.282+).
>
> ```json
> "excludedCommands": [
>   "git push *", "git pull *", "git fetch *",
>   "git clone *", "git ls-remote *", "git remote *", "git submodule *"
> ]
> ```
>
> Це залишає `git status`, `git diff`, `git log`, `git add` і `git commit` усередині пісочниці.

#### `sandbox.allowUnsandboxedCommands`
**Тип:** boolean | **Область дії:** всі | **Типово:** `true`

Дозволити командам обходити пісочницю за допомогою параметру `dangerouslyDisableSandbox`. Встановіть `false` для суворого режиму безпеки, коли всі без винятку команди мають виконуватися в пісочниці або бути явно присутніми в списку `excludedCommands`. Вкладка Overrides в `/sandbox` показує `false` як **Strict sandbox mode**.

Починаючи з v2.1.285, `false` у налаштуваннях користувача, `--settings` або managed-налаштуваннях діє, навіть коли проєкт установлює `true` (раніше перемагав `true` проєкту). `false` із managed-налаштувань або `--settings` також робить пісочницю admin-required: Claude Code тоді ігнорує налаштування репозиторію, що її послабили б, зокрема `excludedCommands`. Дивіться [sandbox, що вимагає адміністратора](../security/sandbox-native.uk.md#sandbox-що-вимагає-адміністратора-admin-required).

#### `sandbox.enableWeakerNestedSandbox`
**Тип:** boolean | **Область дії:** всі | **Типово:** `false`

Увімкнути слабший режим ізоляції для невластивих Docker-середовищ без привілеїв (лише для Linux та WSL2). Знижує рівень безпеки.

#### `sandbox.enableWeakerNetworkIsolation`
**Тип:** boolean | **Область дії:** всі | **Типово:** `false`

(Тільки для macOS) Дозволити доступ до системної служби сертифікатів довіри (`com.apple.trustd.agent`). Необхідно для коректної роботи інструментів на Go, таких як `gh`, `gcloud` та `terraform`, при використанні `httpProxyPort` разом із MITM-проксі та кастомним центром сертифікації (CA). Знижує рівень безпеки.

#### `sandbox.network.allowUnixSockets`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Конкретні шляхи до Unix-сокетів, доступні всередині пісочниці на macOS (наприклад, SSH-агенти, локальні бази даних тощо). Ігнорується на Linux і WSL2, де фільтр seccomp не може інспектувати шляхи сокетів; використовуйте `allowAllUnixSockets` лише після прийняття його ширшої межі. [Випадок inbox між сесіями](../security/sandbox-native.uk.md#inbox-сокети-між-сесіями) не потребує цього винятку для звичайних викликів `SendMessage`.

#### `sandbox.network.allowAllUnixSockets`
**Тип:** boolean | **Область дії:** всі | **Типово:** `false`

Дозволити підключення до всіх Unix-сокетів у пісочниці. Перевизначає параметр `allowUnixSockets`. На Linux і WSL2 це єдиний спосіб дозволити Unix-сокети, бо він пропускає фільтр seccomp, що інакше блокує виклики `socket(AF_UNIX, ...)`.

#### `sandbox.network.allowLocalBinding`
**Тип:** boolean | **Область дії:** всі | **Типово:** `false`

Дозволити біндинг (binding) до портів localhost (лише для macOS). Тоді команди в пісочниці можуть слухати мережеві порти та підключатися до будь-якого порту на localhost, зокрема до кожної іншої служби, що там слухає; неавтентифікована локальна служба, як-от debugger, може тоді діяти від імені команди поза пісочницею. На Linux і WSL2 `localhost` команди в пісочниці є приватним для неї, і цей ключ не має ефекту.

#### `sandbox.network.allowedDomains`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Список доменів, до яких дозволено вихідний мережевий трафік з пісочниці. Підтримує вайлдкарди типу `*.example.com`.

#### `sandbox.network.allowManagedDomainsOnly`
**Тип:** boolean | **Область дії:** managed only | **Типово:** `false`

Коли встановлено `true`, виконуються виключно правила дозволу доменів `allowedDomains` та `WebFetch(domain:...)` з керованих (managed) налаштувань. Усі неперелічені домени блокуються без запиту користувача. Заборонені домени (denied) продовжують діяти з усіх джерел.

#### `sandbox.network.httpProxyPort`
**Тип:** number | **Область дії:** всі | **Типово:** немає

Порт HTTP-проксі для кастомного проксі-сервера (від 1 до 65535). Якщо не вказано, Claude Code запускає та використовує свій власний проксі.

#### `sandbox.network.socksProxyPort`
**Тип:** number | **Область дії:** всі | **Типово:** немає

Порт SOCKS5 для кастомного проксі-сервера (від 1 до 65535).

#### `sandbox.network.deniedDomains`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Домени, до яких команди в пісочниці не можуть дістатися ніколи, навіть коли ширший wildcard `allowedDomains` їх дозволив би. Заборонений хост відхиляється в кожному режимі дозволів, і список `allowed_domains` для окремої команди в auto mode не може його відкрити. Заданий у managed-налаштуваннях або `--settings`, він також не дає репозиторію встановлювати порти проксі (v2.1.285+). IPv6-адреси використовують форму в дужках, `"[::1]"` або `"[::1]:443"` (v2.1.229+).

#### `sandbox.filesystem.allowWrite`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Додаткові шляхи на диску, куди команди всередині пісочниці можуть записувати файли. Об'єднується з усіх рівнів налаштувань. Також об'єднується зі шляхами з правил дозволів типу `Edit(...)`.

**Синтаксис префіксів:** `/` = абсолютний шлях, `~/` = шлях від домашньої папки, `./` або без префікса = шлях відносно кореня проекту (в налаштуваннях проекту) / відносно `~/.claude` (у глобальних налаштуваннях користувача).

#### `sandbox.filesystem.denyWrite`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Шляхи на диску, куди ізольовані команди не мають права записувати дані. Об'єднується з правилами заборони `Edit(...)`.

#### `sandbox.filesystem.denyRead`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Шляхи на диску, звідки ізольовані команди не мають права зчитувати дані. Об'єднується з правилами заборони `Read(...)`.

#### `sandbox.filesystem.allowRead`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Шляхи для відновлення прав доступу на читання всередині областей заборони `denyRead`. Має вищий пріоритет над `denyRead`. Масиви об'єднуються на всіх рівнях конфігу.

Коли правила читання перетинаються, конкретніший шлях перемагає в обох напрямках: `denyRead: ["~/"]` з `allowRead: ["~/projects"]` відкриває лише це піддерево, а `allowRead: ["~/"]` з `denyRead: ["~/.env"]` тримає цей один файл заблокованим. Широкий дозвіл не може непомітно знову відкрити секрет, який охоплює точна заборона.

#### `sandbox.filesystem.disabled`
**Тип:** boolean | **Область дії:** user, managed, `--settings` (налаштування проєкту ігноруються) | **Типово:** `false` | **Починаючи з:** v2.1.216

Пропустити ізоляцію файлової системи, зберігши мережеву ізоляцію. Команди в пісочниці отримують необмежений доступ на читання й запис до хоста, а їхній вихідний трафік залишається обмеженим `allowedDomains`. Використовуйте, коли мета пісочниці полягає в контролі того, куди команди підключаються, а не що вони пишуть.

Вимкнення цього шару також вимикає `filesystem.denyRead`, `credentials.files` і захист власних файлів налаштувань Claude Code, а також припиняє перевизначення `$TMPDIR`. `credentials.envVars` і далі діє, бо очищення середовища не залежить від шару файлової системи.

Налаштування проєкту не можуть його встановити, тож клонований репозиторій не може вимкнути ізоляцію файлової системи. Коли managed-налаштування взагалі конфігурують `sandbox.filesystem` або перелічують будь-який запис `credentials.files`, лише managed-налаштування можуть його встановити. `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` змушує Claude Code ігнорувати його з будь-якого джерела.

> Коли шар файлової системи вимкнено, а команди схвалюються автоматично, команда в пісочниці може записати startup-файли оболонки, виконувані файли з `$PATH` або `~/.claude/settings.json` і використати їх, щоб розширити власний доступ під час наступного запуску. Встановлюйте це лише для навантажень, які, як ви довіряєте, не ескалюватимуть.

#### `sandbox.credentials.files`
**Тип:** array of `{ path, mode }` | **Область дії:** всі (`deny` лише звужує, тож будь-який рівень може додати запис) | **Типово:** `[]` | **Починаючи з:** v2.1.187

Файли облікових даних, які слід сховати від команд у пісочниці. `mode` приймає `"deny"`, що блокує читання так само, як `filesystem.denyRead`, і `"mask"` (v2.1.221+). З `mask` на Linux і WSL2 команди в пісочниці читають копію-sentinel, а проксі підставляє справжнє значення при виході; на macOS файл просто нечитабельний, що дає той самий ефект, що й `deny`, тож інструмент, який автентифікується через нього, перестає працювати всередині пісочниці. Часткове маскування використовує `extract` (регулярний вираз, що позначає секрет), `decode: "jwt"` з `maskClaims`, `onExtractNoMatch` і `maskDuplicates` (v2.1.224+). Типове `onExtractNoMatch: "warn"` пропускає запис, коли шаблон нічого не знаходить, залишаючи справжній файл читабельним; використовуйте `deny`, коли секрет може бути присутнім, але шаблон може його пропустити. Запис `mask` для директорії, glob, файлу понад 8 МіБ чи не-UTF-8 файлу повертається до `deny`. `mask` враховується лише з налаштувань user, managed і `--settings`.

Типова політика читання пісочниці охоплює **всю машину**, і вбудованого denylist облікових даних немає, тож `~/.ssh` і `~/.aws/credentials` доступні для читання кожній команді в пісочниці, доки ви їх не перелічите. Шляхи підпорядковуються тим самим правилам префіксів, що й `sandbox.filesystem.*`, а записи `deny` об'єднуються на всіх рівнях: будь-який рівень може додати запис, жоден не може прибрати запис, доданий іншим рівнем.

```json
{
  "sandbox": {
    "credentials": {
      "files": [
        { "path": "~/.ssh", "mode": "deny" },
        { "path": "~/.aws", "mode": "deny" },
        { "path": "~/.gnupg", "mode": "deny" },
        { "path": "~/.config/gh", "mode": "deny" }
      ]
    }
  }
}
```

Перевірено на 2.1.220: із цим записом `ls ~/.ssh` із команди в пісочниці повертає `Operation not permitted`, тоді як сама директорія все ще з'являється в переліку домашньої директорії.

#### `sandbox.credentials.envVars`
**Тип:** array of `{ name, mode, injectHosts? }` | **Область дії:** `deny` з усіх рівнів; `mask` лише з user, managed, `--settings` | **Типово:** `[]` | **Починаючи з:** v2.1.187 (`deny`), v2.1.199 (`mask`)

Змінні оточення, які слід приховати від команд у пісочниці. Інакше команди в пісочниці успадковують батьківське середовище як є, включно з обліковими даними, і саме цю прогалину залишає відкритою одиничний запис `credentials.files`.

`deny` скасовує встановлення змінної перед кожною командою в пісочниці. Це стосується лише Bash у пісочниці, тож MCP-сервери зберігають свої облікові дані: вони працюють як окремі процеси, а не як команди в пісочниці. Wildcards на кшталт `AWS_*` не підтримуються; перелічуйте кожну змінну. Startup-файл оболонки може це скасувати: zsh читає `~/.zshenv` при кожному запуску, тож змінна, експортована там, знову встановлюється всередині команди в пісочниці, як виміряно на v2.1.302 (дивіться [Поведінка за замовчуванням](../security/sandbox-native.uk.md#поведінка-за-замовчуванням) щодо перевірки та захисту через `CLAUDECODE`).

Для структурованих значень, як-от `DATABASE_URL` або JWT, `extract`, `decode`, `maskClaims` і `onExtractNoMatch` зберігають працездатність інструментів розбору (v2.1.224+). Запити AWS SigV4 потребують спільного маскування `AWS_ACCESS_KEY_ID` і `AWS_SECRET_ACCESS_KEY`, щоб проксі міг їх повторно підписати (v2.1.221+); групуйте змінні з нестандартними назвами через `credentials.awsPairs` і використовуйте `credentials.sigv4`, щоб пересилати потокові завантаження, presigned URL чи запити SigV4A, які проксі не може повторно підписати (обидва v2.1.224+). `claude doctor` попереджає, коли завершення TLS недоступне або запис `injectHosts` ніколи не може збігтися.

`mask` захищає облікові дані, зберігаючи працездатність інструмента, який ними автентифікується. Команда бачить sentinel для кожної сесії; коли запит залишає пісочницю до одного з `injectHosts` облікових даних, проксі підставляє справжнє значення. Команда та все, що вона логує, ніколи не містять справжніх облікових даних. Кожен запис `injectHosts` має сам бути охоплений `allowedDomains`, а `network.tlsTerminate` обов'язковий, бо проксі має бачити вміст запитів, щоб підставляти. Без нього маскування відмовляє закрито (fails closed): sentinel досягає сервера без змін, автентифікація не вдається, і Claude Code повідомляє про помилку конфігурації під час запуску.

```json
{
  "sandbox": {
    "network": { "tlsTerminate": {}, "allowedDomains": ["*.github.com"] },
    "credentials": {
      "envVars": [
        { "name": "ANTHROPIC_API_KEY", "mode": "deny" },
        { "name": "GH_TOKEN", "mode": "mask", "injectHosts": ["api.github.com"] }
      ]
    }
  }
}
```

`deny` перемагає, коли та сама змінна з'являється з обома режимами на будь-якому рівні. Починайте з `deny` і переводьте змінну на `mask` лише тоді, коли CLI справді ламається без неї, бо `mask` вимагає завершення TLS і уповноважує проксі надсилати справжні облікові дані переліченим хостам.

Щоб прибрати облікові дані Anthropic і хмарних провайдерів з **усіх** підпроцесів незалежно від пісочниці, натомість встановіть `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB`.

#### `sandbox.network.tlsTerminate` `⚠️ Experimental`
**Тип:** object | **Область дії:** user, managed, `--settings` (налаштування проєкту ігноруються) | **Починаючи з:** v2.1.199

Змусити вбудований проксі самому завершувати TLS. Потрібно для записів `mask` у `credentials.envVars` і `credentials.files`. Це вмикає підстановку облікових даних; фільтрації вмісту воно не додає.

#### `sandbox.network.strictAllowlist`
**Тип:** boolean | **Область дії:** user, managed, `--settings` (налаштування проєкту ігноруються) | **Типово:** `false` | **Починаючи з:** v2.1.219

Забороняти командам у пісочниці будь-який хост поза allowlist замість показу запиту. Allowlist складається з `allowedDomains` плюс доменів із правил allow `WebFetch(domain:...)`, або лише з managed-записів, коли встановлено `allowManagedDomainsOnly`. Застосовується лише до команд у пісочниці: інструменти в процесі, як-от `WebFetch`, і далі підпорядковуються своїм правилам дозволів.

Вмикайте його останнім, коли список доменів пройшов тиждень реальної роботи. До цього він перетворює кожен відсутній домен із одноразового запиту на жорстку помилку.

#### `sandbox.allowAppleEvents`
**Тип:** boolean | **Область дії:** user, managed, `--settings` (налаштування проєкту ігноруються) | **Типово:** `false`

Дозволити Apple Events на macOS, які пісочниця блокує за замовчуванням. Виправляє збої `open`, `osascript` і браузерних потоків автентифікації з помилкою `-600`.

> Його ввімкнення прибирає ізоляцію виконання коду: команди в пісочниці можуть запускати інші застосунки без пісочниці без запиту та надсилати AppleScript до запущених застосунків, з урахуванням запиту згоди macOS на автоматизацію. Віддавайте перевагу додаванню конкретної команди до `excludedCommands`.

#### `sandbox.filesystem.allowManagedReadPathsOnly`
**Тип:** boolean | **Область дії:** managed only | **Типово:** `false`

Коли встановлено `true`, виконуються виключно шляхи `allowRead` з керованих (managed) налаштувань. Записи `allowRead` з налаштувань користувача, проекту та локальних конфігів ігноруються.

**Приклад налаштування пісочниці:**
```json
{
  "sandbox": {
    "enabled": true,
    "autoAllowBashIfSandboxed": true,
    "excludedCommands": ["git push *", "git fetch *", "docker *"],
    "filesystem": {
      "allowWrite": ["/tmp/build", "~/.kube"],
      "denyRead": ["~/.aws/credentials"]
    },
    "network": {
      "allowedDomains": ["github.com", "*.npmjs.org"],
      "allowLocalBinding": true
    }
  }
}
```

Винятки для Unix-сокетів навмисно відсутні в цій базовій конфігурації. Надання `/var/run/docker.sock` дало б коду в пісочниці керування демоном Docker і ефективний шлях до хоста.

### Плагіни та Маркетплейси (Plugins and Marketplaces)

Про публікацію в маркетплейсі та межу рекомендаційних підказок `<claude-code-hint />` дивіться [Plugin Distribution and Recommendation Hints](../ecosystem/plugin-distribution.uk.md). Налаштування нижче керують локальними та managed-контролями маркетплейсів.

#### `enabledPlugins`
**Тип:** object | **Область дії:** всі | **Типово:** немає

Увімкнути або вимкнути конкретні плагіни за їхнім ключем (формат ключа: `plugin-name@marketplace-name`).

```json
{
  "enabledPlugins": {
    "formatter@acme-tools": true,
    "experimental@acme-tools": false
  }
}
```

#### `extraKnownMarketplaces`
**Тип:** object | **Область дії:** project | **Типово:** немає

Додати кастомні маркетплейси плагінів. Використовуйте значення `"source": "settings"`, щоб оголошувати плагіни inline без необхідності хостити зовнішній репозиторій.

#### `strictKnownMarketplaces`
**Тип:** array | **Область дії:** managed only | **Типово:** немає (без обмежень)

Список дозволених маркетплейсів плагінів. Коли задано, користувачі можуть встановлювати плагіни лише із зазначених джерел. Порожній масив повністю блокує встановлення будь-яких плагінів.

#### `blockedMarketplaces`
**Тип:** array | **Область дії:** managed only | **Типово:** немає

Чорний список (blocklist) джерел маркетплейсів плагінів. Вони перевіряються перед завантаженням, тому заблоковані плагіни ніколи не потраплять на диск.

#### `pluginTrustMessage`
**Тип:** string | **Область дії:** managed only | **Типово:** немає

Кастомне повідомлення, яке додається до стандартного попередження про довіру до плагіна, що показується перед його встановленням. Корисно для корпоративних середовищ (наприклад, для підтвердження того, що плагіни з внутрішнього маркетплейсу пройшли аудит безпеки).

#### `skippedMarketplaces` `📋 Тільки схема`
**Тип:** array | **Область дії:** всі | **Типово:** немає

Маркетплейси, від встановлення яких користувач відмовився (зберігається системою автоматично).

#### `skippedPlugins` `📋 Тільки схема`
**Тип:** array | **Область дії:** всі | **Типово:** немає

Плагіни, від встановлення яких користувач відмовився (зберігається системою автоматично).

#### `pluginConfigs` `📋 Тільки схема`
**Тип:** object | **Область дії:** всі | **Типово:** немає

Конфігурації серверів MCP для кожного конкретного плагіна, які групуються за ключем `plugin@marketplace`.

### Конфігурація Моделей (Model Configuration)

#### `effortLevel`
**Тип:** string | **Область дії:** всі  
**Значення:** `"low"` | `"medium"` | `"high"` | `"xhigh"`

Резервний рівень зусиль для моделі без збереженого вибору. Типові значення залежать від моделі: Opus 5.5, Sonnet 5.5 і Haiku 5.5 використовують `medium`; Fable 5.1 використовує `high`. Застарілий Haiku 4.5 не має параметра effort. Opus 5.5 ігнорує цей застарілий ключ у налаштуваннях користувача, але явні значення проєкту, локальні, managed і `--settings` усе ще діють.

#### `modelSettings`
**Тип:** object | **Область дії:** всі

Починаючи з v2.1.251, `/effort` зберігає рівень активної моделі тут. Підтвердьте `Enter`, щоб зберегти, або `s`, щоб лише для цієї сесії. `max` діє лише в межах сесії й не може бути збережений як `effortLevel`.

```json
{
  "modelSettings": {
    "claude-opus-5-5": { "effortLevel": "high" }
  }
}
```

У межах одного файлу налаштувань рівень для конкретної моделі перемагає резервний. Між файлами діє звичайний пріоритет налаштувань. `CLAUDE_CODE_EFFORT_LEVEL` перевизначає вибраний рівень з урахуванням організаційних обмежень. `/effort auto` очищує збережений вибір для активної моделі.

#### `enforceAvailableModels`
**Тип:** boolean | **Область дії:** всі

Поєднуйте з `availableModels`, щоб тримати вибір Default у `/model` усередині цього списку дозволених. Без цього налаштування сам список дозволених не обмежує Default. Дивіться [офіційний довідник налаштувань моделей](https://code.claude.com/docs/en/settings-reference#enforceavailablemodels).

#### `modelOverrides`
**Тип:** object | **Область дії:** всі | **Типово:** немає

Зіставлення стандартних ідентифікаторів моделей Anthropic із специфічними ідентифікаторами сторонніх провайдерів (наприклад, Bedrock inference profile ARNs). Кожен ключ — назва моделі у виборі; значення — ID моделі у провайдера.

```json
{
  "modelOverrides": {
    "claude-opus-4-6": "arn:aws:bedrock:us-east-1:123456789:inference-profile/anthropic.claude-opus-4-6-v1:0"
  }
}
```

**Аліаси моделей (Model Aliases Reference):**

| Аліас | Опис |
|-------|-------------|
| `"default"` | Рекомендована модель для вашого типу акаунту |
| `"sonnet"` | Sonnet 5.5 в Anthropic API; аліаси хмарних провайдерів можуть вказувати на 4.6 або 4.5 |
| `"opus"` | Opus 5.5 у більшості провайдерів; Opus 4.6 у Foundry |
| `"haiku"` | Haiku 5.5 в Anthropic API (Claude Code v2.1.293+); Haiku 4.5 у хмарних провайдерів |
| `"fable"` | Fable 5.1, де доступно; Fable 5 через шлюз застосунків Claude |
| `"best"` | Fable, де доступно, інакше Opus |
| `"sonnet[1m]"` | Модель Sonnet із розширеним вікном контексту до 1 млн токенів |
| `"opusplan"` | Opus використовується для планування завдання, Sonnet — для його безпосереднього виконання |

### Відображення та UX (Display and UX)

#### `statusLine`
**Тип:** object | **Область дії:** всі | **Типово:** немає

Конфігурація кастомного рядка стану. Команда отримує на свій стандартний ввід (stdin) JSON-об'єкт із полями типу `context_window.used_percentage`, `rate_limits.five_hour.used_percentage` тощо.

```json
{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh",
    "padding": 0
  }
}
```

#### `fileSuggestion`
**Тип:** object | **Область дії:** всі | **Типово:** немає

Налаштування кастомного скрипта для автодоповнення шляхів до файлів через символ `@`. Скрипт отримує на stdin JSON із полем `query` та має виводити шляхи до файлів, розділені символом нового рядка (максимум 15 результатів).

```json
{
  "fileSuggestion": {
    "type": "command",
    "command": "~/.claude/file-suggestion.sh"
  }
}
```

#### `outputStyle`
**Тип:** string | **Область дії:** всі | **Типово:** `"Default"`

Визначає стиль та характер спілкування Claude протягом усієї сесії. Обирайте через `/output-style` або `/config`. Значення налаштування чутливе до регістру; команда приймає назви без урахування регістру.

**Вбудовані стилі виводу:**
- `"Default"`: без інструкцій стилю, стандартний системний промпт Claude Code
- `"Proactive"`: одразу починає реалізацію та робить розумні припущення в рутинних рішеннях; режим дозволів не змінюється
- `"Concise"`: починає з результату, без вступу, коментування процесу чи підсумкового резюме
- `"Explanatory"`: додає блоки `Insight`, що пояснюють міркування за кодом
- `"Learning"`: додає блоки `Insight` і залишає вам складні з погляду дизайну фрагменти в маркерах `TODO(human)`

Значення, що не збігається точно з назвою стилю (наприклад, `explanatory`), повертається до Default. `/output-style` і меню `/config` зберігають вибір у `.claude/settings.local.json`.

**Кастомні стилі:** вкажіть назву стилю (ім'я файлу без `.md`, якщо frontmatter не задає `name`) з `.claude/output-styles/` для проєкту або `~/.claude/output-styles/` для стилю на рівні користувача. Кастомні стилі пропускають вбудовані інструкції Claude Code з програмної інженерії, якщо їхній YAML frontmatter не задає `keep-coding-instructions: true`. Вибір стилю застосовується до наступного повідомлення. Перезапустіть, щоб виявити щойно створені файли стилів.

```json
{ "outputStyle": "Explanatory" }
```

```json
{ "outputStyle": "strict-reviewer" }
```

Налаштування зберігається між сесіями. Стилі Explanatory та Learning збільшують витрату вихідних токенів, але кешування промптів (prompt caching) може знизити вартість повторюваного вхідного вмісту, проте не дає знижки на згенерований вивід. Повний опис дивіться у [Розділі 9.7 основної інструкції](../ultimate-guide.uk.md#97-стилі-виводу).

#### `spinnerTipsEnabled`
**Тип:** boolean | **Область дії:** всі | **Типово:** `true`

Показувати корисні підказки (tips) на спінері під час виконання завдань Claude.

#### `spinnerVerbs`
**Тип:** object | **Область дії:** всі | **Типово:** немає

Кастомізація дієслів дії, які показуються на екрані завантаження та в повідомленнях про тривалість виконання кроку. Встановіть `mode` в значення `"replace"`, щоб використовувати виключно ваші дієслова, або `"append"`, щоб додати їх до стандартного списку.

```json
{
  "spinnerVerbs": {
    "mode": "replace",
    "verbs": ["Cooking", "Brewing", "Crafting", "Conjuring"]
  }
}
```

#### `spinnerTipsOverride`
**Тип:** object | **Область дії:** всі | **Типово:** немає

Перевизначити підказки спінера власними текстовими рядками. `tips`: масив рядків. `excludeDefault`: при значенні `true` показуватимуться виключно ваші кастомні підказки.

```json
{
  "spinnerTipsOverride": {
    "tips": ["Use /compact at 50% context", "Plan mode helps for complex tasks"],
    "excludeDefault": true
  }
}
```

#### `respectGitignore`
**Тип:** boolean | **Область дії:** всі | **Типово:** `true`

Визначає, чи повинен вибір файлів через `@` ігнорувати файли та шляхи, які підпадають під правила `.gitignore`.

#### `prefersReducedMotion`
**Тип:** boolean | **Область дії:** всі | **Типово:** `false`

Вимкнути або значно зменшити анімації інтерфейсу (спінери, ефекти мерехтіння чи спалахів) для кращої доступності (accessibility).

### Атрибуція (Attribution)

**Тип:** string | **Область дії:** всі | **Типово:** трейлер Git з лінією Co-authored-by

Текст підпису, який додається до повідомлень комітів Git. Підтримує стандартні трейлери git. Встановіть порожній рядок `""`, щоб повністю вимкнути атрибуцію для комітів.

#### `attribution.pr`
**Тип:** string | **Область дії:** всі | **Типово:** згенероване повідомлення з посиланням на Claude Code

#### `includeCoAuthoredBy`
**Тип:** boolean | **Область дії:** всі | **Типово:** `true`

### Робочі дерева (Worktrees)

#### `worktree.symlinkDirectories`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Директорії, які необхідно лінкувати (symlink) з головного репозиторію в кожне нове робоче дерево (worktree), щоб уникнути клонування гігантських папок на диск (наприклад, папки `node_modules`).

#### `worktree.sparsePaths`
**Тип:** array of strings | **Область дії:** всі | **Типово:** `[]`

Директорії для часткового завантаження (git sparse-checkout у режимі cone) у кожному робочому дереві. Лише вказані шляхи будуть записані на диск, що має вирішальне значення для гігантських монорепозиторіїв.

```json
{
  "worktree": {
    "symlinkDirectories": ["node_modules", ".cache"],
    "sparsePaths": ["packages/my-app", "shared/utils"]
  }
}
```

## Змінні оточення (Environment Variables)

Встановлюються у вашому командному інтерфейсі перед запуском `claude` або реєструються в ключі `env` вашого `settings.json` для застосування до кожної сесії. Коли діють і змінна оточення, і рівнозначне поле налаштувань, змінна оточення має пріоритет (наприклад, `ANTHROPIC_MODEL` перевизначає налаштування `model`). Зміни набирають чинності під час наступного запуску `claude`.

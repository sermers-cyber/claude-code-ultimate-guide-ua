# Глосарій

Визначення термінів, що використовуються в цьому посібнику. Щодо понять рівня моделі (токени, temperature, RAG) дивіться [глосарій платформи Anthropic](https://platform.claude.com/docs/en/about-claude/glossary).

Для практичних порівнянь прочитайте [AI Concept Boundaries](./ai-concept-boundaries.uk.md): контекст і пам'ять, модель і harness, воркфлоу й агент, інструменти й MCP, інструкції й засоби контролю виконання, оцінювання й докази з продакшену, а також архітектура моделі, клас розміру, модальність і мітки завдань. Він містить сім сценаріїв із виправленнями, вибірково адаптованих із Lexigraph з атрибуцією.

## A

### Agent teams (команди агентів)

Кілька незалежних сесій Claude Code, якими керує тімлід, зі спільним списком завдань і обміном повідомленнями між учасниками. На відміну від subagents, що працюють в одній сесії, кожен учасник команди має власне контекстне вікно, і ви можете взаємодіяти з будь-яким із них безпосередньо. Це експериментальна функція; для ввімкнення потрібен `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`. Див. [§4 Агенти](../ultimate-guide.uk.md#4-агенти).

### Agentic loop (агентний цикл)

Цикл, який Claude проходить для кожного завдання: зібрати контекст, виконати дію, перевірити результат, повторювати, доки завдання не буде виконано. Кожне використання інструмента повертає інформацію, що визначає наступний крок. Більшість точок розширення (hooks, skills, MCP) підключаються до конкретних фаз цього циклу. Див. [§1 How Claude Code Works](../ultimate-guide.uk.md#1-how-claude-code-works).

### Agent-computer interface (інтерфейс «агент-комп'ютер»)

Команди, спостереження, формат зворотного зв'язку та правила взаємодії, через які модель діє на комп'ютері. Кращий інтерфейс може покращити агента без зміни моделі. [SWE-agent](https://arxiv.org/abs/2405.15793) використовує цей термін для свого репозиторно-орієнтованого дизайну команд і зворотного зв'язку. Інтерфейс є одним із компонентів runtime harness, а не лише його візуальним UI.

### Auto memory (автопам'ять)

Нотатки, які Claude пише собі на основі ваших виправлень і вподобань; зберігаються окремо для кожного git-репозиторію в `~/.claude/projects/`. Перші 200 рядків або 25 KB файлу `MEMORY.md` завантажуються на початку сесії. Усі worktrees одного репозиторію використовують спільну директорію автопам'яті. Див. [§3 Пам'ять](../ultimate-guide.uk.md#3-память-та-налаштування).

### Auto mode (автоматичний режим)

Режим дозволів, у якому окрема класифікаторна модель переглядає кожну дію у фоновому режимі замість показу вам запитів на підтвердження. Класифікатор блокує розширення повноважень, недовірену інфраструктуру та спроби prompt injection. Він ніколи не бачить результатів інструментів, тому стійкий до ін'єкцій інструкцій. Це дослідницьке прев'ю. Див. [§3 Режими дозволів](../ultimate-guide.uk.md#3-память-та-налаштування).

## B

### Bare mode (мінімальний режим)

Прапорець запуску (`--bare`), що пропускає автовиявлення hooks, skills, plugins, MCP-серверів, автопам'яті та CLAUDE.md. Діють лише прапорці, передані явно. Рекомендований для CI і скриптових викликів, де потрібна однакова поведінка на різних машинах. Доступний із v2.1.81. Див. [§9 Headless/Non-interactive Mode](../ultimate-guide.uk.md#9-розширені-патерни-частина-a).

### Bundled skills (вбудовані skills)

Промпт-плейбуки, що постачаються разом із Claude Code, як-от `/batch`, `/code-review`, `/debug` і `/loop`. На відміну від вбудованих команд (які виконують фіксовану логіку), bundled skills дають Claude докладний промпт і дозволяють йому самому оркеструвати роботу. Вони можуть запускати агентів, читати файли та пристосовуватися до вашої кодової бази. Див. [§5 Skills](../ultimate-guide.uk.md#5-скіли).

## C

### Channel (канал)

MCP-сервер, який надсилає події у вашу запущену сесію, щоб Claude міг реагувати на те, що відбувається, поки вас немає біля термінала. Канали можуть бути двосторонніми: Claude читає вхідну подію й відповідає через той самий канал. Telegram, Discord та iMessage входять до дослідницького прев'ю. Див. [§8 MCP](../ultimate-guide.uk.md#8-mcp-сервери).

### Checkpoint (контрольна точка)

Точка відновлення, що створюється під час кожного надісланого вами промпту. Claude Code робить знімок файлів перед кожною правкою, тож ви можете повернути код, розмову або обидва до раннього стану. Натисніть `Esc` двічі або виконайте `/rewind`, щоб відновити. Контрольні точки локальні для сесії, відокремлені від git і не відстежують зміни, внесені через інструмент Bash. Див. [§9 Checkpointing](../ultimate-guide.uk.md#9-розширені-патерни-частина-a).

### Директорія `.claude`

Директорія, з якої Claude Code читає конфігурацію рівня проєкту: налаштування, hooks, skills, subagents, правила та автопам'ять. Проєкт має `.claude/` у корені; ваші типові значення рівня користувача лежать у `~/.claude/`. Див. [§3 Конфігурація](../ultimate-guide.uk.md#3-память-та-налаштування).

### CLAUDE.md

Markdown-файл зі сталими інструкціями, який ви пишете для Claude; завантажується на початку кожної сесії як повідомлення користувача після системного промпту. Розмістіть тут конвенції проєкту, нотатки про архітектуру та правила поведінки. CLAUDE.md переживає compaction і після неї заново читається з диска. Див. [§3.1 Файли пам'яті](../ultimate-guide.uk.md#31-файли-памяті-claudemd).

### Compaction (стиснення контексту)

Автоматичне підсумовування вашої розмови, коли контекстне вікно наближається до межі. Спершу очищаються старі виводи інструментів, потім розмова підсумовується. CLAUDE.md та автопам'ять переживають compaction і перезавантажуються з диска; інструкції, дані лише в розмові, можуть бути втрачені. Виконайте `/compact`, щоб запустити вручну. Див. [§2 Контекстне вікно](../ultimate-guide.uk.md#2-основні-концепції).

## D

### Dispatch

Маршрутизатор завдань, що ініціюється з телефона й запускає сесію Claude Code в додатку Desktop, коли ви надсилаєте завдання з кодом із мобільного додатка Claude. Ваш промпт автоматично спрямовується до потрібного інструмента. Доступний на планах Pro і Max. Див. [§9 Desktop Features](../ultimate-guide.uk.md#9-розширені-патерни-частина-a).

## E

### Effort level (рівень зусиль)

Налаштування, що керує тим, яку частину бюджету thinking для адаптивного міркування Claude використовує за один хід. Вищий рівень означає більше thinking-токенів і глибше міркування; нижчий швидший і дешевший. Підтримується в Opus 4.6+ і Sonnet 4.6+. Skills можуть перевизначати рівень зусиль сесії у своєму frontmatter. Див. [§2.5 Model Selection](../ultimate-guide.uk.md#25-model-selection--thinking-guide).

### Extended thinking (розширене мислення)

Видиме покрокове міркування, яке модель виконує перед відповіддю. Ви можете обмежити thinking-токени через `MAX_THINKING_TOKENS` або змінити рівень зусиль. Thinking відображається в терміналі сірим курсивом. Див. [§2.5 Model Selection](../ultimate-guide.uk.md#25-model-selection--thinking-guide).

## G

### Graph engineering (інженерія графів)

Проєктування воркфлоу агента як явного виконуваного графа з версіонованим станом, вузлами, ребрами, умовами маршрутизації, злиттями, контрольними точками та поведінкою відновлення. Граф може містити цикли, але ці два терміни не є синонімами: цикл описує повторюваний зворотний зв'язок, а граф описує топологію, що маршрутизує роботу й стан. Це визначення ще формується і не стандартизоване. Див. [Loop & Graph Engineering](./loop-graph-engineering.uk.md).

## H

### Agent harness

Рантайм навколо моделі, що виконує цикл агента: збирає контекст, надає інструменти, застосовує дозволи, зберігає або відновлює стан і повертає результати інструментів моделі. Claude Code є runtime harness; Claude це модель, яку він запускає. Не плутайте його з repository harness, тобто специфічним для проєкту шаром інструкцій, налаштування, стану та перевірочних бар'єрів. Див. [Agent Harness Engineering](./agent-harness.uk.md), [Agent Harness Landscape](../ecosystem/agent-harness-landscape.uk.md) та [§9.25 Repository Harness Engineering](../ultimate-guide.uk.md#925-repository-harness-engineering).

### Evaluation harness

Повторюваний набір, що запускає агента або модель на визначених завданнях і записує результати, витрати, трасування чи оцінки. Evaluation harness вимірює систему; йому не потрібно володіти інтерактивним циклом інструментів цієї системи чи діяти на репозиторії. Інструментарій SWE-bench є evaluation harness, а SWE-agent це кодовий рантайм, який можна оцінювати за його допомогою. Див. [Agent Evaluation](../roles/agent-evaluation.uk.md).

### Harness-model pair

Точна комбінація моделі, runtime harness, конфігурації, набору інструментів, середовища репозиторію та бюджету, використана для запуску. Оцінюйте цю пару як єдине ціле: зміна harness може змінити точність, вартість і режими відмов, навіть коли модель лишається тією самою. [The Scaffold Effect](https://arxiv.org/abs/2607.22585) надає контрольовані докази цього ефекту на двох моделях і трьох кодових harness. Див. [Agent Harness Engineering](./agent-harness.uk.md#основне-твердження) та [Agent Harness Landscape](../ecosystem/agent-harness-landscape.uk.md).

### Harnessability

Робочий вимір оцінювання того, наскільки надійно модель дотримується конкретного harness під реалістичним тиском: обов'язкові перевірки, межі політик, протокол відновлення, переходи станів і правила ескалації. Це не стандартизований скаляр і не внутрішня властивість моделі. Звітуйте про спостережені частоти та режими відмов для конкретної пари модель-harness замість публікації єдиної універсальної оцінки. Див. [Evaluate Judgment Allocation and Reviewer Independence](../roles/agent-evaluation.uk.md#evaluate-judgment-allocation-and-reviewer-independence).

### Harness optimizer

Система зовнішнього циклу, що пропонує зміни до цільового harness, оцінює версії-кандидати та зберігає або відхиляє ці зміни за визначеними метриками. Її ціль пошуку може охоплювати промпти, правила контексту, інструменти, потік керування, верифікацію або політику пам'яті. Harness optimizer не замінює рантайм-цикл, який оцінює. Див. [Harness Optimizers and Meta-Harnesses](./agent-harness.uk.md#11-оптимізатори-harness-та-мета-harness).

### Hook

Визначений користувачем обробник, що автоматично виконується в конкретній точці життєвого циклу Claude Code, наприклад перед запуском інструмента, після правки файлу або на початку сесії. Конфігурація hook має три рівні: подія hook (яка точка життєвого циклу), matcher (які події його запускають) і обробник hook (що виконується). Обробником може бути shell-команда, HTTP-ендпоінт, MCP-інструмент, LLM-промпт або subagent. Hooks детерміновані: вони спрацьовують у фіксованих точках життєвого циклу, а не на розсуд моделі. Див. [§7 Hooks](../ultimate-guide.uk.md#7-hooks).

## J

### Judgment allocation (розподіл судження)

Явний розподіл рішень між людьми, моделями, детермінованими перевірками, рушіями політик і зовнішніми авторитетами. Він відповідає на питання: хто встановлює планку якості, які докази допустимі, хто вирішує, що доказів достатньо, і хто обробляє винятки. Автоматизація виконання може перемістити людське судження в проєктування циклу, політики, ескалацію чи затвердження релізу, але не усуває його. Див. [Allocate judgment explicitly](./loop-graph-engineering.uk.md#5-розподіляйте-судження-явно).

---

## L

### Loop engineering (інженерія циклів)

Проєктування повторюваного процесу зворотного зв'язку, який знаходить або отримує роботу, викликає агента, спостерігає результати, перевіряє прогрес і обирає наступну дію, доки не спрацює правило зупинки. Термін корисний як практична лексика, але не є формальним стандартом. Цикл може бути закодований усередині графа й обмежений harness. Див. [Loop & Graph Engineering](./loop-graph-engineering.uk.md).

---

## M

### Managed settings (керовані налаштування)

Файл налаштувань, який примусово застосовується в усій організації службами IT або DevOps і розміщується за шляхом рівня ОС поза `~/.claude`. Користувачі не можуть перевизначити або виключити керовані налаштування. Використовуйте для політик безпеки, вимог відповідності чи стандартизованого інструментарію на парку машин. Див. [§3.3 Налаштування](../ultimate-guide.uk.md#33-налаштування-та-дозволи).

### Meta-harness

Перевантажений термін із двома поточними вживаннями. У дослідженнях оптимізаторів це система навколо одного чи кількох цільових harness, що генерує або змінює harness-кандидати, запускає оцінювання й використовує результати для керування наступним кроком оптимізації. [Meta-Harness](https://arxiv.org/abs/2603.28052) та [Agentic Harness Engineering](https://arxiv.org/abs/2604.25850) є поточними прикладами препринтів. Деякі продукти вживають *meta-harness* для спільного клієнта, що розподіляє завдання між наявними runtime harness. Цей посібник відносить другу роль до orchestrator або control plane, якщо система також не змінює й не оцінює сам harness. Див. [Agent Harness Engineering](./agent-harness.uk.md#0-чотири-шари-чотири-відповідальності).

### MCP (Model Context Protocol)

Відкритий стандарт підключення ШІ-інструментів до зовнішніх джерел даних і сервісів. MCP-сервери дають Claude нові інструменти для Slack, Jira, баз даних, браузерів і сотень інших інтеграцій. Підключайте сервери через `/mcp` або додаванням їх до `.mcp.json`. Див. [§8 MCP](../ultimate-guide.uk.md#8-mcp-сервери).

### MCP tool search (пошук інструментів MCP)

Механізм економії контексту, що відкладає схеми інструментів MCP до моменту потреби. На старті завантажуються лише назви інструментів; Claude отримує повну схему на вимогу, коли вирішує використати конкретний інструмент. Це не дає неактивним MCP-серверам споживати контекст. Див. [§8 MCP](../ultimate-guide.uk.md#8-mcp-сервери).

## N

### Non-interactive mode (неінтерактивний режим)

Режим, що виконує один промпт і завершується без розмовної сесії; викликається через `-p` або `--print`. Використовується для CI, скриптів і pipe. Прапорець `--bare` розширює його для автоматизації з чистого аркуша. Раніше називався «headless mode». Див. [§9 Non-interactive Mode](../ultimate-guide.uk.md#9-розширені-патерни-частина-a).

---

## O

### Orchestrator (оркестратор)

Система, що координує запуски, робочі простори, черги, бюджети, передачі завдань або людські підтвердження для одного чи кількох агентів. Оркестратор може викликати окремий runtime harness, не володіючи самим циклом «модель-інструмент-спостереження». Див. [Orchestrators: Products Above the Runtime](../ecosystem/agent-harness-landscape.uk.md#оркестратори-продукти-над-рантаймом).

### Output style (стиль виводу)

Конфігурація, що змінює системний промпт Claude, щоб змінити поведінку, тон чи формат відповідей для всієї сесії, на відміну від CLAUDE.md (який доставляється як повідомлення користувача). Вбудовані стилі Proactive, Concise, Explanatory і Learning зберігають типові інструкції з розробки ПЗ; користувацький стиль їх відкидає, якщо його frontmatter не задає `keep-coding-instructions: true`. Default означає, що жоден стиль не вибрано. Див. [§9.7 Стилі виводу](../ultimate-guide.uk.md#97-стилі-виводу).

## P

### Permission mode (режим дозволів)

Базова поведінка підтвердження для сесії. Доступні режими: `default`, `acceptEdits`, `plan`, `auto`, `dontAsk` і `bypassPermissions`. Перемикайте через `Shift+Tab` у CLI або використовуйте селектор режимів у VS Code, Desktop і claude.ai. Див. [§3.3 Налаштування](../ultimate-guide.uk.md#33-налаштування-та-дозволи).

### Permission rule (правило дозволів)

Запис у налаштуваннях, що дозволяє, запитує або забороняє виклик інструмента на основі назви інструмента й шаблону аргументів. Правила оцінюються в порядку deny, потім ask, потім allow, тож перший збіг виграє. Правила дозволів це деталізовані засоби контролю поверх ширшого режиму дозволів. Див. [§3.3 Налаштування](../ultimate-guide.uk.md#33-налаштування-та-дозволи).

### Plan mode (режим планування)

Режим дозволів, у якому Claude досліджує й пропонує зміни, не редагуючи ваші вихідні файли. Він може читати, шукати й виконувати розвідувальні команди, а потім подає план на затвердження, перш ніж щось чіпати. Увійдіть у plan mode через `/plan` або натиснувши `Shift+Tab`. Див. [§3.3 Налаштування](../ultimate-guide.uk.md#33-налаштування-та-дозволи).

### Plugin

Пакет із skills, hooks, subagents і MCP-серверів, запакований як єдина встановлювана одиниця. Skills плагіна мають простір імен `plugin-name:skill-name`, тож кілька plugins співіснують без конфліктів. Поширюйте plugins між командами через marketplace. Див. [§5 Skills](../ultimate-guide.uk.md#5-скіли).

### Project trust (довіра до проєкту)

Діалог, що приймає директорію перед тим, як Claude Code завантажить її конфігурацію. Згода зберігається для кожної директорії проєкту, окрім вашої домашньої директорії (де довіра діє лише в межах сесії). Довіра відкриває автоінсталяцію plugins із marketplace та виконання hooks, визначених у проєкті. Див. [§3 Конфігурація](../ultimate-guide.uk.md#3-память-та-налаштування).

### Prompt injection

Ворожі інструкції, вбудовані у файл, вебсторінку чи результат інструмента, що намагаються спрямувати Claude на дії, яких ви ніколи не просили. Захист Claude Code включає систему дозволів, блоклисти команд і перевірку довіри. Auto mode додає серверний класифікатор, який ніколи не бачить результатів інструментів, тож ін'єктований текст не може впливати на його рішення про схвалення. Див. [§10 Security](../ultimate-guide.uk.md#10-security).

## R

### Repository harness

Специфічний для проєкту шар, що забезпечує повторюваний запуск агента всередині репозиторію: інструкції, налаштування середовища, довговічний стан, команди тестування, перевірочні бар'єри та конвенції відновлення. Він заземлює й перевіряє runtime harness, але не замінює його цикл «модель-інструмент». Див. [§9.25 Repository Harness Engineering](../ultimate-guide.uk.md#925-repository-harness-engineering) та [Four Layers, Four Responsibilities](./agent-harness.uk.md#0-чотири-шари-чотири-відповідальності).

### Remote Control (віддалене керування)

Спосіб продовжити локальну сесію Claude Code з телефона чи браузера через claude.ai. Ваш код лишається на вашій машині; віддаленим є лише UI. Відрізняється від Claude Code on the web, який працює в хмарній пісочниці. Див. [§9.22 Remote Control](../ultimate-guide.uk.md#922-remote-control-mobile-access).

### Rules (правила)

Модульні файли інструкцій у `.claude/rules/`, що завантажуються разом із CLAUDE.md. Правило можна обмежити шляхами через YAML-frontmatter `paths:`, тоді воно завантажується лише коли Claude читає відповідний файл, і контекст лишається легким до моменту потреби. Див. [§3.1 Файли пам'яті](../ultimate-guide.uk.md#31-файли-памяті-claudemd).

## S

### Sandboxing (пісочниця)

Ізоляція файлової системи та мережі на рівні ОС для інструмента Bash. Команди виконуються всередині межі, яку ви визначаєте наперед, тож Claude може вільно працювати в ній без запитів на підтвердження для кожної команди. Sandboxing є окремим шаром від правил дозволів. Див. [§10 Security](../ultimate-guide.uk.md#10-security).

### Scaffold effect (ефект каркаса)

Варіація результату, використання токенів і режиму відмов, спричинена оточувальним каркасом чи harness агента за незмінної моделі. В одному контрольованому дослідженні з програмування вибір harness змінював використання токенів на розв'язане завдання до 40 разів, тоді як різниці в частці успіху лишалися в межах від 0 до 8 відсоткових пунктів і здебільшого не були статистично значущими. Розглядайте це як доказ з обмеженого експерименту, а не універсальний рейтинг. Див. [The Scaffold Effect](https://arxiv.org/abs/2607.22585).

### Session (сесія)

Розмова, прив'язана до вашої поточної директорії, з власним незалежним контекстним вікном. Сесії можна відновлювати через `claude -c`, відгалужувати через `--fork-session` або запускати паралельно в різних терміналах. Транскрипт кожної сесії зберігається в `~/.claude/projects/`. Див. [§1 How Claude Code Works](../ultimate-guide.uk.md#1-how-claude-code-works).

### Settings layers (шари налаштувань)

Ієрархія, з якої Claude Code читає конфігурацію, у порядку пріоритету від найвищого до найнижчого: керована політика, аргументи командного рядка, локальні налаштування в `.claude/settings.local.json`, налаштування проєкту в `.claude/settings.json`, потім налаштування користувача в `~/.claude/settings.json`. Масиви зливаються між шарами; скаляри вищого шару перевизначають нижчі. Див. [§3.3 Налаштування](../ultimate-guide.uk.md#33-налаштування-та-дозволи).

### Skill

Файл `SKILL.md` з інструкціями, знаннями чи воркфлоу, який Claude додає до свого набору інструментів. Викликається напряму через `/skill-name`. Skills відповідають відкритому стандарту Agent Skills; Claude Code розширює його керуванням викликом і виконанням у subagent. Skills є рекомендованим наступником користувацьких команд: файли `.claude/commands/` і далі працюють, але бажаним місцем є `.claude/skills/`. Див. [§5 Skills](../ultimate-guide.uk.md#5-скіли).

### Subagent

Спеціалізований ШІ-асистент, що працює у власному контекстному вікні з користувацьким системним промптом, окремим доступом до інструментів і незалежними дозволами. Він виконує делеговане завдання й повертає підсумок у головну розмову. На відміну від agent teams (де кожен агент це повноцінна незалежна сесія), subagents працюють усередині батьківської сесії й звітують їй. Див. [§4 Агенти](../ultimate-guide.uk.md#4-агенти).

### Surface (поверхня)

Будь-яке місце, звідки ви отримуєте доступ до Claude Code: CLI, VS Code, JetBrains, Desktop або claude.ai. Усі поверхні мають той самий рушій, тому ваші CLAUDE.md, налаштування та skills працюють однаково на всіх. Slack і розширення для Chrome є інтеграціями, що підключаються до поверхні, а не поверхнями як такими.

## T

### Teleport

Команда (`/teleport`), що переносить хмарну сесію Claude Code у ваш локальний термінал. Claude отримує гілку, завантажує історію розмови й продовжує з останнього стану вебсесії. Зворотний напрям це `--remote`, який надсилає локальне завдання на виконання в вебі. Див. [§9.16 Телепортація сесії](../ultimate-guide.uk.md#916-телепортація-сесії).

### Tool (інструмент)

Дія, яку Claude може виконати: прочитати файл, відредагувати код, виконати shell-команду, пошукати в вебі, запустити subagent. Інструменти роблять Claude Code агентним. Без них Claude може відповідати лише текстом. Кожне використання інструмента повертає результат, що визначає наступне рішення Claude в агентному циклі. Див. [§1 How Claude Code Works](../ultimate-guide.uk.md#1-how-claude-code-works).

### Turn (хід)

Одна повна відповідь Claude в межах сесії. Хід починається, коли ви надсилаєте повідомлення, і закінчується, коли Claude завершує відповідь, із довільною кількістю викликів інструментів між ними. Stop hooks спрацьовують наприкінці кожного ходу. Див. [§7 Hooks](../ultimate-guide.uk.md#7-hooks).

## V

### Verification loop (цикл верифікації)

Патерн сесії, коли ви даєте Claude перевірку, яку він може запустити (набір тестів, збірку чи порівняння скриншотів), і Claude ітерує, доки перевірка не пройде, замість того щоб зупинитися після однієї спроби. Verification loop є передумовою для `/goal`, запусків без нагляду та динамічних воркфлоу: без нього єдиним сигналом, що агент закінчив, є сам агент. Див. [§9 Advanced Features](../ultimate-guide.uk.md#9-розширені-патерни-частина-a).

## W

### Worktree isolation (ізоляція worktree)

Режим ізоляції, у якому Claude працює в окремому git worktree під `.claude/worktrees/`; вмикається прапорцем `-w` або `isolation: worktree` у конфігурації subagent. Зміни лишаються в окремій гілці й директорії, тож паралельні агенти не можуть перезаписати файли один одного. Див. [§4 Агенти](../ultimate-guide.uk.md#4-агенти).

## Застарілі та перейменовані терміни

Ці терміни трапляються в старішій документації та контенті спільноти. Під час пошуку в цьому посібнику використовуйте поточну назву.

| Старий термін | Тепер називається | Примітки |
|----------|-----------|-------|
| Headless mode | Non-interactive mode | Той самий прапорець `-p`, та сама поведінка |
| Custom commands | Skills | Файли `.claude/commands/` і далі працюють |
| Slash commands | Commands | «Slash» прибрано з тексту продукту |

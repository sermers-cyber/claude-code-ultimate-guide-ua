# Computer use у Claude Code

Computer use дає змогу Claude Code керувати схваленими застосунками macOS і переглядати видимий вміст їхніх екранів з інтерактивної CLI-сесії. Це дослідницький превʼю для користувачів Pro і Max. Він недоступний на планах Team і Enterprise, у `claude -p`, а також у CLI на Linux чи Windows. Авторитетним джерелом щодо продукту для цієї сторінки є [актуальна документація Anthropic з Computer Use](https://code.claude.com/docs/en/computer-use).

Використовуйте його для нативного застосунку, симулятора чи інструмента лише з графічним інтерфейсом, для якого немає точнішої інтеграції. Для завдання в браузері віддавайте перевагу [Claude in Chrome](https://code.claude.com/docs/en/chrome); для сервісу з API — MCP-серверу. Офіційний порядок вибору інструментів: MCP, Bash, Chrome, і лише потім computer use.

## Увімкнення вбудованого сервера

Computer use — це вбудований MCP-сервер з назвою `computer-use`, який вимкнений, доки його не увімкнуть для проекту.

1. Запустіть інтерактивну сесію Claude Code і виконайте `/mcp`.
2. Виберіть `computer-use` і натисніть **Enable**. Проект запамʼятовує це налаштування.
3. Коли macOS запитає, надайте **Accessibility** (для кліків, введення та прокручування) і **Screen Recording** (для захоплення екрана). Після надання Screen Recording може знадобитися перезапуск Claude Code.

Сервер зʼявляється лише в придатній сесії: macOS, Pro або Max, автентифікація через claude.ai, інтерактивний режим. `/status` допомагає перевірити план. Вхід лише через стороннього провайдера, зокрема Amazon Bedrock, Agent Platform від Google Cloud чи Microsoft Foundry, не робить CLI-поверхню доступною.

## Чим може керувати Claude

Перший запит на застосунок у сесії показує запит на схвалення. У ньому названо застосунки, будь-який додатковий дозвіл (наприклад, доступ до буфера обміну) і кількість інших застосунків, які буде приховано. Схвалення діє лише протягом цієї сесії.

| Клас застосунку | Задокументований рівень контролю | Що перевірити перед схваленням |
|---|---|---|
| Браузери й торгові платформи | Лише перегляд | Видимі дані все одно можуть потрапити до моделі через скриншоти. |
| Термінали та IDE | Лише кліки | Запит попереджає, що застосунок рівнозначний доступу до оболонки. |
| Finder | Повний контроль | Запит попереджає, що він може читати або записувати будь-який файл. |
| System Settings | Повний контроль | Запит попереджає, що він може змінювати системні налаштування. |
| Інші схвалені застосунки | Повний контроль | Переконайтеся, що застосунок і завдання лежать у межах задуманого. |

Поки Claude керує екраном, він приховує інші видимі застосунки, а після ходу відновлює їх. Термінал залишається видимим і виключений зі скриншотів. Лише одна сесія Claude Code може одночасно використовувати computer use: її загальномашинне блокування зберігається до виходу із сесії, навіть після завершення поточного завдання.

## Витік даних і межа безпеки

Computer use працює на реальному робочому столі, а не всередині [пісочниці Bash](../security/sandbox-isolation.uk.md). Claude Code автоматично зменшує скриншоти перед надсиланням до моделі, але це не робить видимі дані застосунку безпечними для розкриття. Вважайте кожен схвалений застосунок і його видимий вміст частиною вхідної межі моделі.

Claude Code документує схвалення для кожного застосунку, попередження для застосунків із широким охопленням, виключення терміналу зі скриншотів, блокування однією сесією та `Esc` як глобальну зупинку. Також сказано, що Claude перевіряє дії та позначає можливу ін'єкцію промптів із вмісту на екрані. Ці засоби зменшують ризик, але не перетворюють застосунок на робочому столі на ізольовану пісочницю.

Перш ніж вмикати сервер для чутливого робочого процесу:

- закрийте застосунки, які не стосуються завдання;
- використовуйте окремий локальний обліковий запис або тестові дані, коли робочі дані не потрібні;
- схвалюйте найменший корисний набір застосунків;
- тримайте людину біля терміналу для будь-якого потоку, що може змінювати дані, гроші, облікові дані чи конфігурацію системи;
- для засобів контролю поза цією функцією користуйтеся [довідником з інструментів і дозволів](./tools-reference.uk.md) та [рекомендаціями з посилення безпеки](../security/security-hardening.uk.md).

## Безпечна робота та зупинка

Задайте завданню конкретну умову успіху: відкрити певний екран, відтворити дефект верстки за вказаного розміру або зафіксувати стан потоку в симуляторі. Просіть скриншоти чи письмовий результат, коли саме це є потрібним доказом. Computer use може поєднувати кроки в GUI з Bash, але скриншот свідчить лише про видимий стан, а не доводить наслідок на бекенді.

Натисніть `Esc` будь-де, щоб перервати поточну дію computer use. `Ctrl+C` у терміналі теж зупиняє її. Обидва способи відновлюють приховані застосунки, але блокування computer use зберігається до виходу із цієї сесії Claude Code. Не запускайте другу сесію в надії, що вона перейме робочий стіл.

## Режими збою та перевірка

| Симптом | Задокументована причина чи обмеження | Перевірка або реакція |
|---|---|---|
| `computer-use` немає в `/mcp` | Не виконано вимоги щодо платформи, плану, автентифікації чи інтерактивної сесії. | Перевірте macOS, `/status`, автентифікацію через claude.ai і що сесію не запущено з `-p`. |
| Функцію утримує інша сесія | Загальномашинне блокування триває до виходу з її сесії. | Вийдіть із названої сесії. Аварійно завершений процес звільняє блокування після того, як Claude Code виявить його відсутність. |
| macOS повторює запит на дозвіл | Screen Recording може вимагати перезапуску процесу, що його запитує. | Закрийте Claude Code, почніть нову сесію й підтвердьте Screen Recording для застосунку-термінала в налаштуваннях macOS. |
| Текст чи елементи керування важко прочитати | Скриншоти автоматично зменшуються, а цільовий розмір не налаштовується. | Збільшіть текст або елементи керування в застосунку, потім повторіть перевірку видимого стану. |
| Крок у GUI здається успішним | Стан екрана не доводить збереженої зміни чи наслідку далі за ланцюгом. | Перевірте власним підтвердженням застосунку, зчитуванням, тестом чи іншим доказом, специфічним для завдання. |

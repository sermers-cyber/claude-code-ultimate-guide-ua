# Довідник вбудованих інструментів

Claude Code постачається з набором вбудованих інструментів, якими він читає, змінює та виконує речі у вашому середовищі. Вам не потрібно їх встановлювати чи налаштовувати; вони завжди присутні.

Назви інструментів — це точні рядки, які ви використовуєте в правилах дозволів (`allow`/`deny`), у frontmatter `tools` і `disallowedTools` для subagent, у полях `matcher` для hook та в прапорцях CLI `--allowedTools`/`--disallowedTools`. Щоб додати власні інструменти, підключіть [MCP-сервер](../ecosystem/mcp-servers-ecosystem.uk.md). Щоб створити повторно використовувані робочі процеси на основі prompt, напишіть [skill](../../examples/skills/); вони запускаються через наявний інструмент `Skill`, а не додають новий запис інструмента. [Computer Use](./computer-use.uk.md) — це окремий вбудований MCP-сервер із межею дозволів для робочого столу macOS.

## Усі вбудовані інструменти

Таблиці нижче охоплюють вбудовані інструменти та явно позначені видалені інструменти. Доступність залежить від моделі та конфігурації. «Потрібен дозвіл» означає, що перед запуском інструмента з'являється запит під час першого використання (у режимах за замовчуванням і `acceptEdits`). Інструменти з позначкою «Ні» запускаються без запиту.

## Формати правил дозволів

Назви інструментів з'являються в правилах дозволів з необов'язковим специфікатором:

| Формат правила | Застосовується до | Що зіставляє |
|-------------|------------|-----------------|
| `Bash(npm run *)` | `Bash`, `Monitor` | Shell-команди за префіксом/glob |
| `PowerShell(Get-ChildItem *)` | `PowerShell` | Команди PowerShell |
| `Read(~/secrets/**)` | `Read`, `Grep`, `Glob`, `LSP` | Шляхи файлів |
| `Edit(/src/**)` | `Edit`, `Write`, `NotebookEdit` | Шляхи файлів |
| `Skill(deploy *)` | `Skill` | Префікс назви skill |
| `Agent(Explore)` | `Agent` | Назва типу subagent |
| `WebFetch(domain:example.com)` | `WebFetch` | Доменне ім'я |
| `WebSearch` | `WebSearch` | Без специфікатора; дозволити чи заборонити весь інструмент |

Правило дозволу `Edit(...)` також надає доступ на читання до того самого шляху, тож відповідне правило `Read(...)` поруч не потрібне.

Повний синтаксис, зокрема форми префіксів шляху (`//`, `~/`, `/`, `./`) і семантику wildcard для Bash, див. у [Permission Rule Syntax у settings-reference.md](./settings-reference.uk.md#синтаксис-правил-дозволів-permission-rule-syntax).

## Поведінка окремих інструментів

### Bash

Кожна команда виконується в окремому процесі. Зміни робочої директорії через `cd` переносяться на пізніші виклики Bash у головній сесії (але не в subagent), доки ціль лишається всередині директорії проєкту чи шляху `--add-dir`. Змінні середовища, задані через `export`, не зберігаються між командами. Використовуйте `CLAUDE_ENV_FILE` або hook `SessionStart`, щоб передавати стан середовища.

Тайм-аут за замовчуванням — 2 хвилини; Claude може запитати до 10 хвилин на команду. Вивід за замовчуванням обмежено 30 000 символів (налаштовується через `BASH_MAX_OUTPUT_LENGTH`, стеля 150 000). Коли команда перевищує ліміт, повний вивід зберігається у файл у директорії сесії, а Claude отримує шлях і короткий прев'ю.

Для довготривалих процесів Claude встановлює `run_in_background: true`, щоб запустити їх як фонове завдання. Перелічуйте й зупиняйте фонові завдання через `/tasks`.

### Edit

Виконує точну заміну рядка. `old_string` має з'являтися точно так, як написано (символ у символ, включно з пробілами), і лише один раз. Якщо він з'являється більше одного разу, надайте довший рядок із достатнім навколишнім контекстом, щоб однозначно визначити одне входження, або використайте `replace_all: true`. Claude мусить прочитати файл у поточній розмові перед редагуванням, і файл не повинен змінитися на диску після того читання.

### Glob

Знаходить файли за шаблоном імені з підтримкою рекурсивного зіставлення `**`. Результати сортуються за часом зміни, обмежено 100 файлами. Glob за замовчуванням не враховує `.gitignore` (на відміну від Grep, який враховує).

### Grep

Шукає вміст файлів за допомогою ripgrep. Шаблони дотримуються синтаксису regex ripgrep, який не збігається з POSIX grep. Метасимволи на кшталт `{` і `}` потребують екранування (наприклад, `interface\{\}` для пошуку `interface{}` у Go). Grep враховує `.gitignore` і пропускає файли, ігноровані git; передайте шлях напряму, щоб шукати в ігнорованому git файлі. Три режими виводу: `files_with_matches` (за замовчуванням, лише шляхи), `content` (відповідні рядки з номерами рядків), `count` (кількість збігів на файл).

### LSP

Неактивний, доки ви не встановите plugin інтелекту коду для вашої мови. Після кожного редагування файлу автоматично повідомляє про помилки типів і попередження. Також може викликатися напряму, щоб переходити до визначень, шукати посилання, перелічувати символи, відстежувати ієрархії викликів і отримувати інформацію про тип у позиції.

### Monitor (v2.1.98+)

Дозволяє Claude стежити за чимось у фоні й реагувати на зміну. Claude пише скрипт спостереження, запускає його у фоні та отримує кожен рядок виводу в міру надходження. Корисно для tail журналів, опитування статусу CI, спостереження за змінами файлів у директорії чи відстеження виводу довготривалого скрипта. Використовує ті самі правила дозволів, що й Bash. Недоступний на Amazon Bedrock, Google Vertex AI чи Microsoft Foundry, а також коли задано `DISABLE_TELEMETRY` або `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`.

Джерело-команда приймає `timeout_ms` і `persistent`; зупиніть активний monitor через `TaskStop`. Починаючи з v2.1.195, Monitor може натомість використовувати нативне джерело WebSocket: `ws.url` плюс необов'язкові `ws.protocols`. `command` і `ws` взаємовиключні. Текстові фрейми стають подіями; бінарні фрейми стають заповнювачем; фрейм понад 1 MiB або закритий сокет зупиняє monitor. URL має бути ASCII `ws://` або `wss://`, без облікових даних і пробілів. WebSocket-monitor потребують власного схвалення та відмовляються працювати з приватними, link-local адресами та адресами сервісів метаданих.

Подія не є авторизацією. Ставтеся до тексту з будь-якого джерела як до недовірених даних, ніколи як до shell-команди чи надання дозволу. Див. [Monitor, Channels і безпечне делегування Codex](../workflows/monitor-event-delegation.uk.md) про межу GitHub-to-WebSocket і workflow Codex з мінімальними привілеями.

```text
# Ask Claude to set up a monitor like this:
"Tail /var/log/app.log and alert me when you see any ERROR line."
"Watch CI on PR #42 and tell me when it passes or fails."
```

### NotebookEdit

Змінює Jupyter notebook по одній комірці за `cell_id`. Три режими: `replace` (перезаписати вихідний код комірки, за замовчуванням), `insert` (додати нову комірку після цільової), `delete` (видалити цільову комірку). Не виконує заміну рядків у всьому notebook так, як Edit у простих файлах.

### PowerShell

Доступний нативно на Windows; за бажанням на Linux/macOS через `CLAUDE_CODE_USE_POWERSHELL_TOOL=1` (потребує `pwsh` у `PATH`). Claude Code запускає PowerShell із `-ExecutionPolicy Bypass` лише на рівні процесу, тож корпоративні обмеження `MachinePolicy` чи `UserPolicy` усе одно діють. Повні подробиці налаштування див. у [розділі PowerShell Native Tool](../ultimate-guide.uk.md#powershell-native-tool).

### Read

Повертає вміст файлу з номерами рядків. Обробляє зображення (PNG і JPG, повертаються як візуальний вміст), PDF (короткі файли цілком; для PDF понад 10 сторінок читає діапазонами до 20 сторінок через параметр `pages`) і Jupyter notebooks (усі комірки з виводом). Коли читання цілого файлу перевищило б ліміт токенів, Read повертає першу сторінку з повідомленням і зсувом, потрібним для читання далі.

### WebFetch

Приймає URL і prompt вилучення. Отримує сторінку, перетворює HTML на Markdown і запускає prompt вилучення щодо вмісту за допомогою малої швидкої моделі. Claude отримує відповідь тієї моделі, а не сиру сторінку. Це робить WebFetch свідомо lossy. Prompt вилучення визначає, що дійде до Claude. URL з HTTP автоматично підвищуються до HTTPS. Відповіді кешуються на 15 хвилин. Коли URL перенаправляє на інший хост, WebFetch повертає текстовий результат із назвою обох URL замість слідування за перенаправленням; Claude робить другий виклик для нового URL. Для сирої необробленої сторінки використовуйте `curl` через Bash.

### WebSearch

Виконує запит і повертає заголовки та URL результатів. Він не отримує сторінки результатів; Claude продовжує через WebFetch, щоб прочитати знайдену сторінку. Може виконувати до 8 бекенд-пошуків за виклик, щоб уточнити результати внутрішньо.

### Write

Створює новий файл або перезаписує наявний. Якщо цільовий шлях уже існує, Claude мусить прочитати його принаймні один раз у поточній розмові перед перезаписом. Для часткових змін Claude використовує Edit, а не Write.

### Workflow (динамічні workflow, v2.1.154+)

Запускає JavaScript-скрипт, що оркеструє багато subagent у фоні й повертає один консолідований результат. Claude використовує ключове слово `ultracode` (перейменоване з `workflow` у v2.1.160, що було зламною зміною), щоб запустити multi-agent fan-out. Стежте за запущеними workflow через `/workflows`. Потребує явної згоди користувача: Claude не запускає workflow, якщо його не попросити.

Сам скрипт-оркестратор споживає нуль токенів. Усі витрати токенів походять від викликів `agent()`. Скрипти workflow використовують чотири примітиви: `agent()` породжує окремі subagent; `parallel()` запускає пакет одночасно й чекає на всі (бар'єр); `pipeline()` проганяє елементи крізь етапи без глобального бар'єра між етапами; `phase()` оновлює мітку прогресу в UI. Експорт `meta` на початку файлу оголошує назву workflow і заголовки фаз.

Скрипти workflow зберігають прогрес під час виконання: перервана робота відновлюється з останньої завершеної одиниці, а не починається спочатку. Щоб це працювало, оркестратор має бути детермінованим: `Date.now()`, `Math.random()` і API Node.js недоступні всередині оркестратора. Передавайте мітки часу та seed через глобальну змінну `args`.

Повний довідник примітивів, поведінкові гарантії та поширені патерни (змагальна верифікація, loop-until-dry, судійські панелі) див. у [Dynamic Workflows](../workflows/dynamic-workflows.uk.md).

## Просунуті інструменти: як їх запускати

### `/loop` і ScheduleWakeup

Команда `/loop [interval] [prompt]` запускає prompt із повторюваним інтервалом. Пропустіть інтервал, щоб Claude сам визначав темп; після кожної ітерації він викликає `ScheduleWakeup`, щоб вирішити, коли спрацює наступна (між 1 хвилиною та 1 годиною). Відкладене пробудження показується в `session_crons` у вхідних даних hook Stop. Скасуйте через Esc або Ctrl+C.

```text
/loop 5m /ci-status        # check CI every 5 minutes
/loop /monitor-deploys     # self-paced monitoring loop
```

### Заплановані завдання: CronCreate / CronList / CronDelete

Ці інструменти планують prompt у межах поточної сесії. Завдання обмежені сесією й відновлюються при `--resume` або `--continue`, якщо не прострочені. Використовуйте `CronList`, щоб побачити активні завдання, `CronDelete`, щоб скасувати одне за ID. Ви взаємодієте з ними, просячи Claude щось запланувати:

```text
"Remind me to run the test suite in 30 minutes."
"Schedule a deploy check every hour until I cancel it."
```

### Віддалені routines: RemoteTrigger і /schedule

`RemoteTrigger` забезпечує команду `/schedule` і створює Routines на claude.ai. Routines запускаються поза поточною сесією за розкладом, через API або за подіями GitHub. Потребує плану Pro, Max, Team чи Enterprise; недоступний на Bedrock, Vertex AI чи Foundry. Повний посібник із функції див. у [Routines](../ultimate-guide.uk.md#routines-cloud-automation).

### Push-сповіщення: PushNotification

Claude викликає `PushNotification`, щоб надіслати сповіщення на робочий стіл і, коли Remote Control підключено з увімкненим «Push when Claude decides», push на телефон. Корисно для довгих завдань, коли ви відходите. Доставка йде через інфраструктуру Anthropic, тож недоступна на Bedrock, Vertex AI чи Foundry. Див. [Remote Control](../ultimate-guide.uk.md#remote-control).

### Команди агентів: TeamCreate / TeamDelete / SendMessage

Експериментальна функція за `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`. `TeamCreate` породжує команду іменованих учасників; `SendMessage` надсилає повідомлення учаснику або відновлює зупинений subagent за його ID агента; `TeamDelete` розпускає команду. Налаштування, патерни та приклади див. у спеціальному [посібнику Agent Teams](../workflows/agent-teams.uk.md).

### Міжсесійні повідомлення: ListAgents / SendMessage

Відрізняється від Agent Teams вище: це обмін повідомленнями між сесіями, які ніколи не породжували одна одну, кожна вже працює незалежно, на тій самій машині або доступна через ваш акаунт. `ListAgents` (`/list-agents`, псевдонім `/peers`) перелічує кожну доступну сесію з її назвою; дві сесії Claude Code, що одночасно працюють локально, бачать одна одну автоматично, без налаштування. `SendMessage({to: "session-name"})` доставляє текст у власну розмову цільової сесії від імені відправника; сесія-отримувач відповідає так само, без відстеження ID. Повідомлення від рівноправної сесії ніколи не має повноважень: воно не може схвалити запит дозволу чи змінити конфігурацію від імені сесії-отримувача, а власні правила дозволів сесії-отримувача усе одно діють для всього, що вона просить. Потребує v2.1.224+ (macOS/Linux/WSL2) або v2.1.234+ (нативний Windows). Починаючи з v2.1.248, обмін повідомленнями на одній машині працює також на Bedrock, Claude Platform on AWS, Agent Platform від Google Cloud, Foundry і з вимкненим отриманням feature-flag; сесії поза цією машиною усе ще потребують входу в claude.ai і Remote Control. Механіку виявлення, засоби безпеки `crossSessionInbound`/`isolatePeerMachines`, захист від корельованого дрейфу та патерни координації див. у спеціальному [посібнику Cross-Session Messaging](../workflows/cross-session-messaging.uk.md).

### Tasks API: від TaskCreate до TaskStop

Сучасна система керування завданнями (v2.1.16+, за замовчуванням з v2.1.142). Повний набір інструментів:

- `TaskCreate`: додати завдання
- `TaskList`: перелічити всі завдання (огляд статусів; не містить повних деталей)
- `TaskGet`: отримати повні деталі одного завдання
- `TaskUpdate`: змінити статус, залежності чи деталі; також видаляє
- `TaskStop`: зупинити запущене фонове завдання за ID

`TodoWrite` — застаріла альтернатива; її вимкнено за замовчуванням у v2.1.142. Задайте `CLAUDE_CODE_ENABLE_TASKS=0`, щоб натомість знову ввімкнути її. Патерни та збереження між сесіями див. у [розділі Tasks API](../ultimate-guide.uk.md#tasks-api).

## Доступність за провайдерами

Деякі інструменти доступні лише коли Claude Code підключається через власну інфраструктуру Anthropic:

| Інструмент | Недоступний на |
|------|-----------------|
| `Monitor` | Amazon Bedrock, Google Vertex AI, Microsoft Foundry |
| `PushNotification` | Amazon Bedrock, Google Vertex AI, Microsoft Foundry |
| `ScheduleWakeup` | Amazon Bedrock, Google Vertex AI, Microsoft Foundry |
| `RemoteTrigger` | Amazon Bedrock, Google Vertex AI, Microsoft Foundry |
| `WebSearch` | Amazon Bedrock (не надається) |

`Workflow` (ключове слово `ultracode`) має поведінкові відмінності між провайдерами; поточний стан перевіряйте в нотатках до релізів.

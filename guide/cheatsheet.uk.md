## Основні команди

Це добірка щоденних команд. Доступність залежить від вашої версії, провайдера та плану: повний список у [§10.1 посібника](./ultimate-guide.uk.md#101-таблиця-команд), а завжди актуальний офіційний довідник за адресою [code.claude.com/docs/en/commands](https://code.claude.com/docs/en/commands).

| Команда | Дія |
|---------|--------|
| `/help` | Контекстна допомога |
| `/powerup` | Інтерактивні анімовані уроки функцій Claude Code |
| `/clear` | Скинути розмову |
| `/compact` | Звільнити контекст |
| `/status` | Налаштування на вкладці Status: версія, модель, обліковий запис, з'єднання |
| `/context` | Детальний розбір токенів |
| `/plan` | Увійти в режим планування (без змін). Вийти: схвалити план або `Shift+Tab` |
| `/model` | Вибрати модель і зберегти як типову; натисніть `s` у списку, щоб вибрати лише для цієї сесії |
| `/autocompact [auto\|500k]` | Вибрати вікно авто-компакту або повернути типове значення моделі |
| `/output-style [style]` | Вибрати Default, Proactive, Concise, Explanatory, Learning або власний стиль |
| `/insights` | Аналітика використання + звіт з оптимізації |
| `/code-review [level]` | Рев'ю diff на помилки коректності, `--fix` застосовує виправлення, `ultra` запускає в хмарі |
| `/simplify` | Рев'ю зміненого коду лише для чистки: повторне використання, спрощення, ефективність (застосовує виправлення чистки; для помилок коректності використовуйте `/code-review`) |
| `/security-review` | Сканувати diff гілки на ризики ін'єкцій, автентифікації та витоку даних |
| `/batch` | Масштабні рефакторинги через 5–30 паралельних агентів у робочих деревах (worktrees) |
| `/subtask <task>` | Передати побічне завдання форкнутому subagent, який звітує сюди (v2.1.212+) |
| `/teleport` | Телепортувати сесію з вебу |
| `/tasks` | Моніторинг фонових завдань |
| `/remote-env` | Налаштування хмарного середовища |
| `/remote-control` (`/rc`) | Підключити цю локальну сесію до вебу/мобільного; для Team/Enterprise потрібне ввімкнення власником |
| `/mobile` | QR-код для завантаження мобільного додатка Claude |
| `/fast` | Увімкнути швидший вивід Opus; Opus 5.5 у швидкому режимі коштує $8/$40 за MTok |
| `/voice [hold\|tap\|off]` | Увімкнути голосове введення (утримуйте Space для мовлення, відпустіть для відправки). Потрібен обліковий запис Claude.ai |
| `/recap` | Однорядковий підсумок поточної сесії на вимогу (v2.1.108) |
| `/effort [level\|auto\|status\|ultracode [on\|off]]` | Effort: low/medium/high/xhigh/max (max лише на сесію) або auto; `status` виводить поточний (v2.1.111) |
| `/tui [default\|fullscreen]` | Задати рендерер і перезапустити з незмінною розмовою; `fullscreen` без мерехтіння (v2.1.110) |
| `/focus` | Увімкнути мінімалістичний режим фокусування (лише повноекранний рендеринг), окремо від Ctrl+O (v2.1.110) |
| `/auto-mode-setup` | Покроковий майстер, що читає проєкт і недавні сесії, щоб навчити auto mode вашого середовища (v2.1.228+ на Pro/Max/Team, v2.1.283+ на Enterprise або з Console API key) |
| `/fewer-permission-prompts` | Сканувати транскрипти та запропонувати список дозволених read-only інструментів (випущено як `/less-permission-prompts` у v2.1.111) |
| `/btw [question]` | Додаткове питання поверх сесії: read-only тимчасовий агент, без засмічення історії та виклику інструментів |
| `/loop [interval] [prompt]` | Повторювати з фіксованим інтервалом або дозволити Claude вибрати інтервал, якщо його не вказано; повторювані завдання спливають через 7 днів (див. довідник із планування) |
| `/usage` (`/cost`, `/stats`) | Використання токенів і вартість за моделями, ліміти плану, графік активності (об'єднано у v2.1.118) |
| `/ultrareview` | Багатоагентне хмарне рев'ю коду, тепер аліас `/code-review ultra` (v2.1.114). `/code-review --max-findings <n>\|all` обмежує або знімає ліміт кількості зауважень до `default` (v2.1.288) |
| `/goal [condition\|clear]` | Автономний багатокроковий режим: Claude працює, доки не буде виконано умову, живий оверлей показує час/кроки/токени (v2.1.139) |
| `/scroll-speed` | Налаштувати швидкість прокрутки колесом миші інтерактивним повзунком із живим переглядом; лише повноекранний рендеринг (v2.1.139) |
| `/rename [name]` | Назвати або перейменувати поточну сесію |
| `/copy [N]` | Скопіювати N-ту з кінця відповідь; вибір блоку коду або всієї відповіді |
| `/doctor` | Повна перевірка налаштувань: встановлення, settings, hooks, роздування `CLAUDE.md`, невикористані skills (v2.1.205+). `/doctor prompt-audit` позначає патерни промптингу, написані для старіших моделей, у CLAUDE.md, skills, agents і командах (v2.1.283) |
| `/debug` | Увімкнути debug-логування й усувати несправності за логом сесії |
| `/exit` | Вийти (або Ctrl+D) |

## Гарячі клавіші

| Клавіші | Дія |
|----------|--------|
| `Shift+Tab` | Циклічне перемикання режимів дозволів |
| `Esc` × 2 | Rewind (скасувати останню дію / скасування) |
| `Ctrl+C` | Перервати операцію |
| `Ctrl+R` | Пошук в історії команд |
| `Ctrl+L` | Очистити екран (контекст зберігається) |
| `Tab` | Автодоповнення шляхів/файлів |
| `Shift+Enter` | Новий рядок у повідомленні |
| `Ctrl+B` | Фонова робота завдань |
| `Ctrl+X Ctrl+K` | Зупинити запущені фонові subagents |
| `Ctrl+Enter` / `Ctrl+X Ctrl+S` | Негайно надіслати повідомлення з черги, перериваючи поточний хід |
| `Option+T` / `Alt+T` | Перемикання Thinking, де підтримується; не діє на Opus 5.5, Sonnet 5.5, Haiku 5.5 і Fable |

| `Ctrl+D` | Вийти |

## Режими дозволів (Permissions)

| Режим | Редагування | Виконання (Bash) |
|------|---------|-----------|
| Manual (`default`) | Діють правила дозволів | Діють правила дозволів |
| acceptEdits | Автоматично | Запитує |
| Plan Mode | Без змін файлів | Дозволені інструменти read-only дослідження |
| auto | Вирішує класифікатор | Вирішує класифікатор |
| dontAsk | Лише якщо підпадає під правила дозволів | Лише якщо підпадає під правила дозволів |
| bypassPermissions | Автоматично | Автоматично (лише для CI/CD) |

**Shift+Tab** для швидкого перемикання режимів. Починаючи з v2.1.283, інтерактивні сесії в терміналі та VS Code стартують в `auto`, якщо режим дозволів не налаштовано; задайте `permissions.defaultMode`, щоб вибрати інший. `/auto-mode-setup` налаштовує класифікатор під ваше середовище

## Пам'ять та Налаштування (2 рівні)

| Рівень | macOS/Linux | Windows | Область | Git |
|-------|-------------|---------|-------|-----|
| **Проектний** | `.claude/` | `.claude\` | Команда / Проект | ✅ Так |

**Пріоритет**: Проектні налаштування перевизначають персональні.

## Типовий робочий процес

```
1. Запуск сесії        ➔ claude
2. Стан контексту      ➔ /status

4. Опис завдання       ➔ Чіткий, специфічний промпт

8. Коміт               ➔ Після завершення логічного етапу
9. Стиснення           ➔ /compact, коли контекст >70%
```

## Керування контекстом (КРИТИЧНО)

### Рядок статусу (Statusline)

```
Model: Sonnet | Ctx: 89.5k | Cost: $2.11 | Ctx(u): 56.0%
```
**Слідкуйте за `Ctx(u):`** ➔ >70% = `/compact`, >85% = `/clear`

**Покращений статус-рядок ([ccstatusline](https://github.com/sirmalloc/ccstatusline)):** Додайте в `~/.claude/settings.json`:
```json
{ "statusLine": { "type": "command", "command": "npx -y ccstatusline@latest", "padding": 0 } }
```

### Порогові значення контексту

| Контекст % | Стан | Дія |
|-----------|--------|--------|
| 0-50% | Зелений | Працюйте вільно |
| 50-70% | Жовтий | Будьте вибірковими з файлами |
| 70-90% | Помаранчевий | `/compact` негайно |
| 90%+ | Червоний | Обов'язково `/clear` |

### Дії за симптомами

| Симптом | Дія |
|------|--------|
| Короткі або неповні відповіді | `/compact` |
| Часте "забування" контексту | `/clear` |
| >70% використаного контексту | `/compact` |
| Завдання повністю завершено | `/clear` |

### Команди відновлення контексту

| Команда | Використання |
|---------|-------|
| `/compact` | Узагальнити та звільнити контекст |
| `/clear` | Почати з чистого аркуша |
| `/rewind` | Скасувати останні зміни (відкотити кроки) |
| `claude -c` | Продовжити останню сесію (CLI прапорець) |
| `claude -r <id>` | Відновити конкретну сесію за ID (CLI прапорець) |

## Під капотом (Швидкі факти)

| Концепція | Ключовий момент |
|---------|-----------|
| **Master Loop** | Цикл модель/інструменти; дозволи та рев'ю auto mode є окремими засобами контролю |
| **Інструменти** | Bash, Read, Edit, Write, Grep, Glob, Agent та інші ([довідник інструментів](./core/tools-reference.uk.md)) |
| **Контекст** | Залежить від моделі: нативний 1M на поточних Opus, Sonnet, Haiku і Fable; 200K лише на застарілому Haiku 4.5. Перевіряйте через `/context` |
| **Суб-агенти** | Ізольований контекст, максимальна глибина вкладеності = 1 |
| **Філософія** | "Less scaffolding, more model" (менше каркаса, більше моделі; довіра до міркувань Claude) |

**Глибоке занурення**: [Архітектура та внутрішній устрій](./core/architecture.uk.md)

| Model | Міркування та пропозиції викликів інструментів | [Glossary](https://cc.bruniaux.com/guide/glossary/) |
| Runtime harness | Цикл інструментів, дозволи та відновлення | [Agent Harness Engineering](https://cc.bruniaux.com/guide/agent-harness/) |
| Repository harness | Інструкції, стан завдань і верифікація | [Repository Harness Engineering](https://cc.bruniaux.com/guide/ultimate-guide/09-advanced-patterns/#925-harness-engineering) |
| Orchestrator | Координація між runtime або сесіями | [Agent Tools](https://cc.bruniaux.com/guide/agentic-tools/) |

Обирайте найменшу керуючу структуру, яка безпечно закриває потребу: обмежений цикл для одного повторюваного завдання; явний граф для маршрутизації, з'єднань, паралелізму, переривання або надійного відновлення; repository harness для повторюваної поведінки проєкту; orchestrator для кількох запусків або черг. Визначте успіх, збій, тайм-аут, бюджет і ескалацію до виконання. Див. [Loop & Graph Engineering](https://cc.bruniaux.com/guide/loop-graph-engineering/) і порівняння продуктів в [Agent Harness Map](https://cc.bruniaux.com/guide/agent-harness-landscape/).

Оцінюйте саме пару модель-harness для обмеженого завдання кодування. Вводьте оркестрацію лише тоді, коли координація є обмеженням. Harness optimizer стоїть поза чотирма операційними шарами й змінює кандидатів harness за окремим протоколом оцінювання.

## Режим планування та Міркування (Plan Mode & Thinking)

| Функція | Активація | Використання |
|---------|------------|-------|
| **Plan Mode** | `Shift+Tab × 2` або `/plan` | Досліджуйте та плануйте без внесення змін на диск |
| **OpusPlan** | `/model opusplan` | Гібрид: Opus для планування, Sonnet для написання коду |

> **Перевірено 27 жовтня 2026**: Opus 5.5, Sonnet 5.5 і Haiku 5.5 за замовчуванням мають `medium`; Fable 5.1 має `high`. Лише застарілий Haiku 4.5 не має параметра effort. `ultrathink` додає інструкцію міркувань на хід, не змінюючи effort в API.

| Керування міркуваннями | Дія | Збереження |
|---------|--------|-------------|
| **Option+T / Alt+T** | Перемикання Thinking на підтримуваних моделях; Opus 5.5, Sonnet 5.5, Haiku 5.5 і Fable завжди міркують | На сесію |
| **`/effort` або повзунок `/model`** | Вибрати підтримуваний рівень; `Enter` зберігає для моделі, `s` застосовує один раз | На модель або сесію |
| **`/effort max`** | Найвищий підтримуваний effort | На сесію |
| **`CLAUDE_CODE_EFFORT_LEVEL`** | Перевизначити effort у середовищі запуску | Середовище процесу |
| **`modelSettings` / `effortLevel`** | Зберегти `low`, `medium`, `high` або `xhigh`; не `max` | Налаштування |
| **`effort` у Skill Frontmatter** | Перевизначити effort, поки працює скіл | На виклик |

**Порада щодо витрат**: спробуйте нижчий підтримуваний effort для обмежених завдань, потім перевірте результат. На Opus 5.5 засобом керування є зміна effort; вимкнення thinking не діє.

**Effort на рівні скілів**: додайте `effort: low` для суто механічних скілів (коміт, синхронізація, розгортання) та `effort: high` для аналітичних (аудит безпеки, архітектурний огляд). Перевизначає налаштування сесії автоматично.

**Воркфлоу OpusPlan**: `/model opusplan` ➔ `Shift+Tab × 2` (планування з Opus) ➔ `Shift+Tab` (виконання з Sonnet).

**Обов'язково для**: завдань на >3 файли, проектування архітектури, складного дебагу.

### Швидкий вибір моделі

| Завдання | Модель | Рівень міркувань (Effort) |
|------|-------|--------|
| Перейменування, шаблонний код, генерація тестів | Haiku 5.5 | За замовчуванням `medium`; спробуйте `low` |
| Розробка фіч, дебаг, рефакторинг | Sonnet 5.5 або Opus 5.5 | Почніть із типового для моделі |
| Проектування архітектури, аудит безпеки | Opus 5.5; за потреби оцініть Fable 5.1 | Підвищуйте на підставі доказів |

> Детальна таблиця вибору моделі та межі цін: [Розділ 2.5 Інструкції з вибору моделі та міркувань](ultimate-guide.uk.md#25-model-selection--thinking-guide)

### Динамічне перемикання моделей (Mid-Session)

**Патерн**: Початок із Sonnet (швидкість) ➔ перехід на Opus (складність) ➔ повернення на Sonnet.

**Воркфлоу**:
```bash
# Явно вибрати Sonnet для цієї сесії
claude --model sonnet

# Зустрілося складне завдання
> "Implement OAuth2 flow with PKCE"
/model opus                    # Перемикання на глибокі міркування

# Фіча готова, повертаємося до рутини
/model sonnet                  # Оптимізація швидкості та вартості
```

**Кращі практики**:
- ✅ Змінюйте модель **на кордонах завдань**, а не посеред виконання одного кроку.
- ✅ Використовуйте Opus для: архітектурних рішень, складного дебагу, критичного для безпеки коду.
- ✅ Використовуйте Sonnet для: рутинних правок, рефакторингу, написання тестів.
- ✅ Використовуйте Haiku для: швидких фіксів, виправлення друкарських помилок, перевірок валідації.
- Перемикання моделі зберігає історію розмови, але може скинути prompt cache; перемикайтеся на зручній межі завдання.

---

### Динамічний workflow (`.claude/workflows/name.js`)

```js
export const meta = {
  name: 'my-workflow',
  description: 'What this orchestrates',
  phases: [{ title: 'Analyze' }, { title: 'Verify' }],
};
// meta must be the first statement, a pure literal (no variables/spreads)

export default async function ({ agent, parallel, pipeline, phase, log, args, budget }) {
  phase('Analyze');
  const results = await parallel(
    ITEMS.map((item) => () => agent(`Analyze ${item}.`, { schema: MY_SCHEMA }))
  );
  return results.filter(Boolean);
}
```

Тригер: введіть `ultracode` у промпті (або попросіть своїми словами). Моніторинг: `/workflows`.

| Примітив | Поведінка |
|-----------|----------|
| `agent(prompt, { schema })` | Запускає один subagent; повертає текст або валідований JSON |
| `parallel([() => agent(...)])` | Бар'єр: усі виконуються одночасно, повертає, коли завершиться найповільніший |
| `pipeline(items, stage1, stage2)` | Без бар'єра: елементи проходять етапи незалежно |
| `phase(title)` | Оновити мітку прогресу в UI `/workflows` |
| `log(msg)` | Вивести повідомлення про прогрес |
| `budget.remaining()` | Захист відкритих циклів (інакше бюджет впирається в ліміт 1000 агентів) |

Ключові правила: оркестратор не споживає токенів; `Date.now()`/`Math.random()` недоступні (ламають відновлення); фільтруйте результати `parallel()` через `.filter(Boolean)`.

Повний довідник: [Dynamic Workflows](./workflows/dynamic-workflows.uk.md)

## Управління завданнями / Tasks API (v2.1.16+)

**Доступність**: новіші моделі, зокрема Opus 5.5, Sonnet 5.5 і Fable, за замовчуванням не отримують інструменти відстеження завдань. Запустіть `CLAUDE_CODE_ENABLE_TODO_TOOLS=1 claude`, щоб ввімкнути. `CLAUDE_CODE_ENABLE_TASKS=0` вибирає лише застарілий TodoWrite там, де інструменти завдань увімкнено. [Офіційна доступність інструментів](https://code.claude.com/docs/en/tools-reference#task-tool-availability).

**Доступні дві системи:**

| Система | Коли використовувати | Збереження |
|--------|-------------|-------------|
| **Tasks API** (v2.1.16+) | Багатосесійні проекти, залежності | ✅ На диску (`~/.claude/tasks/`) |
| **TodoWrite** (Застаріла) | Прості односесійні завдання | ❌ Лише в межах однієї сесії |

### Команди Tasks API

```bash
# Увімкнути персистентність між сесіями
export CLAUDE_CODE_TASK_LIST_ID="project-name"
CLAUDE_CODE_ENABLE_TODO_TOOLS=1 claude

# Всередині Claude: Створити ієрархію завдань
> "Create tasks for auth system with dependencies"

# Продовжити роботу пізніше (нова сесія)
export CLAUDE_CODE_TASK_LIST_ID="project-name"
CLAUDE_CODE_ENABLE_TODO_TOOLS=1 claude
> "TaskList to see current state"
```

**Ключові можливості:**
- 📁 **Персистентність**: Виживає після закриття сесії та стиснення контексту (`/compact`)
- 🔗 **Залежності**: Завдання А блокує виконання завдання Б
- 🔄 **Мульти-сесійність**: Трансляція статусу виконання на кілька терміналів
- 📊 **Статуси**: `pending` ➔ `in_progress` ➔ `completed`

**⚠️ Обмеження**: `TaskList` показує лише `id`, `subject`, `status`, `blockedBy`.
Для перегляду `description` / `metadata` ➔ використовуйте `TaskGet(taskId)` для кожного завдання.

**Порада**: Зберігайте ключову інформацію в полі `subject` для зручності швидкого сканування.

**Прапорець відкату на стару систему** (v2.1.19+):
```bash
# Повернутися до старої системи TodoWrite
CLAUDE_CODE_ENABLE_TODO_TOOLS=1 CLAUDE_CODE_ENABLE_TASKS=0 claude
```

**➔ Повний воркфлоу**: [guide/workflows/task-management.md](workflows/task-management.uk.md)

## Золоті правила

1. **Завжди перевіряйте diff** перед підтвердженням змін клавішею `y`.
2. **Стискайте контекст** (`/compact`) до того, як він досягне критичного рівня (>70%).
3. **Будьте гранично конкретними** в запитах (ЩО, ДЕ, ЯК, ПЕРЕВІРКА).
4. **Запускайте Plan Mode спочатку** для складних або ризикованих змін.
5. **Створюйте CLAUDE.md** у корені кожного проекту.
6. **Робіть коміти часто** — після кожного логічно виконаного завдання.
7. **Пам'ятайте, що надсилається в Anthropic**: промпти, файли, результати MCP ➔ ([опція відмови від навчання моделей](https://claude.ai/settings/data-privacy-controls)).

## Швидка карта рішень (Decision Tree)

```
Просте завдання     ➔ Просто попросіть Claude зробити його
Складне завдання   ➔ Використовуйте Tasks API для планування
Ризикована зміна   ➔ Спочатку увійдіть у Plan Mode (планування)
Повторювана дія    ➔ Створіть власного агента або команду
Контекст забитий    ➔ Запустіть /compact або /clear
Потрібна дока      ➔ Використовуйте MCP-сервер Context7
Глибокий аналіз    ➔ Використовуйте Opus ( Thinking увімкнено за замовчуванням)
```

## Швидке вирішення типових проблем

| Проблема | Вирішення |
|---------|----------|
| "Command not found" | Перевірте PATH, перевстановіть: `curl -fsSL https://claude.ai/install.sh \| bash` |
| Переповнення контексту (>70%) | Негайно виконайте `/compact` |
| Повільні відповіді моделі | Виконайте `/compact` або `/clear` |
| MCP не працює | `claude mcp list`, перевірте конфіг |
| Permission denied | Перевірте `settings.local.json` |
| Блокування хуком | Перевірте код виходу хука, перегляньте логіку |

**Скрипт перевірки стану (Health Check):**
```bash
# macOS/Linux
which claude && claude doctor && claude mcp list

# Windows PowerShell
where.exe claude; claude doctor; claude mcp list
```

Швидке рішення (5 секунд): точний текст ➔ `rg` | точна назва ➔ `rg`/Serena | концепція ➔ `grepai` | структура коду ➔ `ast-grep`

| Завдання | Інструмент | Команда |
|------|------|---------|

## Основні команди

| Команда | Дія |
|---------|--------|
| `/help` | Контекстна допомога |
| `/powerup` | Інтерактивні анімовані уроки функцій Claude Code |
| `/clear` | Скинути розмову |
| `/compact` | Звільнити контекст |
| `/status` | Стан сесії + використання контексту |
| `/context` | Детальний розбір токенів |
| `/plan` | Увійти в режим планування (без змін) |
| `/ultraplan` | Хмарний режим планування — чернетка в хмарі, перегляд у браузері (v2.1.91+) |
| `/execute` | Вийти з режиму планування (застосувати зміни) |
| `/model` | Змінити модель (sonnet/opus/opusplan) |
| `/insights` | Аналітика використання + звіт з оптимізації |
| `/simplify` | Виявлення "овер-інжинірингу" в зміненому коді + авто-виправлення |
| `/batch` | Масштабні рефакторинги через 5–30 паралельних агентів у робочих деревах (worktrees) |
| `/teleport` | Телепортувати сесію з вебу |
| `/tasks` | Моніторинг фонових завдань |
| `/remote-env` | Налаштування хмарного середовища |
| `/remote-control` | Почати сесію дистанційного керування (Research Preview, Pro/Max) |
| `/rc` | Аліас для `/remote-control` |
| `/mobile` | Отримати посилання на мобільний додаток Claude |
| `/fast` | Увімкнути швидкий режим (2.5x швидкість, 6x вартість) |
| `/voice` | Увімкнути голосове введення (утримуйте Space для мовлення, відпустіть для відправки) |
| `/recap` | Стислий підсумок контексту сесії після повернення з перерви (v2.1.108) |
| `/effort [level]` | Глибина міркувань (Thinking): low/medium/high/xhigh/max; без аргументу = інтерактивний повзунок (v2.1.111) |
| `/tui [fullscreen]` | Повноекранний TUI режим без мерехтіння (v2.1.110) |
| `/focus` | Увімкнути мінімалістичний режим фокусування, окремо від Ctrl+O (v2.1.110) |
| `/less-permission-prompts` | Сканувати транскрипти та запропонувати список дозволених read-only інструментів (v2.1.111) |
| `/btw [question]` | Додаткове питання поверх сесії — read-only тимчасовий агент, без засмічення історії та виклику інструментів |
| `/loop [interval] [prompt]` | Запускати промпт по колу (наприклад: `/loop 5m check the deploy`, за замовчуванням 10m) |
| `/stats` | Графік використання, улюблена модель, серія днів *(аліас для `/usage` починаючи з v2.1.118)* |
| `/usage` | Використання токенів та вартість за моделями (v2.1.118) |
| `/ultrareview` | Багатоагентне хмарне рев'ю коду (v2.1.114) |
| `/rename [name]` | Назвати або перейменувати поточну сесію |
| `/copy` | Інтерактивний вибір для копіювання блоку коду або всієї відповіді |
| `/debug` | Систематичне усунення несправностей |
| `/exit` | Вийти (або Ctrl+D) |

## Керування контекстом (КРИТИЧНО)

### Рядок статусу (Statusline)

```
Model: Sonnet | Ctx: 89.5k | Cost: $2.11 | Ctx(u): 56.0%
```
**Слідкуйте за `Ctx(u):`** ➔ >70% = `/compact`, >85% = `/clear`

**Покращений статус-рядок ([ccstatusline](https://github.com/sirmalloc/ccstatusline)):** Додайте в `~/.claude/settings.json`:
```json
{ "statusLine": { "type": "command", "command": "npx -y ccstatusline@latest", "padding": 0 } }
```

### Порогові значення контексту

| Контекст % | Стан | Дія |
|-----------|--------|--------|
| 0-50% | Зелений | Працюйте вільно |
| 50-70% | Жовтий | Будьте вибірковими з файлами |
| 70-90% | Помаранчевий | `/compact` негайно |
| 90%+ | Червоний | Обов'язково `/clear` |

### Дії за симптомами

| Симптом | Дія |
|------|--------|
| Короткі або неповні відповіді | `/compact` |
| Часте "забування" контексту | `/clear` |
| >70% використаного контексту | `/compact` |
| Завдання повністю завершено | `/clear` |

### Команди відновлення контексту

| Команда | Використання |
|---------|-------|
| `/compact` | Узагальнити та звільнити контекст |
| `/clear` | Почати з чистого аркуша |
| `/rewind` | Скасувати останні зміни (відкотити кроки) |
| `claude -c` | Продовжити останню сесію (CLI прапорець) |
| `claude -r <id>` | Відновити конкретну сесію за ID (CLI прапорець) |

## Під капотом (Швидкі факти)

| Концепція | Ключовий момент |
|---------|-----------|
| **Master Loop** | Простий цикл `while(tool_call)` — жодних складних DAG-графів чи класифікаторів |
| **Інструменти** | 8 базових: Bash, Read, Edit, Write, Grep, Glob, Task, TodoWrite |

| **Суб-агенти** | Ізольований контекст, максимальна глибина вкладеності = 1 |
| **Філософія** | "Less scaffolding, more model" (менше каркаса, більше моделі) — довіра до міркувань Claude |

## Режим планування та Міркування (Plan Mode & Thinking)

| Функція | Активація | Використання |
|---------|------------|-------|
| **Plan Mode** | `Shift+Tab × 2` або `/plan` | Досліджуйте та плануйте без внесення змін на диск |
| **OpusPlan** | `/model opusplan` | Гібрид: Opus для планування, Sonnet для написання коду |
| **Ultraplan** | `/ultraplan <prompt>` | Планування у хмарі, перегляд у браузері, термінал залишається вільним (v2.1.91+, потрібен GitHub) |

> **Opus 4.7** (v2.1.114+): Рівень міркувань (effort) за замовчуванням у Claude Code = **xhigh** для всіх планів. Новий рівень `xhigh` знаходиться між `high` та `max` — тонше управління затримкою та якістю міркувань. Використовуйте `ultrathink` для форсування максимального effort на наступний хід.

| Керування міркуваннями | Дія | Збереження |
|---------|--------|-------------|
| **Alt+T** | Увімкнути/вимкнути Thinking | На сесію |
| **`/config`** | Увімкнути/вимкнути глобально | Постійно |
| **повзунок `/model`** | Стрілки вліво/вправо: `low\|medium\|high\|xhigh` | На сесію |
| **`CLAUDE_CODE_EFFORT_LEVEL`** | Змінна середовища: `low\|medium\|high\|xhigh\|max` | На сесію оболонки |
| **параметр `effortLevel`** | В settings.json: `low\|medium\|high\|xhigh\|max` | Постійно |
| **`effort` у Skill Frontmatter** | Перевизначення в скілі: `low\|medium\|high\|xhigh` (v2.1.80+) | На виклик |

**Порада щодо витрат**: Для простих механічних завдань вимикайте Thinking (`Alt+T`) — це набагато швидше та дешевше.

**Effort на рівні скілів**: додайте `effort: low` для суто механічних скілів (коміт, синхронізація, розгортання) та `effort: high` для аналітичних (аудит безпеки, архітектурний огляд). Перевизначає налаштування сесії автоматично.

**Воркфлоу OpusPlan**: `/model opusplan` ➔ `Shift+Tab × 2` (планування з Opus) ➔ `Shift+Tab` (виконання з Sonnet).

**Воркфлоу Ultraplan**: `/ultraplan <task>` ➔ термінал вільний, поки в хмарі створюється чернетка ➔ перегляд у браузері ➔ схвалення ➔ виконання на веб (PR) або телепортація назад у термінал.

**Обов'язково для**: завдань на >3 файли, проектування архітектури, складного дебагу.

### Швидкий вибір моделі

| Завдання | Модель | Рівень міркувань (Effort) |
|------|-------|--------|
| Перейменування, шаблонний код, генерація тестів | Haiku | low |
| Розробка фіч, дебаг, рефакторинг | Sonnet | medium–high |
| Проектування архітектури, аудит безпеки | Opus | high–max |

> Детальна таблиця вибору моделі з оцінкою вартості: [Розділ 2.5 Інструкції з вибору моделі та міркувань](ultimate-guide.md#25-model-selection--thinking-guide)

### Динамічне перемикання моделей (Mid-Session)

**Патерн**: Початок із Sonnet (швидкість) ➔ перехід на Opus (складність) ➔ повернення на Sonnet.

**Воркфлоу**:
```bash
# Старт сесії (за замовчуванням Sonnet)
claude

# Зустрілося складне завдання
> "Implement OAuth2 flow with PKCE"
/model opus                    # Перемикання на глибокі міркування

# Фіча готова, повертаємося до рутини
/model sonnet                  # Оптимізація швидкості та вартості
```

**Кращі практики**:
- ✅ Змінюйте модель **на кордонах завдань**, а не посеред виконання одного кроку.
- ✅ Використовуйте Opus для: архітектурних рішень, складного дебагу, критичного для безпеки коду.
- ✅ Використовуйте Sonnet для: рутинних правок, рефакторингу, написання тестів.
- ✅ Використовуйте Haiku для: швидких фіксів, виправлення друкарських помилок, перевірок валідації.
- ❌ Не змінюйте модель посеред безпосереднього написання коду (втрата контексту).

**Вплив на вартість**:
| Модель | Вхідні токени (Input) | Вихідні токени (Output) | Застосування |
|-------|--------|--------|----------|
| Opus 4.7 | $5/MTok | $25/MTok | Складні міркування (10-20% завдань) |
| Sonnet 4.6 | $3/MTok | $15/MTok | Основна розробка (70-80% завдань) |
| Haiku 4.5 | $0.80/MTok | $4/MTok | Проста валідація (5-10% завдань) |

**Динамічне перемикання** дозволяє економити кошти без втрати якості на складних ділянках.

```markdown
---
description: Короткий опис команди
argument-hint: "<обов'язковий_аргумент> [--прапорець]"
---
# Назва команди
Інструкції щодо того, що робити...
Аргументи користувача: $ARGUMENTS[0] $ARGUMENTS[1] (або $0 $1)
```

## Дистанційне керування — Мобільний доступ (v2.1.51+, Research Preview)

> **Тільки для тарифів Pro/Max** — недоступно для тарифів Team, Enterprise або при роботі через API-ключі

```bash
# Запустити з терміналу (нова сесія)
claude remote-control

# Або зсередини активної сесії:
/rc        # (або /remote-control)
```

**Підключення з телефону/планшета/браузера:**
1. Відскануйте **QR-код** (натисніть пробіл після запуску для показу)
2. Або відкрийте **URL сесії** у браузері / мобільному додатку Claude
3. Або: `/mobile` ➔ показує посилання на App Store + Play Store

| ⚠️ Відоме обмеження | Опис |
|--------------------|--------|
| 1 сесія одночасно | Лише одна активна дистанційна сесія |
| Зламані слеш-команди | `/new`, `/compact` сприймаються як звичайний текст ➔ запускайте з терміналу |
| Термінал має бути відкритим | Закриття локального терміналу завершує сесію |
| Таймаут мережі | Відключення через ~10 хв ➔ сесія застаріває |

**Просунутий рівень: мульти-сесії через tmux** (обхід ліміту в 1 сесію)
```bash
tmux new-session -s dev
# Кожна панель = своя сесія claude
# Запустіть /rc у тій панелі, якою хочете керувати дистанційно
```

**Авто-ввімкнення:** `/config` ➔ увімкнути "Remote Control: auto-enable"

**Детальний док**: [§9.22 Дистанційне керування](ultimate-guide.md#922-remote-control-mobile-access) | [Примітки з безпеки](security-hardening.md#remote-control-security)

## Управління завданнями / Tasks API (v2.1.16+)

**Доступні дві системи:**

| Система | Коли використовувати | Збереження |
|--------|-------------|-------------|
| **Tasks API** (v2.1.16+) | Багатосесійні проекти, залежності | ✅ На диску (`~/.claude/tasks/`) |
| **TodoWrite** (Застаріла) | Прості односесійні завдання | ❌ Лише в межах однієї сесії |

### Команди Tasks API

```bash
# Увімкнути персистентність між сесіями
export CLAUDE_CODE_TASK_LIST_ID="project-name"
claude

# Всередині Claude: Створити ієрархію завдань
> "Create tasks for auth system with dependencies"

# Продовжити роботу пізніше (нова сесія)
export CLAUDE_CODE_TASK_LIST_ID="project-name"
claude
> "TaskList to see current state"
```

**Ключові можливості:**
- 📁 **Персистентність**: Виживає після закриття сесії та стиснення контексту (`/compact`)
- 🔗 **Залежності**: Завдання А блокує виконання завдання Б
- 🔄 **Мульти-сесійність**: Трансляція статусу виконання на кілька терміналів
- 📊 **Статуси**: `pending` ➔ `in_progress` ➔ `completed`/`failed`

**⚠️ Обмеження**: `TaskList` показує лише `id`, `subject`, `status`, `blockedBy`.
Для перегляду `description` / `metadata` ➔ використовуйте `TaskGet(taskId)` для кожного завдання.

**Порада**: Зберігайте ключову інформацію в полі `subject` для зручності швидкого сканування.

**Прапорець відкату на стару систему** (v2.1.19+):
```bash
# Повернутися до старої системи TodoWrite
CLAUDE_CODE_ENABLE_TASKS=false claude
```

**➔ Повний воркфлоу**: [guide/workflows/task-management.md](../workflows/task-management.md)

## Золоті правила

1. **Завжди перевіряйте diff** перед підтвердженням змін клавішею `y`.
2. **Стискайте контекст** (`/compact`) до того, як він досягне критичного рівня (>70%).
3. **Будьте гранично конкретними** в запитах (ЩО, ДЕ, ЯК, ПЕРЕВІРКА).
4. **Запускайте Plan Mode спочатку** для складних або ризикованих змін.
5. **Створюйте CLAUDE.md** у корені кожного проекту.
6. **Робіть коміти часто** — після кожного логічно виконаного завдання.
7. **Пам'ятайте, що надсилається в Anthropic** — промпти, файли, результати MCP ➔ ([опція відмови від навчання моделей](https://claude.ai/settings/data-privacy-controls)).

## Швидка карта рішень (Decision Tree)

```
Просте завдання     ➔ Просто попросіть Claude зробити його
Складне завдання   ➔ Використовуйте Tasks API для планування
Ризикована зміна   ➔ Спочатку увійдіть у Plan Mode (планування)
Повторювана дія    ➔ Створіть власного агента або команду
Контекст забитий    ➔ Запустіть /compact або /clear
Потрібна дока      ➔ Використовуйте MCP-сервер Context7
Глибокий аналіз    ➔ Використовуйте Opus ( Thinking увімкнено за замовчуванням)
```

## Швидке вирішення типових проблем

| Проблема | Вирішення |
|---------|----------|
| "Command not found" | Перевірте PATH, перевстановіть: `curl -fsSL https://claude.ai/install.sh \| sh` |
| Переповнення контексту (>70%) | Негайно виконайте `/compact` |
| Повільні відповіді моделі | Виконайте `/compact` або `/clear` |
| MCP не працює | `claude mcp list`, перевірте конфіг |
| Permission denied | Перевірте `settings.local.json` |
| Блокування хуком | Перевірте код виходу хука, перегляньте логіку |

**Скрипт перевірки стану (Health Check):**
```bash
# macOS/Linux
which claude && claude doctor && claude mcp list

# Windows PowerShell
where.exe claude; claude doctor; claude mcp list
```

## Швидкий довідник пошукових інструментів

Швидке рішення (5 секунд): точний текст ➔ `rg` | точна назва ➔ `rg`/Serena | концепція ➔ `grepai` | структура коду ➔ `ast-grep`

| Завдання | Інструмент | Команда |
|------|------|---------|
| "Знайти коментарі TODO" | `rg` | `rg "TODO"` |
| "Знайти код авторизації" | `grepai` | `grepai search "authentication"` |
| "Хто викликає метод login?" | `grepai` | `grepai trace callers "login"` |
| "Отримати структуру файлу" | `Serena` | `serena get_symbols_overview` |
| "Асинхронні методи без try/catch" | `ast-grep` | `ast-grep "async function $F"` |

Швидкість: `rg` (~20мс) ➔ Serena (~100мс) ➔ `ast-grep` (~200мс) ➔ `grepai` (~500мс)

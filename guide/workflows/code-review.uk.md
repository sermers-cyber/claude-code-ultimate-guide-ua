# Огляд коду

> **Доступність**: загальнодоступна з 15 жовтня 2026 року (попередній перегляд дослідження діяв з 9 березня 2026 року). Лише плани Team та Enterprise, для репозиторіїв GitHub (зокрема GitHub Enterprise Server та GitHub Enterprise Cloud з data residency). Недоступна за нульового збереження даних (Zero Data Retention), конфігурації HIPAA або ключів шифрування, якими керує клієнт (CMEK). Факти на цій сторінці звірено з [офіційною документацією Code Review](https://code.claude.com/docs/en/code-review) 27 жовтня 2026 року.

Функція Code Review у Claude Code запускає мультиагентний огляд для запитів на злиття (pull request) у GitHub. Кілька агентів досліджують diff у контексті навколишнього коду, причому кожен агент шукає певний клас проблем (логічні помилки, вразливості безпеки, зламані граничні випадки), після чого виконується етап перевірки для відсіювання хибних спрацьовувань.

Знайдені зауваження публікуються як інлайн-коментарі до відповідних рядків, із позначенням рівня важливості, разом із підсумком у тілі огляду та check run із назвою **Claude Code Review**. Огляди ніколи не затверджують і не блокують PR, а check run ніколи не завершується як збій, тому існуючі робочі процеси перевірки залишаються незмінними.

Code Review є керованим варіантом. На будь-якому плані ви також можете запускати [`/code-review`](https://code.claude.com/docs/en/code-review-local) локально, запускати ultrareview із Claude Code або запускати Claude у власному CI.

## Як це працює

1. **Пошук (Find)**: кілька агентів паралельно досліджують diff та навколишній код на інфраструктурі Anthropic
2. **Верифікація (Verify)**: крок верифікації перевіряє знайдені кандидати на відповідність коду та усуває хибні спрацьовування
3. **Ранжування (Rank)**: решту зауважень дедуплікують і ранжують за важливістю
4. **Публікація (Post)**: у PR з'являються інлайн-коментарі, підсумок і check run **Claude Code Review**

Огляд читає diff та навколишній код, не збираючи й не запускаючи його, а його доступ до репозиторію лише на читання: він не пушить коміти. Anthropic повідомила під час GA, що більшість оглядів завершується за 6-10 хвилин, приблизно втричі швидше, ніж приблизно 20 хвилин у попередньому перегляді ([анонс GA](https://claude.com/resources/articles/code-review-is-now-generally-available)). Сприймайте це як цифру від вендора, а не гарантію.

### Рівні огляду

Власник (Owner) задає один рівень за замовчуванням для організації та може перевизначити його для окремого репозиторію:

| Рівень | Компроміс |
|-------|-----------|
| **Quick** | Легший прохід. Найшвидший, найдешевший |
| **Standard** | Збалансовані глибина, швидкість і вартість. Типовий |
| **Deep** | Найретельніший прохід. Найповільніший, найдорожчий |

Code Review сам обирає моделі; у налаштуваннях адміністратора вибору моделі немає. Рівень є засобом керування ретельністю.

### Рівні важливості

| Маркер | Важливість | Значення |
|:-------|:---------|:--------|
| 🔴 | Important | Баг, який слід виправити перед злиттям |
| 🟡 | Дрібниця (Nit) | Незначна проблема, яку варто виправити, але вона не є блокуючою |
| 🟣 | Існуюча раніше | Баг у кодовій базі, який не був внесений цим PR |

Якщо огляд зафіксував свої міркування, у зауваженні є згорнутий розділ **Why this was flagged**, де пояснюється, чому Claude позначив проблему та як він її перевірив.

## Налаштування

**Власник (Owner)** організації Claude вмикає Code Review в **Admin settings > Claude Code** ([claude.ai/admin-settings/claude-code](https://claude.ai/admin-settings/claude-code#code-review)). Огляди виконуються на інфраструктурі Anthropic, тому до репозиторіїв не додаються файли воркфлоу.

Потрібний доступ:

- Роль Owner в організації Claude, для всіх кроків на сторінці адміністратора
- Owner організації GitHub, щоб встановити Claude GitHub App і пов'язати його з організацією Claude
- Доступ на запис до кожного репозиторію, який ви додаєте, з облікового запису GitHub, підключеного до Claude

Кроки:

1. Натисніть перемикач **Allow code review**
2. Підключіть свій обліковий запис GitHub (за потреби спершу виберіть свій екземпляр GitHub Enterprise Server)
3. Встановіть Claude GitHub App в організації GitHub і виберіть репозиторії, до яких він матиме доступ. Набір дозволів додатка ширший, ніж потрібно для огляду, оскільки він спільний з іншими функціями Claude, як-от [GitHub Actions](./github-actions.uk.md)
4. Виберіть репозиторії, потім натисніть **Continue**
5. Натисніть **Finish** у діалозі **Code review is set up**. Якщо закрити його іншим способом, **Allow code review** залишиться вимкненим
6. Відкрийте тестовий PR, що не є чернеткою, і перевірте, що з'явився check run **Claude Code Review**

### Налаштування запуску оглядів

Кожен репозиторій має власне налаштування **Review runs**:

| Варіант | Коли запускається | Профіль вартості |
|--------|-------------|--------------|
| **Once after PR creation** | Коли PR відкрито, повторно відкрито або позначено як готовий до огляду | Найнижчий серед автоматичних |
| **After every push** | При кожному push у гілку PR, автоматично закриваючи гілки обговорення, коли позначені проблеми виправлено | Найвищий (множиться на кількість push) |
| **Manual (@claude review)** | Тільки за командою в коментарі | Контрольований |

Репозиторій, доданий із діалогу **Add a repository**, **починає з After every push**, найдорожчого варіанта. Змініть його одразу після налаштування, якщо хочете менше оглядів. Автоматичні огляди пропускають чернетки PR та PR із форків незалежно від налаштування.

Owner також може охопити всю організацію github.com з її рядка в таблиці **Repositories**, для чого потрібен щомісячний ліміт витрат, і вибраний варіант застосовується до кожного репозиторію там, зокрема доданих пізніше.

## Команди в коментарях

Публікуйте команду як новий коментар верхнього рівня в PR, одним рядком на початку коментаря. Вам потрібні права write, maintain або admin у репозиторії; коментарі ботів не запускають огляди.

| Команда | Ефект |
|---------|--------|
| `@claude review` або `@claude review once` | Запускає один огляд усього PR, **не** підписуючи його на майбутні push |
| `@claude review always` | Запускає огляд і підписує PR на огляди, що запускаються push |
| `@claude review stop` (також `off`, `pause`) | Завершує підписку, не запускаючи й не скасовуючи огляд |

До оновлення в липні 2026 року `@claude review` підписував PR на огляди, що запускаються push. Тепер для такої поведінки використовуйте `@claude review always`. У репозиторії з налаштуванням **After every push** коментар не може зупинити огляди; натомість переведіть PR у чернетку.

Команда в коментарі працює на чернетках і на PR із форків, які автоматичні огляди пропускають. Для форка потрібен доступ на запис до базового репозиторію. Якщо огляд уже виконується для останнього коміту, новий запит не запускає другий.

Якщо репозиторій також запускає [Claude Code GitHub Action](./github-actions.uk.md) із типовою фразою-тригером `@claude`, `@claude review` запустить і Action. Задайте вхідному параметру `trigger_phrase` Action іншу фразу, щоб їх розділити.

### Повторні огляди та збережені результати

Огляд, що стартує після push, зосереджується на тому, що змінилося з часу останнього огляду, і публікує менше дрібниць та зауважень про існуючі раніше проблеми; тіло огляду вказує, скільки було пропущено. Залиште коментар `@claude review` для повного повторного огляду.

Після push, який не змінює додані й видалені рядки (порожній коміт, чисте злиття базової гілки або чистий rebase), Code Review може зберегти попередній результат замість запуску огляду. Заголовок check run тоді починається з **Code review skipped** (жодного відкритого зауваження Important) або **Code review not repeated** (попередні зауваження Important досі відкриті).

### Блокування злиття з власного CI

Check run завершується як нейтральний, ніколи як збій. Щоб блокувати злиття, прочитайте лічильники важливості, якими закінчується текст Details у check run: HTML-коментар на кшталт `<!-- bughunter-severity: {"nit":1,"normal":2,"pre_existing":0} -->`, де `normal` рахує зауваження Important. Відсутній рядок означає відсутність вердикту, а не нуль зауважень. [Офіційна процедура](https://code.claude.com/docs/en/code-review-pull-requests#read-the-result-from-a-script) містить команди `gh api` і `jq` та перевірки заголовка, які слід виконати спершу.

## Налаштування оглядів

Два файли контролюють те, що саме Claude позначає як проблему. Обидва діють як доповнення до стандартних перевірок коректності.

### CLAUDE.md

Claude зчитує всі файли `CLAUDE.md` в ієрархії ваших директорій. Нещодавно внесені порушення позначаються як зауваження рівня Nit. Двонаправлений зв'язок: якщо PR робить якесь твердження в `CLAUDE.md` застарілим, Claude також вкаже на необхідність оновлення документації.

Використовуйте `CLAUDE.md` для інструкцій, які також застосовуються до інтерактивних сесій Claude Code.

### REVIEW.md

Додайте `REVIEW.md` у **корінь репозиторію** для правил, які застосовуються виключно під час огляду. Він виявляється автоматично, додаткове налаштування не потрібне. Code Review читає його з базової або типової гілки, ніколи не зі змін самого PR, тому PR не може послабити власні правила огляду.

```markdown
# Code Review Guidelines

## Always check
- New API endpoints have corresponding integration tests
- Database migrations are backward-compatible
- Error messages don't leak internal details to users

## Style
- Prefer early returns over nested conditionals
- Use structured logging, not f-string interpolation in log calls

## Skip
- Generated files under `src/gen/`
- Formatting-only changes in `*.lock` files
- Migration files in `db/migrations/`
```

Використовуйте `REVIEW.md` для правил, які захаращували б `CLAUDE.md` для звичайних сесій (конвенції лінтерів, списки виключень, специфічні для команди паттерни).

## Ціноутворення

Огляд коду оплачується на основі використання токенів через кредити використання (usage credits), **окремо від використання, включеного у ваш тарифний план**, і виставляється організації, а не розробнику, який відкрив PR або запросив огляд. Витрати відображаються в рахунку Anthropic, навіть якщо організація використовує Amazon Bedrock, Google Cloud's Agent Platform або Microsoft Foundry для інших функцій Claude Code ([витрати та використання](https://code.claude.com/docs/en/code-review-costs)).

- Фіксованої ціни за огляд немає: вартість залежить від рівня огляду, розміру змін, складності навколишнього коду та кількості проблем-кандидатів для верифікації. [Стаття підтримки](https://support.claude.com/en/articles/14233555-set-up-code-review-for-claude-code) наводить середню вартість **$15-25 за огляд**
- Режим "After every push" збільшує вартість пропорційно кількості push, і це початкове налаштування для нових репозиторіїв
- Щомісячний ліміт витрат: **Organization settings > Usage**, для послуги Claude Code Review
- Середня вартість огляду за репозиторієм: стовпець **Average cost** у таблиці **Repositories** в **Admin settings > Claude Code**; цифри аналітики оцінюються за прайсовою ціною і можуть відрізнятися від рахунку
- Промоакція для Enterprise на момент GA: придатні організації Claude Enterprise можуть отримати щонайменше $10 000 кредитів Code Review до 15 січня 2027 року; кредити спливають через 30 днів після отримання ([умови в анонсі GA](https://claude.com/resources/articles/code-review-is-now-generally-available))

## Перехресні посилання

Для ручних робочих процесів огляду коду (CLI, плани Team/Enterprise не потрібні):
- [Мультиагентний робочий процес огляду коду](#split-role-sub-agents): власні команди агентів через CLI
- [Інтеграція з GitHub Actions](./github-actions.uk.md): кастомна автоматизація CI/CD (альтернатива з власним хостингом для цього керованого сервісу)
- [Multi-provider code review](./multi-provider-code-review.uk.md): запуск Claude поряд із CodeRabbit/Greptile без надлишкових зауважень, із власним хостингом
- GitLab CI/CD: інтеграція Claude з власним хостингом для конвеєрів GitLab
- Плагін Code Review: локальний огляд за запитом перед push (доступний у магазині плагінів)
- [From code to merge](https://www.florian.bruniaux.com/guides/from-code-to-merge/): авторський докладний посібник до доповіді про організацію воркфлоу з агентами в команді, від локальних перевірок та AI-оглядів до результатів, прив'язаних до потрібного коміту

## Огляд інформує політику приймання

Опублікований огляд є доказом, який слід кваліфікувати, а не дозволом на злиття. Підтвердьте переглянуту ревізію, фактичне виконання та охоплений обсяг, а потім застосуйте обов'язкові перевірки репозиторію та уповноважений процес ухвалення рішень. Під час підсумовування зберігайте невирішені зауваження та розбіжності. [Multi-provider воркфлоу](./multi-provider-code-review.uk.md#блокування-злиття-гейт-ci) охоплює ці межі та локальну контрольну вправу; він не встановлює поведінку керованого сервісу під час виконання.

## Відомі обмеження

- Лише плани Team та Enterprise, немає доступу для Free/Pro
- Недоступно за нульового збереження даних, конфігурації HIPAA (не охоплена BAA від Anthropic) або ключів шифрування, якими керує клієнт
- Тільки GitHub для керованого сервісу (GitLab підтримується через інтеграцію з CI/CD, а не через цю функцію)
- Огляди не виконуються в середовищах із власним хостингом і не збирають та не запускають ваш код
- Автоматичні огляди пропускають чернетки та PR із форків; запитуйте їх командою в коментарі
- Внутрішня статистика Anthropic з попереднього перегляду: ~7.5 виявлених проблем на PR обсягом >1000 рядків, <1% хибних спрацьовувань (задекларовано розробниками, незалежна перевірка не проводилась)

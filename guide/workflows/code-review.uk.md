# Огляд коду

> **Доступність**: Попередній перегляд дослідження — лише для тарифних планів Teams та Enterprise. Недоступно для безкоштовних (Free) та професійних (Pro) облікових записів, а також для організацій із увімкненим нульовим збереженням даних (Zero Data Retention — ZDR).
> **Запущено**: 9 березня 2026 року

Функція Code Review у Claude Code запускає мультиагентний огляд для кожного запиту на злиття (pull request) у GitHub. Група спеціалізованих агентів досліджує diff у контексті всієї кодової бази, причому кожен агент шукає певний клас проблем (логічні помилки, вразливості безпеки, граничні випадки, регресії), після чого виконується етап перевірки для відсіювання хибних спрацьовувань.

Знайдені зауваження публікуються як інлайн-коментарі до конкретних рядків PR, де були виявлені проблеми, із позначенням рівня важливості. Огляди не затверджують і не блокують PR, тому існуючі робочі процеси перевірки залишаються незмінними.

---

## Як це працює

1. Спрацьовує тригер (відкриття PR, push або ручний коментар `@claude review`)
2. Кілька агентів паралельно аналізують diff та навколишній код на інфраструктурі Anthropic
3. Кожен агент націлений на свій клас проблем
4. Крок верифікації перевіряє кандидатів на відповідність реальній поведінці коду для усунення хибних спрацьовувань
5. Результати дедуплікуються, ранжуються за важливістю та публікуються як інлайн-коментарі в PR
6. Якщо проблем не виявлено, Claude залишає короткий коментар-підтвердження

Огляд завершується в середньому за **20 хвилин**, час масштабується залежно від розміру та складності PR.

### Рівні важливості

| Маркер | Важливість | Значення |
|:-------|:---------|:--------|
| 🔴 | Звичайна | Баг, який слід виправити перед злиттям |
| 🟡 | Дрібниця (Nit) | Незначна проблема, яку варто виправити, але вона не є блокуючою |
| 🟣 | Існуюча раніше | Баг у кодовій базі, який не був внесений цим PR |

Кожне зауваження містить згорнутий розділ із розширеними міркуваннями, де пояснюється, чому Claude позначив цю проблему та як він її перевірив.

## Налаштування

Адміністратор один раз вмикає Code Review для організації та вибирає, які репозиторії слід підключити.

### 1. Відкрийте налаштування адміністратора

Перехід на [claude.ai/admin-settings/claude-code](https://claude.ai/admin-settings/claude-code) та знайдіть розділ **Code Review**. Потрібен адміністративний доступ до вашої організації Claude та дозвіл на встановлення GitHub Apps у вашій організації GitHub.

### 2. Натисніть Setup

Це запустить процес встановлення GitHub App.

### 3. Встановіть Claude GitHub App

Дотримуйтесь інструкцій, щоб встановити Claude GitHub App у вашій організації GitHub. Додаток запитує такі дозволи:

- **Contents**: читання та запис
- **Issues**: читання та запис
- **Pull requests**: читання та запис

Code Review використовує доступ на читання до вмісту та доступ на запис до pull requests. Цей набір дозволів також підтримує [GitHub Actions](./github-actions.uk.md), якщо ви вирішите ввімкнути їх пізніше.

### 4. Виберіть репозиторії

Виберіть, для яких репозиторіїв увімкнути функцію. Якщо якийсь репозиторій відсутній, переконайтеся, що ви надали доступ для GitHub App під час встановлення. Ви зможете додати більше репозиторіїв пізніше з таблиці налаштувань адміністратора.

### 5. Встановіть тригери огляду для кожного репозиторію

Для кожного репозиторію виберіть, коли запускати огляди:

| Тригер | Коли запускається | Профіль вартості |
|---------|-------------|--------------|
| **Один раз після створення PR** | Один раз, коли PR відкривається або позначається як готовий | Найнижчий |
| **Після кожного push** | При кожному push у гілку PR | Найвищий (множиться на кількість push) |
| **Ручний** | Тільки коли хтось залишає коментар `@claude review` | Контрольований |

Після коментаря `@claude review` наступні push у цей PR автоматично запускатимуть огляди незалежно від налаштованого тригера.

**Ручний режим** корисний для репозиторіїв із високою активністю, де ви хочете підключати конкретні PR до огляду, або починати перевірку лише тоді, коли PR повністю готовий до цього.

---

## Ручний тригер

Залиште коментар `@claude review` у будь-кому відкритому (не як чернетка / draft) PR, щоб негайно запустити огляд. Вимоги:

- Коментар верхнього рівня в PR (не інлайн-коментар до diff)
- `@claude review` на початку коментаря
- Доступ власника, учасника (member) або контриб'ютора (collaborator) до репозиторію

Якщо огляд уже запущено, запит стає в чергу до завершення поточної перевірки.

## Налаштування оглядів

Два файли контролюють те, що саме Claude позначає як проблему. Обидва діють як доповнення до стандартних перевірок коректності.

### CLAUDE.md

Claude зчитує всі файли `CLAUDE.md` в ієрархії ваших директорій. Нещодавно внесені порушення позначаються як зауваження рівня Nit. Двонаправлений зв'язок: якщо PR робить якесь твердження в `CLAUDE.md` застарілим, Claude також вкаже на необхідність оновлення документації.

Використовуйте `CLAUDE.md` для інструкцій, які також застосовуються до інтерактивних сесій Claude Code.

### REVIEW.md

Додайте `REVIEW.md` у **корінь репозиторію** для правил, які застосовуються виключно під час огляду. Він виявляється автоматично, додаткове налаштування не потрібне.

```markdown
# Code Review Guidelines

## Always check
- New API endpoints have corresponding integration tests
- Database migrations are backward-compatible
- Error messages don't leak internal details to users

## Style
- Prefer early returns over nested conditionals
- Use structured logging, not f-string interpolation in log calls

## Skip
- Generated files under `src/gen/`
- Formatting-only changes in `*.lock` files
- Migration files in `db/migrations/`
```

Використовуйте `REVIEW.md` для правил, які захаращували б `CLAUDE.md` для звичайних сесій (конвенції лінтерів, списки виключень, специфічні для команди паттерни).

## Ціноутворення

Огляд коду оплачується на основі використання токенів, **окремо від використання, включеного у ваш тарифний план** (через [додаткове використання](https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans)).

- Середня вартість: **$15–25 за огляд**, масштабується залежно від розміру PR, складності кодової бази та кількості проблем, що потребують верифікації
- Режим «Після кожного push» збільшує вартість пропорційно кількості push
- Щоб встановити щомісячний ліміт витрат: [claude.ai/admin-settings/usage](https://claude.ai/admin-settings/usage) → налаштуйте ліміт для послуги «Claude Code Review»
- Моніторинг витрат: [claude.ai/analytics/code-review](https://claude.ai/analytics/code-review) (щоденна кількість PR, щотижневі витрати, розбивка за репозиторіями)

## Перехресні посилання

Для ручних робочих процесів огляду коду (CLI, плани Teams/Enterprise не потрібні):
- [Мультиагентний робочий процес огляду коду](#split-role-sub-agents) — власні команди агентів через CLI
- [Інтеграція з GitHub Actions](./github-actions.uk.md) — кастомна автоматизація CI/CD (альтернатива з власним хостингом для цього керованого сервісу)
- GitLab CI/CD — інтеграція Claude з власним хостингом для конвеєрів GitLab
- Плагін Code Review — локальний огляд за запитом перед push (доступний у магазині плагінів)

## Відомі обмеження (попередній перегляд дослідження)

- Лише плани Teams та Enterprise — немає доступу для Free/Pro
- Недоступно для організацій із увімкненим нульовим збереженням даних (ZDR)
- Тільки GitHub для керованого сервісу (GitLab підтримується через інтеграцію з CI/CD, а не через цю функцію)
- Затримка індексування всього репозиторію при першій активації для великих репозиторіїв
- Внутрішня статистика Anthropic: ~7.5 виявлених проблем на PR обсягом >1000 рядків, <1% хибних спрацьовувань — задекларовано розробниками, незалежна перевірка не проводилась

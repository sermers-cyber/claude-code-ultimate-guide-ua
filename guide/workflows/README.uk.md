## 🎯 Робочі процеси розробки

### [Розробка на основі планування (Plan-Driven Development)](./plan-driven.uk.md)

Структуруйте складні завдання за допомогою planning mode перед виконанням.

**Коли використовувати**: Багатокрокові функції, архітектурні зміни, невпевненість у підході

### [Внески в open source за допомогою ШІ](./ai-assisted-open-source-contributions.uk.md)

Готуйте внесок із відтвореною проблемою, поясненням автора, доказами верифікації та відповідальністю за відгуки мейнтейнерів. Містить багаторазовий пакет внеску (contribution packet).

**Коли використовувати**: Claude Code допомагає підготувати патч для мейнтейнерів чужого проєкту.

### [TDD з Claude](./tdd-with-claude.uk.md)

Робочий процес розробки через тестування (Test-Driven Development): спочатку пишіть тести, потім реалізуйте.

**Коли використовувати**: Критична функціональність, запобігання регресіям, проектування API

### [Розробка спочатку за специфікацією (Spec-First Development)](./spec-first.uk.md)

Пишіть специфікації перед кодом для кращої ясності вимог.

**Коли використовувати**: Спільна робота в команді, складні функції, проекти з пріоритетом документації

### [Ітераційне вдосконалення (Iterative Refinement)](./iterative-refinement.uk.md)

Покращуйте код через кілька циклів вдосконалення.

**Коли використовувати**: Покращення якості, оптимізація продуктивності, очищення коду

### [Best-of-N: генерація, відбір і верифікація](./best-of-n.uk.md)

Згенеруйте заздалегідь визначений набір незалежних кандидатів, оцініть кожного за зафіксованою рубрикою, перевірте обраний результат поза контекстом його генерації та збережіть журнал доказів.

**Коли використовувати**: Є кілька правдоподібних рішень зі значущими компромісами, а рев'юер або виконувана перевірка здатні їх розрізнити

**Багаторазові ресурси**: [skill Best-of-N](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/examples/skills/best-of-n/SKILL.md) і [запис доказів TESTING.md](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/examples/claude-md/TESTING.md)

### [Проекти-шаблони (Skeleton Projects)](./skeleton-projects.uk.md) ⭐ NEW

Використовуйте існуючі перевірені в боях репозиторії як каркас для нових проектів.

**Коли використовувати**: Запуск нових проектів, стандартизація командних паттернів, швидке прототипування на перевіреній основі

### [Інструкції ШІ для команди (Team AI Instructions)](./team-ai-instructions.uk.md)

Масштабуйте CLAUDE.md для команди з багатьох розробників та інструментів за допомогою збірки модулів на основі профілів.

**Коли використовувати**: Команда з 5+ розробників, кілька інструментів ШІ (Claude Code + Cursor/Windsurf), різні ОС

### [Фрагменти журналу змін (Changelog Fragments)](./changelog-fragments.uk.md) ⭐ NEW

**Впроваджуйте обов'язкове документування для кожного PR за допомогою 3-рівневої системи: правило CLAUDE.md + hook UserPromptSubmit + CI gate**

Усуває конфлікти злиття в CHANGELOG.md, фіксує контекст під час реалізації та гарантує, що міграції DB ніколи не будуть розгорнуті непомітно. Включає багаторазовий патерн hook UserPromptSubmit для впровадження будь-го обов'язкового кроку робочого процесу.

**Ключові теми**:
- Правило робочого процесу CLAUDE.md для автономного створення фрагментів
- hook UserPromptSubmit з 3-рівневим пріоритетом (примусове виконання, виявлення, контекстне)
- Шаблон умовної пропозиції: "якщо намір PR без згадки фрагмента"
- CI-контроль з незалежним завданням перевірки міграції

### [Smart-Suggest routing](./smart-suggest-routing.uk.md) ⭐ NEW

**Двомоторна система hook `UserPromptSubmit`: регулярні вирази для примусового виконання + самокалібрований лексичний скоринг BM25**

Вставляє ранжовані підказки skill як `additionalContext`, щоб Claude пропонував потрібний skill, навіть якщо таке формулювання ніхто не передбачав. BM25 узагальнює приклади сценаріїв, а шар регулярних виразів відповідає за примусові патерни. Обидва працюють паралельно на кожен prompt.

**Ключові теми**:
- Таблиця рішень regex проти BM25 (коли виграє кожен рушій)
- Формат корпусу: 10+ позитивних і 3+ негативних сценаріїв на skill
- `build-index.js`: калібрування leave-one-out, поріг F-beta, статуси `ok`/`excluded`/`conflict`
- Підключення двох hooks паралельно через settings.json
- Від'єднане фонове перебудування індексу при зміні корпусу

### [RPI: Research → Plan → Implement (Дослідження → План → Реалізація)](./rpi.uk.md) ⭐ NEW

**3-фазна розробка функцій з явними перевірочними шлюзами (validation gates) між фазами**

Створюйте функції у три заблоковані фази: спочатку досліджуйте технічну можливість (Research), по-друге — плануйте реалізацію (Plan), по-третє — пишіть код (Implement). Кожна фаза створює конкретний артефакт (RESEARCH.md → PLAN.md → код). Кожен шлюз вимагає явного дозволу GO перед початком наступної фази.

**Коли використовувати**: Функції з неясною технічною можливістю, робота обсягом більше ніж на день, невідома технічна область або будь-яка ситуація, де пізнє виявлення помилкового припущення обходиться дорого

### [Робочі процеси GitHub Actions](./github-actions.uk.md) ⭐ NEW

**5 готових до використання у продакшені паттернів для автоматизації оглядів PR, сортування issue та шлюзів якості**

Підключайте Claude безпосередньо до вашого робочого процесу GitHub за допомогою офіційного claude-code-action. Два режими: інтерактивний (згадки @claude) та повністю автоматичний (тригери push/schedule).

**Ключові теми**:
- Налаштування через /install-github-app (30-секундний швидкий старт)
- Паттерн 1: Огляд PR за запитом через згадку @claude
- Паттерн 2: Автоматичний огляд при кожному push
- Паттерн 3: Сортування та маркування issue
- Паттерн 4: Орієнтований на безпеку огляд чутливих шляхів
- Паттерн 5: Запланована щотижнева перевірка стану репозиторію
- Контроль витрат, паралелізм, безпека відгалужень (fork safety)

**Коли використовувати**: Будь-яка команда, яка бажає отримати огляд коду за допомогою ШІ без керування інфраструктурою

### [Multi-Provider code review](./multi-provider-code-review.uk.md) ⭐ NEW

**Запускайте Claude Code Action разом із CodeRabbit і Greptile без потрійних дублікатів знахідок**

Недубльована архітектура для трьох автоматизованих рев'юерів на одному PR: Claude відповідає за глибоке семантичне рев'ю та шлюз, що блокує злиття, детермінований інструмент відповідає за перевірки PASS/FAIL перед злиттям, RAG-інструмент відповідає за міжфайлові інваріанти. Охоплює скрипт CI-шлюзу, пакетну обробку великих PR, дельта-рев'ю та міжінструментну дедуплікацію.

**Коли використовувати**: Працює більше ніж один автоматизований рев'юер і одну й ту саму проблему повідомляють тричі, або потрібно, щоб знахідки Claude справді блокували злиття, а не просто коментували

### [Перемикання когнітивних режимів (Cognitive Mode Switching)](./gstack-workflow.uk.md) ⭐ NEW

Перемикайтеся між спеціалізованими ролями протягом вашого циклу випуску (ship cycle): стратегічний шлюз продукту, огляд архітектури, параноїдальний огляд коду, автоматизований реліз, нативне тестування в браузері (browser QA) та ретроспектива.

**Коли використовувати**: Цикли випуску, де ви хочете мати чіткий поділ між напрямком продукту, інженерною строгістю, оглядом та випуском, а не один універсальний асистент, який виконує всі фази

## Мультиагентні та розширені технології

### [Dynamic workflows](./dynamic-workflows.uk.md) ⭐ NEW

Скрипти JavaScript, що оркеструють десятки й сотні subagents з детермінованим потоком керування, паралельним розгалуженням (fan-out) та автоматичним відновленням після переривання.

**Коли використовувати**: Багатоетапна робота, що розпаралелюється, довготривалі завдання, завдання зі структурованою передачею даних між фазами або будь-яка ситуація, де один agent упреться в ліміти контексту

**Ключові теми**:
- Довідник примітивів: `agent()`, `parallel()`, `pipeline()`, `phase()`, `log()`, `budget`
- `pipeline()` проти `parallel()` з даними бенчмарку (триразова різниця затримки, дворазова різниця токенів)
- Структуровані за схемою виходи між фазами
- 5 іменованих патернів: змагальна верифікація, цикл до вичерпання, панелі суддів, мультимодальне сканування, plan-execute-review
- Поведінкові гарантії: обмеження детермінованості, відновлення/кешування, ліміти паралелізму

### [Обмін повідомленнями між сесіями (Cross-Session Messaging)](./cross-session-messaging.uk.md) ⭐ NEW

`ListAgents` і `SendMessage`: як незалежні, уже запущені сесії Claude Code виявляють одна одну й обмінюються повідомленнями на одній машині або в межах вашого акаунта, без людини, що передає контекст між терміналами.

**Коли використовувати**: Координація сесій, які ви запустили й ведете самі (паралельні worktrees, сесії за ролями, передача між машинами), на відміну від Agent Teams (головна сесія сама створює й контролює своїх teammates)

**Ключові теми**:
- Виявлення через `ListAgents`: subagents, teammates, локальні peers, хмара, Remote Control
- Доставка через сокет на одній машині проти маршрутизації Remote Control між машинами
- Модель безпеки: `crossSessionInbound`, `isolatePeerMachines`, чому повідомлення від peer ніколи не має повноважень
- Хронологія версій та обмеження (ліміт розміру повідомлення, тротлінг сплесків)

# Конфіденційність даних у Claude Code: чого не охоплюють офіційні документи

Сторінка конфіденційності Anthropic описує рівні зберігання даних (Consumer 5 років, ZDR 0 днів тощо). Це корисна довідка, але вона не охоплює ризики, специфічні для Claude Code як локального CLI-інструмента. Цей посібник зосереджений саме на них: шість векторів витоку даних, що існують, бо Claude Code працює з доступом до файлової системи, запускає підпроцеси та викликає MCP-сервери, і як заблокувати кожен із них.

> **Коротка довідка**: рівні зберігання Anthropic підсумовано в таблиці нижче. Повна офіційна політика: [claude.ai/settings/data-privacy-controls](https://claude.ai/settings/data-privacy-controls).

## TL;DR - підсумок зберігання даних

| Конфігурація | Термін зберігання | Навчання моделей | Як увімкнути |
|---------------|------------------|----------|---------------|
| **Споживча (за замовчуванням)** | 5 років | Так | (стан за замовчуванням) |
| **Споживча (з відмовою)** | 30 днів | Ні | [claude.ai/settings](https://claude.ai/settings/data-privacy-controls) |
| **Team / Enterprise / API** | 30 днів | Ні (за замовчуванням) | Використовуйте плани Team, Enterprise або API-ключі |
| **ZDR (Нульове зберігання)** | 0 днів на сервері | Ні | Належним чином налаштовані API-ключі |

**Негайна дія**: [Вимкніть використання даних для навчання моделей](https://claude.ai/settings/data-privacy-controls), щоб скоротити термін зберігання на серверах з 5 років до 30 днів.

## 1. Розуміння потоку даних

### Що залишає вашу машину

Коли ви використовуєте Claude Code, наступні дані надсилаються до Anthropic:

```
┌─────────────────────────────────────────────────────────────┐
│                    ВАШ ЛОКАЛЬНИЙ КОМП'ЮТЕР                  │
├─────────────────────────────────────────────────────────────┤
│  • Промпти, які ви вводите                                  │
│  • Файли, які читає Claude (і .env, якщо не виключені!)     │
│  • Результати MCP (SQL-запити, відповіді API)               │
│  • Результати виконання команд Bash                         │
│  • Повідомлення про помилки та стеки викликів               │
└───────────┬──────────────────┬──────────────┬───────────────┘
            │                  │              │
            ▼ HTTPS/TLS       ▼ HTTPS        ▼ HTTPS
┌───────────────────┐ ┌──────────────┐ ┌─────────────────────┐
│   API ANTHROPIC   │ │   STATSIG    │ │       SENTRY        │
├───────────────────┤ ├──────────────┤ ├─────────────────────┤
│ • Ваші промпти    │ │ • Затримка,  │ │ • Логи помилок      │
│ • Відповіді моделі│ │   надійність │ │ • Без коду й        │
│ • Термін зберіг.  │ │ • Без коду й │ │   шляхів            │
│   згідно тарифу   │ │   шляхів     │ │                     │
└───────────────────┘ └──────────────┘ └─────────────────────┘
                       (вимкнення:      (вимкнення:
                       DISABLE_         DISABLE_ERROR_
                       TELEMETRY=1)     REPORTING=1)
```

### Що це означає на практиці

| Сценарій | Дані, що надсилаються до Anthropic |
|----------|------------------------------------|
| Ви просите Claude прочитати `src/app.ts` | Повний вміст файлу |
| Ви запускаєте `git status` через Claude | Вивід команди |

| Claude зчитує файл `.env` | API-ключі, паролі, секрети |
| У вашому коді виникає помилка | Повний стек викликів (stack trace) із шляхами |

## 2. Відомі ризики

### Ризик 1: автоматичне читання файлів

Claude Code самостійно зчитує файли для розуміння контексту проєкту. За замовчуванням сюди можуть потрапити:

- Файли `.env` та `.env.local` (API-ключі, паролі)
- Файли `credentials.json`, `secrets.yaml` (облікові записи служб)
- Ключі SSH, якщо вони опинилися в межах робочої директорії
- Рядки підключення до баз даних

**Як запобігти**: Налаштуйте правила виключення (див. Розділ 3).

### Ризик 2: доступ до бази даних через MCP

Коли ви налаштовуєте сервери MCP для доступу до баз даних (Neon, Supabase, PlanetScale):

```
Ваш запит: "Покажи мені останні замовлення"
            │
            ▼
MCP виконує: SELECT * FROM orders LIMIT 100
            │
            ▼
Надсилаються результати: 100 рядків із іменами клієнтів, адресами, поштою
            │
            ▼
Зберігається в Anthropic: Відповідно до вашого рівня зберігання даних
```

**Як запобігти**: Ніколи не підключайте продакшн-бази даних. Використовуйте локальні бази для розробки (dev/staging) зі знеособленими (анонімізованими) даними.

### Ризик 3: вивід команд у терміналі

Виконувані команди Bash та весь їхній вивід автоматично додаються до вікна контексту:

```bash
# Цей вивід буде переданий до Anthropic:
$ env | grep API
OPENAI_API_KEY=sk-abc123...
STRIPE_SECRET_KEY=sk_live_...
```

**Як запобігти**: Використовуйте хуки безпеки для фільтрації конфіденційного виводу команд.

### Ризик 4: команда `/bug` відправляє ВСЕ (зберігання 5 років)

Коли ви виконуєте команду `/bug` у Claude Code, вся **повна історія вашої поточної розмови** (включаючи весь код, вміст прочитаних файлів і потенційні секрети) надсилається до Anthropic для аналізу та виправлення помилок CLI. Ці дані зберігаються **5 років**, незалежно від вашої відмови від навчання моделей.

Це правило є незалежним від інших ваших налаштувань приватності: навіть за вимкненого навчання та 30-денного терміну зберігання, повідомлення про баги підпадають під власну 5-річну політику зберігання. Це важливо, бо `/bug` легко запустити випадково, а термін зберігання його даних довший за будь-які інші дані, що надсилаються під час звичайної роботи з Claude Code.

Що потрапляє у звіт про помилку: весь контекст вашої сесії на момент виклику `/bug`. Шляхи файлів, вміст файлів, які Claude читав під час сесії, вивід команд bash, результати MCP-серверів і будь-які секрети, що з'являлися в чомусь із цього. Перед надсиланням жодного очищення чи фільтрації немає.

**Перевірте, чи ви вже вимкнули її:**

```bash
echo $DISABLE_BUG_COMMAND
```

Якщо виведено порожньо, команда активна. Щоб вимкнути назавжди:

```bash
# Додайте до ~/.zshrc або ~/.bashrc
export DISABLE_BUG_COMMAND=1
```

Якщо ви працюєте на кількох машинах або ділитеся dotfiles через репозиторій, додавання цього до профілю оболонки це єдиний спосіб тримати команду вимкненою в усіх середовищах. Змінні середовища, задані в `.claude/settings.json`, не зберігаються між сесіями оболонки.

### Ризик 6: інтеграція Claude Desktop з браузером: тихе встановлення Native Messaging Host

Додаток Claude Desktop встановлює маніфести нативного хоста обміну повідомленнями у системні директорії браузерів `NativeMessagingHosts`, щоб увімкнути функцію "Claude in Chrome". Станом на квітень 2026 року це відбувається без будь-якого явного запиту на згоду з боку користувача.

**Що саме встановлюється:**

```
~/Library/Application Support/Google/Chrome/NativeMessagingHosts/
  com.anthropic.claude_browser_extension.json

/Applications/Claude.app/Contents/MacOS/
  claude_browser_native_host  (допоміжний бінарний файл)
```

Claude Desktop записує ці файли для **всіх виявлених у системі Chromium-браузерів** (Chrome, Brave, Edge, Arc, Vivaldi, Opera, Chromium), включно з тими браузерами, які на момент встановлення Claude Desktop навіть не були запущені. Налаштування відмови від цієї функції ("Don't ask") у меню Claude Desktop не завжди запобігає цьому процесу ([GitHub #53864](https://github.com/anthropics/claude-code/issues/53864), квітень 2026).

**Що нативна інтеграція робить насправді (і чого НЕ робить):**

Нативна інтеграція (Native messaging) — це стандартний і безпечний механізм Chrome, який використовується менеджерами паролів, сервісами VPN та багатьма іншими легітимними додатками. Нативний хост може приймати повідомлення лише від того розширення Chrome, яке явно вказане як його ціль. Він не може самостійно ініціювати підключення до браузера, зчитувати вміст вкладок чи несанкціоновано збирати дані. З архітектурної точки зору це не є шпигунським ПЗ (spyware).

Справжня проблема полягає у **відсутності інформованої згоди**, а не в самому механізмі. Коли додаток тихо модифікує системні директорії стороннього софту, це порушує принцип найменшого подиву (least surprise), незалежно від намірів розробника.

**Як перевірити наявність нативних хостів, якщо ви занепокоєні:**

```bash
# Список усіх встановлених нативних хостів для Chrome
ls ~/Library/Application\ Support/Google/Chrome/NativeMessagingHosts/

# Перевірка наявності маніфесту Anthropic
cat ~/Library/Application\ Support/Google/Chrome/NativeMessagingHosts/com.anthropic.claude_browser_extension.json

# Перевірка для інших браузерів
ls ~/Library/Application\ Support/BraveSoftware/Brave-Browser/NativeMessagingHosts/
ls ~/Library/Application\ Support/Microsoft\ Edge/NativeMessagingHosts/
```

**Як видалити:**

```bash
# Видалення для Chrome (повторіть для кожного браузера за потреби)
rm ~/Library/Application\ Support/Google/Chrome/NativeMessagingHosts/com.anthropic.claude_browser_extension.json

# Перезапустіть Chrome після видалення
```

Видалення Claude Desktop вилучає допоміжний бінарний файл, але може залишити застарілі файли маніфестів у деяких директоріях браузерів. Перезапустіть браузери після очищення.

**Конфлікт із Claude Code CLI**: Коли у системі встановлені одночасно і Claude Desktop, і Claude Code CLI, розширення Chrome завжди намагається зв'язатися з нативним хостом Claude Desktop. Через це інструменти MCP `claude-in-chrome` для CLI-версії стають недоступними ([GitHub #51949](https://github.com/anthropics/claude-code/issues/51949)). Станом на квітень 2026 року це відомий баг, єдиним вирішенням якого є повне видалення Claude Desktop.

**Як діяти:**

Якщо ви не використовуєте функцію інтеграції з браузером, ви можете безпечно видалити файли маніфестів. Anthropic поки не надав офіційного та надійного механізму відмови від встановлення цієї інтеграції. Слідкуйте за оновленнями у гілці [GitHub #53864](https://github.com/anthropics/claude-code/issues/53864).

### Ризик 7: мережевий клієнт, що виглядає локальним

CLI або MCP-сервер може рекламувати «нуль залежностей, без реєстрації, без телеметрії» і все одно надсилати кожен ваш вхід на сервер, якого ви не контролюєте. Ці три твердження стосуються *пакета*, а не *даних*. Тонкий HTTP-клієнт справді має нуль залежностей, бо не містить нічого.

Викриває це арифметика. Перш ніж щось встановлювати, порівняйте розмір розпакованого пакета із заявленою функціональністю:

```bash
npm view <package> --json | grep -E '"unpackedSize"|"fileCount"|"dependencies"'
```

Пакет, що рекламує 148 інструментів аналізу у 17 КБ у 3 файлах, не несе 148 інструментів. Він несе виклик `fetch`. Справжні локальні реалізації токенізаторів, сканерів чи математики ембедингів мають нижню межу розміру, якої в мережевого клієнта немає. Коли цифри не сходяться, прочитайте вихідний код перед запуском; за такого розміру це займає хвилини:

```bash
curl -sL $(npm view <package> dist.tarball) | tar -xzO package/index.js | head -50
```

Чесні проєкти часто прямо кажуть про це в коментарі-заголовку чи README. Проблема в тому, що маркетинговий текст і архітектура живуть у різних місцях, і лише одне з них потрапляє в пост на LinkedIn.

**Чому режим MCP робить це принципово гіршим:**

У режимі CLI кожен вхід обирає людина. Це проблема дисципліни, і уважна команда може жити з хостованим інструментом, просто ніколи не вставляючи в нього нічого чутливого.

У режимі MCP вхід обирає агент, а агент має вашу кодову базу в контексті. Він передасть пропрієтарний вихідний файл у хостований помічник `count_tokens`, бо це розумна річ, яку робить із лічильником токенів. Цей конкретний виклик ніхто не схвалював, бо ніхто не питав. Власна інженерія безпеки інструмента тут не допомагає: захист тимчасових файлів і попередження про секретні параметри захищають від витоків через argv та локальних атак, а не від того, що агент сам вирішує, що надіслати.

Це перетворює правило, яке команда може дотримуватися («не вставляйте дані клієнтів у цей інструмент»), на таке, яке не може («не дозволяйте агентові читати не той файл»). Для регульованих даних, даних неповнолітніх чи клієнтського коду під NDA це є підставою для відмови незалежно від того, наскільки добре написаний клієнт.

**Перевірка, що має значення:**

Для будь-якого хостованого MCP-сервера запитайте, чи є взагалі локальний шлях виконання. Якщо кожен виклик інструмента це мережевий виклик, то додавання сервера до `.mcp.json` означає надання третій стороні доступу на читання до всього, що ваш агент вважатиме релевантним. «Без реєстрації» робить це гіршим, а не кращим: немає акаунта, отже немає угоди про обробку даних, названого субпроцесора і політики зберігання, на яку можна послатися під час аудиту.

## 3. Захисні заходи

### Негайні дії

#### 3.1 Налаштування блокування файлів
У `.claude/settings.json` використовуйте розділ `permissions.deny` для обмеження доступу до конфіденційних файлів:

```json
{
  "permissions": {
    "deny": [
      "Read(./.env*)",
      "Edit(./.env*)",
      "Write(./.env*)",
      "Bash(cat .env*)",
      "Bash(head .env*)",
      "Read(./secrets/**)",
      "Read(./**/credentials*)",
      "Read(./**/*.pem)",
      "Read(./**/*.key)",
      "Read(./**/service-account*.json)"
    ]
  }
}
```

> [!NOTE]
> Застарілі параметри `excludePatterns` та `ignorePatterns` були повністю скасовані у жовтні 2025 року. Завжди використовуйте `permissions.deny`.

> [!WARNING]
> Механізм `permissions.deny` має [відомі технічні обмеження](./security-hardening.uk.md#known-limitations-of-permissionsdeny). Для надійного захисту комбінуйте його з безпековими хуками (hooks) та зовнішнім керуванням секретами.

#### 3.2 Використання хуків безпеки

Створіть файл `.claude/hooks/PreToolUse.sh`:

```bash
#!/bin/bash
INPUT=$(cat)
TOOL_NAME=$(echo "$INPUT" | jq -r '.tool.name')

if [[ "$TOOL_NAME" == "Read" ]]; then
    FILE_PATH=$(echo "$INPUT" | jq -r '.tool.input.file_path')

    # Блокування читання файлів із секретами
    if [[ "$FILE_PATH" =~ \.env|credentials|secrets|\.pem|\.key ]]; then
        echo "BLOCKED: Спроба читання конфіденційного файлу: $FILE_PATH" >&2
        exit 2  # Блокування операції
    fi
fi
```

#### 3.3 Відмова від телеметрії та звітів про помилки

Claude Code зв'язується із зовнішніми сервісами для збору метрик роботи (Statsig) та відстеження помилок (Sentry). Вони не передають ваш код чи шляхи до файлів, але ви можете повністю вимкнути будь-яку мережеву активність такого роду:

| Змінна середовища | Що вона вимикає |
|----------|-----------------|
| `DISABLE_TELEMETRY=1` | Збір оперативних метрик Statsig (затримки, надійність роботи, патерни використання) |
| `DISABLE_ERROR_REPORTING=1` | Надсилання звітів про помилки до Sentry |
| `DISABLE_BUG_COMMAND=1` | Команду `/bug` (запобігає випадковому відправленню повної історії сесії) |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` | Увесь другорядний мережевий трафік одночасно |
| `CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY=1` | Опитування про якість сесії (вони відправляють лише оцінку, але не історію) |

Додайте ці змінні до конфігурації вашої оболонки для постійного ефекту:

```bash
# У ~/.zshrc або ~/.bashrc
export DISABLE_TELEMETRY=1
export DISABLE_ERROR_REPORTING=1
export DISABLE_BUG_COMMAND=1
```

> [!NOTE]
> Під час використання провайдерів Bedrock, Vertex або Foundry увесь другорядний трафік (телеметрія, звіти Sentry, опитування, команда /bug) вимкнений за замовчуванням на рівні платформи.

### Кращі практики для роботи з MCP

| Правило | Обґрунтування |
|------|-----------|
| **Ніколи не підключайте реальні бази (production)** | Усі результати запитів передаються на сервери Anthropic |
| **Використовуйте користувачів із правами Read-only** | Захищає від випадкових або зловмисних `DROP`/`DELETE`/`UPDATE` |
| **Деперсоналізуйте (анонімізуйте) дані для розробки** | Мінімізує ризики витоку персональних даних (PII) |
| **Створюйте мінімальні тестові вибірки даних** | Менше даних у базі = менший ризик компрометації |
| **Ретельно перевіряйте джерела серверів MCP** | Сторонні сервери MCP можуть містити критичні вразливості |

### Оборотна токенізація на межі моделі

Шлюз приватності може замінювати розпізнані значення на заповнювачі перед запитом до моделі та відновлювати їх локально, коли інструменту потрібне вихідне значення. Наприклад, синтетична ціль `10.42.1.5` може стати `IP_PRIVATE_001` у результаті інструмента, видимому моделі. Локальне відображення залишається чутливим, бо дає змогу обернути перетворення.

Покриття залежить від детектора, формату входу та шляху інтеграції. Фільтр, що маскує присвоєння облікових даних у простому тексті, може пропустити те саме значення всередині об'єкта JSON. Важлива й обробка помилок: повернення вихідного вмісту після винятку під час очищення відкриває цей вміст наступному споживачеві. Хук запуску, що відмовляє безпечно, не доводить, що так само безпечно відмовляє кожен подальший результат інструмента.

[Кейс DarkMoon і порівняння зі Strix](./agentic-pentesting.uk.md) пояснюють ці межі. Розглядайте оборотну токенізацію як зменшення експозиції. Щоб оцінити конкретний запуск, перевірте фактичні вихідні запити до моделі із синтетичними канарковими значеннями, зокрема результати інструментів, повторні спроби та шляхи помилок. Самі журнали токенізації не доводять, що саме перетнуло межу провайдера.

## 5. Корпоративні аспекти

### Коли слід переходити на Enterprise API (ZDR)

- Обробка чутливих PII клієнтів (імена, адреси, пошти)
- Діяльність у регульованих індустріях (HIPAA, GDPR, PCI-DSS)
- Робота з даними замовників та клієнтів
- Виконання державних та військових контрактів
- Надання фінансових та банківських послуг

### Чек-лист для оцінки ризиків

- [ ] В організації впроваджена та діє політика класифікації даних
- [ ] Вибраний тарифний план API повністю відповідає рівню чутливості даних
- [ ] Команда розробки пройшла навчання щодо налаштування приватності ШІ
- [ ] Розроблено та затверджено план реагування на витік даних
- [ ] Отримано схвалення від юридичного відділу та офіцерів комплаєнсу

---

### Перевіряйте безперервність доступу, а не лише місце розташування даних

[Розділ про суверенітет від IFTTD](https://bilan.ifttd.io/apprentissage-4/?niveau=2) розрізняє місце розміщення та здатність отримати доступ до даних, коли це потрібно. Розглядайте це як операційне питання: локально збережений експорт усе одно може залежати від віддаленого провайдера ідентифікації, недоступних ключів, пропрієтарного формату чи зовнішнього сервісу. Самого лише місця зберігання даних недостатньо, щоб довести безперервність чи юридичну відповідність.

Проведіть обмежене навчання із синтетичними даними та одноразовим середовищем. Складіть перелік залежностей автентифікації, доступу до моделі, формату експорту, розшифрування та інструментів. Змоделюйте недоступність обраного провайдера, не змінюючи доступу до продакшену. Спробуйте відкрити експортовані дані та виконати одне репрезентативне завдання через затверджений запасний варіант. Зафіксуйте, що спрацювало, що погіршилося, що вимагало недоступного провайдера і хто відповідає за відновлення.

Альтернативна кінцева точка з тією самою моделлю може урізноманітнити хостинг, але не прибирає залежності від провайдера моделі. Перевірте обробку даних і поведінку завдань на запасному варіанті, перш ніж допускати реальні конфіденційні дані. Успішне навчання підтверджує лише перевірене завдання та сценарій відмови; не робіть із нього висновку про суверенітет загалом.

### Швидкий аудит

Виконайте ці перевірки сьогодні. Кожна займає менше двох хвилин.

**1. Відмова від навчання**
Перейдіть на [claude.ai/settings/data-privacy-controls](https://claude.ai/settings/data-privacy-controls) і переконайтеся, що "Allow model training on your conversations" вимкнено (OFF). Якщо воно увімкнено, ваші дані зберігаються 5 років і використовуються для навчання.

**2. Команду `/bug` вимкнено**

```bash
echo $DISABLE_BUG_COMMAND
# Має вивести: 1
# Якщо порожньо: додайте "export DISABLE_BUG_COMMAND=1" до ~/.zshrc
```

**3. Файли `.env` заблоковано**
Перевірте свій `.claude/settings.json`: у `permissions.deny` має бути щонайменше `"Read(./.env*)"`. Якщо файлу ще немає, Claude може прочитати ваш `.env` просто зараз.

**4. Наявність native messaging host (macOS)**

```bash
ls ~/Library/Application\ Support/Google/Chrome/NativeMessagingHosts/ 2>/dev/null | grep anthropic
# Нічого не має з'явитися, якщо ви не користуєтеся Claude Desktop
```

**5. Інвентаризація MCP-серверів**
Відкрийте `~/.claude/claude.json` (або `.mcp.json` у корені проєкту) і складіть список кожного налаштованого MCP-сервера. Для кожного сервера баз даних переконайтеся, що рядок підключення веде до dev чи staging, а не до продакшену.

**6. Змінні телеметрії**

```bash
echo $DISABLE_TELEMETRY
echo $DISABLE_ERROR_REPORTING
# Обидві мають вивести: 1
```

**7. Експозиція команд оболонки**
Виконайте `env | grep -iE 'key|secret|token|pass'`, щоб побачити, які змінні середовища зараз задані. Усе, що тут з'явиться, буде видимим для Claude, якщо він виконає команду bash у цій сесії оболонки.

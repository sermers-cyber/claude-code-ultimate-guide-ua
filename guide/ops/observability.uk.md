## Чому варто моніторити сесії

Використання Claude Code може швидко накопичуватися, особливо під час активної розробки. Моніторинг допомагає вам:

- **Розуміти витрати**: Оцінювати витрати на API до того, як надійдуть офіційні рахунки.
- **Виявляти патерни**: Бачити, які інструменти ви використовуєте найчастіше, та які файли редагуються повторно.
- **Оптимізувати воркфлоу**: Знаходити неефективності (наприклад, повторне читання того самого великого файлу).
- **Відстежувати проекти**: Порівнювати використання в різних кодових базах.
- **Видимість для команди**: Агрегувати дані для бюджетування команди (при об'єднанні логів).

## Пошук та відновлення сесій

Після тижнів використання Claude Code пошук минулих розмов стає складним завданням. Цей розділ охоплює нативні опції та інструменти спільноти.

### Нативні команди

| Команда | Варіант використання |
|---------|----------|
| `claude -c` / `claude --continue` | Відновити останню сесію |
| `claude -r <id>` / `claude --resume <id>` | Відновити конкретну сесію за ID |
| `claude --resume` | Інтерактивний вибір сесії |

Сесії зберігаються локально в `~/.claude/projects/<project>/` як JSONL-файли.

### Порівняння інструментів спільноти

| Інструмент | Встановлення | Швидкість списку | Швидкість пошуку | Залежності | Команда відновлення |
|------|---------|------------|--------------|--------------|----------------|
| **session-search.sh** (цей репо) | Копіювати скрипт | **10мс** | **400мс** | Немає (bash) | ✅ Відображається |
| claude-conversation-extractor | `pip install` | 230мс | 1.7с | Python | ❌ |
| claude-code-transcripts | `uvx` | Н/Д | Н/Д | Python | ❌ |
| ran CLI | `npm -g` | Н/Д | Швидко | Node.js | ❌ (тільки команди) |

### Рекомендовано: session-search.sh

Bash-скрипт без залежностей, вкрай оптимізований для швидкості, з готовими командами для відновлення.

**Встановлення:**
```bash
cp examples/scripts/session-search.sh ~/.claude/scripts/cs
chmod +x ~/.claude/scripts/cs
echo "alias cs='~/.claude/scripts/cs'" >> ~/.zshrc
source ~/.zshrc
```

**Використання:**
```bash
cs                          # Список 10 останніх сесій (~15мс)
cs "authentication"         # Пошук за одним ключовим словом (~400мс)
cs "Prisma migration"       # Пошук за кількома словами (AND-логіка, обидва мають збігатися)
cs -n 20                    # Показати 20 результатів
cs -p myproject "bug"       # Фільтр за назвою проекту
cs --since 7d               # Сесії за останні 7 днів
cs --since today            # Сесії тільки за сьогодні
cs --json "api" | jq .      # JSON-вивід для скриптів
cs --rebuild                # Примусове оновлення індексу
```

**Приклад виводу:**
```
2026-01-15 08:32 │ my-project             │ Implement OAuth flow for...
  claude --resume 84287c0d-8778-4a8d-abf1-eb2807e327a8

2026-01-14 21:13 │ other-project          │ Fix database migration...
  claude --resume 1340c42e-eac5-4181-8407-cc76e1a76219
```

Просто скопіюйте та вставте команду `claude --resume`, щоб продовжити будь-яку сесію.

### Принцип роботи

1. **Режим індексу** (без фільтрів): Використовує закешований індекс TSV. Автоматично оновлюється при зміні сесій. Час пошуку ~15мс.
2. **Режим пошуку** (з ключовим словом/фільтрами): Повнотекстовий пошук із таймаутом 3с. Запити з кількома словами використовують AND-логіку.
3. **Фільтри**: `--project` (частковий збіг), `--since` (підтримує `today`, `yesterday`, `7d`, `YYYY-MM-DD`).
4. **Вивід**: Зручний для читання людиною за замовчуванням, `--json` для скриптів. Виключає сесії субагентів.

### Альтернатива: Інструменти на Python

Якщо ви надаєте перевагу багатшому функціоналу (експорт в HTML, різні формати):

```bash
# Встановлення
pip install claude-conversation-extractor

# Інтерактивний UI
claude-start

# Прямий пошук
claude-search "keyword"

# Експорт у формат markdown
claude-extract --format markdown
```

Повний код скрипту див. у [session-search.sh](../examples/scripts/session-search.sh).

### Обмеження відновлення сесій та міграція між папками

**Стисло**: Нативний `--resume` обмежений поточним робочим каталогом. Для міграції між папками використовуйте ручні операції з файловою системою (рекомендовано) або інструменти автоматизації від спільноти (не тестувалися).

#### Чому відновлення прив'язане до директорії

Claude Code зберігає сесії за шляхом `~/.claude/projects/<encoded-path>/`, де `<encoded-path>` обчислюється на основі абсолютного шляху до вашого проекту. Наприклад:
- Проект у `/home/user/myapp` → Сесії в `~/.claude/projects/-home-user-myapp-/`
- Проект перенесено в `/home/user/projects/myapp` → Claude шукатиме `~/.claude/projects/-home-user-projects-myapp-/` (інша директорія)

**Обґрунтування архітектури**: Сесії зберігають абсолютні шляхи до файлів, специфічний контекст проекту (налаштування MCP-серверів, правила `.claudeignore`, змінні оточення). Відновлення сесії в іншій папці вимагало б переписування шляхів та валідації контексту, що наразі не реалізовано нативно.

**Зв'язані питання**: Запит від спільноти на нативну крос-папкову підтримку відстежується в GitHub issue [#1516](https://github.com/anthropics/claude-code/issues/1516).

#### Ручна міграція (Рекомендовано)

**При перенесенні папки проекту:**

```bash
# Перед перенесенням проекту
cd ~/.claude/projects/
ls -la  # Запишіть поточний закодований шлях

# Перенесіть ваш проект
mv /old/location/myapp /new/location/myapp

# Перейменуйте директорію сесій відповідно до нового шляху
cd ~/.claude/projects/
mv -- -old-location-myapp- -new-location-myapp-

# Перевірка
cd /new/location/myapp
claude --continue  # Має успішно відновити роботу
```

**При копіюванні (розгалуженні) сесій у новий проект:**

```bash
# Скопіюйте файли сесій (зберігає оригінал)
cd ~/.claude/projects/
cp -n ./-source-project-/*.jsonl ./-target-project-/

# Скопіюйте папку субагентів, якщо вона існує
if [ -d ./-source-project-/subagents ]; then
  cp -r ./-source-project-/subagents ./-target-project-/
fi

# Відновіть роботу в цільовому проекті
cd /path/to/target/project
claude --continue
```

#### ⚠️ Ризики та застереження міграції

**Перед міграцією сесій перевірте сумісність:**

| Ризик | Вплив | Заходи безпеки |
|------|--------|------------|
| **Жорстко задані секрети** | Витік облікових даних у новому контексті | Перевірте `.jsonl` файли перед міграцією та видаліть секрети |
| **Абсолютні шляхи** | Посилання на файли зламаються, якщо шляхи відрізняються | Переконайтеся в існуванні файлів у цілі або змиріться з битими посиланнями |
| **Конфігурації MCP-серверів** | Помилки через відсутність MCP у новому проекті | Налаштуйте аналогічні MCP перед відновленням |
| **Правила `.claudeignore`** | Інші шаблони ігнорування | Перегляньте відмінності, об'єднайте правила за потреби |
| **Змінні оточення** | Невідповідність контексту `process.env` | Перевірте сумісність файлів `.env` |

**Коли НЕ ВАРТО мігрувати сесії:**

- Конфліктні залежності (наприклад, різні версії Node.js або менеджери пакетів).
- Розбіжності в стані бази даних (міграції застосовані в джерелі, але не в цілі).
- Контекст авторизації (токени API, сесії OAuth, специфічні для вихідного проекту).
- Межі безпеки (міграція з приватного в публічний репозиторій).

#### Інструмент автоматизації від спільноти

**claude-migrate-session** від Jim Weller (натхненний Alexis Laporte) автоматизує ручний процес, описаний вище:

- **Репозиторій**: [jimweller/dotfiles](https://github.com/jimweller/dotfiles/tree/main/dotfiles/claude-code/skills/claude-migrate-session)
- **Можливості**: Глобальний пошук із фільтрацією, збереження `.jsonl` + субагентів, використання ripgrep для швидкодії.
- **Статус**: Особисті dotfiles (мало зірок на лютий 2026), обмежене використання.
- **Команда**: `/claude-migrate-session <source> <target>`

**⚠️ Застереження**: Цей інструмент має мінімальне тестування спільнотою. Ручний підхід безпечніший і дає вам повний контроль над тим, які дані переносяться. Ретельно протестуйте перед використанням у важливих процесах.

**Типові сценарії міграції:**
- Перенесення результатів прототипування у продуктовий код.
- Перенесення сесії налагодження в ізольований тестовий репозиторій.
- Продовження обговорення архітектури у новому проекті.

#### Альтернатива: Повна портативність сесій CLI

**Нативне обмеження**: `--resume` у Claude Code прив'язаний до абсолютних шляхів, що ламається при перейменуванні папок.

**Рішення від Entire CLI**: Контрольні точки (checkpoints) є **незалежними від шляхів**, забезпечуючи справжню портативність сесій між різними локаціями проекту.

**Принцип роботи:**

```bash
# У вихідному проекті
cd /old/location/myapp
entire capture --agent="claude-code"
# ... робота в Claude Code ...
entire checkpoint --name="migration-complete"

# Перемістіть проект у нове місце
mv /old/location/myapp /new/location/myapp

# Відновлення в цільовій папці (працює, оскільки Entire зберігає відносні шляхи)
cd /new/location/myapp
entire resume --checkpoint="migration-complete"
claude --continue  # Відновлює роботу з повним контекстом
```

**Чому контрольні точки Entire CLI є портативними:**

| Аспект | Нативний `--resume` | Entire CLI |
|--------|-------------------|-----------|
| **Збереження шляхів** | Абсолютні шляхи в JSONL | Відносні шляхи в контрольних точках |
| **Крос-папковість** | Ламається (інше кодування шляху) | Працює (незалежно від шляху) |
| **Збереження контексту** | Тільки історія промптів | Промпти + міркування + стани файлів |
| **Передача між агентами** | Ні | Так (наприклад, від Claude до Gemini) |

**Коли використовувати Entire CLI замість ручної міграції:**

- ✅ Часті перенесення або створення копій проектів.
- ✅ Багатоагентні процеси (передача сесії Claude → Gemini).
- ✅ Відтворення сесій для налагодження (повернення до точного стану).
- ✅ Корпоративний контроль (шлюзи схвалення при відновленні).

**Недолік**: Додає залежність від стороннього інструменту + витрати пам'яті (~5-10% від розміру проекту).

> **Повна документація**: [Гайд із трасування ШІ](./ai-traceability.uk.md#51-entire-cli)

### Моніторинг багатоагентної оркестрації

Про моніторинг кількох одночасних інстансів Claude Code через зовнішні оркестратори (Gas Town, multiclaude) див.:

- **agent-chat** (https://github.com/justinabrahms/agent-chat): Інтерфейс у стилі Slack для комунікації агентів у реальному часі.
- **Гайд з екосистеми**: `guide/ai-ecosystem.md` Розділ 8.1 - Системи багатоагентної оркестрації.

**Патерн архітектури** (для власних реалізацій):
1. Перехоплення логів при запуску агентів: `.claude/hooks/multi-agent-logger.sh`.
2. Збереження в SQLite: `~/.claude/logs/agents.db` (parent_id, child_id, timestamp, task).
3. Стрімінг через SSE: Простий HTTP-сервер на Go/Node.
4. Дашборд: Клієнт на React/HTML, що споживає SSE-потік.

**Нативний моніторинг Claude Code** (цей посібник):
- Пошук сесій: `session-search.sh` (див. [Пошук та відновлення сесій](#пошук-та-відновлення-сесій)).
- Логи активності: хук `session-logger.sh` (див. [Налаштування логування сесій](#налаштування-логування-сесій)).
- Статистичний аналіз: `session-stats.sh` (див. [Аналіз даних сесій](#аналіз-даних-сесій)).

**Коли потрібен моніторинг зовнішнього оркестратора:**
- Запуск Gas Town або multiclaude з 5+ одночасними агентами.
- Необхідність бачити координацію агентів у реальному часі.
- Налагодження збоїв оркестрації (конфлікти агентів, проблеми злиття гілок).

**Коли достатньо нативного моніторингу:**
- Одиночна сесія Claude Code або `--delegate` з менш ніж 3 субагентами.
- Достатньо аналізу результатів постфактум (логи, статистика).
- Обмеження бюджету або складності.

## Налаштування логування сесій

### 1. Встановіть Logger Hook

Скопіюйте логер сесій у вашу директорію хуків:

```bash
# Створіть папку хуків за потреби
mkdir -p ~/.claude/hooks

# Скопіюйте логер (з прикладів цього репозиторію)
cp examples/hooks/bash/session-logger.sh ~/.claude/hooks/
chmod +x ~/.claude/hooks/session-logger.sh
```

### 2. Зареєструйте в налаштуваннях

Додайте конфігурацію в `~/.claude/settings.json`:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "type": "command",
        "command": "~/.claude/hooks/session-logger.sh"
      }
    ]
  }
}
```

### 3. Перевірте встановлення

Виконайте кілька команд у Claude Code, після чого перевірте наявність логів:

```bash
ls ~/.claude/logs/
# Має з'явитися файл виду: activity-2026-01-14.jsonl

# Перегляньте останні записи
tail -5 ~/.claude/logs/activity-$(date +%Y-%m-%d).jsonl | jq .
```

### Параметри конфігурації

| Змінна оточення | За замовчуванням | Опис |
|---------------------|---------|-------------|
| `CLAUDE_LOG_DIR` | `~/.claude/logs` | Папка для зберігання логів |
| `CLAUDE_LOG_TOKENS` | `true` | Увімкнути евристичну оцінку токенів |
| `CLAUDE_SESSION_ID` | генерується авто | Кастомний ідентифікатор сесії |

### Аналіз якості, а не тільки кількості

Обсяг токенів показує інтенсивність використання Claude Code. Проте логи JSONL також можуть вказати на те, **наскільки ефективно працює ваша конфігурація** — якщо знати, що шукати.

Крім фінансових метрик, три патерни вказують на необхідність оновлення скілів, інструкцій або файлу `CLAUDE.md`:

**Повторне читання того самого файлу**

Якщо Claude читає один і той самий файл 3+ рази за одну сесію, необхідна інформація, ймовірно, знаходиться не там, де він очікує. Розгляньте можливість перенесення цього контексту в скіл або розділ `CLAUDE.md`.

```bash
# Файли, прочитані понад 3 рази в останніх сесіях
jq -r 'select(.tool == "Read") | .file' ~/.claude/logs/activity-*.jsonl \
  | sort | uniq -c | sort -rn | awk '$1 > 3'
```

**Повторювані помилки інструментів на одній команді**

Команда Bash, яка постійно падає з помилкою в різних сесіях, зазвичай вказує на застарілий шлях у скілі, перейменований бінарник або команду, несумісну з поточним стеком.

```bash
# Команди, виконання яких завершилося помилкою
jq -r 'select(.tool == "Bash" and (.exit_code // 0) != 0) | .command' \
  ~/.claude/logs/activity-*.jsonl | sort | uniq -c | sort -rn | head -10
```

**Висока частота редагування одного файлу**

Часте переписування файлу в різних сесіях вказує на брак контексту — агент не до кінця розуміє призначення файлу або конвенції проекту щодо нього не задокументовані.

```bash
# Найбільш редаговані файли (сигнал про брак контексту)
jq -r 'select(.tool == "Edit") | .file' ~/.claude/logs/activity-*.jsonl \
  | sort | uniq -c | sort -rn | head -10
```

Виявивши такі патерни, запитайте себе: чи може скіл, правило або розділ `CLAUDE.md` вирішити цю проблему? Детальний процес див. у [§9.23 Configuration Lifecycle & The Update Loop](#923-configuration-lifecycle-the-update-loop).

## Відстеження витрат

### Метод оцінки кількості токенів

Логер оцінює токени за простою евристикою: **~4 символи на один токен**. Це приблизний підрахунок, який зазвичай схильний дещо переоцінювати витрати.

### Тарифи

Тарифи за замовчуванням відповідають моделі Claude Sonnet. Ви можете змінити їх через змінні оточення:

```bash
# Тарифи для Sonnet (за замовчуванням)
export CLAUDE_RATE_INPUT=0.003   # $3 / 1M токенів
export CLAUDE_RATE_OUTPUT=0.015  # $15 / 1M токенів

# Тарифи для Opus (якщо використовуєте Opus)
export CLAUDE_RATE_INPUT=0.015   # $15 / 1M токенів
export CLAUDE_RATE_OUTPUT=0.075  # $75 / 1M токенів

# Тарифи для Haiku
export CLAUDE_RATE_INPUT=0.00025 # $0.25 / 1M токенів
export CLAUDE_RATE_OUTPUT=0.00125 # $1.25 / 1M токенів
```

### Бюджетні попередження (Ручний патерн)

Додайте до вашого профілю оболонки для щоденних попереджень про ліміти витрат:

```bash
# ~/.zshrc або ~/.bashrc
claude_budget_check() {
  local cost=$(session-stats.sh --json 2>/dev/null | jq -r '.summary.estimated_cost.total // 0')
  local threshold=5.00  # Денний ліміт $5

  if (( $(echo "$cost > $threshold" | bc -l) )); then
    echo "⚠️  Денні витрати Claude Code: \$$cost (ліміт: \$$threshold)"
  fi
}

# Запуск при відкритті терміналу
claude_budget_check
```

## Моніторинг активності

Моніторинг витрат показує, *скільки* грошей витрачено. Моніторинг активності показує, *що саме зробив Claude Code*: які файли прочитав, які команди виконав та які веб-ресурси запитував. Це ваш шар аудиту.

### Першоджерело даних: JSONL сесії

Кожен виклик інструменту Claude Code записує у JSONL-файли сесії в папці `~/.claude/projects/<project>/`. Кожен запис із ключем `type: "assistant"` містить масив `content`, де блоки `type: "tool_use"` описують кожну дію.

```bash
# Знайдіть ваші файли сесії
ls ~/.claude/projects/-$(pwd | tr '/' '-')-/

# Перегляньте виклики інструментів у сесії
cat ~/.claude/projects/-your-project-/SESSION_ID.jsonl | \
  jq 'select(.type == "assistant") | .message.content[]? | select(.type == "tool_use") | {tool: .name, input: .input}'
```

### Що розкривають виклики інструментів

| Інструмент | Що він показує |
|------|----------------|
| `Read` | Доступ до файлів (шлях, діапазон рядків) |
| `Write` / `Edit` | Модифікації файлів (шлях, дельта вмісту) |
| `Bash` | Виконані команди (повний рядок команди) |
| `WebFetch` | Запити до URL (може містити конфіденційні дані в POST) |
| `Task` | Запуск субагентів (промпт, переданий дочерній моделі) |
| `Glob` / `Grep` | Шаблони та область пошуку |

### Практичні запити для аудиту

```bash
# Усі файли, які було прочитано протягом сесії
SESSION=~/.claude/projects/-your-project-/SESSION_ID.jsonl
jq 'select(.type == "assistant") | .message.content[]? | select(.type == "tool_use" and .name == "Read") | .input.file_path' "$SESSION"

# Усі виконані bash-команди
jq 'select(.type == "assistant") | .message.content[]? | select(.type == "tool_use" and .name == "Bash") | .input.command' "$SESSION"

# Усі завантажені URL-адреси
jq 'select(.type == "assistant") | .message.content[]? | select(.type == "tool_use" and .name == "WebFetch") | .input.url' "$SESSION"

# Статистика використання інструментів за типами
jq -r 'select(.type == "assistant") | .message.content[]? | select(.type == "tool_use") | .name' "$SESSION" | sort | uniq -c | sort -rn
```

### Шаблони поведінки, на які варто звернути увагу

Ці патерни виклику інструментів варто автоматично перевіряти в цілях безпеки:

| Патерн | Ризик | Спосіб виявлення |
|---------|------|-----------|
| `Read` файлів `.env`, `*.pem`, `id_rsa` | Доступ до облікових даних | `jq '... | select(.input.file_path | test("\\.(env|pem|key)$"))'` |
| `Bash` із командами `rm -rf`, `git push --force` | Деструктивні дії | `jq '... | select(.input.command | test("rm -rf\|force-push"))'` |
| `WebFetch` на зовнішні URL | Ризик несанкціонованого витоку даних | `jq '... | select(.name == "WebFetch") | .input.url'` |
| `Write` у файли поза кордонами проекту | Вихід за межі робочої директорії | Порівняння шляхів із поточною робочою папкою |

> **Безпека**: Claude Code працює з вашою файловою системою в межах ваших прав користувача. Слід логів JSONL — це ваш єдиний запис подій. Для команд розробки рекомендується налаштувати синхронізацію цих логів у незмінне хмарне сховище.

### Трасування MLflow (MLflow Tracing)

**Коли використовувати**: Командам, які вже використовують екосистему MLflow/MLOps, або тим, кому потрібен **точний** облік токенів та автоматична оцінка якості на базі ШІ. Не рекомендується для незалежних розробників, яким потрібна просто швидка статистика витрат (для цього використовуйте ccusage).

**Головна відмінність**: MLflow здійснює перехоплення на рівні викликів API, а не постфактум з JSONL. Це дозволяє отримувати **точні** обсяги витрачених токенів (без похибки в 15-25% при евристичній оцінці) та підключати сценарії **LLM-as-judge** для аналізу регресії поведінки агента.

#### Налаштування: Режим CLI (не вимагає Python)

Працює з інтерактивними сесіями `claude`. Інтегрується через хуки в `.claude/settings.json`:

```bash
pip install "mlflow[genai]>=3.4"

# Увімкнути трасування у поточному проекті
mlflow autolog claude

# Зі збереженням даних у локальну БД (рекомендовано)
mlflow autolog claude -u sqlite:///mlflow.db

# Зі створенням конкретного експерименту
mlflow autolog claude -n "my-project"

# Перевірити статус або вимкнути
mlflow autolog claude --status
mlflow autolog claude --disable
```

Запустіть інтерфейс MLflow для перегляду трас:

```bash
mlflow server  # Адреса: http://localhost:5000
```

**Автоматично записуються**: промпти користувача, відповіді помічника, виклики інструментів (назва, вхідні та вихідні дані), точний обсяг токенів, затримка (latency) кожного запиту, метадані сесії.

#### Налаштування: Режим SDK (для Python-агентів)

```python
import mlflow
mlflow.anthropic.autolog()         # один рядок на самому початку файлу
mlflow.set_experiment("my-agent")

# Використовуйте ClaudeSDKClient як зазвичай — усі взаємодії будуть записані
# ⚠️ Підтримується тільки ClaudeSDKClient. Прямі виклики API не записуються.
from anthropic import claude_agent_sdk
async with ClaudeSDKClient(options=AGENT_OPTIONS) as client:
    await client.query(query)
```

Потребує встановлених пакетів: `mlflow>=3.5` та `claude-agent-sdk>=0.1.0`.

#### MCP-сервер: двостороння інтеграція

Claude Code може безпосередньо запитувати дані своїх власних трас. Додайте в `~/.claude/settings.json`:

```json
{
  "mcpServers": {
    "mlflow-mcp": {
      "command": "uv",
      "args": ["run", "--with", "mlflow[mcp]>=3.5.1", "mlflow", "mcp", "run"],
      "env": { "MLFLOW_TRACKING_URI": "<your-tracking-uri>" }
    }
  }
}
```

Тепер ви можете запитати у Claude Code: *"Знайди всі сесії, в яких агент backend-architect зробив понад 20 викликів інструментів"* — він зробить запит до MLflow самостійно, без ручного копіювання ID.

#### LLM-as-judge: Тестування деградації поведінки агентів

Унікальна можливість MLflow. Після оновлення інструкцій чи системного промпту агента ви можете об'єктивно оцінити, чи покращилася його якість роботи:

```python
from mlflow.genai.scorers import scorer, ConversationCompleteness, RelevanceToQuery
from mlflow.entities.model_registry import Feedback

@scorer
def tool_efficiency(trace) -> int:
    """Підрахунок кількості викликів інструментів — менше значення краще для чітких завдань."""
    return len(trace.search_spans(span_type="TOOL"))

@scorer
def permission_blocks(trace) -> int:
    """Виявляє, як часто агент наштовхувався на блокування дозволів."""
    return sum(
        1 for span in trace.search_spans(span_type="TOOL")
        if span.outputs and "requires approval" in str(span.outputs).lower()
    )

# Запуск оцінки за накопиченими трасами
traces = mlflow.search_traces(experiment_ids=["<id>"], max_results=50)
results = mlflow.genai.evaluate(
    data=traces,
    scorers=[
        tool_efficiency,
        permission_blocks,
        ConversationCompleteness(),
        RelevanceToQuery(),
    ]
)
```

**Вбудовані метрики**: `ConversationCompleteness`, `RelevanceToQuery`, `UserFrustration`, `SafetyScorer`.

**Власні метрики**: мають повний доступ до об'єкта трасування (всі спани, вхідні/вихідні дані, токени).

#### Обмеження MLflow Tracing

| Обмеження | Деталі |
|------------|--------|
| **Цільова аудиторія CLI** | CLI-режим найкраще підходить для інтерактивної роботи; для програмних агентів потрібен SDK |
| **Обмеження SDK** | Тільки `ClaudeSDKClient` — запити через чистий API Anthropic не перехоплюються |
| **Ризик витоку PII** | Траси записують повний текст діалогів. Очищуйте дані перед відправкою у спільне сховище |
| **Бекенд бази даних** | SQLite підходить тільки для локальної розробки. Для продакшену використовуйте PostgreSQL/MySQL |
| **OpenTelemetry** | MLflow 3.6+ вміє транслювати дані у сторонні OTEL-системи (Datadog, Grafana тощо) |

## Проксіювання Claude Code

Часте питання розробників: «Чи можу я запустити Proxyman або Charles, щоб побачити, що саме Claude Code надсилає в Anthropic?»

**Коротка відповідь**: Так, але це потребує додаткових кроків. Нижче описано, як це реалізувати.

### Чому системні налаштування проксі не працюють одразу

Claude Code — це процес Node.js. За замовчуванням Node.js ігнорує системні проксі-налаштування операційної системи (`HTTP_PROXY`, `HTTPS_PROXY`). Він використовує власне TLS-оточення та ігнорує конфігурації macOS/Windows.

Крім того, навіть якщо ви спрямуєте трафік через проксі, виникне помилка сертифіката TLS (`CERT_UNTRUSTED`), і Claude Code відмовиться працювати.

### Спосіб 1: Встановлення CA-сертифіката проксі (Proxyman / Charles)

Змусьте Node.js довіряти кореневому сертифікату вашого проксі-сервера:

```bash
# Експортуйте кореневий сертифікат Proxyman (File → Export → Root Certificate)
# Вкажіть Node.js використовувати його:
export NODE_EXTRA_CA_CERTS="/path/to/proxyman-ca.pem"

# Запустіть Claude Code — тепер трафік піде через Proxyman
claude
```

Аналогічно для Charles: `Help → SSL Proxying → Export Charles Root Certificate`.

**Застереження**:
- Деякі збірки Claude Code використовують сертифікатний пінінг (certificate pinning) для `api.anthropic.com` — у такому разі цей метод не спрацює.
- Для роботи методу необхідно тримати додаток Proxyman/Charles відкритим на вашому комп'ютері.

### Спосіб 2: Перенаправлення трафіку через ANTHROPIC_API_URL

Спрямуйте запити Claude Code на локальний інтерцептор замість прямого звернення до `api.anthropic.com`:

```bash
export ANTHROPIC_API_URL="http://localhost:8080"
claude
```

Запустіть будь-який локальний проксі/логер на порту 8080, який буде записувати дані та перенаправляти їх на `https://api.anthropic.com`. Це повністю прибирає проблеми з TLS на ділянці між Claude Code та вашим локальним проксі.

**Застосування**: Логування тіла запитів, додавання кастомних заголовків, емуляція затримок, повтор запитів.

### Спосіб 3: mitmproxy (Рекомендовано)

[mitmproxy](https://mitmproxy.org) — найзручніше open-source рішення. Це інструмент командного рядка та веб-інтерфейсу для перехоплення HTTPS-трафіку.

```bash
# Встановлення
brew install mitmproxy  # для macOS
# або: pip install mitmproxy

# Запуск проксі на порту 8080
mitmproxy --listen-port 8080

# В новому вікні терміналу запустіть Claude Code з проксі
export NODE_EXTRA_CA_CERTS="$(python3 -c 'import mitmproxy.certs; print(mitmproxy.certs.Cert.default_ca_path())')"
export HTTPS_PROXY="http://localhost:8080"
claude
```

Веб-інтерфейс mitmproxy (`mitmweb`), доступний на `http://localhost:8081`, показуватиме повний вміст запитів та відповідей — включаючи складні JSON-структури, які Claude Code надсилає в Anthropic.

**Що ви побачите**: Системний промпт, репліки користувача, специфікації інструментів, результати їх виконання та параметри генерації моделі.

### Спосіб 4: Мінімальний проксі-сервер на Python

Якщо ви не хочете встановлювати сторонній софт і вам потрібен скрипт без залежностей:

```python
# proxy.py — простий HTTPS-логер-проксі
from http.server import HTTPServer, BaseHTTPRequestHandler
import urllib.request, json, sys

TARGET = "https://api.anthropic.com"

class LoggingProxy(BaseHTTPRequestHandler):
    def do_POST(self):
        length = int(self.headers["Content-Length"])
        body = self.rfile.read(length)
        print(json.dumps(json.loads(body), indent=2))  # Логування запиту
        
        # Створення запиту до Anthropic
        req = urllib.request.Request(
            f"{TARGET}{self.path}",
            data=body,
            headers={k: v for k, v in self.headers.items() if k.lower() != 'host'}
        )
        try:
            with urllib.request.urlopen(req) as response:
                self.send_response(response.status)
                for k, v in response.getheaders():
                    self.send_header(k, v)
                self.end_headers()
                self.wfile.write(response.read())
        except Exception as e:
            self.send_error(500, str(e))

HTTPServer(("localhost", 8080), LoggingProxy).serve_forever()
```

```bash
python3 proxy.py &
export ANTHROPIC_API_URL="http://localhost:8080"
claude
```

> **Попередження про приватність**: Проксіований трафік містить повний контекст розмови — прочитані файли вашого коду, будь-які паролі чи секрети, які потрапили в консоль. Поводьтеся з логами проксі з відповідною обережністю.

## Обмеження

### Що цей моніторинг НЕ МОЖЕ зробити

| Обмеження | Причина |
|------------|--------|
| **Точний підрахунок токенів (без MLflow)** | CLI-клієнт Claude Code не повертає точні білінгові метрики |
| **TTFT (Time to First Token)** | Хуки викликаються після завершення роботи інструменту, а не під час стрімінгу |
| **Метрики стрімінгу в реальному часі** | Події хуків відсутні під час процесу генерації токенів |
| **Фактичні грошові витрати** | Евристичний підрахунок токенів дає лише приблизну оцінку витрат |
| **Використовувана модель** | Лог не фіксує, яка саме модель (Sonnet, Opus) відповіла на запит |
| **Заповненість вікна контексту** | Немає можливості дізнатися відсоток заповнення контексту в реальному часі |

### Примітки щодо точності

- **Оцінка токенів**: має похибку ~15-25% відносно реального білінгу Anthropic.
- **Оцінка вартості**: використовуйте її як орієнтир для планування бюджету, а не для бухгалтерського обліку.
- **Кордони сесій**: сесії визначаються за ID, що може відрізнятися від фактичних сесій API.

### Чому МОЖНА довіряти

- **Кількість викликів інструментів**: 100% точний облік кожного запущеного інструменту.
- **Патерни доступу до файлів**: точний перелік прочитаних та змінених файлів.
- **Порівняльний аналіз**: коректно відображає динаміку між днями та проектами.
- **Таймстампи**: точний час кожної операції.

Для тімлідів та технічних менеджерів, яким потрібно переконатися, що команда використовує Claude Code безпечно та за призначенням.

### Щотижнева швидка перевірка (5 хвилин)

```bash
# Чи відбувалося щось нетипове за останні 7 днів?

# 1. Читання файлів за межами проекту
find ~/.claude/projects/ -name "*.jsonl" -newer "$(date -d '7 days ago' +%Y-%m-%d 2>/dev/null || date -v-7d +%Y-%m-%d)" 2>/dev/null | \
  xargs jq -r 'select(.type == "assistant") |
    .message.content[]? |
    select(.type == "tool_use" and .name == "Read") |
    .input.file_path' 2>/dev/null | \
  grep -v "^$(pwd)" | sort -u

# 2. Виконання деструктивних команд
find ~/.claude/projects/ -name "*.jsonl" -newer "$(date -d '7 days ago' +%Y-%m-%d 2>/dev/null || date -v-7d +%Y-%m-%d)" 2>/dev/null | \
  xargs jq -r 'select(.type == "assistant") |
    .message.content[]? |
    select(.type == "tool_use" and .name == "Bash") |
    .input.command' 2>/dev/null | \
  grep -iE "(drop|delete|truncate|rm -rf|git push --force)"
```

### Звітність про комплаєнс

Для регульованих індустрій — генерація звіту про активність ШІ для аудиторів:

```bash
#!/bin/bash
# Щомісячний звіт комплаєнсу використання Claude Code

START_DATE=${1:-$(date -d '30 days ago' +%Y-%m-%d 2>/dev/null || date -v-30d +%Y-%m-%d)}
END_DATE=${2:-$(date +%Y-%m-%d)}
REPORT_FILE="ai-activity-report-${START_DATE}-${END_DATE}.json"

echo "Generating compliance report: $START_DATE to $END_DATE"

# Підрахунок сесій, викликів інструментів та звернень до файлів
jq -s '{
  report_period: {start: "'"$START_DATE"'", end: "'"$END_DATE"'"},
  tool_usage: (group_by(.tool) | map({tool: .[0].tool, count: length})),
  unique_files_accessed: ([.[].file] | unique | length),
  sessions: ([.[].session_id] | unique | length)
}' ~/.claude/logs/activity-*.jsonl 2>/dev/null > "$REPORT_FILE" || \
  echo "No activity logs found. Set up session-logger.sh hook to enable."

echo "Report saved: $REPORT_FILE"
```

Повний процес налаштування аудиту на рівні компанії див. у [Корпоративне управління ШІ §6.2](../security/enterprise-governance.uk.md#62-налаштування-аудиторського-сліду-audit-trail).

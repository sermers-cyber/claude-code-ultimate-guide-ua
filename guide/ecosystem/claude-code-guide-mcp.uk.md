## TL;DR

Використовуйте MCP-сервер, коли хочете, щоб клієнт для програмування шукав у посібнику, відкривав точний розділ джерела, отримував продакшн-шаблон або переглядав релізи Claude Code, не завантажуючи весь посібник у контекст.

Сервер працює локально через stdio. Версія `1.3.7` не має власної телеметрії. Деякі інструменти під час виклику можуть звертатися до GitHub або Anthropic і записувати локальні файли кешу. Завантаження — це не користувачі, не активні встановлення, не сесії й не виконання.

Встановіть наразі опублікований пакет:

```bash
claude mcp add --scope user claude-code-guide -- npx -y claude-code-ultimate-guide-mcp@1.3.7
codex mcp add claude-code-guide -- npx -y claude-code-ultimate-guide-mcp@1.3.7
```

## Яку проблему розв'язує сервер

Посібник завеликий, щоб вставляти його повністю для кожного запитання. MCP-сервер надає менший цикл пошуку й отримання:

1. шукає в структурованому індексі посібника;
2. повертає відповідні шляхи й якорі;
3. читає лише потрібний розділ джерела;
4. за потреби отримує конкретний шаблон або запис про реліз.

Це зменшує обсяг зайвого контексту. Це не гарантує, що відповідь правильна, актуальна чи придатна для конкретного репозиторію. Клієнт усе одно мусить перевірити отримане джерело й верифікувати твердження, чутливі до часу.

## Перший корисний запит

Попросіть клієнт:

> Call search_guide with query="session-scoped hooks" and limit=20. Find the hooks_session_scoped entry, open its returned path and line with read_section, and cite the source path and exact heading.

Очікувана послідовність інструментів:

```text
search_guide({ query: "session-scoped hooks", limit: 20 })
// Use the path and offset returned for hooks_session_scoped.
// The 2026-10-28 check returned the following values:
read_section({ path: "guide/ultimate-guide.md", offset: 10108, limit: 80 })
```

Перевірена відповідь прочитала рядки 10108-10120 під заголовком `Session-Scoped Hooks`. Під час перевірки 2026-10-05 типове обмеження пошуку в 10 результатів не включало цей точний запис; використовуйте 20 і перевіряйте відповідний результат. Номери рядків можуть змінюватися, тому повторно використовуйте повернуте зміщення, а не припускайте, що 10108 лишається актуальним.

Починаючи з 1.3.6, межі розділів генеруються із заголовків посібника замість застарілих статичних діапазонів. Під час перевірки публічної 1.3.7 2026-10-28 пошук і читання session-scoped hooks повернули правильне посилання на розділ `Guide`, `07-hooks`. Використовуйте повернутий шлях і зміщення, перевіряйте заголовок і цитуйте [джерело на GitHub](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/guide/ultimate-guide.md#L10108) або [розділ Hooks](https://cc.bruniaux.com/guide/ultimate-guide/07-hooks/#session-scoped-hooks). Гілка main на GitHub змінна.

Історичне обмеження: публічна 1.3.5 повертала `08-mcp` для цього самого запису про hooks, бо її статичні діапазони розділів були застарілими. Цей дефект маршрутизації виправлено в 1.3.6; попередня перевірка не фіксувала SHA вмісту GitHub.

Для шаблона почніть із `search_examples`, а потім викличте `get_example` з повернутою назвою. Для змін в офіційній документації виконайте `init_official_docs` один раз, а потім `refresh_official_docs` та `diff_official_docs`, коли потрібне нове порівняння.

## Архітектура й потік даних

```text
MCP client
  -> local stdio process started through npx
     -> bundled indexes and datasets
     -> optional GitHub fetch for guide content and templates
     -> optional Anthropic fetch for official documentation snapshots
     -> local cache under ~/.cache/claude-code-guide/
```

Протокол MCP проходить через стандартний ввід і вивід дочірнього процесу. У цій архітектурі немає хостованої кінцевої точки MCP для посібника. Клієнт контролює, коли запускається локальний процес і які інструменти він викликає.

## Вбудований вміст, отримання з GitHub і кеш

Пакет містить вбудований структурований довідник, історію релізів, навігацію по посібнику та інші оголошені набори даних ресурсів. Ініціалізація, операції переліку та пошук у посібнику використовують вбудовані дані.

Ці інструменти можуть отримувати вміст із GitHub, коли локальна копія чи придатний запис кешу недоступні:

- `read_section`
- `get_example`
- `get_cheatsheet`
- `get_changelog`
- `get_digest`
- `get_threat`
- `list_threats`

Успішні відповіді GitHub можуть кешуватися в `~/.cache/claude-code-guide/<version>/` на 24 години. Коли `GUIDE_ROOT` вказує на локальну копію посібника, інструменти вмісту читають із неї.

`init_official_docs` і `refresh_official_docs` отримують документацію Anthropic та зберігають окремі локальні знімки. `diff_official_docs` і `search_official_docs` читають ці знімки без мережевого запиту.

## Межа мережі та приватності

Версія `1.3.7` не має власної телеметрії, кінцевої точки аналітики, ідентифікатора пристрою чи вивантаження подій. Запити й відповіді MCP не надсилаються авторові цього проекту.

Мережевий доступ залежить від інструмента:

| Операція | Мережа | Локальний запис |
| --- | --- | --- |
| Перелік можливостей і пошук у вбудованому індексі | Ні | Ні |
| Читання некешованого вмісту посібника чи шаблонів | GitHub, за потреби | Кеш на 24 години |
| Ініціалізація чи оновлення офіційної документації | Anthropic | Локальні знімки |
| Diff чи пошук у наявних знімках офіційної документації | Ні | Ні |

MCP-клієнт, npm, `npx`, GitHub, Anthropic та оператор машини можуть мати власні журнали чи політики. Ці системи лежать поза межею власної телеметрії цього сервера.

### Рішення щодо телеметрії для 1.3.7

Централізовану телеметрію продукту свідомо не реалізовано в `1.3.7`. Кількість завантажень не виправдовує додавання кінцевої точки відстеження й не може встановити активного використання.

Будь-яка майбутня пропозиція вимагає розглянутого рішення щодо приватності ще до появи коду. Мінімальні критерії прийняття:

- вимкнено за замовчуванням і вмикається явною дією користувача;
- жодного тексту запитів, аргументів, шляхів до файлів, повернутого вмісту, ідентичності репозиторію, імені хоста чи ідентичності облікового запису;
- локально згенерований випадковий ідентифікатор, який користувач може скинути;
- лише версія пакета, назва інструмента, успіх чи збій і груба затримка;
- задокументовані кінцева точка, строк зберігання, процес видалення та точна схема корисного навантаження;
- негайний механізм вимкнення та публічний спосіб перевірити надіслані події.

Доки ці умови не затверджено й не реалізовано, точне твердження — відсутність власної телеметрії.

## Поведінка офлайн

Сервер працює частково офлайн, а не повністю.

- перелік можливостей, перелік тем, дані релізів, ресурси та пошук в індексі працюють із вбудованого вмісту;
- кешований вміст посібника можна читати, поки кеш лишається придатним;
- некешовані розділи Markdown і шаблони можуть вимагати GitHub;
- пошук і diff в офіційній документації потребують знімків, раніше створених з мережевим доступом;
- перше виконання `npx` може вимагати доступу до реєстру npm, якщо пакет ще не кешовано чи не встановлено.

Для розробки чи контрольованого офлайн-використання встановіть залежності заздалегідь, зберіть пакет і запустіть `dist/index.js` з локальної копії з виставленим `GUIDE_ROOT`.

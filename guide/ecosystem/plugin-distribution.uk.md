# Поширення plugin та підказки-рекомендації

Plugin пакує повторно використовувані skills, agents, hooks, MCP-сервери, LSP-сервери, монітори та налаштування Claude Code. Для локальних або специфічних для проєкту експериментів користуйтеся окремою конфігурацією `.claude/`; plugin потрібен тоді, коли те саме розширення має стати версіонованою одиницею поширення, якою можна ділитися. [Документація Anthropic про plugin](https://code.claude.com/docs/en/plugins) є авторитетним джерелом щодо підтримуваної структури та поведінки завантаження.

Ця сторінка розділяє поширення та рекомендацію. Marketplace робить plugin доступним. Маркер `<claude-code-hint />` може запропонувати користувачеві встановити відповідний офіційний plugin після виконання команди CLI. Жоден із цих механізмів не скасовує потреби перевіряти код, який може запускати hooks, команди, MCP-сервери чи виконувані файли.

## Поширення через marketplace

Офіційний marketplace — це каталог plugin та їхніх джерел. Його `marketplace.json` може посилатися на локальні відносні шляхи, URL GitHub або інших Git-сервісів, підкаталоги git, пакети npm, HTTPS-архіви та каталоги plugin, створені командою. Тип джерела визначає, як Claude Code отримує plugin; він не означає, що plugin безпечний для конкретної організації.

Для поширення в команді чи спільноті створіть plugin, перелічіть їх у `marketplace.json`, розмістіть цей каталог у Git-репозиторії або іншому підтримуваному джерелі, а потім нехай користувачі додадуть marketplace та встановлять окремий plugin. Користувачі оновлюють свою локальну копію marketplace командою `/plugin marketplace update`. [Посібник Anthropic про marketplace](https://code.claude.com/docs/en/plugin-marketplaces) визначає маніфест, типи джерел, поведінку версій і зарезервовані назви офіційних marketplace.

Перед публікацією протестуйте plugin з локального каталогу:

```bash
claude --plugin-dir ./my-plugin
```

Локальний тест показує лише те, що Claude Code може завантажити plugin. Він не доводить, що його hooks, MCP-сервери, залежності чи шляхи до виконуваних файлів підходять для машини іншого користувача. Перевіряйте ці компоненти за тими самими засобами контролю ланцюга постачання, що й інші виконувані залежності.

## Канал рекомендацій `<claude-code-hint />`

Протокол підказок дає змогу команді від супровідника CLI або SDK рекомендувати його офіційний plugin з marketplace Anthropic. Коли команда виконується через інструмент Bash або PowerShell у Claude Code, вона виводить один самозакритий тег в окремому рядку. Claude Code вилучає маркер із виводу команди до того, як цей вивід потрапить до моделі, перевіряє цільовий plugin і може показати запит на встановлення в основній інтерактивній термінальній сесії.

```text
<claude-code-hint v="1" type="plugin" value="example-cli@claude-plugins-official" />
```

Задокументована межа перевірки вузька й конкретна:

| Перевірка або поведінка | Що вона підтверджує | Чого вона не підтверджує |
|---|---|---|
| Маркер займає окремий рядок | Claude Code розпізнає синтаксис протоколу. | Що вивід команди заслуговує на довіру. |
| Ціль розташована в marketplace, контрольованому Anthropic | Claude Code приймає лише відповідну ціль в офіційному marketplace. | Що команда, яка виводить маркер, і plugin належать одному видавцю. |
| Запит називає команду, що його спричинила | Користувач бачить, яка команда запросила рекомендацію. | Що рекомендація команди потрібна або доречна. |
| Маркер вилучається до передавання моделі | Модель не отримує рядок маркера як вивід команди. | Що решта виводу команди чи інструкції на екрані безпечні. |
| Підтвердження користувача | Claude Code не встановлює автоматично. | Що схвалений користувачем plugin безпечно вмикати. |

Останній стовпець — операційний висновок із задокументованих засобів контролю, а не твердження, що протокол перевіряє походження між видавцем CLI та видавцем plugin. Сприймайте запит як рекомендацію з названим джерелом, а перед схваленням перевірте plugin та його запис у marketplace.

## Контроль користувача та обмеження запитів

Claude Code показує щонайбільше один запит-підказку за сесію та щонайбільше один запит для окремого plugin. У субагентах, `claude -p` і запусках Agent SDK він запитів не показує, хоча рядки підказок там усе одно вилучає. Час очікування запиту спливає за 30 секунд, і це рахується як відповідь **No**. Користувач може відхилити один запит або вибрати варіант, що вимикає майбутні підказки зі встановлення plugin.

Підказки не спрацьовують, коли аналітику вимкнено, зокрема через задокументовані змінні відмови від телеметрії та в ситуаціях, коли провайдер автоматично вимикає телеметрію. У командах hook Claude Code вилучає тег і ігнорує його. Тому підказка не є надійним каналом автоматизації чи механізмом примусового застосування політик.

## Рекомендації для супровідників CLI та SDK

Виводьте підказку лише для plugin, що перелічений в офіційному marketplace Anthropic. Задокументований протокол підтримує версію `1`, тип `plugin` та значення виду `name@marketplace`. Записуйте її в stderr в окремому рядку та умовно вмикайте виведення за змінною середовища Claude Code.

Обирайте умову свідомо:

| Змінна | Задокументована сфера | Компроміс |
|---|---|---|
| `CLAUDECODE` | Присутня для команд, які запускає Claude Code, а також у деяких інтегрованих терміналах, сесіях tmux та stdio-підпроцесах MCP. | Широкий охоплення, але людина в терміналі може побачити сирий тег. |
| `CLAUDE_CODE_CHILD_SESSION` | Присутня для підпроцесів, які запускає сам Claude Code. Потребує Claude Code v2.1.172 або новішої. | Зазвичай оминає термінал людини, але старіші сесії не отримують підказку, а довготривалі дочірні процеси можуть зберігати змінну. |

Виводьте підказку в корисній, зрозумілій користувачеві точці взаємодії, як-от `--help`, помилка невідомої підкоманди, успішна автентифікація чи повідомлення першого запуску. Не виводьте тег в очікуванні, що він вплине на модель або примусить до встановлення. Офіційний [довідник plugin-hints](https://code.claude.com/docs/en/plugin-hints) є джерелом протоколу.

## Межа безпеки поширення

Ціль в офіційному marketplace — вимога протоколу для підказок, а не загальний висновок про безпеку виконуваної поведінки plugin. Перш ніж вмикати поширений plugin, визначте його маніфест, компоненти, джерело, поведінку встановлення залежностей і сферу дії. Застосуйте [налаштування plugin та marketplace](../core/settings-reference.uk.md#plugins-and-marketplaces) і [рекомендації щодо посилення безпеки](../security/security-hardening.uk.md), перш ніж поширювати hooks, конфігурацію MCP або виконувані файли.

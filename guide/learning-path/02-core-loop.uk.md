## Як Claude читає ваш проєкт

Claude не читає все підряд. Він **інтелектуально визначає scope**.

### Приклад: Ви просите "Fix the login bug"

Claude зробить наступне:

1. **Шукає "login"** у вашій кодовій базі
2. **Знаходить auth.js, login.js, auth-controller.js**
3. **Читає ці файли першими** (повний вміст)
4. **Знаходить місця викликів** (що викликає ці файли?)
5. **Читає тести** (якщо вони існують)
6. **Знаходить пов'язані конфігурації** (environment variables, константи)

Claude **не** буде читати:
- node_modules (виключається автоматично)
- Історію .git (занадто великий обсяг даних)
- Кожен файл у проєкті (це занадто повільно)
- Всю кодову базу, якщо в цьому немає потреби

### Професійна порада

Будьте конкретними щодо scope:
- ❌ "Fix the bugs" → Claude доведеться вгадувати файли
- ✅ "Fix the login bug in auth.js on line 45" → Claude читає лише те, що має значення

## Context: Головне поняття

**Context** — це обсяг розмови, який Claude тримає в пам'яті. Він є обмеженим (~200K tokens).

### Що використовує Context?

```
Ваш prompt:            50 tokens
Відповідь Claude:      500 tokens
Читання файлів:        2000 tokens на файл
Попередні повідомлення:накопичені tokens
```

### Індикатор Context

```bash
/status
```

Показує:
```
Context: 67%
```

Це означає:
- 0-50%: Залишилося багато місця, працюйте вільно
- 50-70%: Використано наполовину, будьте уважні
- 70-90%: Місця стає мало, скористайтеся `/compact`
- 90%+: Критичний рівень, ви мусите зробити очищення

### `/compact` — Ваш запобіжний клапан

Коли використання context досягає 70%+, виконайте:

```bash
/compact
```

Ця команда:
1. Підсумовує (summarizes) попередню розмову
2. Видаляє старі повідомлення
3. Звільняє близько ~40% context
4. Дозволяє вам продовжувати роботу в тій самій session

Ви можете використовувати `/compact` кілька разів за одну session.

## Режими роботи: Normal проти Plan проти Think

Claude Code має три режими взаємодії.

### Normal Mode (За замовчуванням)

Claude вносить зміни одразу після аналізу. Використовуйте для:
- Простих виправлень багів
- Додавання невеликих фіч
- Рефакторингу невеликих секцій

**Процес**: Запит → Аналіз (1-2 сек) → Пропозиція → Застосування

### Plan Mode (`/plan`)

Claude спочатку обмірковує завдання, пропонує план і чекає на ваше схвалення перед внесенням змін. Використовуйте для:
- Складних фіч
- Ризикованих змін
- Рефакторингу на рівні всієї системи
- Випадків, коли ви не впевнені у правильному підході

**Процес**: Запит → Мислення → Пропозиція плану → Ви схвалюєте → Аналіз → Застосування

**Приклад**:
```bash
/plan
Refactor the authentication system to use JWT instead of sessions
```

Claude відповість покроковим планом для вашої перевірки.

### Think Mode (`/think`)

Claude показує розгорнуті міркування, обмірковуючи проблему крок за кроком. Використовуйте для:
- Розуміння складних багів
- Прийняття архітектурних рішень
- Аналізу безпеки (security)
- Оптимізації продуктивності (performance)

**Процес**: Запит → Розгорнуте мислення → Аналіз → Пропозиція

## Структурування ефективних запитів

### Фреймворк: WHAT, WHERE, HOW, VERIFY

Хороші запити будуються за такою схемою:

| Частина | Призначення | Приклад |
|---------|-------------|---------|
| **WHAT** | Мета | "Fix the null pointer bug" |
| **WHERE** | Scope (де саме) | "in `src/auth/login.js` on line 45" |
| **HOW** | Обмеження | "without changing the API signature" |
| **VERIFY** | Очікуваний результат| "All existing tests should pass" |

### Приклад хорошого запиту

```
Fix the bug where login fails for emails with + symbols
WHERE: src/controllers/auth.js, line 78 (email validation regex)
HOW: Update the regex to allow + in emails, but keep existing validation otherwise
VERIFY: Existing tests in tests/auth.test.js should pass
```

### Приклад поганого запиту

```
Fix the bugs
```

Claude доведеться ставити багато уточнюючих запитань замість швидкого вирішення проблеми.

## Session Context

**Session** — це ваша поточна розмова з Claude.

### Факти про сесії

- Починається, коли ви запускаєте `claude`
- Завершується, коли ви виходите або вводите `/clear`
- Не зберігається за замовчуванням
- Обмежена одним проєктом
- Можна керувати за допомогою `/rewind` (повернутися на N кроків назад)

### Збереження сесій за допомогою Checkpoints

Щоб зберегти стан session (за бажанням):
```bash
/checkpoint save "fixed login, added tests"
```

Пізніше ви можете відновити його:
```bash
/checkpoint load "fixed login, added tests"
```

## Вправа: Повний цикл (The Complete Loop)

### Завдання: Створити просту допоміжну (utility) функцію

1. **Сформулюйте запит за схемою WHAT/WHERE/HOW/VERIFY:**

```
Create a utility function to validate email addresses
WHERE: in src/utils/validators.js
HOW: export as validateEmail(email), return boolean, handle edge cases
VERIFY: Write tests in tests/validators.test.js
```

2. **Claude аналізує:**
   - Знаходить `src/utils/`
   - Читає існуючі validators
   - Перевіряє структуру директорії тестів
   - Пропонує рішення

3. **Перевірте diff:**
   - Перегляньте сигнатуру функції
   - Перевірте логіку валідації
   - Перегляньте тест-кейси

4. **Прийміть зміни або допрацюйте:**
   ```
   Looks good, but make the regex more permissive for + symbols
   ```

5. **Claude оновлює код**, а ви знову перевіряєте diff.

6. **Готово:** Ви отримали протестовану робочу функцію.

## Головні висновки

✓ Кожен запит проходить шлях: читання → аналіз → рішення → пропозиція → застосування

✓ Будьте конкретними (WHAT/WHERE/HOW/VERIFY) для швидших результатів

✓ Context обмежений, стежте за відсотками та використовуйте `/compact` при 70%+

✓ Використовуєте `/plan` для ризикованих змін, а normal mode для безпечних

✓ Sessions тимчасові, використовуйте `/checkpoint` для збереження важливої роботи

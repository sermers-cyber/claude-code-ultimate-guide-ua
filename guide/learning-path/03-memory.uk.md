# Module 03: Memory & config

**Час**: 1 година | **Складність**: ⭐⭐ Intermediate

## Мета

Налаштувати Claude Code для запам'ятовування ваших вподобань та специфічних для проєкту правил. Створити свій перший файл CLAUDE.md.

---

## Що ви дізнаєтеся

- Як працює ієрархія пам'яті (memory hierarchy) Claude Code
- Створення та структурування файлів CLAUDE.md
- Налаштування (settings) та їхній пріоритет (precedence)
- Власні інструкції (custom instructions) та визначення agents
- Конфігурація проєкту проти глобальної конфігурації

---

## Ієрархія пам'яті

Claude Code запам'ятовує ваші вподобання на трьох рівнях:

```
┌──────────────────────────────────────────┐
│ 1. GLOBAL (~/.claude/CLAUDE.md)          │
│    Застосовується до ВСІХ ваших проєктів  │
│    Приклад: Ваш стиль коду, часовий пояс │
└──────────────────────────────────────────┘
                    ▲
                    │ (перевизначається)
                    │
┌──────────────────────────────────────────┐
│ 2. PROJECT (/your-project/CLAUDE.md)     │
│    Застосовується лише до ЦЬОГО проєкту  │
│    Приклад: Стандарти команди, tech stack│
└──────────────────────────────────────────┘
                    ▲
                    │ (перевизначається)
                    │
┌──────────────────────────────────────────┐
│ 3. PERSONAL (/your-project/.claude/)     │
│    Локальні settings, що не комітяться в │
│    git. Приклад: API keys, особисті prefs│
└──────────────────────────────────────────┘
```

### Правило
Налаштування на рівні 3 перевизначають рівень 2, який у свою чергу перевизначає рівень 1.

## Створення вашого першого CLAUDE.md

CLAUDE.md — це простий файл markdown, який повідомляє Claude Code ваші правила та вимоги.

### Базова структура

```markdown
# My Project

## Purpose
Короткий опис того, що робить цей проєкт.

## Tech Stack
- TypeScript
- React 18
- Next.js
- PostgreSQL

## Coding Standards
- Використовувати лише функціональні компоненти
- Усі exports мають бути типізовані
- Максимум 300 рядків на файл
- Використовувати змістовні назви змінних (ніяких `x`, `temp`)

## Behavioral Rules
Завжди перевіряти diff перед підтвердженням.
Використовувати /plan для будь-яких критичних змін.

## Git Workflow
- Уся робота ведеться у feature-гілках
- PRs вимагають 1 схвалення
- Commits мають бути об'єднані (squashed)

## Current Status
Над чим ви зараз працюєте.
```

### Мінімальний приклад (Почніть звідси)

Створіть `/your-project/CLAUDE.md`:

```markdown
# My Project

## Quick Context
- Frontend: React з TypeScript
- Backend: Node.js з Express
- Database: PostgreSQL
- Package manager: pnpm

## Coding Rules
- Перевага віддається функціональному програмуванню
- Усі функції повинні мати сигнатури типів
- Для нових фіч обов'язкові тести
- Жодних console.log у production коді

## My Preferences
- Використовувати /plan для архітектурних змін
- Бути лаконічним у коді, але розгорнутим у коментарях
- Запитувати перед рефакторингом кількох файлів одночасно
```

Claude автоматично прочитає цей файл під час запуску session і дотримуватиметься ваших правил.

## Що може міститися в CLAUDE.md?

Ви можете налаштувати практично будь-що. Популярні розділи:

### 1. Огляд проєкту (Project Overview)
```markdown
## Purpose
Це наш бекенд для обробки платежів.
Він відповідає за валідацію кредитних карток та логування транзакцій.

## Important
- Містить критично важливий код для відповідності PCI-DSS
- Ніколи не логувати номери карток
- Усі зміни потребують security review
```

### 2. Технологічний стек (Tech Stack)
```markdown
## Stack
- Language: Python 3.10+
- Framework: Django 4.0
- Database: PostgreSQL 13
- Cache: Redis
- Task queue: Celery
```

### 3. Стандарти кодування (Coding Standards)
```markdown
## Code Style
- Дотримуватися PEP 8
- Анотації типів (type hints) для всіх функцій
- Docstrings у Google форматі
- Уникати імпортів через зірочку (wildcard imports)
- Максимальна довжина рядка: 100 символів

## Testing
- Мінімум 80% покриття тестами
- Модульні (unit) + інтеграційні тести
- Використовувати pytest
```

### 4. Правила (Rules)
```markdown
## Rules
- Усі PRs вимагають перевірки (review)
- Жодних прямих пушів у main
- Міграції бази даних потребують затвердження
- Зміни безпеки автоматично позначаються прапорцями
- Режим /plan для рефакторингу обсягом >100 рядків
```

### 5. Поточна робота (Current Work)
```markdown
## Current Task
Створення процесу оформлення замовлення (checkout flow).
Робота над: src/checkout/payment-form.tsx
Залежності: бібліотека stripe-js, платіжний API
```

## Глобальний CLAUDE.md

Для налаштувань, які застосовуються до **всіх ваших проєктів**, створіть `~/.claude/CLAUDE.md`:

```markdown
# My Global Preferences

## Communication Style
- Бути прямим і покладатися на факти
- Показувати роботу крок за кроком
- Пропонувати альтернативи, якщо завдання незрозуміле

## Tools I Use
- TypeScript для всіх JS проєктів
- Python для даних/скриптів
- Docker для розгортання
- Git для контролю версій

## My Timezone
America/New_York

## Work Hours
Mon-Fri 9am-5pm (UTC-5)
```

Claude завантажить цей файл під час запуску та об'єднає його з CLAUDE.md вашого проєкту.

## Проєктні проти Глобальних налаштувань

### Використовуйте Глобальні для:
- Вашого загального стилю кодування (угоди про найменування, підходи)
- Інструментів, які ви використовуєте завжди
- Вподобань щодо стилю спілкування
- Загальних принципів роботи

### Використовуйте Проєктні для:
- Стандартів вашої команди (якщо вони відрізняються від ваших глобальних)
- Специфічного для проєкту tech stack
- Бізнес-правил (PCI compliance тощо)
- Поточного контексту роботи (current work context)

### Приклад

**Глобальний** (~/.claude/CLAUDE.md):
```markdown
## My Style
Functional programming, clear variable names, typed functions
```

**Проєктний** (my-payment-app/CLAUDE.md):
```markdown
## Special Rules
Security critical—use /plan for all changes.
Must handle PCI compliance.
```

Claude об'єднає обидва: ваш стиль + специфічні правила проєкту.

## Вправа: Створення власного CLAUDE.md

### Крок 1: Оберіть проєкт

Використовуйте існуючий проєкт або створіть тестову директорію:

```bash
mkdir test-claude-config
cd test-claude-config
git init
```

### Крок 2: Створіть CLAUDE.md

```bash
cat > CLAUDE.md << 'EOF'
# My Test Project

## Tech Stack
- Language: [your main language]
- Framework: [what you use]
- Database: [if applicable]

## Coding Standards
- [Rule 1]
- [Rule 2]

## My Preferences
- [Preference 1]
- [Preference 2]
EOF
```

### Крок 3: Запустіть Claude

```bash
claude
```

Claude покаже в терміналі, що він успішно завантажив CLAUDE.md при запуску.

### Крок 4: Протестуйте його

Попросіть Claude зробити щось. Він має діяти відповідно до ваших правил.

```
Add a function called greet that returns "Hello, World!"
```

Claude повинен:
1. Згадати ваш tech stack
2. Дотримуватися ваших coding standards
3. Поважати ваші вподобання (preferences)

## Директорія .claude/

Для локальних налаштувань (які не комітяться у git), використовуйте директорію `.claude/`:

```
my-project/
├── CLAUDE.md           (комітиться — правила команди)
├── .claude/
│   ├── settings.json   (не комітиться — особисті налаштування)
│   ├── agents/         (користувацькі agents)
│   ├── skills/         (користувацькі skills)
│   └── hooks/          (скрипти автоматизації)
```

Додайте до вашого `.gitignore`:
```
.claude/
.claude/settings.json
```

Виняток: Ви можете комітити директорію `.claude/agents/`, якщо ці agents призначені для використання всією командою.

## Settings.json (Опціонально)

Для точнішого контролю налаштувань створіть `.claude/settings.json`:

```json
{
  "model": "claude-opus-5-5",
  "temperature": 0.7,
  "context_threshold": 0.75,
  "auto_compact": true,
  "require_diff_review": true,
  "max_file_size": 10000
}
```

Популярні параметри:
- **model**: Яку модель Claude використовувати
- **temperature**: Параметр творчості генерації коду (креативність)
- **context_threshold**: Поріг попередження про context (0.7 = 70%)
- **auto_compact**: Автоматично запускати `/compact`, коли поріг досягнуто
- **require_diff_review**: Вимагати перевірки кожного diff (безпечне значення за замовчуванням)

## Agents & Skills (Попередній перегляд)

У CLAUDE.md ви можете посилатися на користувацьких agents:

```markdown
Use with: /agent code-reviewer
```

Ці agents визначаються в директорії `.claude/agents/` (детальніше у модулі 04).

## Найкращі практики

### РЕКОМЕНДУЄТЬСЯ

✅ Оновлювати CLAUDE.md в міру розвитку вашого проєкту

✅ Зберігати проєктний CLAUDE.md під контролем версій (це допомагає вашим колегам)

✅ Бути конкретними у своїх вимогах (уникати розмитих формулювань)

✅ Додавати розділ "Current Status", щоб Claude завжди мав актуальний контекст

✅ Документувати важливі бізнес-правила

### НЕ РЕКОМЕНДУЄТЬСЯ

❌ Зберігати паролі чи секрети в CLAUDE.md (використовуйте `.env` або менеджери секретів)

❌ Робити файл занадто довгим (більше 500 рядків важко сприймати)

❌ Створювати правила у глобальному файлі, що суперечать проєктним

❌ Припускати, що Claude пам'ятатиме налаштування та контекст із попередніх sessions

## Подальші кроки: пам'ять між сесіями та командна пам'ять

Розділи вище охоплюють базові патерни CLAUDE.md. Коли будете готові заглибитися, екосистема пропонує більше:

**Auto Memory та Auto Dream (нативні, v2.1.59+)**

Claude Code може сам записувати MEMORY.md між сесіями (Auto Memory) і консолідувати його у фоновому режимі (Auto Dream). Обидві функції працюють одразу після встановлення, а керувати збереженими записами можна через `/memory`. Див. [Memory Systems: Auto Memory](../core/memory-systems.uk.md#22-auto-memory-v2159) та [Auto Dream](../core/memory-systems.uk.md#23-auto-dream-консолідація-памяті).

**Інструменти між сесіями для окремих розробників**

- **claude-mem** (111K зірок, перевірено 2026-11-03): автоматичне стиснення сесій через hooks, ручні виклики не потрібні. Увімкніть приховування секретів (secret redaction), яке типово вимкнене. Встановлення: `/plugin marketplace add thedotmack/claude-mem`
- **agentmemory** (30K зірок, перевірено 2026-11-03): гібридний пошук BM25 + векторний + граф, 12 hooks, які за замовчуванням захоплюють дані (впровадження контексту вмикається окремо), самостійно заявлений показник R@5 95,2% на LongMemEval-S
- **ICM** (бінарний файл на Rust): епізодичне затухання + постійний граф знань, `brew install icm`, 14 IDE-клієнтів

**Спільний доступ для команди**

- Патерн «Трійця»: CLAUDE.md + `.mcp.json` + `/skills`, усе закомічене в репозиторій. Жодної інфраструктури, жодних витрат.
- **Mem0 Cloud MCP**: спільний пул пам'яті через `npx mcp-add --url https://mcp.mem0.ai/mcp`, безкоштовний тариф
- **doobidoo**: семантичний пошук у 13+ IDE, локальний SQLite або бекенд Cloudflare D1

Повний огляд усіх інструментів, архітектурних патернів, ризиків і блок-схему вибору див. у [посібнику Memory Systems](../core/memory-systems.uk.md).

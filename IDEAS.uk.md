## Виконано

### Зміцнення безпеки MCP ✅
Об'єднане дослідження безпеки, що охоплює вразливості MCP, промпт-ін'єкції та виявлення секретів.

**Завершено**: [Посібник зі зміцнення безпеки](./guide/security/security-hardening.md) охоплює:
- CVE-2025-53109/53110, 54135, 54136 із заходами пом'якшення.
- Робочий процес перевірки MCP з 5-хвилинним чек-лістом аудиту.
- "Білий список" MCP (перевірений спільнотою).
- Техніки обходу промпт-ін'єкцій (Unicode, ANSI, нульові байти).
- Порівняння інструментів виявлення секретів (Gitleaks, TruffleHog, GitGuardian).
- Процедури реагування на інциденти (витік секрету, компрометація MCP).
- 3 нових хуки: `unicode-injection-scanner.sh`, `repo-integrity-scanner.sh`, `mcp-config-integrity.sh`.

## Високий пріоритет

### Команди, натхненні gstack (відкладено після аудиту 26.03.2026)

Аудит [gstack](https://github.com/garrytan/gstack) (набір інструментів Гаррі Тана для Claude Code) виявив прогалини. Пріоритетні (HIGH) елементи вже впроваджено (`/investigate`, `/qa`, `/canary`, `/land-and-deploy`, оновлення `/review-pr`). Решта елементів відкладена сюди.

**`/autoplan`** — єдина команда, яка автоматично об'єднує CEO → Design → Eng review із закодованими принципами прийняття рішень. Поділ рішень на механічні (авто-рішення) та рішення на основі "смаку" (виносяться на користувача). Передумова: наші команди `/plan-ceo-review` і `/plan-eng-review` мають спершу стати стабільними. Джерело: `gstack/autoplan/SKILL.md`.

**`/office-hours`** — діагностика продукту в стилі YC з 6 ключовими питаннями перед будь-яким плануванням. Передує `/plan-ceo-review`. Записує дизайн-бриф у `~/.claude/projects/`. Джерело: `gstack/office-hours/SKILL.md`.

**`/design-review`** — візуальний аудит сайту + цикл виправлень. Робить скріншот URL, аналізує відступи/типографіку/колір/контраст, виявляє патерни "AI-slop" (фіолетові градієнти, 3-колонкові сітки, вирівнювання всього по центру). Спершу потрібна стандартизація браузерних інструментів. Джерело: `gstack/design-review/SKILL.md` + `design-checklist.md`.

**`/benchmark`** — виявлення регресій Core Web Vitals (TTFB, FCP, LCP, завантаження DOM, розміри бандлів). Базове порівняння з порогами регресії (>50% АБО >500 мс = регресія). Джерело: `gstack/benchmark/SKILL.md`.

**`/retro`** — щотижневе ретро з аналізом git-логів по кожному учаснику. Поточне вікно порівнюється з попереднім. Джерело: `gstack/retro/SKILL.md`.

**`/freeze` + `/unfreeze`** — блокування редагування директорії під час роботи через hook PreToolUse (жорстка заборона, а не попередження). Файл стану: `~/.claude/freeze-dir.txt`. Поєднується з `/careful` в команду `/guard`. Джерело: `gstack/freeze/SKILL.md`.

**`/document-release`** — оновлення документації після релізу. Читає diff від останнього релізу, оновлює README/ARCHITECTURE/CONTRIBUTING/CLAUDE.md, шліфує CHANGELOG, чистить TODOS. Джерело: `gstack/document-release/SKILL.md`.

**Таблиці стиснення зусиль (Effort compression)** — додати до шаблонів skill: час людини проти часу AI для кожного типу завдань. Це архітектурне рішення щодо формату skill, тож його варто обговорити до впровадження в усіх skill.

**Тригер до впровадження**: запити читачів або "спринт повноти воркфлоу".

### Agent Skills — прогалини в документації (за офіційною документацією agentskills.io, 14.05.2026)

Шість фактичних елементів, яких бракує в розділі про skill, підтверджено після звірки з офіційною специфікацією agentskills.io та посібником із реалізації для клієнтів.

**[HIGH] Міжклієнтна конвенція директорій `.agents/skills/`** — Посібник документує лише `.claude/skills/` (специфічно для Claude Code). Відкритий стандарт визначає `.agents/skills/` (проєкт) і `~/.agents/skills/` (користувач) як міжклієнтні шляхи. Skill, розміщені там, працюють у всіх 35+ сумісних клієнтах. Це розрізнення напряму впливає на твердження про портативність. Додати до розділу "Де живуть skill".

**[HIGH] 4-рівневий пріоритет завантаження skill** — Посібник не документує повну ієрархію: Enterprise → Personal → Project → Plugins. Зараз із тексту випливає лише розподіл Personal проти Project. Бракує Enterprise (керовані налаштування, найвищий пріоритет) і Plugins (найнижчий). Додати до розділу про ієрархію пріоритетів.

**[MEDIUM] Вартість поступового розкриття в токенах** — Специфікація дає конкретні цифри: ~50-100 токенів на skill для каталогу (лише name + description), <5000 токенів рекомендовано для повного тіла SKILL.md, ресурси підвантажуються на вимогу. Посібник пояснює концепцію, але не наводить цифр у токенах. Корисно для читачів, які вирішують, скільки skill встановлювати.

**[MEDIUM] Ліміт тіла SKILL.md у 500 рядків** — Специфікація рекомендує тримати SKILL.md менше 500 рядків. У посібнику цього ніде немає. Додати як практичне правило до розділу про структуру.

**[MEDIUM] `name` має збігатися з назвою батьківської директорії** — Специфікація вимагає цього як структурного обмеження. Посібник документує правила символів і формату для `name`, але пропускає цю вимогу. Невідповідність призводить до помилки `skills-ref validate`.

**[LOW] Конвенція зберігання eval** — Специфікація визначає стандартну структуру файлів: `evals/evals.json` усередині теки skill + `my-skill-workspace/iteration-N/with_skill|without_skill/` для запусків eval. У розділі посібника про оцінювання цього немає. Важливо для сумісності між інструментами з мета-skill `skill-creator`.

**Джерело**: `claudedocs/anthropic-cert/01-agent-skills/agentskills-io-docs.md` (розділи 2, 6, 8)

## Спостереження (очікуємо попиту)

a### prompt-caching MCP Plugin

MCP plugin, що автоматизує розміщення `cache_control` для розробників застосунків на Anthropic SDK. Оцінювався через локальне встановлення, підключене до Claude Code.

**Статус:** триває тестування. Перед будь-яким рішенням щодо документації потрібні реальні дані використання.

**Що ми знаємо:**
- 29 зірок, v1.3.0, єдиний мейнтейнер — ризик підтримки
- Бенчмарки, заявлені автором (економія 80-92%), не перевірені, цитувати їх не можна
- Закриває реальну прогалину: жоден інший інструмент MCP цього не робить; Spring AI / LiteLLM / Pydantic AI обслуговують іншу аудиторію
- Допис у блозі (Mathieu Grenier) незалежно описує ту саму проблему + 5 антипатернів — оцінка 3/5, у будь-якому разі варто інтегрувати в "Strategy 6"

**Відкриті питання:**
- [ ] Чи справді реальні сесії в цьому проєкті потрапляють у кеш? (запустити `get_cache_stats` після 10+ ходів)
- [ ] Чи достатньо стабільний plugin, щоб його рекомендувати? Помилки, витоки пам'яті, проблеми сесій?
- [ ] Яка реальна економія на проєкті з великим CLAUDE.md, як цей посібник?

**Якщо результати тестів позитивні (потрапляння в кеш підтверджено, проблем зі стабільністю немає):**
- Додати до `guide/ecosystem/third-party-tools.md` із перевіреною статистикою (а не заявами з README)
- Додати до розділу про сторонні інструменти на лендингу
- Підвищити оцінку: 3/5 → 4/5

**Якщо результати непереконливі або plugin нестабільний:**
- Перенести до "Відкладених ідей"
- Залишити інтеграцію допису Mathieu Grenier (самостійна цінність)

**Перевірити знову:** після 1 тижня реального використання

### Type-Driven API Design для ефективності AI-агентів
Вплив schema-first розробки на споживання токенів у Claude Code.

**Статус:** лише анекдотичні свідчення (емпіричних даних немає). Переоцінити, якщо з'являться бенчмарки.

**Оцінений ресурс (лютий 2026):**
- [ShipTypes](https://shiptypes.com/) від Boris Tane (Cloudflare)
- **Оцінка:** 2/5 (маргінально) — твердження "types → менше токенів" не перевірене
- **Повна оцінка:** `docs/resource-evaluations/shiptypes-evaluation.md`

**Чого бракує:**
- Бенчмарка споживання токенів: типізовані API (tRPC/Zod) проти нетипізованих (REST/документація)
- A/B-тесту ітерацій AI-агента з типами та без них
- Кейсу з відтворюваними метриками

**Тригери для переоцінки:**
- [ ] Академічна стаття/блог з емпіричними даними (метрики споживання токенів)
- [ ] Офіційна рекомендація Anthropic щодо schema-first для Claude Code
- [ ] 5+ обговорень/issue спільноти із запитом на цю тему

**Якщо підтвердиться (підвищення оцінки до 4/5):**
- Додати підрозділ до `guide/core/methodologies.md` (після CDD, рядок 172)
- Використати шаблон мікроінтеграції: `docs/resource-evaluations/shiptypes-evaluation.md` (розділ "Integration Plan")

**Перевірити знову:** серпень 2026
- Згадка з 3 рядків у розділі "See Also"
- Без окремого посібника (тягар підтримки, розповзання scope)

## Відкладені ідеї (Discarded Ideas)

| Ідея | Причина відхилення |
|------|------------------|
| Посібник з fine-tuning LLM | Поза межами — користувачі не керують навчанням моделей |
| Внутрішня архітектура моделей | Занадто теоретично, не практично |
| Оптимізація ціни за токени | Змінюється надто часто, використовуйте офіційні доки |
| Протокол A2A (Agent-to-Agent) | Claude Code — це одноагентна система з субагентами, а не справжня мультиагентна |
| Корпоративна панель AgentOps | Інфраструктури для CLI-інструмента не існує |
| LLM-as-a-Judge оцінювання | Надмірно для CLI, додає затримку без пропорційної цінності |
| Логування траєкторії рішень | Немає доступу до внутрішніх трейсів (чорна скринька) |
| Формальний фреймворк "4 стовпи" | Надто академічно — посібник уже прагматично охоплює симптоми |
| Canary/Blue-Green деплої | Патерни інфраструктури, не релевантно для CLI |
| Захист від отруєння пам'яті | Теоретичний ризик, що вимагає попередньої компрометації системи |
| Prompt Engineering для генерації коду | Уже добре охоплено (xml_prompting, prompt_formula) |
| Оптимізація вікна контексту | Уже добре охоплено (context_management, context_triage) |
| Патерни декомпозиції завдань | Охоплено через plan_mode, interaction_loop |
| Порівняння архітектур агентів | Поза межами — це не теорія мультиагентних систем |
| Реальні кейси | Неперевірні метрики, схильні до маркетингу |
| Порівняння з іншими інструментами | Поза межами, швидке застарівання |

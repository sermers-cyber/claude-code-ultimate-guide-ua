# Критерії рев'ю архітектури

Під час рев'ю архітектури (планів або коду) оцінюйте такі виміри:

## Дизайн системи
- Чи чіткі та добре визначені межі компонентів?
- Чи має кожен компонент одну, добре зрозумілу відповідальність?
- Чи мінімальні й добре задокументовані інтерфейси між компонентами?

## Залежності
- Чи є граф залежностей ациклічним і керованим?
- Чи є циклічні залежності, які треба розірвати?
- Чи виправдані й актуальні зовнішні залежності?

## Потік даних
- Чи зрозуміло, хто володіє даними (який компонент є джерелом істини)?
- Чи є потенційні вузькі місця в конвеєрі даних?
- Чи відбувається перетворення даних на правильному шарі?

## Масштабування
- Які є єдині точки відмови?
- Де система зламається під 10-кратним навантаженням?
- Чи правильно розділено компоненти без стану та зі станом?

## Безпека
- Чи правильно розшаровано автентифікацію та авторизацію?
- Чи контролюється доступ до даних на правильних межах?
- Чи валідуються межі API (санітизація вводу, обмеження частоти запитів)?
- Чи правильно керуються секрети (жодних захардкоджених значень)?

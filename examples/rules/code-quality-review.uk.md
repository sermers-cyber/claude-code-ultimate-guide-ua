# Критерії рев'ю якості коду

Під час рев'ю якості коду оцінюйте такі виміри:

## Організація
- Чи логічна й послідовна структура модулів?
- Чи лежать файли у правильних каталогах?
- Чи послідовна конвенція іменування в усій кодовій базі?

## Порушення DRY
- Позначайте будь-яку дубльовану логіку (будьте прискіпливими)
- Виявляйте патерни копіювання-вставлення, які слід абстрагувати
- Перевіряйте повторювану конфігурацію або магічні значення

## Обробка помилок
- Чи обробляються помилки на правильному рівні (не ковтаються, не перехоплюються надміру)?
- Чи граничні випадки оброблено явно або задокументовано як такі, що виходять за межі обсягу?
- Чи дають повідомлення про помилки достатньо контексту для налагодження?
- Чи є тихі збої (порожні блоки catch, ігноровані значення, що повертаються)?

## Технічний борг
- Які ділянки мають найбільше навантаження на супровід?
- Чи є коментарі TODO/FIXME, які слід опрацювати вже зараз?
- Чи є мертвий код, який слід видалити?

## Інженерний баланс
- Чи є ділянки з надмірною інженерією (передчасна абстракція, зайва складність)?
- Чи є ділянки з недостатньою інженерією (крихкі, на милицях, без валідації)?
- Чи відповідає складність реальним вимогам?

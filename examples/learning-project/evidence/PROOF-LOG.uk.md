## Запис підходу «спершу тест»

Приймальний тест CLI спочатку впав, бо `src/cli.mjs` не існувало. Потім випадки неповного, некоректного, дубльованого кандидата та кандидата з некоректною версією впали на початковій реалізації, що підтримувала лише готовий стан. Під час циклів рев'ю тести падали на `NOT RUN`, `no retained output`, `UNKNOWN`, `failed`, `not executed` і `unverified`, доки не з'явилися відповідні перевірки маркерів у доказах. Тести hook спочатку впали, бо hook не існувало. Випадок із Docker push і варіанти з порожніми лапками отримували рішення `allow`, доки не додали відповідні правила заборони. Негативний тест пакета приймав некоректний JavaScript, доки `node --check` не увійшов до шлюзу пакування.

## Підсумкове твердження

Статус: `PASS` для локального контракту приймання Node.js. Збирання та виконання Docker залишаються `UNKNOWN`.

Перевірки Node.js можуть довести лише перелічену локальну поведінку на записаній ревізії та runtime. Валідація доказів кандидата — це фільтр маркерів над неструктурованим рядком; докази команд, кодів виходу й контрольних сум несе журнал доказів, а не це поле. `package:check` перевіряє синтаксис JavaScript і npm-маніфест, але не виконує запакований CLI. Поведінка Docker залишається `UNKNOWN`, доки обидві команди Docker не виконаються успішно.

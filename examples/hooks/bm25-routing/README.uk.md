# BM25-маршрутизатор skills для Codex і Claude Code

Цей hook `UserPromptSubmit` ранжує активні skills відносно підібраних прикладів за допомогою Okapi BM25. Він підтримує одне глобальне встановлення Codex, яке знаходить і проєктні, і користувацькі skills, починаючи з `cwd` prompt.

Hook має рекомендаційний характер. Він видає лише `additionalContext`. Він ніколи не викликає skill і не схвалює жодних дій.

У термінах патернів проєктування цей hook — детермінований [Content-Based Router](../../../guide/core/ai-design-patterns.uk.md#content-based-router), розміщений перед власним вибором skill моделлю. [Покрокове пояснення](../../../guide/workflows/smart-suggest-routing.uk.md#маршрутизатор-bm25-крок-за-кроком) розбирає кожне рішення на цьому шляху.

## Що змінилося порівняно з першим прикладом

Початкова реалізація працювала лише на рівні проєкту й лише для Claude. Крім того, вона маршрутизувала корпуси зі статусом `conflict`, сприймала будь-яке заперечення як відмову від маршрутизації, показувала частку оцінки як відсоток упевненості й пропускала деякі інвалідації кешу.

Ця версія:

- знаходить `.agents/skills` від `cwd` до кореня Git;
- потім знаходить `~/.agents/skills`, `~/.codex/skills`, `/etc/codex/skills` і `SKILL_ROUTER_EXTRA_ROOTS`;
- дозволяє найближчому проєктному skill затінювати глобальний skill з тим самим `name`;
- маршрутизує лише відкалібровані корпуси зі `status: ok` для активних skills;
- зберігає весь кеш і необов'язковий лог поза репозиторіями;
- виявляє додавання, правки й видалення за допомогою відбитка SHA-256 з версією алгоритму;
- серіалізує перебудови за допомогою блокування з терміном дії та атомарно записує файли кешу;
- видає `$skill-name` для Codex і `/skill-name` для Claude Code;
- ніколи не логує сирий prompt.

Skills без валідного корпусу залишаються доступними через нативний механізм зіставлення skills у Codex. Маніфест позначає їх як `native-only`.

## Вимоги

- Node.js 18 або новіший
- жодних залежностей npm
- hook `UserPromptSubmit` у Codex або Claude Code

## Рекомендоване встановлення для Codex

Перегляньте кожне місце призначення, контрольну суму та зміну hook:

```bash
node install.js --host codex --scope user --dry-run
```

Встановіть після перегляду попереднього огляду:

```bash
node install.js --host codex --scope user --apply
```

Інсталятор копіює середовище виконання в `~/.codex/hooks/skill-router/`, зберігає кеш окремо в `~/.codex/skill-router-data/`, зберігає наявні обробники в `~/.codex/hooks.json` і створює резервну копію з часовою міткою, перш ніж щось замінювати. Друге ідентичне встановлення не вносить жодних змін. Зберігання даних кешу поза каталогом середовища виконання також зберігає їх під час оновлень маршрутизатора.

Codex вимагає, щоб некеровані hooks були переглянуті й позначені як довірені. Відкрийте `/hooks`, перегляньте встановлену команду й схваліть її хеш. Доки цей крок не виконає людина, файли можуть існувати, а hook залишатиметься неактивним.

Не встановлюйте на тій самій машині ще й проєктний BM25-hook. Codex поєднує відповідні глобальні та проєктні hooks, тож два обробники можуть додавати дубльований контекст. Глобальний hook і так знаходить проєктні skills.

## Встановлення лише для проєкту

Для машини без глобального маршрутизатора:

```bash
node install.js \
  --host codex \
  --scope project \
  --project-root /absolute/path/to/repo \
  --dry-run
```

Після перегляду замініть `--dry-run` на `--apply`. Середовище виконання встановлюється в `<repo>/.codex/hooks/skill-router/` і використовує ту саму логіку пошуку та кешування. Згенерований hook встановлює `SKILL_ROUTER_DATA_DIR` у `~/.codex/skill-router-data`, тож prompts ніколи не записують файли кешу в репозиторій.

Проєктний режим Claude Code використовує `--host claude --scope project`. Синтаксис підказки змінюється на `/skill-name`. Не активуйте одночасно глобальний маршрутизатор Codex і проєктний маршрутизатор Codex.

## Формат корпусу

Суміжний корпус розміщується в `<skill>/evals/scenarios.json`:

```json
{
  "skill": "my-skill",
  "positive": [
    "run the linter on this file",
    "check code style"
  ],
  "negative": [
    "review this PR for security",
    "deploy the application"
  ]
}
```

Значення `skill` має дорівнювати активному `name` у `SKILL.md` і відповідати `^[a-z0-9][a-z0-9:_-]{0,127}$`. Для калібрування потрібно щонайменше вісім позитивних і два контрастні негативні приклади.

Використовуйте `SKILL_ROUTER_OVERLAY_ROOTS` для skill, каталог якого не може містити `evals/`. Це демонструє вбудований корпус `agentic-project-finder`. Overlay приймається, лише якщо його skill активний в одному з розв'язаних коренів.

## Збирання та перегляд

Зберіть кеш для конкретного робочого каталогу:

```bash
SKILL_ROUTER_CWD=/absolute/path/to/repo \
node routing/build-index.js
```

Перегляд без запису:

```bash
SKILL_ROUTER_CWD=/absolute/path/to/repo \
node routing/build-index.js --dry-run
```

Згенеровані файли для кожної області:

- `index.json`: токенізовані позитивні та контрастні негативні сценарії;
- `thresholds.json`: відкалібровані пороги та статус `ok`, `conflict` або `excluded`;
- `manifest.json`: розв'язані корені, активні skills, шляхи, покриття, виключення та відбиток джерел;
- `coverage.json`: skills `covered`, міжskill-ові `eligible` і `native-only`;
- `metrics.json`: початкова та відфільтрована якість leave-one-out, вилучення та глобальний F1;
- `verified.json`: часова мітка останньої глибокої перевірки джерел.

У підказці BM25 можуть з'являтися лише skills зі статусом `ok`, які також пройшли міжskill-ове оцінювання. Якщо допустимий набір залишається нижче глобального F1 0.70, проєктний корпус найнижчої якості залишається `native-only`. Overlay-skills, перевірені на приймальному наборі, зберігаються, а зашумлені проєктні корпуси вилучаються. Skills зі статусами `conflict`, `excluded`, некоректні, неактивні та `native-only` залишаються мовчазними.

## Оцінювання

Приймальний файл незалежний від навчального корпусу:

```bash
SKILL_ROUTER_CWD=/absolute/path/to/repo \
node routing/eval.js \
  --acceptance test/acceptance-prompts.json \
  --strict
```

Суворий режим вимагає точності щонайменше 0.80, F1 щонайменше 0.70 і нуля заборонених збігів. Звіт також містить p50, p95 і максимальну затримку оцінювання в межах процесу.

Запустіть усі тести:

```bash
node --test test/*.test.js
```

Виміряйте 1 000 «теплих» рішень маршрутизації в цільовій області:

```bash
SKILL_ROUTER_HOST=codex \
SKILL_ROUTER_DATA_DIR="$HOME/.codex/skill-router-data" \
node routing/benchmark.js --iterations 1000 --cwd /absolute/path/to/repo
```

## Контракт середовища виконання

Кожна команда hook має встановлювати `SKILL_ROUTER_HOST=codex` або `SKILL_ROUTER_HOST=claude`. Середовище виконання не визначає хост за нестабільними полями корисного навантаження.

Приклад виводу для Codex:

```json
{
  "hookSpecificOutput": {
    "hookEventName": "UserPromptSubmit",
    "additionalContext": "Skill routing candidates:\n- $agentic-project-finder (/absolute/path/SKILL.md)\nUse only if the intent matches."
  }
}
```

Вивід містить щонайбільше трьох кандидатів і 500 символів. Звичайний збіг не має `systemMessage` і жодного фіктивного відсотка впевненості.

Звичайне заперечення не вимикає маршрутизацію. Її вимикають явні відмови, як-от `ne suggère aucune skill` і `disable skill routing`. Prompt, який уже містить активну згадку `$skill` для Codex або команду `/skill` для Claude Code, також проходить мовчки.

## Конфігурація

| Змінна | Призначення |
|---|---|
| `SKILL_ROUTER_HOST` | Обов'язковий адаптер: `codex` або `claude` |
| `SKILL_ROUTER_CWD` | Цільовий робочий каталог для збирання |
| `SKILL_ROUTER_HOME` | Перевизначення домашнього каталогу для тестів або ізольованих встановлень |
| `SKILL_ROUTER_DATA_DIR` | Корінь для кешу та необов'язкового логу |
| `SKILL_ROUTER_EXTRA_ROOTS` | Додаткові авторизовані корені skills, розділені роздільником шляхів ОС |
| `SKILL_ROUTER_OVERLAY_ROOTS` | Зовнішні корені корпусів, розділені роздільником шляхів ОС |
| `SKILL_ROUTER_LOG=1` | Увімкнути логи маршрутизації лише з метаданими |
| `SKILL_ROUTER_DEEP_CHECK_MS` | Інтервал для фонової перевірки хешу вмісту, типово 60000 мс |

## Відкат

1. Вилучіть із відповідного файлу hooks лише той обробник, команда якого містить `skill-router/bm25-suggest.js`.
2. Відновіть резервну копію з часовою міткою, яку вивів інсталятор.
3. Відкрийте `/hooks` у Codex і переконайтеся, що жоден змінений недовірений hook не залишився активним.
4. Тимчасово збережіть кеш для діагностики. Він містить сценарії та метадані, а не prompts користувачів.

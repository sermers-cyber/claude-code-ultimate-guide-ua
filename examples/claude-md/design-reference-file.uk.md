# Файл-довідник дизайну: патерн для CLAUDE.md

Тримайте `brand-book.html` і `ui-kit.html` у корені проєкту як постійні файли контексту. Claude Code читає їх перед генеруванням будь-якого UI — кожна нова сторінка автоматично успадковує вашу дизайн-систему.

Натхненно воркфлоу Боріса Пайяра (mixt.care, березень 2026): щойно дизайн-систему налаштовано, нова сторінка займає 5 хвилин замість 30.

## Проблема

Коли ви будуєте сайт із Claude Code протягом кількох сесій, кожна нова сторінка ризикує відійти від дизайну — не ті кольори, непослідовна типографіка, нові варіанти компонентів. Повторювати обмеження дизайну в кожному prompt — це одноманітно й ненадійно.

## Рішення

Два HTML-файли в корені проєкту слугують дизайн-пам'яттю, яку Claude може прочитати будь-коли:

- `brand-book.html` — палітра кольорів із семантичними ролями, шрифти, CSS-змінні, коефіцієнти контрастності WCAG
- `ui-kit.html` — задокументовані компоненти (кнопки, форми, trust bars, підписи розділів)

Одна інструкція в CLAUDE.md змушує Claude звертатися до них перед кожним UI-завданням.

## Структура проєкту

```
project/
├── brand-book.html     # Палітра кольорів + типографіка + CSS-змінні (постійний довідник)
├── ui-kit.html         # Бібліотека компонентів, задокументована з Tailwind
├── CLAUDE.md           # Інструкція щодо дизайн-системи нижче
├── src/
│   ├── styles/
│   │   └── tokens.css  # CSS-змінні, витягнуті з brand-book.html
│   └── components/
└── ...
```

## Фрагмент для CLAUDE.md

Додайте це до `CLAUDE.md` рівня проєкту:

```markdown
## Дизайн-система

Завжди читай `brand-book.html` і `ui-kit.html` перед генеруванням будь-якого UI-компонента, сторінки чи макета.

Правила:
- Ніколи не прописуй кольори чи розміри шрифтів жорстко — використовуй CSS-змінні з brand-book.html
- Перевикористовуй компоненти з ui-kit.html, перш ніж створювати нові варіанти
- Нові сторінки мають використовувати ті самі design tokens (--color-primary, --font-primary тощо)
- Якщо запитаного елемента дизайну немає в UI kit, задокументуй його в ui-kit.html після створення
```

## Крок 1 — згенеруйте brand-book.html

```
Створи файл brand-book.html у корені проєкту.

Для кожного кольору з моєї палітри покажи картку з:
- Зразком кольору (блок 120×80px)
- Назвою, hex-кодом, значеннями RGB, значеннями HSL
- Назвою CSS-змінної (наприклад, --color-primary)
- Семантичною роллю: PRIMARY | DARK | LIGHT | ACCENT | NEUTRAL
- Правилом використання простим текстом (наприклад, "CTA, кнопки, активні посилання")
- Коефіцієнтом контрастності WCAG щодо білого: X.X:1 — AA PASS/FAIL — AAA PASS/FAIL
- Коефіцієнтом контрастності WCAG щодо чорного: X.X:1 — AA PASS/FAIL — AAA PASS/FAIL

Моя палітра:
[ПЕРЕЛІЧІТЬ ТУТ СВОЇ КОЛЬОРИ ТА РОЛІ]

Мої шрифти:
[ПЕРЕЛІЧІТЬ ТУТ СВОЇ ШРИФТИ]

Додай розділ зі шкалою розмірів: 12px / 16px / 20px / 24px / 32px / 48px / 64px / 96px з еквівалентами в rem.

Унизу виведи блок <style>, який можна скопіювати, з усіма CSS-змінними (:root { ... }).

Оформи сам brand-book.html за допомогою цих змінних — він має демонструвати дизайн-систему.
```

## Крок 2 — згенеруйте ui-kit.html

```
Створи ui-kit.html, що документує мої базові компоненти з використанням Tailwind і CSS-змінних із brand-book.html.

Додай:
- Кнопки: варіанти primary/secondary/ghost, 3 розміри (sm/md/lg)
- Trust bars із вертикальними кольоровими роздільниками
- Підписи розділів із горизонтальними лініями (верхній регістр, letter-spacing)
- Зразки типографіки: h1–h4, body, caption — з використанням --font-primary і --font-secondary
- Сітку зразків кольорів із показаними коефіцієнтами контрастності
- Елементи форм: input, select, textarea у станах default/focus/error

Для кожного компонента покажи: назву компонента, примітки щодо використання та використані класи Tailwind.
Посилайся на CSS-змінні з brand-book.html — жодних жорстко прописаних значень.
```

## Крок 3 — аудит кольорів за WCAG (необов'язково, але рекомендовано)

Запустіть це після генерування brand book, щоб виявити проблеми доступності ще до розробки:

```
Перевір палітру кольорів у brand-book.html на відповідність WCAG 2.1:

1. Для всіх імовірних комбінацій переднього плану й тла обчисли точні коефіцієнти контрастності (2 знаки після коми)
2. Познач пари, що не проходять WCAG AA: 4.5:1 для звичайного тексту, 3:1 для великого тексту й UI-компонентів
3. Змоделюй дейтеранопію, протанопію, тританопію — познач проблемні комбінації
4. Для кожної пари, що не проходить, запропонуй мінімальне коригування hex, щоб пройти AA, не відхиляючись від тону більш ніж на 10%
5. Результат: markdown-таблиця з колонками: Combination | Ratio | AA Normal | AA Large | AAA | Color Blind Safe

Зовнішні довідники:
- WebAIM Contrast Checker: https://webaim.org/resources/contrastchecker/
- ColorOracle (симулятор дальтонізму): https://colororacle.org/
```

## Крок 4 — анімації під час прокручування (необов'язково)

```
Додай анімації прокручування до всіх карток і заголовків розділів за допомогою Intersection Observer на чистому JS.
Елементи мають плавно з'являтися + зсуватися вгору з переходами 0.6s ease-out і затримкою 100ms між елементами.
Застосовуй лише до елементів з атрибутом [data-animate] — за явним увімкненням, не глобально.
Не використовуй жодних бібліотек анімацій — лише чистий JS.
```

## Приклад — палітра кольорів mixt.care

Добре структурована палітра із семантичними ролями та CSS-змінними:

```css
:root {
  /* Colors */
  --color-primary: #5C1A2E;   /* Deep bordeaux — CTAs, buttons, active links */
  --color-dark: #3D2B1F;      /* Warm brown — body text, dark backgrounds */
  --color-accent: #B87333;    /* Copper — hover states, secondary highlights */
  --color-secondary: #6B5B8E; /* Soft violet — badges, illustrations */
  --color-light: #F5F0EA;     /* Cream — section backgrounds, cards */

  /* Typography */
  --font-primary: 'Geist', sans-serif;       /* Body text */
  --font-secondary: 'Newsreader', serif;     /* Emphasis, quotes */
  --font-display: 'Fraunces', serif;         /* Logo, display headings only */

  /* Type scale */
  --text-xs: 0.75rem;
  --text-sm: 0.875rem;
  --text-base: 1rem;
  --text-lg: 1.25rem;
  --text-xl: 1.5rem;
  --text-2xl: 2rem;
  --text-3xl: 3rem;
  --text-display: 6rem;        /* Desktop statement footer */
  --text-display-mobile: 3rem;
}
```

**Примітки щодо WCAG для цієї палітри** (орієнтовно):
- Бордо на кремовому: ~8.2:1 — AA PASS
- Коричневий на кремовому: ~9.1:1 — AA PASS
- Білий на бордо: ~8.2:1 — AA PASS
- Мідний на білому: ~3.1:1 — AA FAIL для звичайного тексту (використовуйте лише для UI-компонентів або затемніть до #9B5F20)
- Фіолетовий на кремовому: ~4.8:1 — AA PASS

## Коли використовувати цей патерн

- Ви створюєте маркетинговий сайт, лендинг або сайт продукту з Claude Code
- Вам потрібен узгоджений дизайн на кількох сторінках, згенерованих у різних сесіях
- Перед початком UI-роботи над будь-яким проєктом з усталеними брендовими настановами
- Щоб замінити ручну документацію дизайн-системи інтерактивним довідником, який сам себе демонструє

## Обмеження

- Ефективно для статичних/маркетингових сайтів і MVP — складним бібліотекам компонентів потрібен повноцінний інструмент дизайн-системи (Storybook, Figma)
- Часові рамки у 2 год передбачають, що ви знаєте свій дизайнерський задум ще до написання prompt (кольори, шрифти, напрям макета)
- Аудит WCAG від Claude орієнтовний — перевіряйте критичні пари у WebAIM або спеціалізованому інструменті

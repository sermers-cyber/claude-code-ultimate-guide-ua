# Аркуш запобіжного заходу репозиторного harness

Використовуйте для одного повторюваного збою в одному класі завдань. Це запропонований експеримент, а не доказ того, що hook, skill чи агент рев'ю покращує доставку. Тримайте власника й початковий збій прив'язаними до контролю.

| Рішення | Запис |
|---|---|
| Запит користувача й завершений результат | Назвіть поведінку або розв'язану проблему. Тримайте прийнятий код, реліз і ефект для користувача окремо. |
| Збій, якого слід уникнути | Збережіть збійний вхід, хибне рішення та ревізію, де це сталося. |
| Точка збою | Джерела немає, хибна ревізія, не завантажено, неправильно прочитано, перевірку не виконано або результат проігноровано. Невизначені етапи позначайте `UNKNOWN`. |
| Кандидат на запобіжний захід | Розмістіть перевірку в найраніший надійний момент роботи. Вкажіть, чи вона попереджає, блокує або запитує судження людини. |
| Випадок хибного твердження | Відтворіть випадок, який контроль має відхилити. |
| Дозволений сусідній випадок | Відтворіть схожий валідний випадок, який контроль має дозволити. |
| Альтернативний шлях | Спробуйте інший редактор, команду чи точку входу агента, що могли б обійти контроль. |
| Доказ виконання | Запишіть хост, ревізію репозиторію, команду чи слід подій, результат перевірки та рішення рев'юера. |
| Вартість | Порахуйте хибні блокування, повтори, перехоплення людиною, очікування рев'ю, використання токенів чи інструментів, де це доступно, та супровід. |
| Рішення про впровадження | Власник приймає, переглядає або виводить контроль з обігу після порівняння еквівалентних завдань за співставними проміжками. |

Для міграції застарілого коду перевірка цитування встановлює лише те, що розташування джерела існує. Вона не встановлює, що цей код робить. Простежте шлях виклику й запустіть характеризаційні випадки на наявному застосунку перед його зміною. Проведіть одну придатну до використання одиницю через звичайний шлях рев'ю й релізу, а тоді перевірте, чи можна вивести зі вжитку старий шлях. Якщо кодування чи закінчення рядків файлу мають значення, перевірте отримані байти через реальний шлях запису та альтернативний шлях.

Для правила контексту розрізняйте **присутнє**, **згенероване**, **завантажене**, **використане** та **ефект перевірено**. Спершу виправте авторитетне джерело, потім відтворіть хибне твердження й дозволений сусідній випадок. Коротший промпт чи новий skill є лише кандидатом на контроль, доки запущена сесія його не використає і намічена помилка не зникне.

Для спільної черги рев'юера скористайтеся [аркушем допуску до рев'ю](review-admission.uk.md). Експеримент із harness вимірює, чи нова перевірка запобігає названому дефекту, не перекладаючи більше роботи на очікування, повторні рев'ю чи приховані обходи. Локальний зелений тест, прийняття CI та результат для користувача є різними спостереженнями; фіксуйте кожне на його власній межі.

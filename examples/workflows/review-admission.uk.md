# Аркуш політики допуску до рев'ю

Це запропонований аркуш політики, а не встановлений планувальник чи підтверджене покращення пропускної здатності. Застосовуйте його до одного сервісу й співставного класу змін.

| Поле | Рішення команди |
|---|---|
| Черга й відповідальний власник | |
| Придатний клас змін і виключена робота | |
| Результат для користувача та докази завершення | Назвіть поведінку чи розв'язану проблему; записуйте реліз і впровадження окремо від прийняття рев'ю |
| Відомий дефект і раніша запобіжна перевірка | Збережіть інцидент, випадок, який перевірка має відхилити, і сусідній валідний випадок, який вона має дозволити |
| Базове вікно спостереження | |
| Подія надходження | Перше оголошення готовності на зазначеній ревізії |
| Подія прийняття | Прийняття за необхідною політикою на цій ревізії |
| Робота в черзі та зарезервовані слоти | Рахуйте унікальні зміни; авторів у процесі відстежуйте окремо |
| Міра віку та схвалений власником ліміт | |
| Правило призупинення | Призупиніть нове авторство, коли досягнуто ліміту черги чи віку, місткість недоступна або телеметрія застаріла |
| Правило відновлення | Використовуйте нижчий поріг черги, прийнятний вік, свіжу телеметрію й доступну місткість верифікації |
| Робота, дозволена під час паузи | Наявне рев'ю, узгоджені виправлення, реагування на інциденти в межах наявних повноважень |
| Термінове виключення | Названий схвалювач, причина, обмежений обсяг, витіснена робота, термін дії |
| Вартість цієї політики | Зусилля рев'юерів, повторні перевірки, хибні блокування, обходи та супровід |

Почніть із заявленої доступності та названого верифікатора. Перший пілот може лишатися ручною політикою. Якщо допуск автоматизовано, резервуйте слот верифікації атомарно перед відправленням і робіть звільнення чи перетворення ідемпотентним за стабільною ідентичністю резервації. Узгоджуйте невизначене підтвердження перед повтором. Скасоване завдання не зараховується як прийнята зміна. Виправлення лишаються прив'язаними до початкової зміни. Нова ревізія робить недійсними докази прийняття, яких вона торкається.

Кожне відкладене завдання фіксує причину, власника, умову поновлення та термін дії або точку перегляду. Повторні відкладання потребують перегляду, звуження обсягу, перепризначення чи явного скасування за узгодженою політикою. Спливання терміну резервації не уповноважує її попереднього власника продовжувати. Не робіть висновків про втому з телеметрії активності й не додавайте планувальник лише для реалізації цього аркуша.

## Настільне навчання

Наведені числа є синтетичними вхідними даними політики, а не рекомендованими лімітами команди. Припустіть ліміт черги в три зайняті/зарезервовані слоти, відновлення за один чи менше, обраний ліміт віку та свіжу телеметрію.

| Стан чи подія | Очікуване рішення |
|---|---|
| Два зайняті слоти; два автори одночасно просять допуску | Зарезервувати один слот, допустити одного автора, іншого поставити в чергу; ніколи не перебронювати |
| Три зайняті слоти; наявний рев'юер завершує перевірку | Дозволити рев'ю завершитися; не скасовувати його через призупинене авторство |
| Два слоти після прийняття | Лишатися на паузі, доки не виконано умову відновлення |
| Один слот, але найстаріша зміна перевищує ліміт віку | Лишатися на паузі; розв'язати застарілу зміну |
| Один слот, прийнятний вік, свіжа телеметрія, рев'юер доступний | Відновити допуск за правилом резервації |
| Дані черги недоступні або рев'юер недоступний | Призупинити нове авторство; зберегти записи й спрямувати блокер власнику |
| Термінове прохання без схвалення названого виключення | Лишити в черзі |

Фіксуйте спостережені рішення під час випробування реалізації. До того це лише очікувані результати. Порівнюйте еквівалентні класи змін за співставними вікнами. Відстежуйте прийняті зміни, пропущені дефекти, зусилля людей і час до названого результату для користувача разом із розміром черги, щоб швидші схвалення не видавалися за покращення. Якщо політика затримує повний результат або блокує валідну роботу, не запобігаючи відомому збою, перегляньте її разом із власником.

[Локальне контрольне навчання](review-control-demo.py) тестує довговічні бюджети й одночасні ефекти на симульованому сервісі. Воно не реалізує цю політику місткості й не вимірює доступність людей.

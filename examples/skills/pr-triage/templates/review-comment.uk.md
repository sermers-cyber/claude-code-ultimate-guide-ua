# Шаблон коментаря рев'ю

Використовуйте цей шаблон для генерації коментарів рев'ю GitHub PR. Заповніть кожен розділ на основі виводу agent code-reviewer. Коментарі публікуються **англійською** (міжнародна аудиторія).

---

## Шаблон

```markdown
## Review

**Scope**: Security, code quality, performance, test coverage, architecture

### Summary

{1–2 речення: загальна оцінка. Будьте прямі: у чому головний висновок?}

### Critical Issues

{Перелічіть блокувальні проблеми, які треба виправити до мерджу. Для кожної:}
{- `file:42` — Опис проблеми. Чому це важливо. Запропоноване виправлення.}

{Якщо немає: "None found."}

### Important Issues

{Перелічіть суттєві проблеми, які варто виправити. Для кожної:}
{- `file:42` — Опис. Чому це важливо. Запропоноване виправлення.}

{Якщо немає: "None found."}

### Suggestions

{Перелічіть бажані та дрібні покращення. Для кожного:}
{- Опис. Контекст. Необов'язкове виправлення.}

{Якщо немає: пропустіть цей розділ.}

### What's Good

{Завжди додавайте принаймні 1 позитивний пункт. Будьте конкретні: що працює добре і чому.}
{- Опис того, що зроблено правильно.}

---
*Automated review via Claude Code `/pr-triage` — add your project-specific checks in SKILL.md*
```

---

## Правила форматування

**Формат цитування**: `file:42` або `` `code snippet` `` для inline-посилань

**Серйозність проблем**:
- Critical: вразливість безпеки, ризик втрати даних, зламана функціональність, відсутній тест для нової функції
- Important: прогалина в обробці помилок, регресія продуктивності, розповзання обсягу, відсутня валідація
- Suggestion: іменування, можливість DRY, документація, стиль

**Тон**: Професійний, конструктивний, фактичний. Критикуйте код, а не людину.
Без суперлативів ("great", "amazing", "perfect"). Без води ("as mentioned", "it's worth noting").

**Довжина**: Орієнтуйтеся на 200–400 слів. Достатньо довго, щоб бути корисним, і достатньо коротко, щоб його прочитали.

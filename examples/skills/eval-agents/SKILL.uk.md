# Оцінювач агентів

Знайдіть кожного власного агента в межах обсягу, перевірте його згідно з нативною схемою його хоста, оцініть, а потім перегляньте з користувачем по одному агенту за раз.

Батьківський агент обирає агентів за їхнім `description`. Розмитий або перетинний опис робить делегування непередбачуваним, тож перетин є дефектом коректності, а не питанням стилю. Мета: залишити кожного агента таким, що завантажується, відрізняється від інших, має правильну модель і якому безпечно делегувати.

## Коли використовувати

- Аудит парку агентів перед підключенням до воркфлоу делегування чи оркестрації
- Батьківський агент постійно делегує не тому агенту або ніколи не делегує
- Після копіювання агентів з іншого проєкту чи встановлення plugin
- Додано нового агента, який може конфліктувати з наявними
- Періодична гігієна: чи всі ці агенти досі роблять щось своє?

Не для: skills (`eval-skills`), hooks (`eval-hooks`), правил Claude Code (`eval-rules`) або звіту про стан конфігурації між хостами (`eval-agent-config`).

## Довідка щодо хостів

### Claude Code: звідки завантажуються агенти

Коли кілька визначень мають однаковий `name`, Claude Code бере визначення з розташування з найвищим пріоритетом:

| Пріоритет | Розташування | Обсяг |
|---|---|---|
| 1 | Каталог керованих налаштувань, `.claude/agents/` | Організація |
| 2 | Прапорець CLI `--agents` (JSON або шлях до JSON-файлу з `-p`) | Поточна сесія |
| 3 | `.claude/agents/` | Проєкт |
| 4 | `~/.claude/agents/` | Користувач |
| 5 | Каталог `agents/` plugin | Там, де plugin увімкнено |

- `.claude/agents/` і `~/.claude/agents/` скануються рекурсивно. Підкаталоги не змінюють ідентичність.
- Агенти проєкту знаходяться проходом угору від робочого каталогу; сканується кожен `.claude/agents/` аж до кореня репозиторію, і перемагає визначення, найближче до робочого каталогу.
- Каталоги, додані через `--add-dir` або `/add-dir`, також додають свої `.claude/agents/`.
- Підкаталоги plugin стають частиною ідентифікатора: `agents/review/security.md` у plugin `my-plugin` реєструється як `my-plugin:review:security`.

### Claude Code: файли, які runtime мовчки пропускає

- Немає `name`: вважається документацією, що лежить поряд з агентами.
- Відкривальний `---` не на першому рядку: читається як файл без frontmatter.
- `name` починається з `-` або містить `:`: пропускається, помилка в debug-лозі.
- `name` без `description`: пропускається.
- YAML не парситься: пропускається. Агент plugin без `name` або з frontmatter, що не парситься, однаково завантажується під іменем свого файлу.

«Не парситься» означає власний парсер Claude Code, який приймає деякі frontmatter, що їх відхиляє сувора YAML-бібліотека, наприклад багаторядковий `description` без лапок, рядки якого містять `: `. Вирішуйте за допомогою `claude plugin validate <agents directory>` (v2.1.233 або новіша) чи списку агентів сесії (`/agents`), а не лише за допомогою суворої YAML-бібліотеки. Файл, який відхиляє лише суворий парсер, завантажується: повідомте про нього як про попередження щодо переносимості (інші інструменти можуть його відхилити) і запропонуйте блоковий скаляр `>`.

Два файли в одному дереві агентів з однаковим `name`: завантажується лише один, обраний за порядком читання файлової системи, а не за задокументованим пріоритетом. `/doctor` повідомляє про такі випадки.

### Claude Code: поля frontmatter

Обов'язкові лише `name` і `description`. Назви полів пишуться в camelCase і мають збігатися точно; невідоме поле ігнорується без помилки.

| Поле | Примітки |
|---|---|
| `name` | Обов'язкове. Унікальна ідентичність; hooks отримують його як `agent_type`. Назва файлу не мусить збігатися. |
| `description` | Обов'язкове. Коли батьківському агенту слід делегувати. |
| `tools` | Рядок через кому або YAML-список. Не вказано: успадковує кожен інструмент, доступний subagents. Жодного запису, який можна розв'язати: агент зазвичай не запускається. |
| `disallowedTools` | Вилучаються з успадкованого чи оголошеного списку. Специфікатор на кшталт `Bash(git push *)` вилучає весь інструмент. |
| `model` | `sonnet`, `opus`, `haiku`, `fable`, повний ID моделі або `inherit`. |
| `permissionMode` | `default` (псевдонім `manual`), `acceptEdits`, `auto`, `dontAsk`, `bypassPermissions`, `plan`. Ігнорується, коли основна розмова працює в `bypassPermissions`, `acceptEdits` або автоматичному режимі. |
| `maxTurns` | Обмеження кількості агентних ходів; вивід повертається з позначкою «частковий». |
| `skills` | Skills, повністю попередньо завантажені під час запуску. |
| `mcpServers` | Назви серверів або вбудовані визначення серверів. |
| `hooks` | Hooks, активні, поки працює цей агент; `Stop` стає `SubagentStop`. Hooks агентів проєкту запускаються лише після прийняття довіри до робочого простору. |
| `memory` | Обсяг постійної пам'яті: `user`, `project` або `local`. |
| `background` | `true` тримає агента у фоні. |
| `omitClaudeMd` | `true` запускає без файлів CLAUDE.md користувача, проєкту й локального. |
| `effort` | `low`, `medium`, `high`, `xhigh`, `max`; доступні рівні залежать від моделі. |
| `isolation` | `worktree` запускає агента в тимчасовому git worktree. |
| `color` | Колір відображення. |
| `initialPrompt` | Перший хід користувача, коли агент працює як агент основної сесії. |
| `experimental` | Map; читається лише `cacheTtl: 5m` або `1h`, і лише з файлів агентів. |

Агенти plugin ігнорують `hooks`, `mcpServers` і `permissionMode`; `initialPrompt` теж ігнорується для агентів plugin.

Позначайте як нерозпізнані (Claude Code мовчки ігнорує): `allowed-tools`, `disallowed-tools`, `context`, `argument-hint` і будь-який інший ключ, якого немає в таблиці. Це поля skills, а не агентів.

### Claude Code: визначення моделі

1. Параметр `model` для конкретного виклику, переданий батьківським агентом
2. `model` у frontmatter агента (`inherit` обирає модель основної розмови)
3. `CLAUDE_CODE_SUBAGENT_MODEL`, якщо встановлено псевдонім або ID моделі
4. Модель основної розмови

`CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` змушує кожного агента ігнорувати своє поле `model`. Псевдонім родини розв'язується в точну модель основної розмови, якщо ця модель належить до тієї самої родини. Значення, заблоковане через `availableModels` організації, замінюється.

### Claude Code: інструменти, яких subagent ніколи не отримує

Runtime вилучає ці інструменти з кожного subagent, що не є fork, навіть якщо вони перелічені в `tools`: `AskUserQuestion`, `EndConversation`, `EnterPlanMode`, `ExitPlanMode` (якщо не `permissionMode: plan`), `ScheduleWakeup`, `WaitForMcpServers`, а також `Agent` на межі глибини.

### Codex: власні агенти

| Елемент | Правило |
|---|---|
| Розташування | Один TOML-файл на агента в `~/.codex/agents/` (особисті) або `.codex/agents/` (проєкт) |
| Обов'язкові ключі | `name`, `description`, `developer_instructions` |
| Ідентичність | `name` є джерелом істини; назва файлу є лише конвенцією |
| Необов'язкові ключі | Будь-який підтримуваний ключ `config.toml`, як-от `model`, `model_reasoning_effort`, `sandbox_mode`, `mcp_servers`, `skills.config`; пропущені ключі успадковуються від батьківської сесії |
| Вбудовані агенти | `default`, `worker`, `explorer`; власний агент із тим самим іменем має пріоритет |
| Глобальні налаштування | `[agents]` у `config.toml`: `enabled`, `max_concurrent_threads_per_session` (застаріле `max_threads`), `default_subagent_model`, `default_subagent_reasoning_effort`, `interrupt_message` |

Markdown-агент із YAML frontmatter або TOML-файл, що використовує `prompt` замість `developer_instructions`, є визначенням у форматі Claude і не відповідає схемі Codex.

| # | Критерій | Макс. | Що перевіряється |
|---|---|---|---|
| 1 | **завантажуваність** | 3 | TOML парситься (1); `name` і `description` присутні (1); `developer_instructions` присутній і непорожній (1) |

**Пороги:** Добре >= 80%, Потребує роботи 60-79%, Виправити < 60%.

### Сигнали рівня моделі

| Робота | Claude Code | Codex (згідно з документацією Codex про subagents) |
|---|---|---|
| Механічна: пошук, витягування, бінарна перевірка | `haiku` | легша модель, як-от `gpt-6-luna` |
| Обмежене судження: рев'ю, налагодження, тести, документація | `sonnet` | `gpt-6-sol`, effort `medium` |
| Наскрізний синтез: архітектура, модель загроз, компроміси між кількома системами | `opus` | `gpt-6-sol`, `high` або вище |

Позначайте обидва напрями: надто слабку модель для роботи, що потребує судження, і надто потужну модель для механічної роботи, яка виконується багато разів. Вказуйте вартість за опублікованими цінами замість фіксованого множника; наприклад, посібник наводить для Opus 5.5 $4/$20, а для Haiku 5.5 $0.10/$0.50 за мільйон вхідних/вихідних токенів (промпти до 100K токенів). Haiku 5.5 підтримує effort і за замовчуванням використовує `medium`; лише застаріла Haiku 4.5 не має параметра effort, тож поле `effort` в агента, закріпленого за Haiku 4.5, не має ефекту.

### Антипатерн «людина в циклі»

Subagents не отримують `AskUserQuestion` чи інструментів режиму планування і за замовчуванням працюють у фоні. Будь-яку інструкцію системного промпту на кшталт «запитай користувача», «підтверди перед видаленням» чи «дочекайся схвалення» виконати неможливо. Безпечна альтернатива: «Якщо контексту недостатньо, поверни `{ "status": "needs_context", "missing": [...] }` і зупинись.»

## Інструкції з виконання

### Крок 1: Виявлення

Визначте обсяг з аргументу або за замовчуванням візьміть обсяг проєкту й користувача для кожного запитаного хоста.

| Запит | Виконання |
|---|---|
| За замовчуванням | Кроки 1-6 з інтерактивним переглядом |
| `audit-only`, або користувач просить нічого не змінювати | Кроки 1-4 і 6: перелічіть запропоновані зміни замість запитань чи редагування |
| Понад 20 агентів в обсязі | Тріаж: виконайте кроки 1-3 і структурні перевірки кроку 2 для кожного файлу, повністю оцініть лише агентів зі знахідками плюс вибірку решти, а інших подайте в одній компактній таблиці |

```bash
# Claude Code: every .md file, recursively (-L follows symlinked directories)
find -L .claude/agents -name "*.md" 2>/dev/null
find -L ~/.claude/agents -name "*.md" 2>/dev/null   # user scope, when requested

# Codex: one TOML file per agent
find -L .codex/agents -name "*.toml" 2>/dev/null
find -L ~/.codex/agents -name "*.toml" 2>/dev/null  # user scope, when requested
```

Також перелічіть вкладені каталоги `.claude/agents/` між робочим каталогом і коренем репозиторію.

Коли доступний звіт `ctxharness doctor --format json`, згенерований під час цього завдання, кожна знахідка щодо шару агентів із нього має з'явитися в аудиті.

Готово, коли: кожен файл-кандидат перелічено з його хостом і обсягом, або звіт повідомляє, що каталогу агентів немає, і зупиняється.

### Крок 2: Розбір і перевірка завантажуваності

Для кожного файлу прочитайте його повністю й зафіксуйте: хост, обсяг, `name`, довжину `description`, `model`, `tools` або `(inherits)`, усі інші ключі, кількість рядків тіла або `developer_instructions`.

Для Claude Code команда `claude plugin validate .claude/agents` (v2.1.233 або новіша) повідомляє про файли, frontmatter яких не парситься; вона не позначає файл, що парситься, але не має `name`, тож перевірте це окремо. Вона лише читає файли, тому безпечна в режимі `audit-only`.

Перевіряйте значення, а не лише назви полів:

- `permissionMode` має одне з задокументованих значень; будь-що інше, наприклад `ask`, не є режимом.
- `model` є псевдонімом із таблиці або повним ID моделі; `effort`, `memory`, `isolation` і `experimental.cacheTtl` мають задокументовані значення.
- Кожен запис `tools` і `disallowedTools` називає інструмент із довідника інструментів (https://code.claude.com/docs/en/tools-reference) або MCP-інструмент (`mcp__server__tool`). Незадокументована назва, як-от `MultiEdit`, не розв'язується: позначте її, а агента позначте як ризик невдалого запуску, коли жоден запис не розв'язується.
- Кожен запис `skills` розв'язується в skill, доступний у цьому обсязі.

Готово, коли: кожен файл класифіковано як завантажуваний, пропущений runtime (з причиною з довідки щодо хостів вище) або нечитабельний, а його недійсні значення перелічено.

### Крок 3: Перевірка колізій і перетинів

- Той самий `name` двічі в одному дереві агентів Claude Code або власний агент Codex, що затіняє вбудованого: повідомте, який файл перемагає або що вибір не визначено.
- Той самий `name` в обсягах користувача й проєкту: всередині проєкту перемагає визначення проєкту, тож копія користувача там мертва. Перелічіть ці пари й чи відрізняються визначення.
- Порівняйте описи попарно в межах кожного хоста й обсягу. Позначте пари, що претендують на той самий тип запитів без зазначеної межі.

Готово, коли: кожну колізію й перетинну пару перелічено з обома шляхами до файлів.

### Крок 4: Оцінювання

Застосуйте таблицю оцінювання хоста. Виведіть рівень моделі із системного промпту й позначте невідповідності.

Готово, коли: кожен завантажуваний агент має оцінку, статус і не більше трьох пріоритетних виправлень.

### Крок 5: Інтерактивний перегляд

Обробляйте агентів по одному. Покажіть хост, обсяг, `name`, модель, інструменти, оцінку й позначені проблеми, потім запитайте:

1. Чи достатньо конкретний опис, щоб відрізнити цього агента? (y / rewrite)
2. Чи правильний рівень моделі? (y / change)
3. Чи правильно обмежено інструменти? (y / add / remove)
4. Чи треба щось змінити в системному промпті чи інструкціях? (describe / skip)

Застосовуйте підтверджені правки за допомогою редагування файлів і підтверджуйте кожну. Для агента, якого користувач позначив як застарілого, попросіть явне «так, видали його», перш ніж видаляти файл.

Готово, коли: кожен агент має зафіксовану відповідь (підтверджено, відредаговано, позначено застарілим або пропущено).

## Граничні випадки

- **`tools` не вказано**: агент успадковує пул інструментів subagent. Це не помилка завантаження; позначте для перегляду, коли агенту не потрібен доступ на запис чи до shell.
- **`model` не вказано**: визначення переходить до `CLAUDE_CODE_SUBAGENT_MODEL` або моделі основної розмови. Повідомте фактичне джерело.
- **`allowed-tools` замість `tools`**: Claude Code ігнорує це поле, тож агент успадковує кожен інструмент. Позначте як виправлення високого пріоритету.
- **`effort` в агента Haiku**: не має ефекту; запропонуйте прибрати.
- **Агент plugin із `hooks`, `mcpServers` або `permissionMode`**: ігноруються; щоб їх використати, користувач має скопіювати агента в `.claude/agents/` або `~/.claude/agents/`.
- **Файл агента в каталозі, створеному після початку сесії**: Claude Code не відстежує його до перезапуску; повідомте про це, коли новий агент «не з'являється».
- **Codex TOML, що використовує `prompt`**: це не поле Codex; потрібен `developer_instructions`.
- **Опис на кшталт «use for everything»**: прийнятний лише для навмисного універсального агента; інші позначайте.

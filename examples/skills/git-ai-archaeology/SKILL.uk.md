# git-ai-archaeology

Відновлює історію AI coding harness за даними git: які файли й коли з'явилися, хто їх підтримував, як вони поширювалися між модулями, що було покинуто і як змінювалися AI-асистовані коміти. Вбудований скрипт робить підрахунки за один прохід; агент перевіряє класифікацію і пише розповідь на основі даних.

**Вивід**: `{out}/{slug}-harness.json` і `{out}/{slug}-harness.md` (скрипт), потім `{out}/{slug}-git-archaeology.md` (розповідь).

```
/git-ai-archaeology repo_path=/path/to/repo [out=./reports] [slug=name] [ref=main] [since=2025-01-01] [remotes=yes]
```

## Воркфлоу

1. **Визначте обсяг.** Перевірте шлях командою `git -C {repo_path} rev-parse --git-dir`. Використовуйте гілку за замовчуванням як `ref`, якщо користувач не назвав іншу; feature-гілка спотворює кожен підрахунок. Вирішіть, чи сканувати віддалені гілки (`--remotes`) на предмет незлитої роботи з harness. Готово, коли репозиторій, ref, період і каталог виводу зафіксовано.

2. **Запустіть скрипт.**

   ```bash
   python3 -I ${CLAUDE_SKILL_DIR}/scripts/harness_archaeology.py \
     --repo {repo_path} --out {out} --ref {ref} [--since {since}] [--remotes] [--slug {slug}]
   ```

   Він один раз проходить кожен не-merge коміт, що зачіпає шлях harness (`git log --raw --numstat -M`), тож його вартість зростає з довжиною історії, а не з кількістю запусків. Наявність, копії та застарілість зчитуються з дерева `--ref`, а не з робочої копії. З `--since` файли, старші за вікно, отримують як дату створення свій перший коміт у вікні, і звіт повідомляє, скільки таких файлів. Скрипт завершується з ненульовим кодом і нічого не пише, якщо шлях не є git-репозиторієм. Готово, коли він виводить `harness_commits` і обидва файли існують.

3. **Перевірте класифікацію, перш ніж довіряти числам.** Прочитайте таблиці "By tool family" і "Most edited files". Шукайте хибні спрацювання (каталог `commands/` тестового набору, каталог `agents/` із бізнес-документацією) і файли harness, які патерни пропустили:

   ```bash
   git -C {repo_path} -c core.quotePath=false ls-files | grep -iE 'agent|prompt|llm|copilot|claude|codex|cursor|mcp|skill' | grep -vE '\.(java|ts|py|go|kt)$' | head -50
   ```

   Перезапустіть із `--extra-glob 'path/**'` (можна повторювати, родина `custom`) для пропущеного розташування і з `--exclude-glob 'path/**'` для файлів, що є вмістом продукту, а не harness, наприклад skills, які репозиторій публікує як приклади. Хибне спрацювання, залишене на місці, згадується в обмеженнях розповіді, а не приховується. Готово, коли файли кожної родини перевірено вибірково і кожне виправлення або перезапущено, або перелічено.

4. **Прочитайте події, потім опишіть фази.** Працюйте з JSON, а не з пам'яті про типові проєкти. Використовуйте [сітку читання](references/reading-grid.uk.md), щоб інтерпретувати кожен індикатор. Шукайте: хвилі створення, той самий файл, доданий у багато модулів за один день (поширення), файли, додані й видалені за кілька днів (метод спроб і помилок), перейменування з каталогу одного інструмента в каталог іншого (міграція), видалення, тема коміту яких формулює політику, структурувальні коміти і роботу, що існує лише у віддалених гілках. Виведіть фази з цих зламів; їхня кількість і назви походять із даних. Готово, коли кожна фаза називає свій період, кількість комітів і щонайменше один хеш.

5. **Порівняйте використання з активністю harness.** У місячній таблиці поставте частку AI-трейлерів поруч із комітами harness. Трейлер є нижньою межею: inline-автодоповнення не залишає жодного, а `Co-authored-by: Copilot` не каже, яку функцію використано. Скрипт зараховує трейлер, коли його e-mail належить вендору інструмента або коли він називає інструмент із bot- чи noreply-адресою, тож колега на ім'я Claude не враховується. Готово, коли розповідь називає перший місяць з AI-трейлерами, останню частку і чи рухаються використання й робота з harness разом.

6. **Напишіть `{slug}-git-archaeology.md`.** Розділи: обсяг і метод; ключові показники; хронологія першої появи для кожної родини; фази з доказами; поширення й дублювання; churn і покинуті файли; хто підтримує (лише кількості й частки); використання проти harness; незлита робота; обмеження. Кожне число береться з JSON або з команди, наведеної у звіті. Готово, коли наведений нижче чекліст перевірки пройдено.

## Правила

- **Лише читання.** Жодних git-команд, що пишуть, жодного checkout, жодного fetch, якщо користувач не попросить.
- **Приватність.** Автори з'являються лише як кількості й частки. Не виводьте імена чи e-mail, навіть із `git shortlog`. Скрипт хешує e-mail із випадковою сіллю для кожного запуску, тож хеші не можна обчислити повторно; передавайте `--salt` лише для порівняння двох запусків і не допускайте цієї солі у вивід. Якщо учасників один чи двоє, частка все одно вказує на людину: скажіть про це.
- **Перевіряйте, перш ніж стверджувати.** Дата чи подія, не знайдена в git, записується як «не знайдено» разом із випробуваною командою.
- **Перейменування не є створенням.** Скрипт відстежує перейменування між шляхами harness через `-M` і наводить первісну дату створення. Файл, перенесений із шляху поза harness, показується як створений у момент переміщення.
- **Показуйте порожні місяці.** Скрипт перелічує кожен місяць, починаючи з першого коміту harness, включно з місяцями без жодного коміту.

## Чекліст перевірки

- [ ] Ref є гілкою за замовчуванням, або звіт пояснює, чому ні
- [ ] Класифікацію перевірено вибірково; виправлення перезапущено або перелічено як обмеження
- [ ] Кожна фаза наводить період, кількість і хеш
- [ ] Використання подано як нижню межу з першим місяцем і останньою часткою
- [ ] У жодному виводі немає імен авторів чи e-mail
- [ ] Обидва виводи скрипту й розповідь існують у `{out}`

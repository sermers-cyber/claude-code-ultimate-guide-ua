# Перевірка змін перед комітом

Оцінює staged-зміни git за допомогою агента output-evaluator, щоб виявити проблеми перед комітом.

## Процес

### Крок 1: перевірте наявність staged-змін

Виконайте `git diff --cached --stat`, щоб побачити, що додано до staging. Якщо нічого не додано, повідомте користувача й завершіть.

### Крок 2: отримайте повний diff

Виконайте `git diff --cached`, щоб отримати повний diff усіх staged-змін.

### Крок 3: викличте оцінювача

Використайте інструмент Task, щоб запустити агента `output-evaluator` із diff:

```
Evaluate these staged changes for correctness, completeness, and safety.
Return a JSON verdict with scores and issues.

Changes:
[paste the git diff here]
```

### Крок 4: розберіть вердикт і дійте відповідно

Залежно від результату оцінювання:

**Якщо APPROVE:**
- Повідомте користувача, що зміни пройшли оцінювання
- Покажіть підсумок і оцінки
- Запитайте, чи хоче він продовжити з комітом

**Якщо NEEDS_REVIEW:**
- Покажіть усі знайдені проблеми (згруповані за серйозністю)
- Покажіть пропозицію оцінювача
- Запитайте користувача, як діяти далі:
  - Виправити проблеми й оцінити повторно
  - Закомітити попри це (визнаючи ризики)
  - Перервати

**Якщо REJECT:**
- Чітко повідомте, що зміни відхилено
- Покажіть критичні проблеми, що призвели до відхилення
- НЕ пропонуйте закомітити попри це
- Запропонуйте конкретні виправлення

### Крок 5: коміт (якщо схвалено)

Якщо користувач підтверджує, створіть коміт за стандартним процесом комітів.

## Приклади використання

```
/validate-changes
```

Вивід:
```
Evaluating 3 staged files...

VERDICT: NEEDS_REVIEW

Scores:
  Correctness:  8/10
  Completeness: 6/10
  Safety:       9/10

Issues Found:
  [MEDIUM] src/api/handler.ts:45
    Missing error handling for network failures

  [LOW] src/utils/format.ts:12
    Consider adding input validation

Suggestion: Add try-catch around the fetch call in handler.ts

How would you like to proceed?
  1. Fix issues and re-evaluate
  2. Commit anyway (1 medium issue)
  3. Abort
```

## Усвідомлення вартості

Ця команда викликає LLM-оцінювання, яке витрачає токени API:
- **Типова вартість**: $0.01-0.05 за оцінювання (з використанням Haiku)
- **Більші diff**: можуть коштувати більше через більшу кількість токенів

## Коли використовувати

- Після значних змін коду перед комітом
- Під час роботи над незнайомими частинами кодової бази
- Для змін, що торкаються коду, критичного для безпеки
- Перед пушем у спільні гілки

## Коли пропускати

- Тривіальні зміни (опечатки, форматування)
- Зміни лише в документації
- Коли ви вже ретельно перевірили вручну
- Під час швидких ітерацій на гілці функції

## Інтеграція з git hooks

Для автоматичного оцінювання на кожному коміті дивіться hook `pre-commit-evaluator.sh`.
Ця команда є ручною альтернативою, коли ви хочете контролювати, коли запускається оцінювання.

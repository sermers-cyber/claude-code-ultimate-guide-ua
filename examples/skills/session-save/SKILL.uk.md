# /session-save

Фіксує поточну сесію у структурованому файлі передачі, щоб ви (або інший екземпляр) могли продовжити з повним контекстом. Створює Markdown-файл із часовою позначкою в `.claude/sessions/`.

## Коли використовувати

- Перед завершенням сесії, яка ще не закінчена
- Перед переходом до іншого завдання
- Перш ніж контекст заповниться на 75% і більше (щоб зберегти важливе)
- У природних проміжних точках довгого завдання (після кожної фази)
- Щоб передати роботу другому екземпляру Claude

## Інструкції

Підготуйте документ передачі з такою структурою:

---

## Передача сесії: [TIMESTAMP]

### Що робилося
[Один абзац: мета, підхід, на якому етапі зараз усе перебуває]

### Файли, змінені в цій сесії
[Перелік кожного створеного, відредагованого або видаленого файлу із зазначенням характеру зміни]

```
path/to/file.ts      - [що змінилося і чому]
path/to/other.ts     - [що змінилося і чому]
```

### Ухвалені ключові рішення
[Архітектурні вибори, прийняті компроміси, відхилені підходи та причини]

- **Рішення**: [Що вирішено]
  - **Обґрунтування**: [Чому]
  - **Відхилені альтернативи**: [Що ще розглядалося]

### Поточний статус
[Де зараз усе перебуває: що працює, що зламано, що в процесі]

- Працює: [...]
- У процесі: [...]
- Відомі проблеми: [...]

### Наступні кроки (по порядку)
[Точні наступні дії для продовження, достатньо конкретні, щоб свіжий контекст міг підхопити роботу без повторного читання всього]

1. [Перша дія]: `path/to/file.ts` - [що зробити]
2. [Друга дія]: [...]
3. [...]

### Контекст для перезавантаження
[Файли, які потрібно прочитати, щоб відновити повне розуміння; тримайте цей список коротким]

- `path/to/key-file.ts`: [чому це важливо]
- `CLAUDE.md`: правила проєкту

### Блокери / відкриті питання
[Усе, що лишається невирішеним і потребує рішення або зовнішніх даних перед продовженням]

- [ ] [Питання або блокер]: [хто/що може його розв'язати]

## Реалізація

Збережіть передачу в `.claude/sessions/handoff-[YYYY-MM-DD-HHMM].md`. Потім виведіть шлях до файлу, щоб користувач знав, де його шукати.

## Шаблон відновлення

Щоб відновити роботу з передачі:

```
/session-resume .claude/sessions/handoff-YYYY-MM-DD-HHMM.md
```

Або вручну: прочитайте файл передачі, а тоді прочитайте файли з розділу «Контекст для перезавантаження» перед продовженням.

## Приклади

### Приклад 1: збереження посеред функції

```
/session-save
```

Claude фіксує:
- Middleware автентифікації рефакторилося (файли: `src/middleware/auth.ts`, `src/middleware/jwt.ts`)
- Рішення: перехід із токенів сесії на JWT (обґрунтування: краще масштабується між сервісами)
- Статус: валідація JWT працює, логіка оновлення в процесі
- Далі: реалізувати `refreshToken()` у `src/services/auth.service.ts`, потім оновити тести

### Приклад 2: збереження під тиском контексту

Коли контекст сягає 70%, виконайте `/session-save` перед `/compact`, щоб зберегти контекст рішень, який компактизація може втратити.

## Примітки

- Тримайте «Контекст для перезавантаження» в межах 5 файлів. Мета: швидке відновлення, а не повторне читання всього.
- «Наступні кроки» мають бути достатньо конкретними, щоб Claude, який починає з нуля, міг виконати крок 1 без уточнювальних питань
- Не зберігайте у передачі вивід інструментів чи фрагменти коду; посилайтеся на шляхи до файлів.

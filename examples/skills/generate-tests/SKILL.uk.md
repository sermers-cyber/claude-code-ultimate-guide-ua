# Генерація тестів

Генерація вичерпних тестів для вказаного коду.

## Інструкції

1. Прочитайте цільовий файл(и)
2. Визначте одиниці, які можна тестувати (функції, класи, методи)
3. Згенеруйте тести відповідно до конвенцій проєкту
4. Забезпечте добре покриття граничних випадків

## Процес генерації тестів

### 1. Аналіз цілі
- Визначте публічні інтерфейси
- Зрозумійте залежності
- Зверніть увагу на граничні випадки й межі

### 2. Визначення тестового фреймворку
Перевірте наявність:
- `jest.config.js` → Jest
- `vitest.config.ts` → Vitest
- `pytest.ini` → pytest
- `mocha` у package.json → Mocha

### 3. Генерація тестів
Дотримуйтеся конвенцій виявленого фреймворку.

## Категорії тестів

### Щасливий шлях
Звичайна очікувана поведінка з коректними вхідними даними.

### Граничні випадки
- Порожні вхідні дані
- Значення null/undefined
- Граничні значення (0, -1, MAX_INT)
- Один елемент проти кількох

### Випадки помилок
- Некоректні типи вхідних даних
- Відсутні обов'язкові параметри
- Збої мережі/вводу-виводу
- Сценарії тайм-ауту

### Точки інтеграції
- Взаємодія з базою даних
- Виклики зовнішніх API
- Операції з файловою системою

## Формат виводу

```typescript
describe('[ComponentName]', () => {
  describe('[methodName]', () => {
    // Happy path
    it('should [expected behavior] when [condition]', () => {
      // Arrange
      // Act
      // Assert
    });

    // Edge cases
    it('should handle empty input', () => {});
    it('should handle null values', () => {});

    // Error cases
    it('should throw when [invalid condition]', () => {});
  });
});
```

## Конвенції

- Одна перевірка на тест (коли це практично)
- Описові назви тестів
- Патерн AAA (Arrange-Act-Assert)
- Жодної взаємозалежності тестів
- Мокайте зовнішні залежності

## Використання

```
/generate-tests src/utils/calculator.ts
/generate-tests src/services/
```

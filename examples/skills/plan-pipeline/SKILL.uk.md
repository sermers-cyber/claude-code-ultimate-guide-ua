# Оркестратор конвеєра планування

Оркеструє повний конвеєр від плану до виконання. Може запускати весь конвеєр або один ізольований етап.

## Етапи

| Етап | Skill | Призначення |
|-------|-------|---------|
| 1 | `/plan-pipeline:ceo-review` | Поставити під сумнів бриф, зафіксувати напрям продукту |
| 2 | `/plan-pipeline:eng-review` | Зафіксувати архітектуру, діаграми та матрицю тестів |
| 3 | `/plan-pipeline:start` | 5-фазове планування: PRD, дослідження, ADR, список завдань |
| 4 | `/plan-pipeline:validate` | 2-шарова валідація до написання будь-якого коду |
| 5 | `/plan-pipeline:execute` | Ізоляція worktree, паралельні агенти, quality gate, PR |

## Використання

```
/plan-pipeline                     # full pipeline, asks for context
/plan-pipeline --from=start        # skip gates, start from planning phase
/plan-pipeline --from=validate     # validate an existing plan
/plan-pipeline --from=execute      # execute a validated plan
```

## Коли використовувати кожен етап

**ceo-review**: використовуйте перед будь-якою суттєвою функцією, коли напрям не зафіксовано. Особливо цінний, коли запит конкретний (конкретика сигналізує про згорнутий простір рішень).

**eng-review**: використовуйте після фіксації напряму. Обов'язковий для функцій з асинхронними компонентами, зовнішніми залежностями або багатокроковими потоками.

**start**: використовуйте для будь-якої нетривіальної функції, що зачіпає понад 2 файли або передбачає архітектурні рішення.

**validate**: завжди перед execute. Вартість валідації мізерна порівняно з вартістю виявлення проблем посеред виконання.

**execute**: після того, як validate підтвердить, що всі проблеми розв'язано.

## Робочий процес

1. **Зібрати контекст**: що ми будуємо і з якого етапу починаємо?
2. **ceo-review**: гейт напряму продукту (можна пропустити через `--from=eng-review` або пізніше)
3. **eng-review**: гейт архітектури (можна пропустити через `--from=start` або пізніше)
4. **КОНТРОЛЬНА ТОЧКА**: попросіть користувача підтвердити напрям і архітектуру перед плануванням
5. **start**: виконайте 5-фазове планування, створіть `docs/plans/plan-{name}.md`
6. **КОНТРОЛЬНА ТОЧКА**: покажіть план на розгляд перед валідацією
7. **validate**: 2-шарова валідація (структурна + агенти-спеціалісти)
8. **execute**: ізоляція worktree -> паралельні агенти -> quality gate -> PR

## Граф залежностей

```
   ceo-review
        |
   eng-review
        |
      start
        |
    validate
        |
    execute
```

## Примітки

Кожен етап записує свій результат на диск до початку наступного етапу. Якщо конвеєр перервано, відновіть його через `--from=<stage>` із правильною назвою етапу. Усі рішення фіксуються в `docs/plans/plan-{name}.md` і відповідних ADR у `docs/adr/`.

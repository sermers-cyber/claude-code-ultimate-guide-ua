# Правила розбору CHANGELOG

Як витягувати й категоризувати записи з `CHANGELOG.md` для генерації контенту для соцмереж.

## Формат CHANGELOG

Проєкт дотримується [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

```
## [Unreleased]

## [X.Y.Z] - YYYY-MM-DD

### Added
- **Title**: Description
  - Sub-detail 1
  - Sub-detail 2

### Changed
- **Title**: Description

### Fixed
- **Title**: Description

---
(horizontal rule separates grouped entries within same version)
```

## Методи витягу

### За версією (`/guide-recap v3.20.5`)

1. Прочитайте CHANGELOG.md
2. Знайдіть рядок, що збігається з `## [3.20.5]`
3. Витягніть усе до наступного рядка `## [`
4. Розберіть усі розділи `### Added/Changed/Fixed`

### Остання (`/guide-recap latest`)

1. Прочитайте CHANGELOG.md
2. Пропустіть `## [Unreleased]`
3. Витягніть перший блок `## [X.Y.Z]` (= остання випущена версія)

### За тижнем (`/guide-recap week` або `/guide-recap week 2026-01-27`)

1. Визначте діапазон дат:
   - `week` без дати: понеділок поточного тижня -> сьогодні
   - `week YYYY-MM-DD`: той понеділок -> наступна неділя
2. Прочитайте CHANGELOG.md
3. Зберіть усі записи `## [X.Y.Z] - YYYY-MM-DD`, дата яких потрапляє в діапазон
4. Об'єднайте всі записи з різних версій

## Структура запису

Кожен маркер верхнього рівня під `### Added/Changed/Fixed` є одним **записом**. Розберіть:

| Поле | Джерело | Приклад |
|-------|--------|---------|
| `title` | Жирний текст після `- **` | `Visual Reference` |
| `description` | Текст після `:` або `--` у тому ж рядку | `4 new high-value ASCII diagrams (16 -> 20 total)` |
| `sub_items` | Маркери з відступом нижче | Список рядків із деталями |
| `section` | Батьківський заголовок `###` | `Added`, `Changed`, `Fixed` |
| `files` | Імена файлів/шляхи в описі | `guide/ultimate-guide.md`, `machine-readable/reference.yaml` |
| `source` | URL або названі посилання | `Pat Cullen's Final Review Gist` |
| `metrics` | Числа в описі | `227 -> 257`, `+522 lines`, `4 new` |
| `score` | Оцінка, якщо є | `Score: 4/5` |

## Класифікація за категоріями

Кожен запис отримує рівно одну категорію з вагою:

| Категорія | Вага | Патерн |
|----------|--------|---------|
| `NEW_CONTENT` | 3 | Нові розділи посібника, нові файли, нові діаграми, нові питання вікторини |
| `GROWTH_METRIC` | 2 | Зростання кількості рядків, кількості шаблонів, зміни кількості питань вікторини |
| `RESEARCH` | 1 | Оцінювання ресурсів, інтеграції зовнішніх джерел |
| `FIX` | 1 | Виправлення помилок, корективи, покращення точності |
| `MAINTENANCE` | 0 | Оновлення README, оновлення бейджів, синхронізація лічильників, синхронізація лендингу |

### Правила класифікації

1. Якщо запис створює новий файл `.md` або новий розділ -> `NEW_CONTENT`
2. Якщо запис містить `-> ` із числами (зростання) -> `GROWTH_METRIC`
3. Якщо запис посилається на зовнішнє джерело з оцінкою -> `RESEARCH`
4. Якщо запис під `### Fixed` -> `FIX`
5. Якщо запис лише оновлює лічильники, бейджі або синхронізацію -> `MAINTENANCE`
6. Якщо запис має підпункти зі змістовним наповненням -> підвищте на один рівень
7. У неоднозначних випадках обирайте категорію з вищою вагою

### Приклади

```
"4 new ASCII diagrams (16 -> 20)"           -> NEW_CONTENT (new diagrams)
"30 New Quiz Questions (227 -> 257)"        -> NEW_CONTENT (new questions)
"Quiz badge updated (227 -> 257)"           -> MAINTENANCE (badge sync)
"Guide line count: 15,771 -> 16,293"        -> GROWTH_METRIC (growth)
"Score: 4/5 - Docker Sandboxes"             -> RESEARCH (evaluation)
"Fixed 14 -> 15 categories in landing"      -> FIX (correction)
"README.md: Added Visual Reference to table" -> MAINTENANCE (nav update)
```

## Алгоритм оцінювання

Для кожного запису обчисліть:

```
score = (category_weight * 3)
      + (has_number * 2)
      + (named_source * 1)
      + (new_file * 1)
      + (min(impact_files, 3))
      + (breaking * 2)
```

| Чинник | Значення | Виявлення |
|--------|-------|-----------|
| `category_weight` | 0-3 | З таблиці категорій вище |
| `has_number` | 0 або 1 | Запис містить числову зміну (`N -> M`, `+N lines`, `N new`) |
| `named_source` | 0 або 1 | Запис вказує людину чи зовнішнє джерело |
| `new_file` | 0 або 1 | Запис згадує створення нового файлу (`NEW`, новий `.md`) |
| `impact_files` | 0-3 | Кількість різних згаданих файлів (максимум 3) |
| `breaking` | 0 або 1 | Запис під `### Breaking` або згадує несумісну зміну |

### Інтерпретація оцінки

| Оцінка | Дія |
|-------|--------|
| 10+ | Головний акцент (рядок-гачок) |
| 6-9 | Другорядний акцент (маркер) |
| 3-5 | Додати, якщо вистачає місця |
| 0-2 | Пропустити (шум від супроводу) |

Оберіть 3-4 записи з найвищими оцінками. Якщо всі оцінки < 3, позначте як «no social content recommended».

## Правила агрегації за тиждень

Під час генерації для тижня з кількома версіями:

1. Оцініть усі записи з усіх версій у діапазоні дат
2. Усуньте дублікати: якщо та сама тема з'являється у кількох версіях, залиште запис із найвищою оцінкою
3. Додайте до виводу тижня префікс із кількістю версій: `X releases this week`
4. Використовуйте діапазон дат у заголовку, а не номери окремих версій

# agent-rationale

Записує коротке обґрунтування кожного hunk, який ви змінили, у git note до коміту, щоб рецензент читав ваші причини поруч із кодом, а не відновлював їх. Нотатка прив'язується до hunk за хешем його доданих рядків; якщо hunk згодом зміниться, `show` повторно прив'язує нотатку за текстом анотованого рядка, коли цей текст трапляється рівно один раз серед доданих рядків коміту для цього файлу, а в іншому разі позначає нотатку як застарілу (stale), а не вгадує.

Це шаблон із [Claude Code Ultimate Guide](https://cc.bruniaux.com/guide/), продемонстрований власними тестами, а не виміряне покращення якості рецензування.

## Воркфлоу

1. **Спершу закомітьте.** Нотатки прикріплюються до коміту. Закомітьте зміну, яку хочете пояснити. Готово, коли `git log -1` її показує.

2. **Одна нотатка на кожен hunk, до якого рецензент матиме питання.** Для кожного такого hunk виберіть один рядок усередині нього (номер рядка в закомітеній версії файлу) і запишіть:

   ```bash
   python3 -I ${CLAUDE_SKILL_DIR}/scripts/rationale.py add --file src/cart.py --line 42 \
     --intent "Sum prices, not item objects" \
     --rejected "Give Item an __add__ method" \
     --risk "Items without a price attribute now raise AttributeError" \
     --evidence "tests/test_cart.py::test_total_uses_price" \
     --open-question "unknown"
   ```

   - `--intent` обов'язковий. Напишіть, навіщо потрібна зміна, а не що вона робить рядок за рядком.
   - `--rejected`: альтернатива, яку ви розглядали, і чому ви її не обрали.
   - `--risk`: що це може зламати і для кого.
   - `--evidence`: тест, команда або вивід, що підтверджує зміну. Напишіть `unknown`, а не вигадуйте.
   - `--open-question`: що ви не змогли вирішити й хочете, щоб рецензент відповів. `unknown` є допустимою відповіддю для будь-якого поля, крім intent.

   Готово, коли команда друкує `rationale recorded`. Рядок поза змінами коміту відхиляється; видалені рядки й бінарні файли анотувати не можна, тому виберіть сусідній доданий рядок. Шляхи можна вказувати з будь-якого каталогу, а зберігаються вони відносно кореня репозиторію.

3. **Перевірте, що побачить рецензент.**

   ```bash
   python3 -I ${CLAUDE_SKILL_DIR}/scripts/rationale.py show
   ```

   Кожна нотатка має стан `[anchored]`, `[reanchored]` (hunk змінився, але анотований рядок усе ще на місці) або `[stale]` (анотованого рядка немає або його текст більше не унікальний; перевірте ще раз, перш ніж довіряти нотатці). Готово, коли кожна написана вами нотатка показана як anchored.

## Збереження нотаток через amend і rebase

Git переносить нотатки під час `git commit --amend` і `git rebase` лише тоді, коли йому про це сказати. Один раз для репозиторію:

```bash
git config notes.rewriteRef refs/notes/rationale
```

Локальний `git merge --squash` створив коміт без нотатки в тесті цього посібника; squash через кнопку merge на forge не тестувався. Нотатки за замовчуванням не пушаться: `git push origin refs/notes/rationale`.

## Правила

- Пишіть нотатку з того, що ви реально зробили й перевірили. Обґрунтування є твердженням, яке рецензент перевірить, а не доказом саме по собі.
- Не кладіть у нотатку секрети, облікові дані чи дані клієнтів: нотатки пушаться разом із refs репозиторію.
- Нотатки людей тримайте під іншим notes ref: `refs/notes/rationale` містить один документ agent-rationale на коміт, а `show` відмовляється працювати з нотаткою, яку не писав сам.

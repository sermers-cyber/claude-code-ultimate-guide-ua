# Асистент рефакторингу SOLID

Проаналізуйте код на порушення SOLID і запропонуйте цільові покращення.

## Призначення

Виявляти можливості рефакторингу на основі:
- Порушень принципів SOLID
- Code smells та антипатернів
- Метрик складності
- Виявлення дублювання

## Інструкції

### Крок 1: Аналіз обсягу

Визначте обсяг рефакторингу за введенням користувача:
- Один файл: глибокий аналіз
- Каталог: виявлення патернів між файлами
- Функція/клас: сфокусовані пропозиції щодо винесення

```bash
# Get file/directory stats
if [ -f "$TARGET" ]; then
  wc -l "$TARGET"
  echo "Single file analysis"
elif [ -d "$TARGET" ]; then
  find "$TARGET" -type f \( -name "*.ts" -o -name "*.js" -o -name "*.py" \) | wc -l
  echo "Directory analysis"
fi
```

### Крок 2: Виявлення порушень SOLID

#### S - single responsibility (єдина відповідальність)

Шукайте:
- Файли > 300 рядків
- Функції > 50 рядків
- Класи з > 10 методів
- Змішані відповідальності (дані + UI + бізнес-логіка)

```bash
# Find large files
find . -name "*.{ts,js,py}" -exec wc -l {} + 2>/dev/null | sort -rn | head -10

# Functions with high line count (approximate)
grep -rn "function\|def \|fn " --include="*.{ts,js,py,rs}" . | head -20
```

#### O - open/closed principle (принцип відкритості/закритості)

Шукайте:
- Оператори switch/case за типами
- Повторювані перевірки типів через if/else
- Пряме змінювання замість розширення

#### L - liskov substitution (принцип підстановки Лісков)

Шукайте:
- Перевизначені методи, що кидають "not implemented"
- Перевірки типів перед викликами методів
- Порожні перевизначення методів

#### I - interface segregation (розділення інтерфейсів)

Шукайте:
- Великі інтерфейси (> 10 методів)
- Класи, що реалізують невикористані методи інтерфейсу
- «Жирні» сервісні класи

#### D - dependency inversion (інверсія залежностей)

Шукайте:
- Пряме створення залежностей (`new Service()`)
- Захардкоджені посилання на класи
- Відсутня ін'єкція залежностей

### Крок 3: Code smells

```bash
# Duplication patterns
grep -rn --include="*.{ts,js,py}" . 2>/dev/null | \
  awk -F: '{print $3}' | sort | uniq -c | sort -rn | head -10

# Long parameter lists (> 4 params)
grep -rn "function.*,.*,.*,.*," --include="*.{ts,js}" . 2>/dev/null | head -10

# Deep nesting (4+ levels)
grep -rn "^\s\{16,\}" --include="*.{ts,js,py}" . 2>/dev/null | head -10
```

### Крок 4: Оцінка складності

Для кожної знайденої проблеми оцініть:
- **Вплив**: Скільки коду зачеплено?
- **Ризик**: Що може зламатися?
- **Зусилля**: Скільки рядків змінити, які тести потрібні?

## Чекліст безпеки рефакторингу

Перед застосуванням пропозицій:

- [ ] Для зачепленого коду існують тести
- [ ] Створено feature-гілку
- [ ] Поточний стан закомічено
- [ ] Застосовуйте по одному рефакторингу за раз
- [ ] Запускайте тести після кожної зміни
- [ ] Перегляньте diff перед комітом

## Використання

**Проаналізувати конкретний файл:**
```
/refactor src/services/user.ts
```

**Проаналізувати каталог:**
```
/refactor src/api/
```

**Сфокусуватися на конкретному принципі:**
```
/refactor --focus=srp src/services/
```

**З порогом складності:**
```
/refactor --threshold=high
```

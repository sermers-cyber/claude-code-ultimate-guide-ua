# Етап 3 доповіді: Concepts

Будує вичерпний каталог усіх концепцій, які можна виявити у вихідному матеріалі. Кожну концепцію нумеровано, категоризовано й оцінено за потенціалом для доповіді.

## Коли використовувати цей skill

- Після етапу 1 (і етапу 2 у режимі REX)
- Перед етапом 4 (Position потребує каталогу концепцій)
- Коли потрібен структурований перелік доступного перед вибором ракурсу

## Що робить цей skill

1. **Читає підсумок**: завантажує `{slug}-summary.md`
2. **Читає хронологію** (якщо є): збагачує оцінювання перевіреними датами
3. **Витягує концепції**: повне сканування вихідного матеріалу
4. **Категоризує**: відносить кожну концепцію до доменної категорії
5. **Оцінює**: HIGH / MEDIUM / LOW за потенціалом для доповіді
6. **Необов'язкове збагачення з репозиторію**: якщо задано repo_path, аналізує концепції конфігурації ШІ
7. **Записує файли виводу**

## Вхідні дані

- `talks/{YYYY}-{slug}-summary.md` (обов'язково)
- `talks/{YYYY}-{slug}-timeline.md` (необов'язково, збагачує концепції REX)
- `repo_path` (необов'язково, для витягу концепцій конфігурації/інфраструктури)

## Вивід

- `talks/{YYYY}-{slug}-concepts.md` (основний каталог)
- `talks/{YYYY}-{slug}-concepts-enriched.md` (якщо задано repo_path)

## Критерії оцінювання

### HIGH: сильний потенціал
- Можна показати наживо або на скриншоті
- Контрінтуїтивна або дивовижна (викликає реакцію)
- Пов'язана з перевірюваними числами
- Конкретна й дієва (пояснюється за 30 секунд)
- Вирізняє доповідь з-поміж інших на ту саму тему

### MEDIUM: помірний потенціал
- Корисна, але очікувана (не дивує)
- Бракує конкретних доказів чи чисел
- Надто специфічна для одного контексту
- Потребує надто багато пояснень для 30-хвилинної доповіді

### LOW: слабкий потенціал
- Надто абстрактна або філософська без конкретного підґрунтя
- Уже широко висвітлена іншими доповідачами
- Вимагає специфічної технічної підготовки
- Важко проілюструвати на слайді

**Дисципліна оцінювання**: не більше 30% HIGH. Якщо все HIGH, то нічого не HIGH.

## Стандартні категорії

| Категорія | Опис |
|-----------|------|
| **Architecture** | Технічні рішення, стек, структурні патерни |
| **Tooling** | Інструменти, воркфлоу, автоматизації |
| **Philosophy** | Принципи, мислення, підходи |
| **Workflow** | Робочі процеси, звички |
| **Knowledge Transfer** | Онбординг, команда, обмін знаннями |
| **Problems** | Зустрінуті перешкоди, компроміси |
| **Open Source** | Внески, обмін, спільнота |
| **AI Config** | Конфігурація ШІ, профілі, наповнення знаннями |
| **AI Infrastructure** | Агенти, skills, hooks, команди |
| **AI Quality** | Рев'ю, тести, антипатерни |
| **AI Security** | Hooks безпеки, запобіжники |
| **Optimization** | Продуктивність, зменшення вартості/токенів |

Адаптуйте або створіть категорії, якщо доповідь має специфічні для домену напрями.

## Формат виводу

### concepts.md

```markdown
# Key Concepts: {provisional title}

**Date**: {date}
**Source**: {source path} x Summary x Timeline (if available)

---

## Concept table

| # | Concept | Category | Short description | Talk potential |
|---|---------|----------|------------------|----------------|
| 1 | **{Concept name}** | {Category} | {1-2 concrete sentences} | HIGH / MEDIUM / LOW |
...

---

## Category breakdown

| Category | Count | HIGH concepts | Examples |
|----------|-------|---------------|---------|
| {category} | {n} | {n} | {examples} |
...
| **TOTAL** | **{N}** | **{N HIGH}** | |

---

## Recommendations for positioning

{3-5 sentences on concept clusters that could form the talk's acts.
Which HIGH concepts reinforce each other? What narrative arc is emerging?}
```

### concepts-enriched.md (якщо є репозиторій)

Та сама структура, але з фокусом на тому, що розкриває аналіз репозиторію:
- Спеціалізовані агенти (кількість, розмір, ролі)
- Skills, що викликаються (каталог, охоплені домени)
- Системні hooks (події, логіка)
- Модульна конфігурація (профілі, модулі, конвеєр)
- Специфічні для проєкту патерни коду

Для кожної збагаченої концепції вкажіть:
- **Точне джерело**: файл і приблизний рядок
- **Демонстрованість**: так/ні (чи можна показати на слайді або наживо?)

## Антипатерни

- Надто дрібні концепції (одна функція = щонайбільше одна концепція)
- Оцінювання HIGH за замовчуванням (будьте вибірковими)
- Пропуск концепцій LOW (вони корисні в позиціонуванні як «ракурси, яких слід уникати»)
- Дублювання дуже схожих концепцій (замість цього зливайте їх)
- Аналіз коду репозиторію, якщо репозиторій недоступний

## Контрольний список валідації

- [ ] Визначено щонайменше 15 концепцій (20+ для REX із репозиторієм)
- [ ] Кожна концепція має конкретний опис в 1-2 речення
- [ ] Оцінки відкалібровано (не все HIGH, не все LOW)
- [ ] Категорії охоплюють теми з підсумку
- [ ] Є рекомендації щодо позиціонування
- [ ] Файли збережено за правильними шляхами

## Поради

- З каталогу концепцій черпає етап 4 (Position); що він багатший, то кращий вибір ракурсів
- Концепції LOW цінні: вони окреслюють межі того, що НЕ слід ставити в доповідь
- Якщо дві концепції здаються дуже схожими, зливайте їх (менший, чіткіший список краще за довгий розбавлений)

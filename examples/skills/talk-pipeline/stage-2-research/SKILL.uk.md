# Етап 2 доповіді: Research (лише режим REX)

Будує git-докази для доповіді REX. Зіставляє історію git, CHANGELOG і підсумок етапу 1, щоб отримати перевірену хронологію й аналіз швидкості.

**Автоматично пропускається в режимі `--concept`.** Запускається лише тоді, коли вихідний матеріал є REX з доступом до git-репозиторію.

## Коли використовувати цей skill

- Після етапу 1 (Extract) під час побудови доповіді REX
- Коли маєте доступ до git-репозиторію проєкту
- Щоб звірити метрики з вихідного матеріалу з реальними даними git

## Що робить цей skill

1. **Читає підсумок**: з'ясовує період і теми з етапу 1
2. **Git-археологія**: витягує метрики швидкості (лише команди читання)
3. **Аналіз changelog**: сканує релізи, функції, задокументовані метрики
4. **Перехресні перевірки**: вирівнює git, CHANGELOG і підсумок
5. **Будує хронологію**: перевірені дати, а не оцінки
6. **Записує 3 файли виводу**

## Вхідні дані

- `talks/{YYYY}-{slug}-summary.md` (з етапу 1, обов'язково)
- `repo_path`: абсолютний шлях до git-репозиторію
- Необов'язково: шлях до CHANGELOG, якщо він відрізняється від `{repo_path}/CHANGELOG.md`

## Вивід

Три файли:
- `talks/{YYYY}-{slug}-git-archaeology.md`
- `talks/{YYYY}-{slug}-changelog-analysis.md`
- `talks/{YYYY}-{slug}-timeline.md`

## Команди git (лише читання)

```bash
# Commits by month
git -C {repo_path} log --pretty=format:"%Y-%m" | sort | uniq -c

# Commits by contributor
git -C {repo_path} shortlog -sn --no-merges

# First and last date
git -C {repo_path} log --pretty=format:"%ad" --date=short | tail -1
git -C {repo_path} log --pretty=format:"%ad" --date=short | head -1

# Merged PRs (if merge commit convention)
git -C {repo_path} log --merges --oneline | wc -l

# Tags (releases)
git -C {repo_path} tag --sort=version:refname

# Velocity peak (busiest months)
git -C {repo_path} log --pretty=format:"%Y-%m" | sort | uniq -c | sort -rn | head -5
```

## Ключові правила

- **Лише читання**: жодних git-команд, що змінюють стан репозиторію
- **Перевіряйте, перш ніж стверджувати**: дата, якої немає в git = «неперевірена»
- **Перехресна перевірка**: позначайте розбіжності між джерелами, не обирайте жодне довільно
- **Деталізація**: щонайменше помісячно; потижнево, якщо період короткий (< 2 місяців)

## Антипатерни

- Запуск git-команд, що змінюють репозиторій
- Оцінка дат замість їх перевірки в git
- Округлення метрик без позначки про це
- Мовчазне злиття суперечливих даних із різних джерел
- Пропуск тихих періодів (плато теж розповідають історію)

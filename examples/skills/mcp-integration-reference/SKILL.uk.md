# Патерн довідника для MCP-інтеграції

> Це шаблонний skill. Він показує, як структурувати skill, що обгортає MCP-сервер. Замініть `sentry` на назву вашого MCP-сервера й адаптуйте довідковий файл `references/sentry-mcp.md`.

## Яку проблему розв'язує цей патерн

Коли skill викликає MCP-сервер без попереднього контексту, Claude вгадує синтаксис запитів. Для простих викликів це працює, але ламається на всьому з неочевидною поведінкою: особливості пагінації, обов'язкові комбінації параметрів, ліміти запитів чи тонкі обмеження формату.

Розв'язання: файл `references/<mcp-name>.md`, що фіксує всі підводні камені. Skill читає цей файл перед будь-яким викликом MCP. Жодного вгадування.

До довідкового файлу потрапляють три типи вмісту:
1. Семантика параметрів, що відрізняється від того, що натякає назва інструмента
2. Відомі патерни помилок та їхні першопричини
3. Робочі приклади запитів (копіюй-вставляй, без роздумів)

---

## Крок 1: Прочитати довідковий файл MCP

**Перш ніж робити щось інше**, прочитайте повний довідник MCP:

```
Read: references/sentry-mcp.md
```

Цей файл містить синтаксис запитів, відомі підводні камені та робочі приклади для Sentry MCP. Не пропускайте цей крок.

---

## Крок 2: Зібрати від користувача межі завдання

Запитайте користувача:

- **Часовий діапазон**: останні 24 години? 7 днів? Власний діапазон?
- **Середовища**: `production`, `staging` чи обидва?
- **Проєкти**: усі чи конкретні? (За замовчуванням: усі)

Якщо користувач каже «просто запусти зі стандартними значеннями», використовуйте:
- Часовий діапазон: останні 72 години
- Середовище: лише `production`
- Проєкти: усі

---

## Крок 3: Отримати дані про помилки

Використовуючи знання про інструменти з Кроку 1, отримайте:

1. **Список issues**: активні невирішені issues, упорядковані за частотою
2. **Деталі подій**: повні стек-трейси для топ-5 issues за кількістю подій

Обмежте результати 50 issues. Якщо їх більше, зазначте кількість і зосередьтеся на елементах із найвищою частотою.

---

## Крок 4: Згрупувати й проаналізувати

Групуйте issues за першопричиною, а не за повідомленням про помилку. Дві issues із різними повідомленнями можуть мати спільну першопричину (спільний шлях коду, та сама зовнішня залежність, та сама конфігурація).

Для кожної групи:
- Кількість issues у групі
- Найраніша дата першої появи
- Кількість уражених користувачів (якщо доступно)
- Найімовірніша першопричина (одне речення, на основі доказів)
- Релевантні шляхи файлів зі стек-трейсу

---

## Крок 5: Згенерувати звіт

Виведіть markdown-звіт із такою структурою:

```markdown
# Error Report: [Project or Scope]

**Period**: [start] to [end]
**Environment**: [env]
**Total active issues**: [N]

## Summary

[2-3 sentences: what is the overall health picture?]

## Issue Groups

### Group 1: [Root Cause Label]

| Attribute      | Value                    |
|----------------|--------------------------|
| Issues         | N                        |
| Total events   | N                        |
| Affected users | N                        |
| First seen     | YYYY-MM-DD               |
| Key file       | path/to/file.py:line     |

**Root cause**: [One paragraph. Specific, evidence-based. Point to file and line.]

**Suggested investigation**: [One or two concrete next steps.]

---

[Repeat for each group]

## Out of Scope

[List issues explicitly excluded and why. Example: "404s on /static/ excluded - expected behavior for SPA asset versioning."]
```

---

## Правила меж

- Цей skill виявляє й описує issues. Він не змінює код і не створює тікети.
- Якщо issue неоднозначна, позначте її як «needs investigation», а не вгадуйте.
- Не включайте інформаційні логи чи попередження, якщо вони безпосередньо не корелюють із помилками.

---

## Адаптація цього шаблону

Щоб зробити форк цього skill для іншого MCP:

1. Скопіюйте цю директорію: `cp -r examples/skills/mcp-integration-reference examples/skills/<your-skill>/`
2. Перейменуйте `references/sentry-mcp.md` на `references/<your-mcp>.md`
3. Замініть вміст довідкового файлу підводними каменями вашого MCP
4. Оновіть `allowed-tools` у frontmatter відповідно до назв інструментів вашого MCP
5. Скоригуйте кроки аналізу відповідно до вашої предметної області даних

Патерн працює для будь-якого MCP з неочевидною поведінкою запитів: Datadog, PagerDuty, Linear, Jira, Posthog, Mixpanel тощо.

# Оптимізатор продуктивності

Проаналізуйте й запропонуйте покращення продуктивності для коду, запитів чи систем.

## Призначення

Виявити можливості оптимізації:
- Вузькі місця продуктивності під час виконання
- Проблеми з використанням пам'яті
- Неефективність запитів до бази даних
- Проблеми з розміром бандла
- Складність алгоритмів

## Інструкції

### Крок 1: Визначення обсягу

Визначте ціль оптимізації:
- **Функція**: продуктивність однієї функції
- **Модуль**: пов'язані функції/класи
- **Запит**: оптимізація запиту до бази даних
- **Бандл**: аналіз фронтенд-бандла
- **Система**: оптимізація на рівні архітектури

### Крок 2: Аналіз продуктивності

#### Аналіз під час виконання

```bash
# Find potentially slow patterns
grep -rn "forEach\|\.map\|\.filter\|\.reduce" --include="*.{ts,js}" . | head -20

# Find nested loops (O(n²) potential)
grep -rn "for.*for\|\.forEach.*\.forEach\|\.map.*\.map" --include="*.{ts,js}" . | head -10

# Find sync operations that could be async
grep -rn "readFileSync\|writeFileSync\|execSync" --include="*.{ts,js}" . | head -10
```

#### Аналіз пам'яті

```bash
# Large array operations
grep -rn "new Array\|Array\.from\|\.concat\|spread" --include="*.{ts,js}" . | head -10

# Potential memory leaks (event listeners, intervals)
grep -rn "addEventListener\|setInterval\|setTimeout" --include="*.{ts,js}" . | head -10
```

#### Аналіз запитів до бази даних

```bash
# N+1 query patterns
grep -rn "await.*find\|await.*query" --include="*.{ts,js}" . | head -15

# Missing indexes hints
grep -rn "WHERE\|ORDER BY\|GROUP BY" --include="*.{ts,js,sql}" . | head -15
```

#### Аналіз бандла

```bash
# Check bundle size (if applicable)
[ -f "package.json" ] && npm run build 2>/dev/null && ls -lh dist/*.js 2>/dev/null

# Large dependencies
[ -f "package.json" ] && cat package.json | jq '.dependencies | keys[]' | head -20
```

**Оптимізований код**:
```typescript
// O(n) - Map lookup
const permMap = new Map(permissions.map(p => [p.userId, p]));

  const perm = permMap.get(user.id);

});
```

## Поширені патерни

### Операції з масивами

| Патерн | Проблема | Виправлення |
|---------|-------|-----|
| `arr.filter().map()` | Дві ітерації | Один `reduce()` або `flatMap()` |
| `arr.find()` у циклі | O(n²) | Спершу побудувати Map/Set |
| `[...arr1, ...arr2]` | Виділення пам'яті | `arr1.concat(arr2)` або push |

### База даних

| Патерн | Проблема | Виправлення |
|---------|-------|-----|
| Цикл із await | Запити N+1 | Пакетний запит із `IN` |
| `SELECT *` | Надмірне отримання | Вибирати лише потрібні стовпці |
| Немає індексу для WHERE | Повне сканування таблиці | Додати складений індекс |

### React/фронтенд

| Патерн | Проблема | Виправлення |
|---------|-------|-----|
| Вбудовані функції в JSX | Повторні рендери | `useCallback` |
| Рендеринг великого списку | Перевантаження DOM | Віртуалізація |
| Неоптимізовані зображення | Повільний LCP | Next/Image, lazy loading |

### Node.js

| Патерн | Проблема | Виправлення |
|---------|-------|-----|
| Синхронні файлові операції | Блокують event loop | Асинхронні альтернативи |
| JSON.parse великих файлів | Стрибок пам'яті | Потоковий парсер |
| Немає пулу з'єднань | Накладні витрати на з'єднання | Пул із pg-pool тощо |

## Використання

**Проаналізувати конкретний файл:**
```
/optimize src/services/user.ts
```

**Сфокусуватися на конкретній ділянці:**
```
/optimize --queries src/repositories/
/optimize --bundle
/optimize --memory src/workers/
```

**З цільовими метриками:**
```
/optimize --target=100ms src/api/search.ts
```

**Швидке сканування:**
```
/optimize --quick
```

## Примітки

- Вимірювання переважають припущення: профілюйте перед оптимізацією
- Передчасна оптимізація є коренем усього зла (Кнут)
- Зосередьтеся на гарячих шляхах: оптимізуйте те, що виконується часто
- Враховуйте компроміси: швидкість проти читабельності проти підтримуваності

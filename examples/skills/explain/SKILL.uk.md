# Пояснювач коду

Пояснення коду, концепцій або поведінки системи з налаштовуваним рівнем глибини.

## Призначення

Отримуйте зрозумілі пояснення:
- Як працює конкретний код
- Чому використано певні патерни
- Що робить система/модуль
- Архітектурних рішень і компромісів

## Інструкції

### Крок 1: Визначте обсяг

З'ясуйте, що потрібно пояснити:
- **Файл**: структура й призначення всього файлу
- **Функція/метод**: деталі конкретної реалізації
- **Концепція**: архітектурний патерн або проєктне рішення
- **Потік**: як дані/керування рухаються системою

### Крок 2: Оцініть складність

```
Simple (1-2 min read)     → Quick summary, key points only
Standard (3-5 min read)   → Purpose, how it works, key decisions
Deep (10+ min read)       → Full breakdown, alternatives, trade-offs
```

### Крок 3: Зберіть контекст

```bash
# For file explanations
head -50 "$FILE"  # See imports and structure

# For function explanations
grep -A 30 "function $NAME\|def $NAME\|fn $NAME" "$FILE"

# For module explanations
ls -la "$DIR"
cat "$DIR/index.ts" 2>/dev/null || cat "$DIR/__init__.py" 2>/dev/null
```

## Рівні глибини

### Простий (`/explain --simple`)

```markdown
**validateUser()** перевіряє, чи має об'єкт користувача обов'язкові поля
(email, password), і повертає boolean. Для формату email використовує regex.
```

### Стандартний (`/explain` - за замовчуванням)

```markdown
**validateUser(user: User): ValidationResult**

**Призначення**: валідує введені користувачем дані перед операціями з базою даних.

**Потік**:
1. Перевірити наявність обов'язкових полів (email, password)
2. Перевірити формат email через regex
3. Перевірити, що пароль відповідає вимогам (8+ символів, спецсимвол)
4. Повернути { valid: boolean, errors: string[] }

**Використовується в**: signup(), updateProfile()
```

### Глибокий (`/explain --deep`)

```markdown
[Усе зі стандартного рівня, плюс:]

**Проєктні рішення**:
- Повертає ValidationResult замість кидання винятку, щоб дозволити пакетну валідацію
- Regex обрано замість бібліотеки заради нуля залежностей
- Правила паролів налаштовуються через config.ts

**Компроміси**:
- Плюс: швидко, без залежностей
- Мінус: валідація email через regex не відповідає RFC

**Розглянуті альтернативи**:
- Схема Zod: потужніша, але додає 50KB
- Class-validator: краща для декораторів, але сильно орієнтована на ООП
```

## Приклади використання

**Пояснити файл:**
```
/explain src/auth/middleware.ts
```

**Пояснити функцію:**
```
/explain функцію handleWebhook у payments.ts
```

**Пояснити концепцію:**
```
/explain як у нас працює event sourcing
```

**Пояснити з певною глибиною:**
```
/explain --deep потік автентифікації
/explain --simple що робить useCallback
```

**Пояснити для навчання:**
```
/explain --learn патерн repository, який тут використовується
```

# Аудит покриття вікторини: пропозиції нових питань за недавніми змінами

Мета: прочитати, що нещодавно змінилося в посібнику та в самому Claude Code, зіставити з чинною вікториною й запропонувати нові питання для всього, що ще не має покриття. Це робочий процес **лише для пропозицій**: ніколи не додавай питання до чинної вікторини автоматично без перегляду людиною.

## Джерела для читання

1. `CHANGELOG.md` у цьому репозиторії — розділ `[Unreleased]` плюс останні 5-10 випущених записів, щоб побачити, який вміст посібника нещодавно змінився чи додався.
2. `machine-readable/reference.yaml` — індекс тем/розділів посібника (ключі `deep_dive`), щоб знати, що задокументовано і де.
3. `machine-readable/claude-code-releases.yaml` — історія версій самого Claude Code (`latest`, `releases[]`, `breaking_summary`, `milestones`). Зосередься на останніх 10-15 версіях.
4. `guide/core/claude-code-releases.md` — зручна для людини версія того самого, корисна для повного контексту щодо конкретного релізу.

```yaml
---
id: NN-NNN            # category-two-digit, question three-digit
category_id: N         # 1-16
difficulty: junior|intermediate|senior|power
profiles: [junior, senior, power, pm]   # підмножина
correct: a|b|c|d
options:
  a: "..."
  b: "..."
  c: "..."
  d: "..."
doc_reference:
  file: guide/....md   # має існувати в корені репозиторію посібника
  section: "..."
  anchor: '#...'       # необов'язково
official_doc: https://...   # необов'язково
---

Текст питання тут

---

Текст пояснення тут
```

**Пастка YAML**: будь-яке значення опції чи поля, що містить двокрапку (`: `), ОБОВ'ЯЗКОВО візьми в подвійні лапки, інакше frontmatter не розбереться (це двічі ламало збірку під час останнього аудиту вікторини, див. `claudedocs/quiz-audit-2026-07-08/` щодо інциденту).

## Що робити

Якщо `$ARGUMENTS` називає id категорії або slug, обмеж аналіз прогалин лише цією категорією. Якщо `$ARGUMENTS` порожній або `all`, охопи кожну категорію.

Для кожної категорії в межах аналізу:

1. Прочитай `question` і `doc_reference` кожного наявного питання в директорії цієї категорії (лише id і питання, пропускай пояснення, щоб було дешево), щоб знати, що вже покрито.
2. Зіставляй із:
   - Будь-яким записом `[Unreleased]` чи недавнім записом `CHANGELOG.md`, що описує доповнення посібника, релевантне темі цієї категорії.
   - Будь-яким записом `claude-code-releases.yaml` (недавні версії), що описує нову функцію Claude Code, прапорець, зміну значення за замовчуванням чи поведінку, релевантну цій категорії, про яку ще немає питання.
   - Будь-яким ключем `deep_dive` у `reference.yaml` для цієї теми, розділ посібника за яким не має відповідного питання.
3. Підготуй 2-5 НОВИХ питань на категорію, що заповнюють справжню прогалину (не переформулювання наявного питання). Кожне має:
   - Бути нетривіальним (перевіряє розуміння/застосування, а не суху «дрібницю»).
   - Мати рівно 4 правдоподібні варіанти з однією перевірювано правильною відповіддю (перед фіналізацією сам перевір цитований розділ посібника).
   - Посилатися на реальний `doc_reference` (файл, що справді існує в репозиторії посібника, розділ, що справді підтверджує відповідь).
   - Надавати пріоритет недавнім змінам Claude Code (останні 2-3 релізи) і нещодавно доданим розділам посібника перед старішим, уже стабільним вмістом.
4. Однорядкове обґрунтування на питання: яку прогалину воно заповнює і чому саме зараз (напр. "v2.1.202 додав X, жодне питання цього не покриває").

## Вивід

Запиши пропозиції в `claudedocs/quiz-coverage-audit-{сьогоднішня дата}/proposals-new-questions.md`, згруповані за категоріями, у форматі готових до вставлення блоків frontmatter + питання + пояснення за схемою вище, кожен з обґрунтуванням. Не чіпай жодних файлів у `claude-code-ultimate-guide-landing/`. Нічого не коміть і не роби push.

Наприкінці виведи короткий підсумок: проскановані категорії, знайдені прогалини, запропоновані питання за категоріями та будь-яку категорію, де CHANGELOG/релізи згадують щось релевантне, але ти не був достатньо певний, щоб скласти питання (назви тему, а не вгадуй).

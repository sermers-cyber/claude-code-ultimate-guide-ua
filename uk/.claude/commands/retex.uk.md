# Retex - Фіксація засвоєного уроку

**Аргументи**: $ARGUMENTS

Зафіксувати й зберегти засвоєний урок (хибний слід, внесений баг, відкіт, рішення, яке варто переглянути) у memory для майбутніх сесій.

---

## Крок 1: Зібрати git-контекст

Виконай паралельно:

- `rtk git status`
- `rtk git log --oneline -5`
- `git branch --show-current`

---

## Крок 2: Зібрати вхідні дані

**Режим 1 — Прямий** (якщо `$ARGUMENTS` не порожній):

- Використай `$ARGUMENTS` як опис інциденту
- Виведи категорію та першопричину з тексту

**Режим 2 — Інтерактивний** (якщо аргументів немає):

- Використай `AskUserQuestion` із двома питаннями:
  1. "Що сталося?" — варіанти: Хибний слід, Баг скрипта/hook, Відкіт, Рішення в документації, яке варто переглянути, Пастка інструмента/стеку, Інше
  2. "Опиши в 1-3 реченнях: що сталося і що слід було зробити"

---

## Крок 3: Структурувати Retex

Синтезуй із git-контексту й вводу користувача в такому форматі:

| Поле                           | Опис                                                                                                                                                                                                    |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Title**                      | 3-5 слів, іменникова форма (напр.: "Quarto render wrong format")                                                                                                                                        |
| **What happened**              | 1-3 фактичні речення, без оцінок                                                                                                                                                                        |
| **Root cause**                 | Технічна першопричина — НЕ симптом                                                                                                                                                                      |
| **What should have been done** | Правильний підхід, придатний до виконання                                                                                                                                                               |
| **Prevention rule**            | Коротке імперативне правило, що починається з дієслова (напр.: "Завжди використовувати --to whitepaper-typst для PDF")                                                                                  |
| **Tags**                       | 1-4 теги з: `documentation`, `markdown`, `yaml`, `versioning`, `release`, `landing-sync`, `whitepaper`, `template`, `hook`, `script`, `quarto`, `typst`, `writing`, `structure`, `configuration`        |
| **Severity**                   | `critical` (зламана синхронізація/заблокований реліз), `high` (зламана функціональність), `medium` (втрата часу >1 год)                                                                                  |
| **Scope**                      | `project` (специфічно для цього посібника) або `general` (будь-який проєкт документації/Quarto)                                                                                                         |

---

## Крок 4: Обчислити ім'я memory

Формат: `retex-{YYYY-MM-DD}-{slug}`

- Slug = 2-4 слова в kebab-case про першопричину
- Якщо дублікат того ж дня: додай суфікс `-2`, `-3`...
- Приклад: `retex-2026-03-03-quarto-wrong-format`

---

## Крок 5: Записати Retex у memory

Через інструмент Write створи файл `.claude/memories/retex-{slug}.md` з точно таким вмістом:

```
# Retex: {Title}

**Date**: {YYYY-MM-DD} | **Severity**: {severity} | **Scope**: {scope}
**Tags**: {tag1, tag2, tag3}

## What Happened

{фактичний опис}

## Root Cause

{технічний аналіз першопричини}

## What Should Have Been Done

{правильний підхід, придатний до виконання}

## Prevention Rule

> {імперативне правило}

## Context

- Branch: `{current-branch}`
- Files: {ключові задіяні файли, якщо відомі}
- Commit: {короткий хеш, якщо застосовно}
```

---

## Крок 6: Оновити індекс Retex

1. Прочитай `.claude/memories/retex-index.md` (або створи, якщо його немає)
2. Додай новий запис у таблицю:

```markdown
# Retex Index

| Date   | Slug   | Title   | Severity   | Tags   | Scope   |
| ------ | ------ | ------- | ---------- | ------ | ------- |
| {date} | {slug} | {title} | {severity} | {tags} | {scope} |

Total: {N} | Last updated: {date}
```

3. Обмеж до 50 записів (видаляй найстаріші у разі перевищення)
4. Запиши оновлений індекс

---

## Крок 7: Підтвердити

Виведи стислий підсумок:

```
✓ Retex зафіксовано:
  Файл       : .claude/memories/retex-{slug}.md
  Title      : {title}
  Severity   : {severity}
  Prevention : "{prevention rule}"
  Tags       : [{tags}]
```

---

## Крайні випадки

- **Перший retex**: створи `retex-index.md` з нуля (заголовок + перший запис)
- **Немає git-контексту**: пропусти розділ "Context" без помилки
- **Дуже короткі $ARGUMENTS** (<10 символів): перейди в інтерактивний режим

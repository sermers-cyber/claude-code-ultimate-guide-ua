# Оновлення розвідданих про загрози через AgentSec

Охоплення: цей репозиторій посібника та його споживачі AgentSec і лендінг. Цей skill
не змінює глобальну конфігурацію агентів. Його канонічне джерело —
`.claude/skills/update-threat-db/`; перегенеруй проєкцію для Codex командою
`python3 scripts/sync-threat-skill.py --write` від кореня посібника.

## Визначити робочий процес

Прочитай повністю `.claude/commands/update-threat-db.md` від кореня посібника. Він керує
контрактом делегування та перевірками споживачів. Визнач `AGENTSEC_REPO`, якщо задано,
інакше сусідній `../agentsec-triage`. Перевір потрібні файли перед
продовженням. Не підміняй мовчки базу сумісності посібника.

Прочитай повністю `AGENTS.md` визначеного AgentSec і
`.claude/commands/update-threat-db.md`, потім виконай цей робочий процес.
Зберігай непов'язані правки в усіх checkout. Використовуй дату останнього записаного оновлення
до сьогоднішньої дати як вікно дослідження.

## Докази та зміни

Переглянь первинні джерела, перш ніж приймати нові записи. Тримай джерела доказів,
датовані події, точні вхідні дані детекторів і публічний фід як окремі артефакти. Фіксуй
уражені діапазони, виправлені версії та невизначеність лише тоді, коли джерело їх
підтверджує. Дедуплікуй псевдоніми CVE/GHSA. Виправлення зберігай як датовані події.

Додавай потрібний регресійний тест перед кожною прийнятою зміною даних. Розрізняй
`detected`, `partial`, `not_detected` і `not_applicable`; задокументований CVE не
доводить виконуване виявлення. Не запускай шкідливі зразки.

## Дампи IOC від дослідників і приманки в репозиторіях

Звіт про кампанію часто надходить як допис у соцмережі плюс CSV чи gist
індикаторів. Сприймай допис як контекст, а файл індикаторів — як докази,
які слід переглянути рядок за рядком.

- Отримуй файл через API або raw URL у новий скретч-каталог. Ніколи не
  клонуй, не відкривай і не розпаковуй зазначений репозиторій чи архів.
- Зберігай власну впевненість кожного рядка. Хеш, підтверджений запуском у пісочниці, і C2-
  адреса, яку автор позначає на рівні кампанії, — різні твердження.
- Тримай URL репозиторіїв defanged. Записуй статус «живий чи видалений» з датою
  перевірки автором і шлях закоміченого архіву, коли його надано.
- Оцінюй покриття детекторів за тим, де міститься payload. Чистий `SKILL.md` чи файл
  налаштувань нічого не доводить, коли README посилається на архів, закомічений у
  репозиторій, або коли архів лежить під `.claude/`, `.codex/` чи подібною
  директорією агента.
- Перш ніж приймати «нову» кампанію, пошукай в AgentSec назви її родини, завантажувача
  та шкідливого ПЗ. Зріз, про який повідомлено сьогодні, може належати кампанії, розкритій
  місяцями раніше: донаповни цю лінію як датовані події замість початку нової.

Вкажи дослідника в тексті посібника з публічним посиланням на допис або
файл індикаторів.

## Перевірки завершення

1. Пройди бар'єри валідації AgentSec і двічі перегенеруй артефакти без дрейфу.
2. Синхронізуй схвалений публічний фід у посібник і лендінг; перевір побайтову
   рівність і запусти інтеграційні перевірки кожного споживача.
3. Оновлюй базу сумісності посібника та рекомендації для читачів лише після того, як канонічні
   записи пройшли перевірку. Онови changelog кожного зачепленого репозиторію.
4. Виконай `python3 scripts/sync-threat-skill.py --check` після редагування цього skill чи
   його сценаріїв маршрутизації. Перевір обидва маршрути хостів встановленим роутером.
5. Повідом вікно дослідження, прийняті й відкладені записи, обмеження детекторів,
   зміни файлів, результати валідації та стан синхронізації.

Commit, push, тегування та публікація — окремі стани. Дотримуйся меж
дозволів і ліцензій на дані AgentSec; локальне оновлення не дозволяє
публічний реліз. Явно вкажи будь-який незавершений бар'єр.

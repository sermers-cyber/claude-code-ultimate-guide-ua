# Правила розбору CHANGELOG

Як витягувати й класифікувати записи з `CHANGELOG.md` для генерації контенту для соцмереж.

## Формат CHANGELOG

Проєкт дотримується [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

```
## [Unreleased]

## [X.Y.Z] - YYYY-MM-DD

### Added
- **Title**: Description
  - Sub-detail 1
  - Sub-detail 2

### Changed
- **Title**: Description

### Fixed
- **Title**: Description

---
(horizontal rule separates grouped entries within same version)
```

## Методи витягування

### За версією (`/guide-recap v3.20.5`)

1. Прочитай CHANGELOG.md
2. Знайди рядок, що відповідає `## [3.20.5]`
3. Витягни все до наступного рядка `## [`
4. Розбери всі розділи `### Added/Changed/Fixed`

### Остання (`/guide-recap latest`)

1. Прочитай CHANGELOG.md
2. Пропусти `## [Unreleased]`
3. Витягни перший блок `## [X.Y.Z]` (= остання випущена версія)

### За тиждень (`/guide-recap week` або `/guide-recap week 2026-01-27`)

1. Визнач діапазон дат:
   - `week` без дати: понеділок поточного тижня -> сьогодні
   - `week YYYY-MM-DD`: той понеділок -> наступна неділя
2. Прочитай CHANGELOG.md
3. Збери всі записи `## [X.Y.Z] - YYYY-MM-DD`, дата яких потрапляє в діапазон
4. Агрегуй усі записи з різних версій

## Структура запису

Кожен маркований пункт верхнього рівня під `### Added/Changed/Fixed` є одним **записом**. Розбери:

| Поле | Джерело | Приклад |
|------|---------|---------|
| `title` | Жирний текст після `- **` | `Visual Reference` |
| `description` | Текст після `:` або `--` у тому самому рядку | `4 new high-value ASCII diagrams (16 -> 20 total)` |
| `sub_items` | Марковані пункти з відступом нижче | Список рядків з деталями |
| `section` | Батьківський заголовок `###` | `Added`, `Changed`, `Fixed` |
| `files` | Імена файлів/шляхи в описі | `guide/ultimate-guide.md`, `machine-readable/reference.yaml` |
| `source` | URL або іменовані посилання | `Pat Cullen's Final Review Gist` |
| `metrics` | Числа в описі | `227 -> 257`, `+522 lines`, `4 new` |
| `score` | Оцінка, якщо присутня | `Score: 4/5` |

## Класифікація за категоріями

Кожен запис отримує рівно одну категорію з вагою:

| Категорія | Вага | Шаблон |
|-----------|------|--------|
| `NEW_CONTENT` | 3 | Нові розділи посібника, нові файли, нові діаграми, нові питання квізу |
| `GROWTH_METRIC` | 2 | Збільшення кількості рядків, кількість шаблонів, зміни кількості питань квізу |
| `RESEARCH` | 1 | Оцінювання ресурсів, інтеграції зовнішніх джерел |
| `FIX` | 1 | Виправлення помилок, корекції, покращення точності |
| `MAINTENANCE` | 0 | Оновлення README, оновлення бейджів, синхронізація лічильників, синхронізація лендингу |

### Правила класифікації

1. Якщо запис створює новий файл `.md` або новий розділ -> `NEW_CONTENT`
2. Якщо запис містить `-> ` із числами (зростання) -> `GROWTH_METRIC`
3. Якщо запис посилається на зовнішнє джерело з оцінкою -> `RESEARCH`
4. Якщо запис під `### Fixed` -> `FIX`
5. Якщо запис лише оновлює лічильники, бейджі або синхронізацію -> `MAINTENANCE`
6. Якщо запис має підпункти зі значним вмістом -> підвищ на один рівень
7. У неоднозначних випадках віддавай перевагу категорії з вищою вагою

### Приклади

```
"4 new ASCII diagrams (16 -> 20)"           -> NEW_CONTENT (new diagrams)
"30 New Quiz Questions (227 -> 257)"        -> NEW_CONTENT (new questions)
"Quiz badge updated (227 -> 257)"           -> MAINTENANCE (badge sync)
"Guide line count: 15,771 -> 16,293"        -> GROWTH_METRIC (growth)
"Score: 4/5 - Docker Sandboxes"             -> RESEARCH (evaluation)
"Fixed 14 -> 15 categories in landing"      -> FIX (correction)
"README.md: Added Visual Reference to table" -> MAINTENANCE (nav update)
```

## Алгоритм оцінювання

Для кожного запису обчисли:

```
score = (category_weight * 3)
      + (has_number * 2)
      + (named_source * 1)
      + (new_file * 1)
      + (min(impact_files, 3))
      + (breaking * 2)
```

| Чинник | Значення | Виявлення |
|--------|----------|-----------|
| `category_weight` | 0-3 | З таблиці категорій вище |
| `has_number` | 0 або 1 | Запис містить числову зміну (`N -> M`, `+N lines`, `N new`) |
| `named_source` | 0 або 1 | Запис вказує особу або зовнішнє джерело |
| `new_file` | 0 або 1 | Запис згадує створення нового файлу (`NEW`, новий `.md`) |
| `impact_files` | 0-3 | Кількість окремих згаданих файлів (обмежено 3) |
| `breaking` | 0 або 1 | Запис під `### Breaking` або згадує зміну, що ламає сумісність |

### Інтерпретація оцінки

| Оцінка | Дія |
|--------|-----|
| 10+ | Провідна головна подія (рядок-гачок) |
| 6-9 | Другорядна головна подія (маркований пункт) |
| 3-5 | Включити, якщо вистачає місця |
| 0-2 | Пропустити (шум від супроводу) |

Відбери топ-3-4 записи за оцінкою. Якщо всі оцінки < 3, познач як "no social content recommended".

## Правила агрегації за тиждень

Під час генерації за тиждень із кількома версіями:

1. Оціни всі записи з усіх версій у діапазоні дат
2. Усунь дублікати: якщо та сама тема зустрічається в кількох версіях, залиш запис із найвищою оцінкою
3. Додай до виводу за тиждень кількість версій: `X releases this week`
4. Використовуй у заголовку діапазон дат, а не окремі номери версій

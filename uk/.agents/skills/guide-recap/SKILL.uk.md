# Guide Recap

Генерує контент для соціальних мереж із записів CHANGELOG.md. За замовчуванням створює 8 результатів (4 формати x 2 мови).

## Коли використовувати

- Після виконання `/release`, щоб створити соціальні анонси
- Щотижня, щоб підсумувати кілька релізів
- Перед публікацією в LinkedIn, Twitter/X, розсилці чи Slack

## Використання

```
/guide-recap latest              # Latest released version
/guide-recap v3.20.5             # Specific version
/guide-recap week                # Current week (Monday to today)
/guide-recap week 2026-01-27     # Specific week (Monday to Sunday)
```

### Прапорці

| Прапорець | Ефект | За замовчуванням |
|-----------|-------|------------------|
| `--interactive` | Режим із підказками: вибір кута подання, аудиторії, головної події | Вимкнено (автоматична чернетка) |
| `--format=X` | Один формат: `linkedin`, `twitter`, `newsletter`, `slack` | Усі 4 формати |
| `--lang=X` | Одна мова: `fr`, `en` | Обидві FR + EN |
| `--save` | Зберегти вивід у `claudedocs/social-posts/` | Лише показати |
| `--force` | Генерувати, навіть якщо є лише записи про супровід | Пропускати низькі оцінки |

## Воркфлоу (7 кроків)

### Крок 1: Розібрати вхідні дані

Розбери `$ARGUMENTS`, щоб визначити режим:

| Вхід | Режим | Ціль |
|------|-------|------|
| `latest` | Одна версія | Перший `## [X.Y.Z]` після `[Unreleased]` |
| `vX.Y.Z` або `X.Y.Z` | Одна версія | Точний збіг версії |
| `week` | Діапазон тижня | Понеділок поточного тижня -> сьогодні |
| `week YYYY-MM-DD` | Діапазон тижня | Той понеділок -> наступна неділя |

Якщо аргумент відсутній або недійсний, покажи використання й заверши.

### Крок 2: Витягти записи CHANGELOG

Прочитай `CHANGELOG.md` з кореня проєкту.

**Одна версія:**
1. Знайди рядок, що відповідає `## [{version}]`
2. Витягни весь вміст до наступного рядка `## [`
3. Розбери розділи `### Added`, `### Changed`, `### Fixed`

**Діапазон тижня:**
1. Збери всі записи `## [X.Y.Z] - YYYY-MM-DD`, дата яких потрапляє в діапазон
2. Розбери всі розділи з усіх відповідних версій

**Помилка: версію не знайдено** -> Перелічи останні 5 версій, запропонуй `latest`.
**Помилка: за тиждень немає записів** -> Покажи дату останнього релізу, запропонуй цю версію.

### Крок 3: Класифікувати записи

Для кожного запису верхнього рівня (маркований пункт першого рівня під `###`) признач категорію:

| Категорія | Вага | Виявлення |
|-----------|------|-----------|
| `NEW_CONTENT` | 3 | Нові файли, нові розділи, нові діаграми, нові питання квізу |
| `GROWTH_METRIC` | 2 | Зростання кількості рядків, зміни кількості елементів |
| `RESEARCH` | 1 | Оцінювання ресурсів, інтеграції зовнішніх джерел |
| `FIX` | 1 | У розділі `### Fixed`, виправлення |
| `MAINTENANCE` | 0 | Оновлення README, синхронізація бейджів, синхронізація лендингу, оновлення лічильників |

Докладні правила класифікації дивись у `references/changelog-parsing-rules.md`.

### Крок 4: Перетворити на цінність для користувача

Застосуй зіставлення з `references/content-transformation.md`:

- Технічна мова -> вигода для користувача
- Витягни конкретні числа
- Вказуй названі джерела
- Групуй пов'язані записи

Звір із чек-листом DO/DON'T у `references/tone-guidelines.md`.

### Крок 4b: Інтерактивний режим (лише з --interactive)

Якщо встановлено прапорець `--interactive`, вставити між кроками 4 і 5:

1. Покажи кандидатів на головні події з оцінками:
   ```
   Highlights (by score):
   [14] 4 new ASCII diagrams (16 -> 20)     [NEW_CONTENT]
   [ 9] 30 new quiz questions (227 -> 257)   [NEW_CONTENT]
   [ 6] Docker sandbox isolation guide        [NEW_CONTENT]
   [ 1] README updated                        [MAINTENANCE]
   ```

2. Запитай про кут подання:
   - Auto (найвища оцінка = гачок)
   - Користувач обирає конкретний запис як гачок
   - Власний кут (користувач надає тему)

3. Запитай про цільову аудиторію:
   - `devs` (технічна глибина)
   - `tech-leads` (акцент на впливі)
   - `general` (доступна мова)
   - `all` (за замовчуванням, збалансовано)

4. Запитай про головну подію:
   - Auto (найвища оцінка)
   - Користувач обирає зі списку

5. Підтверди вибір і переходь до кроку 5.

### Крок 5: Оцінити та відібрати

Обчисли оцінку для кожного запису:

```
score = (category_weight * 3)
      + (has_number * 2)
      + (named_source * 1)
      + (new_file * 1)
      + (min(impact_files, 3))
      + (breaking * 2)
```

Відбери топ-3-4 записи за оцінкою. Найвища оцінка = рядок-гачок.

**Якщо всі оцінки < 3**: виведи "No social content recommended for this version. Use `--force` to generate anyway." і заверши (окрім випадку з `--force`).

### Крок 6: Згенерувати контент

Для кожного запитаного формату (за замовчуванням: усі 4) і мови (за замовчуванням: обидві):

1. Прочитай відповідний шаблон із `assets/`
2. Заповни поля шаблону, використовуючи оцінені й перетворені записи
3. Застосуй чек-лист якості з tone-guidelines.md

**Посилання:**

| Формат | Ціль посилання |
|--------|----------------|
| LinkedIn | URL сайту лендингу |
| Twitter | URL репозиторію GitHub |
| Newsletter | Обидва (лендинг + GitHub) |
| Slack | URL репозиторію GitHub |

**URL:**
- Лендинг: `https://florianbruniaux.github.io/Codex-ultimate-guide-landing/`
- GitHub: `https://github.com/FlorianBruniaux/Codex-ultimate-guide`

### Крок 7: Вивід

Покажи кожен згенерований пост у блоці коду, позначеному форматом і мовою:

```
## LinkedIn (FR)

```text
[content]
`` `

## LinkedIn (EN)

```text
[content]
`` `

## Twitter/X (FR)

```text
[content]
`` `

...
```

Якщо вказано прапорець `--save`: запиши всі результати до `claudedocs/social-posts/YYYY-MM-DD-vX.Y.Z.md` (для версії) або `claudedocs/social-posts/YYYY-MM-DD-week.md` (для тижня). Створи теку `claudedocs/social-posts/`, якщо її немає.

## Обробка помилок

| Помилка | Відповідь |
|---------|-----------|
| Немає аргумента | Показати блок використання |
| Недійсний аргумент | Показати блок використання з прикладами |
| Версію не знайдено | Перелічити 5 найновіших версій, запропонувати `latest` |
| За тиждень немає записів | Показати дату останнього релізу, запропонувати версію |
| Усі записи MAINTENANCE (оцінка 0) | "No social content recommended. Use `--force` to override." |
| CHANGELOG.md не знайдено | "CHANGELOG.md not found in project root." |

## Довідкові файли

- `references/tone-guidelines.md` - правила DO/DON'T, бюджет емодзі, мовний регістр
- `references/changelog-parsing-rules.md` - формат CHANGELOG, витягування, алгоритм оцінювання
- `references/content-transformation.md` - зіставлення "технічне -> цінність для користувача" (30+)
- `assets/linkedin-template.md` - ~1300 символів, гачок + пункти + CTA + хештеги
- `assets/twitter-template.md` - 280 символів: один твіт або тред із 2-3 твітів
- `assets/newsletter-template.md` - ~500 слів, структуровані розділи
- `assets/slack-template.md` - Компактно, багато емодзі, форматування Slack
- `examples/version-output.md` - Повний приклад виводу для v3.20.5
- `examples/week-output.md` - Повний приклад виводу для тижня 2026-01-27

## Поради

- Запускай `/guide-recap latest` одразу після `/release`, щоб підготувати соціальні пости
- Використовуй `--interactive` перші кілька разів, щоб зрозуміти оцінювання
- Використовуй `--format=linkedin --lang=fr`, коли потрібен лише один конкретний результат
- Виводи з `--save` ігноруються git через конвенцію `claudedocs/`
- Перегляньте й персоналізуйте перед публікацією (це чернетки, а не фінальний текст)

# Eval Resource

Оціни ресурс (URL або скопійований текст), щоб визначити його доречність для цільового посібника/проєкту.

## Визначення типу вводу

Skill приймає два типи вводу через `$ARGUMENTS`:

1. **URL**: починається з `http://` або `https://`
2. **Скопійований текст**: будь-який інший вміст (markdown, звичайний текст, нотатки)

## Інструкції

### Крок 0: Визначити тип вводу

```
SI $ARGUMENTS commence par "http://" ou "https://" :
  → input_type = "url"
  → source_url = $ARGUMENTS
SINON :
  → input_type = "text"
  → content = $ARGUMENTS
  → source_url = null
```

### Крок 1: Отримати та підсумувати

**Якщо URL:**
Використай `WebFetch` для URL, щоб:
- Витягти основний вміст
- Визначити ключові тези (щонайбільше 3-5)
- Зазначити тип вмісту (туторіал, довідник, блог, транскрипт відео тощо)

**Якщо скопійований текст:**
Проаналізуй наданий вміст безпосередньо:
- Визнач ключові тези (щонайбільше 3-5)
- Зазнач тип вмісту (особисті нотатки, конспект, документація тощо)
- Визнач джерела, цитовані в тексті (для подальшої перевірки фактів)

### Крок 2: Перевірка контексту

**Визначити цільовий посібник/проєкт:**

1. Якщо ти в проєкті з `machine-readable/reference.yaml` → використай цей файл
2. Якщо ти в проєкті з `CLAUDE.md` → проаналізуй задокументовану структуру
3. Якщо контексту немає → запитай користувача:
   ```
   Який цільовий посібник/проєкт для цієї оцінки?
   1. Claude Code Ultimate Guide (якщо доступний)
   2. Документація поточного проєкту
   3. Інше (уточнити)
   ```

**Проаналізувати цільовий контекст:**
- Поточну структуру посібника/проєкту
- Наявні розділи
- Потенційні прогалини

### Крок 3: Аналіз прогалин

Використай `grepai_search` із витягнутими ключовими поняттями, щоб:
- З'ясувати, чи/де це вже задокументовано
- Визначити схожі розділи
- Помітити прогалини

### Крок 4: Вивід

Підготуй структурований звіт, наведений нижче.

### Крок 5: Challenge (самокритика)

Використай інструмент `Task` із `subagent_type: technical-writer`, щоб:
- Поставити під сумнів рішення про доречність
- Визначити, що могло бути пропущено
- Запропонувати покращення плану інтеграції

Промпт для агента:
```
Critique cette évaluation de ressource pour le Claude Code Ultimate Guide:

[Coller le rapport généré à l'étape 4]

Challenge:
1. Le score est-il justifié ? Arguments pour un score +1 ou -1 ?
2. Y a-t-il des aspects de la ressource non mentionnés ?
3. Les recommandations d'intégration sont-elles les meilleures ?
4. Quels risques si on n'intègre PAS cette ressource ?

Sois brutal et direct.
```

### Крок 6: Перевірка фактів (верифікація)

**ОБОВ'ЯЗКОВО перед завершенням.**

**Якщо URL:**
1. **Перечитай джерело**: знову виконай WebFetch для URL, щоб перевірити кожне твердження
2. **Перевір статистику/цитати**:
   - Кожне згадане число (%, х разів тощо) → перевір, що воно є в статті
   - Кожну атрибуцію (автор, компанія, дослідження) → перевір точність
   - Кожну дату → перевір (увага: зараз 2026 рік, а не 2024!)

**Якщо скопійований текст:**
1. **Визнач твердження, які можна перевірити**: статистика, бенчмарки, атрибуції, дати
2. **Використай Perplexity** (`mcp__perplexity__perplexity_search`), щоб перевірити кожне важливе твердження
3. **Звір джерела**: не покладайся на одне джерело

**У будь-якому випадку:**
3. **Якщо є сумнів щодо вторинного джерела**: запитай користувача:
   ```
   ⚠️ Stats non vérifiables:
   - "[stat X]" - source citée: [Y]

   Voulez-vous une recherche Perplexity approfondie?
   ```
4. **Виправ звіт** перевіреною інформацією

**Чек-лист перевірки фактів:**
- [ ] Автор/роль правильні?
- [ ] Дата публікації правильна?
- [ ] Цитована статистика є в статті?
- [ ] Вторинні джерела визначено?
- [ ] Жодних вигаданих цифр?

# Аудит cheatsheet вашого лендингу

> Самодостатній prompt, що оцінює, чи потрібен вашому проєкту cheatsheet, і перевіряє наявні cheatsheet за еталонним стандартом.

**Автор**: [Florian BRUNIAUX](https://github.com/FlorianBruniaux) | Fractional Chief AI Officer

**Еталон**: [Claude Code Ultimate Guide Cheatsheet](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/guide/cheatsheet.md) (золотий стандарт)

---

## 1. Що це робить

Цей prompt доручає Claude провести систематичний аудит cheatsheet у 4 фази:

1. **Виявлення**: дослідити вихідний код проєкту та лендинг, щоб зрозуміти обсяг
2. **Оцінка**: оцінити, чи потрібен проєкту cheatsheet (об'єктивні критерії)
3. **Аудит**: якщо cheatsheet існує, оцінити його за 13 контрольними точками якості
4. **Рекомендація**: рішення «так/ні» з практичним планом

**Охоплює 3 сценарії**:
- Cheatsheet немає → оцінка потреби + рішення «так/ні»
- Часткове cheatsheet (лише HTML або лише MD) → аналіз прогалин
- Повне cheatsheet (MD + PDF + HTML) → аудит якості

**Час**: ~3-5 хвилин залежно від розміру проєкту

| Аудиторія | Що ви отримаєте |
|----------|-----------------|
| **Мейнтейнер проєкту** | Чітке рішення «так/ні» щодо створення cheatsheet |
| **Той, хто будує лендинг** | Контрольний список якості для сторінок cheatsheet |
| **Керівник документації** | Аналіз прогалин і пріоритезовані покращення |

**Передумови**:

- Доступ до вихідного коду проєкту (репозиторій із docs/README)
- Доступ до сайту-лендингу (якщо він є)
- Оболонка Bash (нативна на macOS/Linux, WSL на Windows)

## 4. Prompt

````markdown
# Cheatsheet Audit

## Контекст

Ти аудитор якості документації. Твоє завдання: оцінити, чи потрібен цьому проєкту cheatsheet, а якщо він існує, перевірити його якість за перевіреним золотим стандартом.

**Еталон золотого стандарту**: cheatsheet Claude Code Ultimate Guide: Markdown-файл на 527 рядків, що стискає 11-тисячорядковий посібник до 1 друкованої сторінки, з відповідними версіями PDF і HTML-лендингу.

## Інструкції

Виконай усі 4 фази послідовно. Звітуй про висновки після кожної фази, перш ніж переходити далі.

---

### Фаза 1: Виявлення

**Мета**: зрозуміти обсяг проєкту, аудиторію та наявні ресурси документації.

#### 1.1 Сканування коду проєкту

```bash
bash -c '
echo "=== PROJECT IDENTITY ==="
[ -f "package.json" ] && echo "Name: $(grep -m1 \"name\" package.json | cut -d\" -f4)"
[ -f "Cargo.toml" ] && echo "Name: $(grep -m1 "name" Cargo.toml | cut -d\" -f2)"
[ -f "VERSION" ] && echo "Version: $(cat VERSION)" || echo "Version: not found"
echo ""

echo "=== DOCUMENTATION ==="
for f in README.md CLAUDE.md CHANGELOG.md; do
  [ -f "$f" ] && echo "✅ $f ($(wc -l < "$f") lines)" || echo "❌ $f"
done
echo ""

echo "=== GUIDE/DOCS DIRECTORY ==="
for d in guide docs doc documentation; do
  [ -d "$d" ] && echo "✅ $d/ ($(find "$d" -name "*.md" | wc -l | tr -d " ") md files)" || echo "— $d/ not found"
done
echo ""

echo "=== CHEATSHEET FILES ==="
find . -maxdepth 3 -iname "*cheatsheet*" -o -iname "*cheat-sheet*" -o -iname "*quick-ref*" -o -iname "*quickref*" 2>/dev/null | head -20
echo ""

echo "=== EXAMPLES/TEMPLATES ==="
for d in examples templates; do
  [ -d "$d" ] && echo "✅ $d/ ($(find "$d" -type f | wc -l | tr -d " ") files)"
done
'
```

#### 1.2 Сканування сайту-лендингу

Якщо в проєкту є пов'язаний сайт-лендинг, проскануй його:

```bash
bash -c '
echo "=== LANDING SEARCH ==="
# Check common landing locations relative to project
PROJECT_NAME=$(basename "$PWD")
for suffix in "-landing" "-site" "-web" "-docs"; do
  LANDING="../${PROJECT_NAME}${suffix}"
  [ -d "$LANDING" ] && echo "✅ Found: $LANDING" && ls "$LANDING"/*.html 2>/dev/null | head -5
done

# Check for cheatsheet in landing
echo ""
echo "=== LANDING CHEATSHEET ==="
find .. -maxdepth 3 -path "*landing*" -name "*cheatsheet*" 2>/dev/null | head -10
'
```

#### 1.3 Оцінка складності вмісту

```bash
bash -c '
echo "=== COMPLEXITY INDICATORS ==="

# Commands/CLI
echo "--- Commands ---"
grep -rh "^\`[a-z]" README.md guide/*.md docs/*.md 2>/dev/null | sort -u | wc -l | xargs echo "CLI commands found:"
grep -rhi "slash command\|/command\|custom command" README.md guide/*.md docs/*.md 2>/dev/null | wc -l | xargs echo "Slash command refs:"

# Keyboard shortcuts
echo "--- Shortcuts ---"
grep -rhi "ctrl\|alt\|shift\|cmd\|⌘\|shortcut" README.md guide/*.md docs/*.md 2>/dev/null | wc -l | xargs echo "Shortcut references:"

# Config files
echo "--- Configuration ---"
grep -rhi "config\|settings\|\.env\|\.json\|\.yaml\|\.toml" README.md guide/*.md docs/*.md 2>/dev/null | wc -l | xargs echo "Config references:"

# API surface
echo "--- API/Features ---"
grep -rhi "endpoint\|api\|route\|feature\|flag" README.md guide/*.md docs/*.md 2>/dev/null | wc -l | xargs echo "API/feature refs:"

# Total doc volume
echo "--- Volume ---"
find . -name "*.md" -not -path "./.git/*" -not -path "*/node_modules/*" | xargs wc -l 2>/dev/null | tail -1 | xargs echo "Total MD lines:"
'
```

**Після виконання Фази 1 повідом:**
- Назву проєкту, версію, тип (CLI-інструмент / бібліотека / застосунок / фреймворк)
- Цільову аудиторію (розробники / нерозробники / змішана)
- Обсяг документації (рядки, файли)
- Знайдені наявні ресурси cheatsheet (MD, PDF, HTML, жодного)
- Підсумок показників складності

### Фаза 2: Оцінка потреби

**Мета**: об'єктивно визначити, чи виправдовує проєкт створення cheatsheet.

Оціни кожен критерій від 0 до 2 (0 = ні, 1 = частково, 2 = так):

| # | Критерій | Шкала оцінки | Бал |
|---|-----------|-------------|-------|
| 1 | **Поверхня команд** | 2 = 10+ команд, 1 = 5-9, 0 = <5 | |
| 2 | **Гарячі клавіші** | 2 = 5+ скорочень, 1 = 2-4, 0 = 0-1 | |
| 3 | **Складність конфігурації** | 2 = кілька конфігураційних файлів/рівнів, 1 = одна конфігурація, 0 = мінімальна | |
| 4 | **Багатокрокові workflow** | 2 = задокументовані workflow, 1 = неявні workflow, 0 = немає | |
| 5 | **Точки вибору** | 2 = кілька режимів/опцій на вибір, 1 = кілька, 0 = лінійно | |
| 6 | **Частота звернень до довідки** | 2 = користувачі заглядають щодня, 1 = щотижня, 0 = один раз і досить | |
| 7 | **Обсяг документації** | 2 = >2000 рядків документації, 1 = 500-2000, 0 = <500 | |
| 8 | **Широта аудиторії** | 2 = початківці + досвідчені, 1 = один рівень, 0 = вузькі експерти | |

**Оцінювання**:
- **12-16**: Сильна потреба: cheatsheet має високу цінність
- **8-11**: Помірна потреба: cheatsheet додає цінності
- **4-7**: Низька потреба: розгляньте натомість розділ «Quick Start»
- **0-3**: Потреби немає: достатньо доброго README

**Звіт**: таблиця з балами, сумою та вердиктом (Сильна/Помірна/Низька/Немає).

### Фаза 3: Аудит якості (якщо cheatsheet існує)

**Мета**: оцінити наявне cheatsheet за 13 контрольними точками якості золотого стандарту.

Якщо cheatsheet не знайдено у Фазі 1, переходь до Фази 4.

Для кожної контрольної точки постав оцінку: Pass / Partial / Fail / N/A.

#### A. Синхронізація версії та дати

Перевір, що номери версій збігаються з джерелом істини проєкту:
- Версія в заголовку/нижньому колонтитулі збігається з файлом `VERSION` або `package.json`
- Дата «Last updated» актуальна (у межах 1 місяця від останнього релізу)
- HTML: `dateModified` у schema.org збігається
- HTML: метадані Open Graph збігаються

#### B. Фактична точність

Вибірково перевір 3-5 фактичних тверджень за вихідною документацією:
- Чи описані можливості досі актуальні? (жодних застарілих елементів, поданих як активні)
- Чи точні вимоги до версій?
- Чи задокументовані «ключові слова» або «магічні рядки», які насправді не працюють?

#### C. Повнота команд

Порівняй перелічені команди з фактично доступними:
- Порахуй команди в cheatsheet і у вихідній документації
- Познач будь-які відсутні ключові команди
- Познач будь-які застарілі команди, що досі перелічені

#### D. Повнота гарячих клавіш

Порівняй перелічені скорочення з фактичними:
- Звір із вихідною документацією
- Перевір платформні варіанти (macOS проти Windows/Linux)
- Переконайся, що застарілих скорочень немає

#### E. Точність таблиць можливостей

Для кожної таблиці можливостей у cheatsheet:
- Перевір значення стовпців за вихідною документацією
- Шукай застарілі записи
- Перевір, що посилання досі працюють

#### F. Дерева рішень / швидка довідка

Якщо cheatsheet містить дерева рішень або блок-схеми:
- Перевір, що всі шляхи ведуть до чинних рекомендацій
- Переконайся, що згадані можливості/команди існують
- Пересвідчись, що глухих кутів немає

#### G. Структура папок / конфігурація

Якщо задокументовано структуру папок або розкладку конфігурації:
- Порівняй із фактичною структурою проєкту
- Перевір, що всі перелічені файли/каталоги існують
- Познач будь-які відсутні важливі шляхи

#### H. Коректність встановлення

Якщо включено інструкції зі встановлення:
- Перевір, що назва пакета правильна
- Перевір обмеження за версіями
- Подумки перевір команду встановлення відносно поточної екосистеми

#### I. Покриття розділів (між форматами)

Порівняй покриття між доступними форматами:

| Розділ | MD | PDF | HTML |
|---------|:--:|:---:|:----:|
| Команди | ? | ? | ? |
| Скорочення | ? | ? | ? |
| Конфігурація | ? | ? | ? |
| Workflow | ? | ? | ? |
| Усунення несправностей | ? | ? | ? |

Познач розділи, що є в одному форматі, але відсутні в іншому.

#### J. Точність вартості / цін

Якщо включено інформацію про ціни або вартість:
- Звір з актуальними офіційними цінами
- Перевір, що назви моделей актуальні
- Перевір будь-які твердження про «безкоштовний тариф»

#### K. Повнота прапорців CLI

Якщо задокументовано прапорці CLI:
- Порівняй із виводом `--help` або вихідною документацією
- Познач відсутні часто вживані прапорці
- Познач застарілі прапорці, що досі перелічені

#### L. SEO / Schema.org (лише HTML-лендинг)

Для HTML-сторінок cheatsheet:
- Перевір, що схема `<script type="application/ld+json">` існує
- Перевір, що `dateModified` актуальний
- Перевір канонічний URL
- Перевір теги Open Graph (title, description, image)
- Перевір точність meta description
- Перевір наявність CSS для друку (cheatsheet друкують)

#### M. Якість рендерингу PDF

Для PDF-cheatsheet:
- Таблиці рендеряться правильно (без зламаних стовпців)
- Спеціальні символи відображаються коректно (позначки, стрілки, емодзі)
- Блоки коду читабельні (моноширинний шрифт, підсвітка синтаксису)
- Вкладається в передбачену кількість сторінок (1 для швидкої довідки, 2-4 для детальної)
- Придатне для друку (без темних фонів, що з'їдають чорнило)

**Звіт**: таблиця з усіма 13 контрольними точками та оцінками, плюс примітки щодо критичних збоїв.

## Еталон золотого стандарту

Cheatsheet Claude Code слугує орієнтиром. Ось що робить його золотим стандартом:

### Структура (527 рядків, 17 розділів)

```
1. Essential Commands (15 команд, табличний формат)
2. Keyboard Shortcuts (9 скорочень, табличний формат)
3. File References (синтаксис + скорочення IDE)
4. Hidden Features (таблиця можливостей за версіями)
5. Permission Modes (матриця з 3 режимів)
6. Memory & Settings (дворівнева конфігурація зі шляхами)
7. .claude/ Folder Structure (діаграма-дерево)
8. Typical Workflow (нумерований покроковий)
9. Context Management (пороги + симптоми + відновлення)
10. Under the Hood (таблиця коротких фактів)
11. Plan Mode & Thinking (керування + вартість + перемикання моделей)
12. MCP Servers (7 серверів, табличний формат)
13. Creating Custom Components (шаблони agent/command/hook)
14. Anti-patterns (таблиця «робити/не робити»)
15. Quick Prompting Formula (шаблон + приклад)
16. CLI Flags Quick Reference (13 прапорців)
17. Golden Rules (7 нумерованих правил)
```

### Характеристики якості

- **Щільність**: 527 рядків стискають 19 000+ рядків (співвідношення 36:1)
- **Зручність перегляду**: кожен розділ використовує таблиці, блоки коду або нумеровані списки
- **Дієвість**: кожен запис відповідає на питання «що мені набрати?», а не «що це таке?»
- **Міжформатність**: MD (джерело) + PDF (друк) + HTML (лендинг, з темною темою та CSS для друку)
- **Синхронізація версій**: заголовок, нижній колонтитул і schema.org збігаються з файлом VERSION
- **Урахування платформ**: шляхи macOS + Windows там, де доречно
- **Розділ антипатернів**: показує, чого НЕ робити (високу цінність для початківців)
- **Дерево рішень**: швидка маршрутизація «що мені робити?»

### Патерни HTML-лендингу

Оцінюючи HTML-сторінки cheatsheet, золотий стандарт включає:
- Темну тему з підсвіткою синтаксису
- CSS, оптимізований для друку (`@media print`)
- Розмітку Schema.org `TechArticle` із `dateModified`
- Теги Open Graph для соціальних мереж
- Адаптивний дизайн (таблиці, зручні для мобільних)
- Інтеграцію з навігацією (є посилання з головного лендингу)
- CTA для завантаження PDF-версії
````

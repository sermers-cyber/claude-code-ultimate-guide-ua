## Підсумок змісту

just-bash — це повноцінний інтерпретатор bash, написаний на TypeScript: лексер, парсер рекурсивного спуску, AST і рушій виконання на основі віртуальної файлової системи в пам'яті. Жодних процесів не запускається. Немає ні `child_process`, ні worker у ролі гостьової ОС, ні межі WASM VM для самої оболонки. Інтерпретатор просто обходить AST і викликає функції TypeScript. Понад 90 команд, що відповідають coreutils, вбудовано (`grep`, `sed`, `awk`, `find`, `tar`, `jq`, `xan`, `yq`...), плюс необов'язкові CPython (через Emscripten), QuickJS (`js-exec`) і sql.js, кожен з яких вмикається лише явним прапорцем, бо кожен додає реальну поверхню атаки.

Чотири бекенди файлової системи охоплюють практичний діапазон, потрібний застосунку, що вбудовує інтерпретатор: `InMemoryFs` (типовий, без доступу до диска), `OverlayFs` (читання зі справжнього диска, запис за принципом copy-on-write, використовується в CLI), `ReadWriteFs` (читання й запис на справжній диск, щоб агент міг справді змінювати робочий простір) і `MountableFs` (поєднує кілька бекендів в одному просторі імен, наприклад, базу знань лише для читання, змонтовану поруч із робочим простором для запису). Клас `Sandbox` навмисно повторює API `@vercel/sandbox`, тож проєкт може почати з just-bash і згодом перейти на справжню мікро-VM Vercel Sandbox, не змінюючи місць виклику.

`THREAT_MODEL.md` (31.5 KB) — найсильніший артефакт у репозиторії. Він називає три типи загроз (недовірений автор скрипту, зловмисне джерело даних, скомпрометована залежність), проводить явні межі довіри й зводить у таблицю поверхню атаки: бомби з токенів, бомби з розкриття фігурних дужок, глибина підстановки команд, бомби з glob, забруднення прототипів через ключі IFS/env, DNS rebinding у необов'язковому `curl`; кожен рядок називає захист, значення ліміту й вихідний файл. Кожен числовий ліміт (`maxCallDepth`, `maxSubstitutionDepth: 50`, `maxBraceExpansionResults: 10K`, `maxExecutionTimeMs: 30_000`...) налаштовується для кожного екземпляра й перевизначається для кожного виклику `exec()`, з профілями `normal` (ліберальний) і `hardened` (суворіший, вмикається явно).

## Модель ізоляції та важливе застереження

README прямо називає власне обмеження: "All execution happens without VM isolation." Між інтерпретатором і процесом Node, у який його вбудовано, немає ні межі процесу, ні тим паче гіпервізора. Захист спирається на стримування на рівні JavaScript: `DefenseInDepthBox`, що підміняє `Function`, `eval`, `setTimeout`, `process.*` і `Module._resolveFilename` у контексті з областю `AsyncLocalStorage`, відкличні проксі над `Reflect`/`JSON`/`Math` та об'єкти з null-прототипом для всього, ключі чого контролює скрипт (env, асоціативні масиви, змінні AWK). Документація чесно вказує, де цього недостатньо: відкличний проксі не може відкликати посилання, яке скрипт закешував до активації, `resourceLimits` у Node ненадійно обмежують лінійну пам'ять WASM, яку використовують CPython чи sql.js, а для будь-кого, кому потрібна жорстка гарантія щодо пам'яті чи процесу, порада — використати для цієї частини справжню межу worker/процесу або Vercel Sandbox.

Через це ізоляція just-bash за своєю природою слабша, ніж в agentOS (`docs/resource-evaluations/agentos-in-process-agent-vm.md`), який принаймні ставить між гостьовим кодом і хостом sidecar на Rust та ізолят V8. just-bash не ставить туди нічого, крім дисциплінованого TypeScript. Натомість отримуємо архітектурну простоту: немає набору інструментів Rust, немає sidecar-процесу, яким треба керувати, а всю модель безпеки можна перевірити як звичайний TypeScript плюс один markdown-файл, що називає кожен ліміт.

## Місце щодо наявного охоплення в посібнику

`guide/security/sandbox-isolation.md` §5 уже наводить agentOS як «внутрішньопроцесний контрприклад» до чотирьох платних хмарних постачальників (Fly.io Sprites, Cloudflare Sandbox SDK, Vercel Sandboxes, E2B). just-bash належить до того самого підрозділу, не як дублікат agentOS, а як інший кінець спектра внутрішньопроцесних рішень: agentOS запускає справжню (хоч і без гіпервізора) VM з ядром на Rust та ізолятом V8; just-bash не запускає жодної VM, лише bash-сумісний інтерпретатор, написаний безпосередньо мовою хоста. Читачеві, який їх порівнює, потрібні обидві точки даних, бо «всередині процесу, без хмарного облікового запису» охоплює значно ширший діапазон реальної сили ізоляції, ніж може здатися з самої фрази.

Він також є прямим «родичем» наявного в посібнику запису "Vercel Sandboxes" двома підрозділами вище (рядок 435): Vercel постачає обидва кінці того самого компромісу від однієї компанії, повноцінний продукт мікро-VM на Firecracker для справжньої ізоляції та симульовану оболонку без інфраструктури для розробки, тестування й вбудованого використання з низькими ставками. Цей зв'язок варто назвати явно, бо з документації жодного з продуктів він не очевидний.

Перехресний пошук восьми продуктів sandbox для агентів, які зазвичай порівнюють у цій ніші (Perplexity, 2026-08-04), підтверджує, що just-bash і WebContainers (StackBlitz) — єдині два записи типу «симуляція, а не ізоляція»; E2B (~150-200 мс холодного старту Firecracker), Daytona (~90 мс, Docker/Kata), Modal Sandboxes (gVisor, від менше секунди до ~3 с), Cloudflare Sandboxes і Fly Machines (~2-3 с) платять реальною затримкою завантаження за справжню межу ОС. Такий поділ на дві категорії (симулювати vs ізолювати) — чіткіша ментальна модель для читачів посібника, ніж плаский список постачальників, і жоден наявний розділ посібника не формулює її прямо.

## Рішення

**Інтегрувати в `guide/security/sandbox-isolation.md` §5** як підрозділ поруч з agentOS, явно поданий як відповідник «симулювати, а не ізолювати», з чесним твердженням, що він дає менше стримування, ніж agentOS, а не більше, в обмін на відсутність рухомих частин. Додати один рядок TL;DR. Пропустити матрицю порівняння в §6, як і під час інтеграції agentOS: більшість її стовпців (Docker-in-Docker, ізоляція ядра) не застосовні до внутрішньопроцесного симулятора. Прямо вказати на відсутність файлу `LICENSE`, а не повторювати заяву README про Apache-2.0 як факт.

**Привід переглянути**: з'явиться файл `LICENSE` (розв'язує позначену прогалину), другий супровідник перевищить 15% комітів за ковзний квартал, або мажорна версія змінить модель ізоляції (наприклад, межа worker-потоку, що вмикається явно, для ядра інтерпретатора, а не лише для середовищ WASM).

## Короткий зміст

Ґрунтовна книга, що веде розробників від «вайб-кодингу» (швидкого прототипування за допомогою ШІ без глибокого розуміння) до професійних інженерних практик із залученням ШІ. Видана O'Reilly, охоплює кілька ШІ-інструментів для програмування (Claude Code, Cursor, GitHub Copilot, Gemini CLI) з практичними стратегіями розробки, готової до продакшену.

**Структура з шести розділів**:
1. **Вступ і спектр**: визначення вайб-кодингу проти інженерії за допомогою ШІ
2. **Принципи та найкращі практики**: контекст, довіра, планування, документація
3. **Просунуті техніки**: промпт-інженерія, інженерія контексту, MCP
4. **CLI-агенти та оркестратори**: термінальні інструменти та мультиагентні системи
5. **Розробка, готова до продакшену**: безпека, тестування, інтеграція в SDLC
6. **Майбутні тренди**: автономні агенти, візуальна розробка, моделі міркування

**Ключові рамки**:
- **Проблема 70%**: ШІ пришвидшує 70% розробки, останні 30% вимагають інженерної строгості
- **Інженерія контексту через метафору ОС**: context window = оперативна пам'ять CPU (динамічне завантаження/керування пам'яттю)
- **Розробка, керована критикою**: перетворення відгуків з рев'ю коду на промпти для ШІ
- **MCP як «USB-C для ШІ»**: стандартизований протокол для інтеграції інструментів
- **Двовимірна рамка**: технічна майстерність × рівні абстракції ШІ

## Обґрунтування мінімальної інтеграції

### Чому НЕ повна інтеграція

1. **Платний ресурс**: посібник має відкритий код, тож перевагу варто віддавати безкоштовним/відкритим джерелам
2. **90% перетину**: 10/14 тем уже охоплено на 100% з первинних джерел
3. **2 статті Osmani вже інтегровано**:
   - Spec-First (4/5, додано 180 рядків)
   - 80% Problem (3/5, додано 30 рядків)
4. **Посібник уже повніший**: 11 тис. рядків проти загального підходу книги (охоплення кількох інструментів)
5. **Книга = консолідація**: синтез наявних статей + помірне розширення, а не принципово нове дослідження

### Чому згадка для відстеження ВСЕ Ж цінна

1. **Зовнішнє підтвердження**: публікація в O'Reilly = довіра практиків до патернів посібника
2. **Корисність перехресних посилань**: користувачі, знайомі з книгою, зможуть зіставити її з розділами посібника
3. **Обізнаність про екосистему**: документує важливі ресурси в галузі розробки за допомогою ШІ
4. **Навчальна подача**: «контекст як RAM», «MCP як USB-C» = запам'ятовувані метафори (варті уваги, навіть якщо концепції охоплено)

**Низький вплив**:
1. Жодного унікального технічного змісту не втрачено (90% уже задокументовано)

**Середній вплив**:
1. Бракує зовнішнього підтвердження (O'Reilly = сигнал авторитетності)
2. Користувачі, знайомі з книгою, можуть не знайти перехресних посилань
3. Навчальні метафори («контекст як RAM») мають педагогічну цінність

**Рішення**: мінімальна інтеграція (згадка для відстеження + перехресні посилання) = зберігає цінність без дублювання

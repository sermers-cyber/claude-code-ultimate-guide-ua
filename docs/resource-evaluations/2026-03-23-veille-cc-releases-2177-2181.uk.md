# Моніторинг релізів CC 2.1.77 → 2.1.81 (17-20 березня 2026)

## Підсумок

5 релізів за 4 дні (17-20 березня 2026): режим `--bare` для CI/скриптів, мобільний permission relay `--channels`, hook `StopFailure`, постійне сховище плагінів `${CLAUDE_PLUGIN_DATA}`, ліміт output tokens для Opus/Sonnet 4.6 піднято до 64k/128k, `allowRead` у файловій системі sandbox, поле `rate_limits` у statusline. Зміни, що ламають сумісність: параметр `resume` в Agent видалено (→ SendMessage), `bypassPermissions` посилено для `.git`/`.claude`.

## Оцінка: 3/5

**Обґрунтування**: releases.yaml і claude-code-releases.md уже були актуальні (коміт 03e5260 «docs: update Claude Code releases to v2.1.81»). Цінність цього моніторингу це аудит покриття, що виявив 5 прогалин у тематичних розділах посібника. Сам моніторинг є переформулюванням офіційного changelog із втратами (бракує ANTHROPIC_CUSTOM_MODEL_OPTION, обходу безпеки PreToolUse, витоку пам'яті в auto-updater). Зміст інтегровано безпосередньо з releases.md, а не з моніторингу.

## Деталі інтеграцій

### Hook `StopFailure` (v2.1.78)

Додано в таблицю Event Types (ultimate-guide.md). Спрацьовує, коли хід завершується помилкою API (rate limit, збій автентифікації). Сценарій використання: сповіщення системи спостережуваності про вичерпання квоти.

### Поле `rate_limits` у statusline (v2.1.80)

Додано в розділ Custom Statusline Setup. Поле JSON показує використання Claude.ai (вікна 5 год і 7 днів) із `used_percentage` і `resets_at`. Дозволяє стежити за витратою токенів, не відкриваючи дашборд.

### `${CLAUDE_PLUGIN_DATA}` (v2.1.78)

Додано як callout у розділ Plugin Commands. Змінна середовища, що вказує на каталог постійного сховища, який зберігається під час оновлень плагіна. Видаляється лише при `/plugin uninstall` після підтвердження.

### Режим `--bare` (v2.1.81)

Додано після прикладу GitHub Actions `claude -p`. Вимикає hooks, LSP, синхронізацію плагінів, скан skills. Потребує `ANTHROPIC_API_KEY` (без OAuth). Робить CI-завдання детермінованими, не даючи локальній конфігурації розробника забруднювати середовище CI.

### Налаштування `sandbox.filesystem` (v2.1.77/2.1.78)

Розширено розділ «Configuring Filesystem Restrictions» у sandbox-native.md. Задокументовано три поля: `allowWrite` (розширює запис за межі CWD), `denyRead` (блокує шляхи читання), `allowRead` (повторно дозволяє читання всередині області denyRead). Виправлено хибне твердження «Filesystem restrictions are configured through permission rules only»: налаштування sandbox.filesystem існують і були виправлені у 2.1.78.

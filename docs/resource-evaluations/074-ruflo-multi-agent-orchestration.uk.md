## Оновлення (2026-06-01)

*Цей блок документує зміни від березневого оцінювання 2026 року. Оригінальний основний текст французькою збережено нижче.*

**Зміни статусу від березня 2026:**

- **Міграція npm: вирішено.** Пакет тепер опублікований на npm як `ruflo` (підтверджено бейджами README: `npmjs.com/package/ruflo`). Стару назву пакета `claude-flow` оголошено застарілою. Попередження про `curl|bash` лишається чинним: URL CDN досі посилається на стару назву репозиторію.
- **Ребрендинг: стабільний.** `github.com/ruvnet/ruflo` — активний репозиторій. Перехід, позначений у березневій оцінці як «триває», тепер завершено.
- **Федерація агентів: випущено.** Це найсуттєвіша нова можливість. Ruflo тепер підтримує zero-trust співпрацю агентів між машинами через mTLS і верифікацію ідентичності ed25519, а конвеєр виявлення 14 типів PII прибирає чутливі дані перед будь-яким вихідним повідомленням. Поведінкова оцінка довіри оновлюється для кожного пірa безперервно. 9 інструментів MCP і 10 команд CLI керують повним життєвим циклом. Ця можливість не має еквівалента в LangGraph, AutoGen чи CrewAI (усі за замовчуванням одноінстансні). Вона була **відсутня в усьому посібнику** до цього оновлення.
- **Маркетплейс plugin: випущено.** 33 нативні plugins для Claude Code, що охоплюють swarm, RAG-пам'ять, безпеку, браузерне тестування, IoT, трейдинг тощо. Тепер чітко задокументовано два шляхи встановлення (plugin-lite vs повний CLI), що усуває раніший ризик «складність для нових користувачів», дозволяючи початківцям стартувати без жодних файлів робочого простору.
- **Оновлення масштабу:** 98 спеціалізованих агентів (було 60+), 30 skills (було 42+ у ранішому твердженні), 314 інструментів MCP (шлях CLI).
- **Вебповерхні:** необов'язковий хостингований вебінтерфейс на flo.ruv.io і планувальник цілей GOAP на goal.ruv.io. Жоден не потрібен для використання CLI.

**Перегляд оцінки: 3/5 → 4/5**

Березнева оцінка 2026 року 3/5 була виправдана нестабільним ребрендингом і неперевіреною назвою npm. Обидва питання тепер вирішено. Додавання федерації агентів як справді відмінної можливості (відсутньої в конкуруючих фреймворках) піднімає оцінку до 4/5. Запис у посібнику оновлено в `guide/ecosystem/third-party-tools.md`, щоб відобразити можливість федерації та два шляхи встановлення.

Показники продуктивності (84.8% SWE-Bench, 352x, 32.3%, SONA <0.05ms) досі позначені як твердження автора без незалежного відтворення. Тепер існує gist зі SOTA-бенчмарком, що порівнює з LangGraph, AutoGen і CrewAI на darwin-arm64 і linux-x64, але незалежне відтворення не підтверджено. Жоден із цих показників не входить до запису в посібнику.

## Важливий контекст

Ruflo раніше був відомий як **claude-flow** (github.com/ruvnet/claude-flow). Нещодавній ребрендинг — структурна інформація, яку варто зафіксувати: пакет npm лишається `claude-flow`, URL встановлення через curl досі вказує на старий репозиторій. Стежити за стабільністю переходу.

## Підсумок змісту

- **Фреймворк мультиагентної оркестрації**: перетворює Claude Code на мультиагентну платформу з королевою + ієрархічними воркерами, mesh-топологіями або swarms
- **Шарувата архітектура**: CLI + MCP server → маршрутизатор Q-Learning → Mixture of Experts (8) → 60+ спеціалізованих агентів (кодери, тестувальники, рев'юери, архітектори, аудитори безпеки...)
- **42+ skills, 17 вбудованих hooks**
- **RuVector**: компонент WebAssembly, векторний пошук HNSW, самооптимізація SONA, 9 алгоритмів навчання з підкріпленням
- **Персистентність SQLite** (AgentDB, режим WAL) + 8 типів пам'яті, включно зі спільним доступом між агентами
- **Встановлення**: `npx ruflo@latest init --wizard` (рекомендований шлях) або `curl -fsSL https://cdn.jsdelivr.net/gh/ruvnet/claude-flow@main/scripts/install.sh | bash` (шлях, якого слід уникати)
- **Твердження про продуктивність** (див. розділ «Фактчекінг»):
  - 84.8% рівень розв'язання SWE-Bench
  - 32.3% зменшення токенів
  - 2.8-4.4x прискорення паралельної координації
  - 352x трансформацій WASM vs виклики LLM
  - 16 400 векторних запитів/секунду
  - Самооптимізація SONA <0.05ms

## Рекомендації

**Дія: інтегрувати в середньостроковій перспективі — після аудиту джерела та уточнення тверджень**

**Де інтегрувати**: `guide/ecosystem/third-party-tools.md`, розділ «Multi-Agent Orchestration» — не як окремий запис про інструмент, а як основний приклад нової підкатегорії **«External Orchestration Frameworks»**, відмінної від наявних мультиінстансних інструментів (Gas Town, multiclaude).

Розрізнення важливе: Gas Town / multiclaude = запуск кількох Claude Code паралельно. Ruflo = заміна/доповнення внутрішньої оркестрації Claude Code повним фреймворком. Це два різні архітектурні рівні.

**Що має статися перед інтеграцією:**

1. **Аудит джерела `npx ruflo@latest`** через `npm pack ruflo` — перевірити відсутність шкідливих preinstall-скриптів, підтвердити, що пакет відповідає опису в README
2. **Уточнити ребрендинг**: підтвердити, що `ruvnet/ruflo` справді активний репозиторій, а claude-flow заархівований або перенаправляє
3. **Позначити всі твердження** як «твердження автора, неперевірене» — жодна цифра (84.8%, 352x, 16 400/с) не може потрапити до посібника без опублікованої методології
4. **Виключити шлях curl|bash** з рекомендацій (див. розділ безпеки)

**Правильне формулювання для запису в посібнику:**
> Ruflo (раніше claude-flow) — найпоширеніший зовнішній фреймворк оркестрації для Claude Code (18,9 тис. зірок, станом на 2026-07-28 уже 66 272). Він додає повний мультиагентний шар поверх Claude Code: 60+ спеціалізованих агентів, маршрутизація Q-learning, персистентність SQLite. Використовувати, коли нативних можливостей Claude Code (Task tool, субагенти) недостатньо для конкретного сценарію.

## Виклик (technical-writer)

**Початкова запропонована оцінка:** 4/5
**Оцінка після виклику:** 3/5 (знижено)

Ключові пункти агента:

**Чому 4/5 було надто щедро:**
- 18,9 тис. зірок (станом на 2026-07-28 уже 66 272) з 830 за день = сплеск трендовості, а не стійке прийняття. Потрібно 3-4 тижні даних після сплеску, щоб підтвердити утримання
- Ребрендинг claude-flow → ruflo = нетривіальна подія. URL curl|bash досі вказує на старий репозиторій (`ruvnet/claude-flow`) — неузгодженість, що вказує на триваючий перехід
- 84.8% SWE-Bench було б SOTA, що б'є закриті лабораторії. Твердження неправдоподібне без статті та відтворюваності. Інші цифри (352x, 32.3%, <0.05ms) мають штучну точність без джерела
- «Byzantine fault tolerance + CRDT» в інструменті для індивідуальних розробників = «architectural theater» (цитата агента), якщо не задокументовано докладно

**Чому 3/5, а не 2:**
- Реальна прогалина в посібнику: категорії «external orchestration framework» не існує
- Тяга незалежно підтверджена (Perplexity: трендовий #42 AI-репозиторіїв, активна китайська спільнота)
- TypeScript, MIT, доступний npm = легше аудитувати, ніж проєкт без менеджера пакетів

**Ризики рекомендації:**
- Висока складність: користувач, що перескакує до 60 агентів + Q-learning, не опанувавши нативний Task tool, обирає хибний шлях
- Нестабільний ребрендинг: конвенції іменування (claude-flow vs ruflo) можуть змінитися знову
- Агресивні твердження: 84.8% SWE-Bench, якщо цитувати без застереження, позичає довіру посібника

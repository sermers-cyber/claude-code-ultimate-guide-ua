## 📄 Підсумок змісту

- **Spec-Driven Development з ізоляцією виконання**: кожен робочий пакет (work package) виконується у власному git worktree, що усуває хаос гілок під час паралельних збірок
- **Явний цикл управління**: `next → review → accept → merge`, з окремими командами
- **Локальний kanban-дашборд**: стан місії версіонується в репозиторії (специфікації, плани, робочі пакети, критерії приймання, стан рев'ю, рішення про злиття)
- **Явне позиціонування проти «чорної скриньки»**: документація стверджує "not a lights-out black box by default", тобто людина визначає намір/архітектуру/критерії приймання, агенти реалізують у відстежуваних worktrees, рецензенти приймають/відхиляють/зливають з журналом аудиту
- **Сумісний** із Claude Code, Codex, Cursor, Gemini, Copilot, OpenCode, Kiro та іншими

## 📍 Рекомендації

**Де інтегрувати**: `guide/workflows/spec-first.md`, розділ «Integration with Tools», короткою згадкою після блоку BMAD-METHOD, поданою як «якщо вам додатково потрібна ізоляція паралельного виконання через worktree з kanban-дашбордом, spec-kitty реалізує саме цей патерн». Без окремого повного розділу з огляду на поки обмежене впровадження.

**Рекомендований формат**: 3–4 рядки + команда встановлення, без повної порівняльної таблиці (вона зарезервована для інструментів із доведеним впровадженням).

## 🔥 Перевірка

**Перевірене заперечення**: «1 397 зірок у нещодавно створеного інструмента — чи не зарано його інтегрувати?»

**Відповідь**: порогом має бути не лише кількість зірок, а й унікальність патерну. Spec-Kitty — єдиний проєкт, знайдений у цьому дослідженні, що поєднує ізоляцію виконання + kanban + журнал аудиту в одному легкому інструменті під MIT. Популярніші альтернативи (Spec Kit, BMAD) не покривають цієї конкретної комбінації. Коротка згадка (а не повний розділ) — правильна міра: вона сигналізує про існування патерну, не надаючи надмірної ваги інструменту з поки невизначеним впровадженням.

**Ризик відмови від інтеграції**: низький. Концепцію ізоляції через worktree вже задокументовано деінде в посібнику (`guide/security/sandbox-isolation.md`, нативні git worktrees у Claude Code), spec-kitty — лише одна з можливих упакованих реалізацій.

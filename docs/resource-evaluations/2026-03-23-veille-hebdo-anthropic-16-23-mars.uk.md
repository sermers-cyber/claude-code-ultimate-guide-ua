# Щотижневий моніторинг Anthropic (16-23 березня 2026)

Синтез Perplexity охоплює п'ять груп подій у вікні 16-23 березня: Claude Code 2.1.81, Python SDK v0.85.0/v0.86.0, два записи в release notes Platform API (thinking.display + поля можливостей моделей) і блог-дослідження «What 81,000 people want from AI».

## Оцінка: 3/5

**Обґрунтування**: вторинне джерело (синтез Perplexity, а не первинна документація). CC 2.1.81 уже відстежується в нашому releases YAML/MD. Реальна цінність це дві недокументовані функції API платформи (`thinking.display: "omitted"` + поля можливостей моделей), які належать до розділу про extended thinking. Зміни Python SDK поза межами охоплення посібника з Claude Code CLI. Дослідження 81k надто далеке від технічної аудиторії посібника.

## Рекомендації щодо інтеграції

### P1 — `thinking.display: "omitted"` (API платформи, 16 березня)

**Де**: `guide/ultimate-guide.md` — розділ Extended Thinking (шукати «extended_thinking» або «thinking budget»)

**Що додати**: невеликий підрозділ або примітка, що пояснює:
- `thinking.display: "omitted"` приховує текст thinking у відповіді, зберігаючи поле `signature` для безперервності в багатоходових розмовах
- Сценарій використання: швидший streaming, чистіший UX, коли кінцевому користувачу не потрібен зміст thinking
- Тарифікація не змінюється: стягується повна вартість токенів thinking незалежно від налаштування відображення
- Компроміс: внутрішні процеси аудиту чи маркування, що спираються на текст thinking, мусять використовувати інший режим відображення

### P2 — Поля можливостей моделей в API (API платформи, 18 березня)

**Де**: `guide/ultimate-guide.md` — розділ API Integration або нова примітка «Model Discovery»

**Що додати**: `GET /v1/models` і `GET /v1/models/{model_id}` тепер повертають `max_input_tokens`, `max_tokens` та об'єкт `capabilities`. Це дозволяє динамічний вибір моделі в оркестраторах замість жорстко закодованих карт можливостей.

### P1 — Компроміси скриптового режиму з прапорцем `--bare` (пропущено в першому проході)

**Де**: `guide/ultimate-guide.md` — розділ скриптового / CI/CD використання (шукати прапорець `-p`, headless, pipeline)

**Що додати**: таблицю компромісів `--bare` проти стандартного `-p`. `--bare` пропускає hooks, LSP, синхронізацію плагінів і обхід каталогів skills; потребує `ANTHROPIC_API_KEY` або `apiKeyHelper` (без OAuth). Швидкий і мінімальний для CI-скриптів, але втрачає всю спостережуваність, яку дають hooks. Командні середовища, що потребують аудиторських слідів, мають використовувати стандартний `-p`.

## Виклик (technical-writer)

**Оцінку збережено: 3/5** (дві прогалини API + одна пропущена прогалина CLI не досягають порогу 4/5 для «значного інтегрованого покращення»)

Ключові виправлення з виклику:

- **`thinking.display: "omitted"` значніший, ніж зазначено.** Посібник висвітлює extended thinking лише з погляду CLI (рядки 13539-13632). Багатоходові патерни API з безперервністю ланцюга відсутні повністю. Це стосується тих, хто будує оркестратори. Переводить пріоритет із «прогалини» на «відсутню концепцію».
- **API можливостей моделей недооцінено.** `GET /v1/models` з об'єктом `capabilities` дає змогу динамічно вибирати модель під час виконання в мультиагентній маршрутизації, а посібник сьогодні документує цей патерн лише як ручний. Це не примітка про метадані, а зсув патерну.
- **Наслідки скриптового використання прапорця `--bare` пропущено в першому проході.** Відстеження релізів каже «охоплено», але посібник не документує компроміси `--bare` проти стандартного `-p` для CI/CD. Додано як P1.
- **Python SDK: пропустити, а не P3.** Посібник завжди виключав Python SDK зі свого охоплення. Застережень не потрібно.
- **Дослідження 81k: відхилити (оцінка 1), а не «P4 або пропустити».** Дослідження стосується споживачів Claude.ai і того, чого вони загалом хочуть від AI. Поза темою для посібника з Claude Code CLI.

**Ризики неінтеграції**: ті, хто будує оркестратори, платять зайві витрати токенів або ламають безперервність ланцюга через незнання `thinking.display: "omitted"`. Автори CI-пайплайнів не мають настанов щодо того, коли `--bare` доречний, а коли ризикований.

## Підсумок

Simone Ruggiero (1 лютого 2026) просуває **qmd** (github.com/tobi/qmd) - локальний індексатор документів, доступний як MCP-сервер для Claude Code. Головне твердження: «95% економії токенів» завдяки заміні Glob/Grep/Read на індексований семантичний пошук. Інструмент локально індексує кодову базу й віддає результати через MCP, тож Claude Code запитує індекс замість читати сирі файли.

**Ключове твердження**: замінити нативні файлові операції Claude Code на пошук в індексі, щоб скоротити споживання токенів приблизно на 95%.

## Підсумок змісту

**Основні тези**:
- **qmd** - локальний індексатор документів від Tobi Lutke (CEO Shopify)
- Надає сервер Model Context Protocol (MCP) для Claude Code
- Заявляє 95% економії токенів на операціях дослідження файлів
- Сценарій підрахунку токенів: файл на 500 рядків = ~10K токенів через Read → qmd повертає ~500 токенів (підсумок/фрагменти)
- Позиціонує qmd як заміну процесу Glob + Grep + Read
- Налаштування: `qmd index .`, а потім налаштувати як MCP-сервер у параметрах Claude Code

### Фактичні виправлення

**Головна проблема**: твердження про 95% бере за базу найгірший випадок (читання цілих сирих файлів) і порівнює його з найкращим випадком індексованого отримання. Реальна економія залежить від того:
1. Чи прочитав би Claude Code весь файл узагалі (часто він читає конкретні діапазони рядків)
2. Чи повертає семантичний індекс правильні фрагменти (важлива точність)
3. Чи потребує запит точного збігу (де Grep кращий)

**Бракує контексту**: стаття не згадує, що Claude Code уже оптимізує використання токенів через:
- Читання діапазонів рядків (параметри offset + limit)
- Цільові пошуки Grep (повертають лише рядки зі збігами)
- Патерн reference.yaml (машинозчитуваний індекс, ~2K токенів)

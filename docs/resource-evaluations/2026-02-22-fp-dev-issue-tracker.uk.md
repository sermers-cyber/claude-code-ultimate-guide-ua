## 📄 Підсумок змісту

- **fp.dev** — local-first інструмент відстеження issues, створений спеціально для Claude Code
- Issues зберігаються у `.md` у `/.claude/` — їх можна комітити в git (реальна відмінність від Tasks API)
- Воркфлоу через власні skills (`/fp-plan`, `/fp-implement`, `/fp-review`) + CLI (`fp tree`, `fp issue list`, `fp issue show`, `fp review`)
- Розв'язує «context rot»: дає змогу виконати `/clear` у сесії, не втрачаючи стан проєкту
- Desktop-застосунок для Mac (лише Apple Silicon) + UI для code review із вбудованим diff viewer
- Нуль зовнішніх залежностей, нуль MCP-серверів
- Встановлення: `curl -fsSL https://setup.fp.dev/install.sh | sh -s && fp setup claude && fp init`

## 🔥 Виклик (technical-writer)

Аргументи на користь зниження до 2/5:

1. **Надлишковість**: `/clear` + Tasks API вже покривають основну проблему
2. **Обмеження платформи**: desktop лише для Apple Silicon — неприйнятно для Linux/Windows
3. **Бракує сигналів прийняття**: немає зірок на GitHub, немає задокументованої частоти релізів → ризик, що проєкт занедбають
4. **Хибна категоризація**: не належить поруч із Gas Town/multiclaude (оркестрація мультиагентності) — fp.dev стосується відстеження завдань
5. **Одна реальна відмінність**: issues у `.md`, які можна комітити в git → але самої цього замало для 3/5

**Скоригована оцінка**: 2/5
**Ризики неінтеграції**: низькі. Посібник уже покриває проблему. Цінність у тому, щоб задокументувати ПРОГАЛИНУ (відстеження issues на основі markdown), а не обов'язково fp.dev.

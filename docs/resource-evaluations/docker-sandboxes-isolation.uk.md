## Підсумок

1. **Docker Sandboxes** (Docker Desktop 4.58+) дають ізоляцію на основі microVM для ШІ-агентів програмування, замінюючи старіший підхід на основі контейнерів. Claude Code працює в пісочниці з `--dangerously-skip-permissions`, бо межею безпеки є сама VM.
2. **Мережеві політики** пропонують режими білого/чорного списку з фільтрацією на рівні доменів, конфігурацією для кожної пісочниці та вбудованим моніторингом через `docker sandbox network log`. Приватні діапазони CIDR заблоковано за замовчуванням.
3. **Власні шаблони** використовують стандартні Dockerfile, що розширюють `docker/sandbox-templates:claude-code`. Базовий образ містить Ubuntu, Node.js, Python 3, Go, Git, Docker CLI, GitHub CLI, ripgrep, jq.
4. **Ширший ландшафт** включає Fly.io Sprites (microVM Firecracker, чекпоінт/відновлення ~300ms), Cloudflare Sandbox SDK (на основі контейнерів, інтеграція з Workers), E2B (Firecracker із відкритим кодом, холодний старт 150ms) і Vercel Sandboxes (GA 2026-01-30, microVM Firecracker).
5. **Прогалина в посібнику**: немає жодної документації про запуск Claude Code в ізольованих середовищах. Попередженню про `--dangerously-skip-permissions` (ultimate-guide.md:3943) бракує безпечного альтернативного шляху.

## Рішення щодо інтеграції

**Обґрунтування оцінки**: 4/5 (висока цінність), а не 5/5, бо:
- Docker Sandboxes справді корисні й закривають реальну прогалину (безпечна автономність)
- Офіційна документація Docker надійна (джерело рівня 1)
- Проте функція доступна лише в Docker Desktop (немає підтримки окремого Docker Engine)
- Підтримка Linux обмежена застарілим режимом контейнерів (не microVM)
- MCP Gateway усередині пісочниць поки не підтримується
- Хмарні альтернативи є додатковим контекстом, а не функціями, специфічними для Claude Code

**Дія**: створити окремий файл посібника (`guide/security/sandbox-isolation.md`), що охоплює Docker Sandboxes як основне рішення з альтернативами для хмарних/CI-сценаріїв.

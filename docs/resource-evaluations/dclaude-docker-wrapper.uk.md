## Підсумок

1. **dclaude** це однофайловий bash-скрипт, що обгортає Claude Code CLI у стандартний Docker-контейнер для ізоляції файлової системи. Пряма заміна: усі прапорці Claude CLI передаються далі.
2. **Основна мотивація**: Claude Code може переміщатися всією файловою системою, зокрема іншими гілками git worktree, ризикуючи випадково змінити продакшен-код. dclaude обмежує видимість лише змонтованими каталогами.
3. **Функції**: переадресація SSH-агента, підпис GPG, Docker-in-Docker (через сокет хоста), автоматичне зіставлення портів із переписуванням URL, постійні іменовані контейнери, передавання token GitHub, автоматичне завантаження `.env`.
4. **Встановлення**: одне завантаження через `curl`, образ Docker автоматично збирається під час першого запуску. Потрібен лише Docker Engine (без Docker Desktop).
5. **Модель безпеки**: стандартна ізоляція контейнера (не microVM). Монтує сокет Docker хоста (`/var/run/docker.sock`), `~/.ssh`, `~/.gnupg` у контейнер, що розширює поверхню атаки порівняно з підходом Docker Sandboxes із приватним демоном.

## Обґрунтування оцінки

**2/5 (маргінально)**, бо:

- Посібник уже охоплює Docker Sandboxes (офіційне рішення, ізоляція microVM) плюс 5 альтернатив, суттєвої прогалини немає
- dclaude використовує стандартні контейнери, а не microVM, тобто слабшу ізоляцію, ніж Docker Sandboxes. Власні антипатерни посібника (рядок 377) застерігають: "Assuming containers = VMs"
- Монтування сокета Docker хоста означає, що Claude у контейнері може керувати демоном Docker хоста, на противагу приватному демону в Docker Sandboxes
- Bash-скрипт одного супровідника без гарантій життєвого циклу
- Проте: працює на Linux із Docker Engine (реальна прогалина), а авторитет Patrick Debois у спільноті DevOps додає довіри

**Чому не 3/5**: слабша модель безпеки і вузька відмінність (прогалина лише для Linux) не виправдовують окремого розділу. Посібник уже документує обмеження для Linux.

**Чому не 1/5**: закриває легітимну прогалину для користувачів Linux Docker Engine. Внесок Debois заслуговує на визнання.

## Виклик (technical-writer)

Агент technical-writer підтвердив оцінку 2/5 і додав аналіз:

- **Безпеку проаналізовано недостатньо**: монтування сокета Docker хоста є суттєвою проблемою, а не просто «слабшою ізоляцією»
- **Авторитет Debois применшено**: він придумав термін «DevOps», а не просто «відома постать»
- **Твердження про пряму заміну не перевірено**: граничні випадки (MCP-сервери, `--resume`, збереження сесій), імовірно, мають тертя
- **Уточнено рекомендацію щодо розміщення**: виноска в підрозділі Limitations (рядок 225), а НЕ в матриці порівняння
- **Ризик неінтеграції**: мінімальний: жоден читач не залишиться без рішення для пісочниці через відсутність dclaude

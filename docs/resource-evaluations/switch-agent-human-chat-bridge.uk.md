## Підсумок змісту

Switch — інфраструктура, що поєднує AI-агентів і людей в одній розмові, у чат-застосунках, якими команда вже користується (Slack, Microsoft Teams, Discord, Telegram, Mattermost). Як внутрішню шину повідомлень він використовує **Matrix** (сервер Tuwunel): кожен учасник — людина, агент чи міст для співпраці — є клієнтом Matrix (`matrix-nio`). Кімната Switch зіставляється з одним зовнішнім каналом через рядок у базі даних, тож зіставлення переживає перезапуск.

Три компоненти: `core/switch_core/` (сервер FastAPI, Agent Bridge, у якому агенти реєструються й автентифікуються через ключ API, плюс мости для співпраці); `gateway/` (адмін-інтерфейс на React для агентів, кімнат, ресурсів, ключів); `console/` (десктопний застосунок на Electron, форк зі згадкою upstream, який керує локальними сесіями агентів для кодування, визначає, до яких кімнат належить агент, і автоматично запускає сесію Claude Code, коли до нього звертаються в Slack, а сесії немає).

Протокол (`docs/official/internals/agent-protocol.md`): один потік SSE вниз на з'єднання, HTTP вгору для кожної дії агента, чотири моделі з'єднання (`always_on`, `session_addressable`, `auto_session`, `session_passive`), що описують, як агент справді досяжний, замість припущення однакової доступності. Авторизація — єдина контрольна точка (`authz.py`): `can(principal, action, resource)`; запит, ініційований агентом, зводиться до ідентичності його власника й успадковує рівно ті самі дозволи власника, з публічною/приватною видимістю для кожного ресурсу.

Конектор для Claude Code (`connectors/claude-code-plugin/hooks/switch_hook.py`) вбудовується в життєвий цикл Claude Code до та після виклику інструмента, щоб опосередковувати дії й повідомляти події назад до мосту; еквівалентні конектори існують для Codex і OpenCode.

## Основний механізм, перевірений у коді

`core/switch_core/authz.py` — невеликий чистий модуль (без БД, без I/O) на 89 рядків: `Action = Literal["read", "write", "delete"]`, одна функція `can()`, однакова для References, Documents, Packages і Rooms. Консолідує те, що, за власним docstring модуля, раніше було розкидано як довільні перевірки `owner == user or public or admin` у місцях виклику, — реальне спрощення, якщо твердження справджується для всієї кодової бази (у цьому проході незалежно не простежено по кожному місцю виклику).

`docs/official/internals/collaboration-bridge.md` безпосередньо документує контракт адаптера мосту: `start`, `stop`, `send_message`, `update_message`, `delete_message`, `send_typing`, `create_channel`, `add_agents_to_channel`, `translate_inbound`/`translate_outbound`. У поставці п'ять адаптерів (Slack Socket Mode, Mattermost WebSocket, Discord Gateway WebSocket, опитування Telegram Bot API, Microsoft Teams як HTTP-слухач для самостійного розгортання — єдиний, що потребує публічної адреси). Сам міст є учасником Matrix: він приєднується до кімнат і бачить лише те, що відбувається після приєднання, — реальне обмеження на дозавантаження історії через щойно доданий міст, а не просто примітка щодо дизайну.

Дистрибуція більше схожа на продакшен, ніж зазвичай буває в окремого репозиторію GitHub віком шість тижнів: `docs/official/deploy/self-host.md` документує артефакт Docker Compose (`ghcr.io/sandbox-quantum/standalone-compose`) і чарт Helm (`oci://ghcr.io/sandbox-quantum/charts/switch`), обидва з тією самою версією релізу, плюс окремий `RELEASING.md` у корені репозиторію.

## Місце відносно наявного покриття в посібнику

Перш ніж дійти висновку, що це справжня прогалина, а не невдале розміщення, як кандидатів було перевірено три розділи:

`guide/core/memory-systems.md` §4.7 («Why the Team Gap Is Structural») документує шість бар'єрів для *семантичної* командної пам'яті (однокористувацьке сховище, вартість OAuth, стандарти таксономії, корпоративні покупці). Switch не має сховища ембедингів і шару пошуку; це шина реального часу, а не система пам'яті. Модель успадкування від власника в `authz.py` — релевантний факт саме щодо бар'єра вартості OAuth, але розміщення самого Switch у цьому розділі неправильно класифікувало б, чим він є.

У `guide/ecosystem/third-party-tools.md` розділи «Multi-Agent Orchestration» (abtop, Conductor, Agent Orchestrator, рядки 1409-1536) і «External Orchestration Frameworks» (Ruflo, Athena Flow, Pipelex + MTHDS) мають спільну вісь: кілька екземплярів того самого агента для кодування на одній машині, скоординовані через git worktrees і зворотний зв'язок PR/CI. Вісь Switch інша: різнорідні агенти (Claude Code, Codex, LangChain, будь-що, що говорить протоколом) досягають людей на п'яти *зовнішніх* чат-платформах через кероване управлінням модель ідентичності. Це не варіація наявних записів, а інша категорія.

`guide/ecosystem/ai-ecosystem.md` §8.1 «agent-chat» (рядки 1655-1666) у власному тексті посібника позначено як «Slack-like», що виглядає як покриття того самого простору, доки не перевірити код: це дашборд SSE лише для читання над `beads.db` від Gas Town і JSON-логами multiclaude, без живого з'єднання із зовнішньою платформою, без моделі автентифікації, явно несумісний з окремим Claude Code. Структурно це інструмент моніторингу, а не міст.

`third-party-tools.md` «Known Gaps» (рядки 1850-1866), розділ, що вже називає прогалини в можливостях, які посібник виявив, але не закрив (Sandcastle, fp.dev та інші), не має запису «cross-platform agent-human chat bridge with governance». Це підтверджує прогалину, а не закриває її.

## Рішення

**Не інтегрувати окремий розділ посібника. Додати один рядок до «Known Gaps» у `third-party-tools.md`, що називає категорію й наводить Switch як першого помітного кандидата, плюс запис у списку спостереження.**

Прецедент посібника для окремого файлу (`ai-executive-agents.md`, `agent-harness-landscape.md`) — це порівняння багатьох рівноцінних проєктів із таблицею маршрутизації, а не опис одного постачальника. Жодного аналога Switch (керованого, багатоплатформного, багатофреймворкового мосту чату між агентами й людьми) у дослідженні для цієї оцінки не знайдено; окремий розділ зараз читався б як сторінка продукту для OSS-релізу однієї компанії, а не нейтральне покриття посібника.

**Тригер повторного перегляду**: з'являється другий, незалежний інструмент-міст для чату з порівнянним обсягом (що уможливить порівняльну таблицю), або Switch випускає позначений тегом реліз `1.0.0`, або з'являється незалежно задокументоване розгортання в продакшені (не від SandboxAQ/Flint AI).

## Стислий підсумок

**Підсумкова оцінка**: **5/5 (КРИТИЧНО)**

agent-browser — це headless-браузер з CLI, створений спеціально для AI-агентів. Його запустила Vercel Labs у січні 2026 року; під капотом він використовує Playwright, але приховує всю складність для LLM-орієнтованих робочих процесів. Головна відмінність: на 82,5% менше спожитих token порівняно з Playwright MCP в ідентичних тестових сценаріях завдяки компактним посиланням на елементи (`@e1`, `@e2`) і мінімальному виводу лише з придатною до дії інформацією. Написаний на Rust, тому стартує менш ніж за мілісекунду. Безпосередньо стосується розділів посібника про тестування та агентні процеси: закриває задокументовану прогалину в рядку 10510, де Playwright MCP — єдиний наведений інструмент автоматизації браузера.

## Огляд ресурсу

### Ключові можливості

| Можливість | Деталі |
|---------|---------|
| **Реалізація** | Rust (основна, старт менш ніж за мс) + запасний варіант на Node.js |
| **Протокол** | Chrome DevTools Protocol (CDP) через Playwright |
| **Браузери** | Chromium, Firefox, WebKit |
| **Скорочення token** | -82,5% порівняно з Playwright MCP (задокументований бенчмарк, блог Pulumi 2026-03-03) |
| **Посилання на елементи** | Стабільний формат `@e1`, `@e2` (замість XPath/CSS-селекторів) |
| **Безпека (v0.15.0)** | Сховища автентифікації, allowlist доменів, політики дій, обмеження довжини виводу |
| **Кілька сесій** | Ізольовані екземпляри браузера з окремими cookies/сховищем/автентифікацією |
| **Збереження сесій** | Збереження/відновлення стану з шифруванням AES-256-GCM (`--session-name`) |
| **Стрімінг браузера** | Живий перегляд через WebSocket для «парного браузингу» (людина + агент) |
| **Інтеграції з AI** | Нативна підтримка Claude, Gemini, Cursor, GitHub Copilot |

### Основні можливості

- Навігація, клік, введення тексту, прокручування, знімок екрана, генерація PDF
- Знімки дерева доступності (оптимізовані для обробки LLM)
- Візуальні попіксельні порівняння з еталоном
- Порівняння дерева доступності з налаштовуваною глибиною та селекторами
- Перехоплення та мокання мережевих запитів
- Керування cookies і сховищем
- Емуляція пристроїв, симуляція геолокації
- Керування клавіатурою/мишею, обробка діалогів
- Виконання JavaScript, захоплення консолі
- Трасування та профілювання продуктивності

### Темп релізів

v0.10.0 → v0.15.0 з середини до кінця лютого 2026. Нове в останніх релізах: розширене профілювання, конфігураційні файли, покращена емуляція пристроїв, сховища автентифікації, allowlist доменів.

## Оцінювання

### Оцінка: 5/5 (КРИТИЧНО)

**Обґрунтування**:

1. **Пряма прогалина**: посібник описує Playwright MCP у рядку 10510 лише з 4 інструментами та 3 сценаріями. agent-browser — спеціально створений наступник для агентних робочих процесів.

2. **Ефективність використання token — головний чинник**: основна місія посібника включає оптимізацію token. -82,5% порівняно з Playwright MCP в ідентичних сценаріях — конкретна задокументована метрика (а не маркетинг).

3. **Патерн Ralph Wiggum Loop**: блог Pulumi (2026-03-03) описує патерн агента, що сам себе перевіряє, і він ідеально лягає на розділи посібника про агентні процеси. Build → Deploy → Verify → Iterate, усе автономно.

4. **12 100+ зірок менш ніж за 3 місяці**: сигнал про впровадження на рівні найшвидше зростаючих інструментів для розробників 2025-2026 років.

5. **Витіснення RPA**: консенсус спільноти (обговорення в Slack, «10 Best Agentic Browsers» від Bright Data 2026-02-04) позиціонує agent-browser як інструмент, що витісняє традиційний RPA у веб-процесах.

### Застереження

- **Не заміна Playwright для традиційних E2E-наборів**: він усе ж призначений для агентних процесів, а не як пряма заміна тест-раннерів Playwright (jest-playwright тощо)
- **Захист від ботів нікуди не дівся**: репутація IP, поведінка сесії, патерни прокручування, user agent — тут нічого не змінюється. Для скрейпінгу зовнішніх сайтів досі потрібні сервіси на кшталт Browserbase.
- **Рання стадія**: функції безпеки (v0.15.0) нові. Підготовка до продакшену триває.

## Порівняння: agent-browser і Playwright MCP

| Вимір | Playwright MCP | agent-browser |
|-----------|---------------|---------------|
| Основна аудиторія | Розробники (тести) | AI-агенти |
| Обсяг виводу | Високий (повний DOM) | Мінімальний (лише придатне до дії) |
| Використання token | Базовий рівень | **-82,5%** |
| Посилання на елементи | XPath/CSS | `@e1`, `@e2` (стабільні) |
| Реалізація | Node.js | **Rust** (старт менш ніж за мс) |
| Збереження сесій | Ні | Так (AES-256-GCM) |
| Кілька сесій | Ні | Так |
| Засоби безпеки | Немає | Сховища автентифікації, allowlist |
| Стрімінг браузера | Ні | Так (експериментально) |
| Агенти, що самі себе перевіряють | Незграбно | **Нативний патерн** |

## Цикл Ralph Wiggum

Основний патерн, який agent-browser уможливлює для агентних процесів:

```
Build → Deploy → [agent-browser verifies] → Fix → Repeat
```

1. Агент пише код (фічу, компонент, виправлення)
2. Розгортає (Vercel, Pulumi або будь-яка інша ціль)
3. Автономно запускає agent-browser
4. Переходить на розгорнутий URL, тестує сценарії
5. У разі збою: агент читає знімок, виправляє код, розгортає повторно
6. Людина не залучена, доки перевірка не пройде

Задокументовано в продакшені в Pulumi (2026-03-03) на 6 тестових сценаріях: завантаження головної сторінки, скорочення URL, перегляд дашборду, навігація аналітикою, огляд аналітики, фільтр за датою.

## Сценарії використання для посібника з Claude Code

1. **E2E-тестування в агентних циклах написання коду** (основний: замінює ручні скрипти Playwright)
2. **Розгортання з самоперевіркою** (Ralph Wiggum Loop)
3. **Цикли зворотного зв'язку для спостережуваності** (знімок екрана + порівняння дерева доступності при кожному розгортанні)
4. **Автоматизація форм** для AI-агентів, яким треба взаємодіяти з веб-інтерфейсами
5. **Візуальне регресійне тестування** з попіксельним порівнянням з еталоном

## Короткий зміст

Розповідь практика про 9 місяців використання Claude Code у продакшені в Cloudflare. Описує структурований воркфлоу, керований планом, з оригінальним патерном, **циклом анотацій** (Annotation Cycle): людина й агент ітеративно працюють над файлом плану в markdown ще до початку будь-якої реалізації.

## Ключові висновки

### 1. Наполеглива мова для дослідження
Без сильного сигналу Claude проглядає побіжно. Слова на кшталт «deeply», «in great detail», «intricacies» змінюють поведінку з поверхового перегляду на ретельне дослідження. Результат треба записувати у файл: усні підсумки зникають під час стиснення контексту.

### 2. Цикл анотацій
Головна інновація: ітеративно працювати над `plan.md` з анотаціями людини, перш ніж буде написано хоч рядок коду. Людина додає коментарі безпосередньо у файл плану, агент переглядає, і так доти, доки не лишиться відкритих питань. Зазвичай: 1-6 ітерацій.

Запобіжний промпт «do NOT implement anything yet» критично важливий: без нього Claude почне писати код ще під час планування.

### 3. Markdown як спільний змінюваний стан
Цитата: «The markdown file acts as shared mutable state between you and the agent.» Це ключовий висновок: файл плану не просто документація, а артефакт координації.

### 4. Лаконічні відгуки на етапі реалізації
Після затвердження плану реалізація стає механічною. Короткі відгуки («that looks right», скриншоти) ефективніші за абзаци, бо рішення вже ухвалено.

### 5. Додаткові техніки
- Cherry-picking: реалізувати підмножину плану
- Обрізання обсягу: прибрати пункти перед реалізацією
- Настанови на основі прикладу: «do it like auth.ts»
- Відкат і переналаштування обсягу: `git revert` + перезапуск із вужчим планом

# Оцінка ресурсу №079: Fabro, графовий оркестратор воркфлоу для ШІ-агентів програмування

**Джерело:** [fabro.sh](https://fabro.sh) / [github.com/fabro-sh/fabro](https://github.com/fabro-sh/fabro)
**Тип:** інструмент із відкритим кодом (MIT), окремий оркестратор воркфлоу для ШІ-агентів програмування
**Автор:** Bryan із qlty.sh (bryan@qlty.sh)
**Оцінено:** 2026-03-17
**Зрілість на момент оцінки:** створено 2026-03-13 (4 дні, 28 зірок, станом на 2026-07-28 уже 1 449), 1 форк

## Підсумок

- **Оркестратор воркфлоу для ШІ-агентів програмування**: пайплайни описуються графами Graphviz DOT із розгалуженнями, циклами, паралелізмом і точками людського схвалення; їх можна порівнювати через diff і версіонувати
- **Маршрутизація між кількома моделями**: CSS-подібні таблиці стилів призначають різні LLM (Claude, OpenAI, Gemini) окремим вузлам воркфлоу з автоматичними ланцюжками резервних варіантів
- **Git-чекпоінти на кожному етапі**: кожен етап комітить зміни коду та метадані виконання в окрему гілку Git; унікальна функція, прямого аналога якій у цій царині не знайдено
- **Хмарні пісочниці**: ізольовані віртуальні машини Daytona з налаштуванням на основі знімків, контролем мережі, SSH-доступом і автоматичним прибиранням
- **Автоматичні ретроспективи**: кожен запуск генерує ретроспективу з вартістю/тривалістю/наративом для постійного вдосконалення
- **Пряма інтеграція з Claude Code**: `curl -fsSL https://fabro.sh/install.md | claude` (примітка з безпеки: вивід передається прямо в Claude, без проміжної перевірки)
- **Єдиний бінарний файл на Rust, нуль залежностей часу виконання**: не потрібні ні Python, ні Node.js, ні Docker
- **REST API + SSE-стрімінг + вебінтерфейс на React**: запуск воркфлоу програмно або як сервісу

**Фінальна оцінка: 3/5 (Watch)**

**Обґрунтування:** Fabro прямо потрапляє в категорію «External Orchestration Frameworks», уже задокументовану в посібнику (`third-party-tools.md`). Його підхід на основі DOT-графів архітектурно відрізняється від усіх трьох наявних записів (Ruflo дорівнює ройам, Athena Flow дорівнює шару hooks, Pipelex дорівнює DSL). Git-чекпоінти на кожному етапі є справжньою відмінністю, аналогів у конкурентних фреймворках не знайдено. Пряма інтеграція з Claude Code через пайплайн `claude` легітимна. Проте 28 зірок (станом на 2026-07-28 уже 1 449) за 4 дні дають той самий профіль ранньої зрілості, що й Athena Flow (№073, оцінка 2/5). Підвищено до 3/5 порівняно з Athena Flow через чіткішу архітектуру, ширший набір функцій із більшою кількістю доказів і справді унікальний кут із Git-чекпоінтами.

## Конкурентне середовище (дослідження Perplexity, 2026-03-17)

Проведено повний конкурентний аналіз. Ключові висновки:

| Інструмент | Категорія | Зірки | Ключова відмінність від Fabro |
|------|----------|-------|--------------------------|
| **LangGraph** (LangChain) | Графові пайплайни | ~34k | Python-бібліотека (не окремий бінарний файл), універсальна (не спеціалізована під агентів програмування), без Git-чекпоінтів |
| **Goose** (Block) | Оркестрація агентів програмування | ~15k | На основі рецептів (не граф), розмовна архітектура, без Git-чекпоінтів, але значно зріліший |
| **OpenHands** | Платформа агентів програмування | ~48k | Архітектура потоку подій, Docker-пісочниці, орієнтований на дослідження; немає DOT-графів і Git-чекпоінтів на етапах |
| **Ruflo** | Зовнішня оркестрація (посібник) | 18.9k | На основі ройів (королева + робітники), npm, пам'ять SQLite; немає DOT-графів і Git-чекпоінтів |
| **Athena Flow** | Runtime на шарі hooks (посібник) | Watch | Hook → UDS → Node.js: зовсім інший архітектурний шар |
| **Pipelex** | MTHDS DSL (посібник) | Watch | Декларативний DSL для пайплайнів із кількома LLM: інша абстракція |
| **AutoGen** (Microsoft) | Багатоагентні розмови | ~47.9k | Універсальний, модель циклу розмови, без специфіки агентів програмування |
| **CrewAI** | Команди агентів за ролями | ~34.7k | Модель розподілу ролей, без опису графа, без Git-чекпоінтів |

**Унікальна комбінація Fabro** (жоден конкурент не робить усіх трьох речей):
1. Опис воркфлоу DOT-графом у вигляді окремого бінарного файлу
2. Git-чекпоінти на кожному етапі (код + метадані комітяться в гілки)
3. Нативна інтеграція з Claude Code через `claude`

**Найрелевантніша альтернатива для читачів посібника сьогодні**: LangGraph для графових воркфлоу (значно зріліший, Python), Goose (Block) для оркестрації агентів програмування (краще впровадження, MIT).

**Як:** короткий запис (у форматі Athena Flow) із:
- Архітектурною відмінністю (DOT-граф, що відрізняється від усіх трьох наявних записів)
- Відмінністю у вигляді Git-чекпоінтів
- Приміткою з безпеки щодо встановлення `curl | claude` (за тим самим шаблоном, що й застереження про `curl | bash` для Ruflo)
- Статусом: «Опубліковано в березні 2026, ще не аудійовано»

**НЕ слід:**
- Рекомендувати встановлення `curl | claude` без примітки з безпеки
- Подавати будь-яку функцію як перевірену в продакшені (доказів від спільноти ще немає)
- Додавати до досягнення тригера впровадження

**Додаткова знахідка:** Goose (Block, github.com/block/goose) заслуговує на окрему оцінку (№080). 15k зірок, MIT, рецепти + субагенти + 20 провайдерів LLM, потенційно безпосередніше релевантний для аудиторії посібника.

## Виклик (technical-writer agent)

**Початково запропонована оцінка:** 4/5
**Оцінка після виклику:** 3/5 (знижено)

Висловлені зауваження:

- **Прапорець незрілості**: 28 зірок / 4 дні = той самий патерн, що й в Athena Flow (оцінка 2/5). Непослідовне застосування підриває рамку оцінювання. Компроміс: 3/5, бо Fabro демонструє більше архітектурних доказів, ніж Athena Flow в еквівалентному віці.
- **Безпека `curl | claude`**: небезпечніше за типовий `curl | bash`, бо вивід іде прямо в кодову базу без кроку перевірки. Власний розділ посібника з безпеки це позначив би. Це слід зазначити в будь-якій майбутній інтеграції.
- **Амбітний неперевірений набір функцій**: хмарні пісочниці, маршрутизація DOT, ретроспективи; жодну з них на момент оцінки спільнота не перевірила на практиці.
- **Ризик неінтеграції на цьому етапі**: майже нульовий. Категорію вже покривають 3 записи.
- **Що справді нове**: опис через DOT-граф як текст, який можна порівнювати через diff (відмінно від Ruflo/Pipelex/Athena), + Git-чекпоінти на етапі = кути, які варто відстежувати.

# Оцінка: Augment Code - Context Engine MCP

**Дата**: 2026-02-19
**Оцінювач**: Claude Sonnet 4.6
**Тип джерела**: сторінка продукту (комерційний інструмент)
**URL**: https://www.augmentcode.com/product/context-engine-mcp
**Вердикт**: ДОРЕЧНО (Оцінка: 3/5)

---

## Підсумок змісту

6 лютого 2026 року Augment Code випустила свій Context Engine як окремий MCP-сервер. Він надає семантичний пошук коду для будь-якого агента програмування, сумісного з MCP (Claude Code, Cursor, Zed, Kilo Code, Roo Code, GitHub Copilot).

**Ключові тези**:

1. **Що робить**: хмарний MCP для семантичного пошуку, який індексує кодові бази (у різних репозиторіях, документації, вікі) і надає контекст AI-агентам через протокол MCP. Індексує до 400 000-500 000 файлів за допомогою семантичних графів залежностей.

2. **Твердження бенчмарку**: протестовано на 300 pull request-ах Elasticsearch (900 спроб, по 3 промпти на кожен). Результати:
   - Claude Code + Opus 4.5: покращення якості на +80%
   - Cursor + Opus 4.5: покращення на +71% (повнота +60%, коректність у 5 разів)
   - Cursor + Composer-1: покращення на +30%

3. **Ефективність**: потребує менше викликів інструментів і обмінів репліками; зменшує використання токенів порівняно з базовим варіантом без context engine.

4. **Архітектура**: хмарний (не локальний), індексування в реальному часі, конектори до кількох джерел (GitHub, GitLab, Bitbucket).

5. **Ціни**: на основі кредитів ($20/місяць Indie = 40 000 кредитів, $50/місяць Developer = 600 повідомлень). 1 000 безкоштовних запитів у період запуску (до лютого 2026, уже закінчився).

### Фактичні виправлення

**Розбіжність у версії моделі**: сторінка продукту посилається на «Claude Opus 4.6», але оригінальний допис про бенчмарк (6 лютого 2026) і всі вторинні джерела посилаються на «Claude Opus 4.5». Імовірно, сторінку продукту оновили під поточну модель уже після запуску бенчмарку. Це незначна, але помітна неузгодженість: цифра 80% отримана під час тестування Opus 4.5.

**Твердження «у 2 рази швидше»**: це конкретне число з'являється в маркетинговому тексті на сторінці продукту, але не підкріплене даними бенчмарку Elasticsearch. Бенчмарк вимірює виміри якості (коректність, повнота, найкращі практики, повторне використання коду, документація), а не швидкість виконання завдань. Вважати неперевіреним.

## Аналіз прогалин: що посібник уже охоплює

Посібник добре висвітлює сферу MCP для семантичного пошуку коду:

| Аспект | Висвітлення в посібнику | Augment Context Engine |
|--------|---------------|----------------------|
| **MCP для семантичного пошуку** | grepai (повністю задокументовано, розділ Code Search & Analysis) | Той самий сценарій, хмарний |
| **Компроміс «локально чи в хмарі»** | grepai = локальний/приватний, задокументовано явно | Augment = хмарний, локального варіанта немає |
| **Аналіз графа викликів** | grepai: інструменти callers/callees/graph | У продукті Augment не згадано |
| **Встановлення та конфігурація** | Повна інструкція встановлення grepai | Встановлення через конфігурацію MCP |
| **Ефективність токенів** | grepai: ~4K токенів проти 15K при переборі | Augment: «менше викликів інструментів» (без кількісних даних) |
| **Дані бенчмарків** | Для grepai немає | 300 PR, 3 виміри, конкретні % приросту |
| **Підтримка кількох репозиторіїв** | У grepai немає | Так - конектори GitHub, GitLab, Bitbucket |
| **Ціни/вартість** | grepai = безкоштовний, локальний | Augment = підписка від $20/місяць |
| **Приватність** | grepai = повністю локальний («жодні дані не залишають вашу машину») | Augment = хмарний, дані надсилаються в Augment |

**Виявлена прогалина**: розділ Code Search & Analysis у посібнику документує лише grepai (1 сервер). Вступ до розділу не обговорює компроміс між хмарними й локальними MCP для семантичного пошуку і не визнає комерційних/хмарних альтернатив на зразок Augment. Користувачі, яким потрібне кероване рішення для кількох репозиторіїв із підтвердженими результатами бенчмарків, не отримують жодних настанов.

**Другорядна прогалина**: бенчмарк Augment - найконкретніші опубліковані дані про вплив семантичного контексту на AI-агентів програмування. Посібник не наводить жодних еквівалентних бенчмарків покращення якості для grepai.

## Порівняльний аналіз: Augment, grepai і поточне висвітлення в посібнику

| Вимір | Grepai (у посібнику) | Augment Context Engine | Переможець для посібника |
|-----------|-------------------|----------------------|-----------------|
| **Приватність** | Лише локально, нуль хмари | Хмарний | Grepai для тих, хто дбає про приватність |
| **Складність налаштування** | Висока (Ollama + nomic-embed-text + grepai init) | Низька (конфігурація MCP + реєстрація акаунта) | Augment за простоту |
| **Кілька репозиторіїв** | Один проєкт за раз | Між репозиторіями й вікі | Augment для великих організацій |
| **Вартість** | Безкоштовно | Від $20/місяць | Grepai |
| **Граф викликів** | Повний (callers/callees/graph) | Не задокументовано | Grepai |
| **Докази з бенчмарків** | Не опубліковано | Покращення якості на 80% (опубліковано вендором) | Augment |
| **Незалежність** | Відкритий код (MIT) | Пропрієтарний, прив'язка до вендора | Grepai |

**Ключовий висновок**: це справді різні інструменти для різних користувачів. Grepai = приватність насамперед, безкоштовно, локально, з графами викликів. Augment = керований, платний, хмарний, для кількох репозиторіїв, з даними бенчмарків. Зараз посібник подає grepai як єдиний варіант у цій категорії, і це неповна картина.

## Рекомендація щодо інтеграції

Оцінка 3/5 - інтегрувати як задокументовану альтернативу.

**Рекомендована дія**: додати Augment Context Engine MCP як другорядний запис у розділ Code Search & Analysis файлу `mcp-servers-ecosystem.md`, явно позиціонуючи його як «хмарну/керовану альтернативу grepai».

**Що включити**:
1. Короткий опис інструмента та його відмінностей (хмара, кілька репозиторіїв, керованість)
2. Посилання на бенчмарк Elasticsearch (із застереженням: опубліковано вендором, Opus 4.5)
3. Попередження про приватність: дані надсилаються в хмару Augment
4. Примітка про ціни: потрібна підписка на основі кредитів
5. Посилання: https://www.augmentcode.com/product/context-engine-mcp

**Чого явно НЕ робити**:
- Не подавати маркетингові цифри 80% чи «у 2 рази швидше» як факти без застереження
- Не витісняти grepai з позиції основної рекомендації (grepai лишається кращим щодо приватності, вартості та аналізу графа викликів)
- Не розширювати це до повного розділу - це згадка альтернативи, а не основна рекомендація

**Запропоноване розміщення** в `mcp-servers-ecosystem.md` після наявного розділу про grepai:

### Чому НЕ вища оцінка?

- Не нова концепція: та сама категорія, що й grepai, уже добре висвітлена

- Лише хмара = неприйнятно для будь-якого середовища, чутливого до приватності
- Основна аудиторія посібника (розробники, що користуються Claude Code CLI), імовірно, віддає перевагу локальним/безкоштовним інструментам, а не керованим підпискам

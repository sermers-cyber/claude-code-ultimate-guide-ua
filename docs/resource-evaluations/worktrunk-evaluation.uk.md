# Оцінка: Worktrunk (worktrunk.dev)

**Дата:** 2026-01-25 (оновлено після поглибленого аналізу)
**Оцінювач:** Claude (Sonnet 4.5)
**Статус:** ⚠️ Рекомендовано за умов (див. оновлений висновок)

## 📄 Підсумок змісту

- **Worktrunk** — CLI на Rust для спрощення керування git worktrees, створений max-sixty (автором PRQL, 10 тис. зірок)
- Скорочує синтаксис `git worktree add -b feat ../repo.feat && cd ../repo.feat` до `wt switch -c feat`
- 3 основні команди: `switch`, `remove`, `list` + hooks, які можна налаштовувати + повідомлення комітів від LLM
- **GitHub: 1,6 тис. зірок (станом на 28.07.2026 уже 6 103), 54 форки, 15 контриб'юторів, v0.18.2 (січень 2026), 64 активні релізи**
- Створений саме для мультиагентних AI-воркфлоу (Claude Code явно згадано в README)

## 🔍 Поглиблений аналіз: розбір 4 джерел

### Джерело 1: Worktrunk на GitHub (github.com/max-sixty/worktrunk)

**Перевірені функції:**
- Шаблони шляхів, які можна налаштовувати (менше повторюваного набору)
- Hooks на рівні проєкту для автоматизації
- Інтеграція з LLM через інструмент `llm`
- Статус CI + генерація посилань на PR
- Інтерактивний вибір worktree
- Інтеграція з оболонкою (можливість змінювати теку)

**Метрики поширення:**
- 1,6 тис. зірок, 64 релізи, понад 15 контриб'юторів
- Мультиплатформність: macOS (Homebrew), Linux (Cargo/AUR), Windows (Winget)
- Автор: max-sixty (PRQL, 10 тис. зірок; мейнтейнер Xarray)

### Джерело 2: блог incident.io (shipping-faster-with-claude-code-and-git-worktrees)

**Ключові знахідки:**
- ❌ **НЕ використовують Worktrunk** — створили власну bash-обгортку `w`
- ✅ **Підтвердження патерну**: git worktrees усувають «branch management friction»
- ✅ **Виміряна віддача**: покращення на 18% (30 с) у часі генерації API
- ✅ **Масштаб**: кілька екземплярів Claude паралельно без конфліктів
- **Власне налаштування**: `w myproject new-feature claude` → автоматичний запуск Claude в ізольованій гілці

**Цитата:**
> «Rather than constantly switching branches in a single repository, they maintain separate working directories for each feature branch—all connected to the same Git database.»

### Джерело 3: найкращі практики Anthropic (anthropic.com/engineering/claude-code-best-practices)

**Критичні знахідки:**
- ❌ **ЖОДНОЇ згадки Worktrunk** (на відміну від того, що я припускав спочатку)
- ✅ **Git worktrees рекомендовано** як офіційний підхід Anthropic:
  > «Git worktrees allow you to check out multiple branches from the same repository into separate directories.»
- ✅ **3 рекомендовані підходи**:
  1. Кілька checkout (3-4 git clone)
  2. Git worktrees (у фокусі рекомендації)
  3. Власний harness + headless-режим (`claude -p`)

**Найкращі практики Anthropic:**
- Ізоляція контексту через `/clear`
- Розділення спеціалізованих інструментів (екземпляри для коду проти екземплярів для рев'ю)
- Успадкування CLAUDE.md між worktrees
- Консервативний підхід до дозволів

### Джерело 4: GitHub issue #1052 (репозиторій claude-code)

**Знахідки:**
- ❌ **НЕ використовує Worktrunk** — власний воркфлоу у Fish shell
- ✅ **Повний патерн воркфлоу** з 8 власними git-функціями:
  - `git worktree-llm` → створити + запустити Claude
  - `git worktree-merge` → завершити + rebase + merge
  - `git commit-llm` → коміти, згенеровані LLM
  - `git llm-message` → структурований diff→коміт через LLM
- ✅ **Статус issue**: CLOSED як `NOT_PLANNED` (обмін документацією, а не запит на функцію)
- ✅ **Цитата автора**: *«I now use it for basically all my development where I can use claude code»*

**Патерн воркфлоу:**
```bash
git worktree-llm feature-name    # Start feature
# ... work with Claude ...
git worktree-merge                # Finish, commit, rebase, merge
```

# Трейси походження агентних змін: AgentNote, docket і специфікація Agent Trace

**Переглянуто**: 2026-11-08. **Оцінки**: специфікація Agent Trace 3/5, docket 3/5, AgentNote 2/5. Інтегровано в [AI Traceability §3.5](../../guide/ops/ai-traceability.uk.md#35-походження-provenance-у-git-notes) поруч із git-ai, який було протестовано; ці три прочитано, але не запускали.

Усі три записують, яка сесія агента створила які рядки, щоб рев'юер міг повернутися від рядка до розмови чи наміру, що стоїть за ним. Код AgentNote і docket прочитано статично на наведених нижче SHA; нічого не встановлювали й не запускали. Показники атрибуції та твердження про збереження належать авторам, якщо не зазначено інше.

## Не той самий проєкт, що в попередній оцінці «agent-trace»

[`Siddhant-K-code/agent-trace`](https://github.com/Siddhant-K-code/agent-trace), оцінений 2026-03-16 ([2/5](2026-03-16-agent-trace-siddhant-github.uk.md)), — це рекордер і програвач сесій на Python з експортом в OpenTelemetry. Ця оцінка стосується **специфікації Agent Trace**, формату даних для атрибуції на рівні рядків, опублікованого на [agent-trace.dev](https://agent-trace.dev/) і віддзеркаленого в [`superhq-dev/agent-trace`](https://github.com/superhq-dev/agent-trace/tree/f7577a60e2f720ac83fab825fa3903e932d90bcb). У них спільна назва, але різні охоплення й формат.

## Специфікація Agent Trace (3/5)

- **Запис трейсу** містить версію, ідентифікатор, мітку часу, необов'язкові ревізію VCS та інструмент, а також список файлів. Для кожного файлу перелічено **розмови**, кожна з необов'язковим `url`, автором внеску (`human`, `ai`, `mixed` або `unknown`, з `model_id`) і **діапазонами** рядків.
- Діапазон може містити `content_hash` «for position-independent tracking», щоб атрибуція могла слідувати за кодом, який переміщується в межах файлу чи між файлами.
- Номери рядків стосуються записаної ревізії. Щоб дізнатися, хто сьогодні написав рядок N, специфікація радить зробити blame рядка, а потім знайти трейс для цієї ревізії.
- Специфікація не визначає сховища («local files, git notes, a database, or anything else») і лишає відкритими rebase та merge-коміти: «We expect to see different implementations in open source.»
- README дякує Amp, Cloudflare, Cognition, git-ai, Jules, OpenCode і Vercel за допомогу у формуванні специфікації. Чи хтось із них постачає цей формат, не перевіряли.

**Що додає**: нейтральну щодо постачальників форму запису, з якою можна порівнювати інструменти, де ключовою ідеєю для переживання редагувань є хеш вмісту. **Обмеження**: RFC версії 0.1.0, канонічний репозиторій якого сьогодні недоступний; переписування історії залишено на розсуд реалізацій (лише `revision` у jj, тобто change ID, описано як «stable across amend/rebase operations»); немає поля для наміру чи обґрунтування, лише посилання на розмову.

## docket (3/5)

- Записи формуються під час коміту з транскриптів сесій агента (Claude Code, Codex, opencode), підписуються ed25519 і зберігаються в orphan ref `refs/docket/records`.
- Намір — це останній текст асистента перед редагуванням, а якщо його немає, то блок thinking, обрізаний до 200 символів і пропущений через редагування секретів. Його відновлюють із транскрипту, а не пишуть для рев'юера.
- Атрибуція прив'язана до вмісту: рядок зараховується, лише якщо його текст є в записаному виводі редагування (висока впевненість), інакше середня або жодної.
- Кожен hunk отримує щільність доказів від 0 до 1 і поле `human_contact` (`none`, `edited`, `approved`). Hunks зі щільністю 0,15 і нижче позначаються як «no evidence», а коментар у pull request упорядковує hunks за оцінкою ризику, побудованою з цієї щільності, невідомого походження й відсутності людського контакту.
- Rebase чи cherry-pick не перезапускають `prepare-commit-msg`, тож trailer коміту копіюється на diff, для якого його не створювали, а індекс за комітами й далі вказує на старий SHA. Лише GitHub; GitLab є в списку README «not yet built».
- Показники атрибуції з README (98,1%, 94,7%, 92,9%, 59,2%) належать авторові, виміряні на його власних сесіях, і не відтворювалися.

**Що додає**: з трьох прочитаних це дизайн, найближчий до подання для рев'юера: намір для кожного hunk, явні hunks «no evidence», упорядкування за ризиком, прив'язка до вмісту. **Обмеження**: проєкт одного автора, версія 0.0.7, 23 коміти; часткове переживання переписування історії; записи існують, лише якщо кожен розробник їх пушить.

## AgentNote (2/5)

- Hooks Claude Code (SessionStart, Stop, UserPromptSubmit, PreToolUse і PostToolUse на інструментах редагування та `git commit`) захоплюють розмову й прикріплюють її до кожного коміту в `refs/notes/agentnote`. Trailer `Agentnote-Session` пов'язує коміти із сесіями.
- `agent-note why file:line` запускає `git blame`, знаходить коміт і його нотатку та вибирає взаємодії, серед зачеплених файлів яких є цей файл. Гранулярність — файл, а не hunk.
- GitHub Action рендерить таблицю в описі pull request між HTML-маркерами.
- **Конфіденційність**: повні промпти й відповіді агента зберігаються в нотатці як є і пушаться hook `pre-push` без редагування секретів. Про це сказано в архітектурному документі проєкту.
- **Переписування історії**: `notes.rewriteRef` задокументовано як заплановане, але жоден прочитаний код його не встановлює, тож нотатки, індексовані за SHA, осиротіють після amend, rebase чи squash.
- Згенеровані hooks викликають `npx --yes agent-note hook` без закріпленої версії, тож кожна подія агента запускає ту версію, яку визначить npm.

**Що додає**: робочий приклад захоплення через hooks у git notes і пошук від blame до розмови. **Обмеження**: нецензуровані транскрипти за замовчуванням пушаться у віддалений репозиторій і не переживають переписування історії. Згадувати лише як дизайнерський приклад.

## Сигнали атрибуції в комітах — слабкий доказ

Sachin Gupta (eBay) [перевірив текстові сигнали](https://www.youtube.com/watch?v=TJPInBjhE4Q&t=636) (футер co-authored, префікси гілок, фрази «generated by») на «three public repos, which comprised of 524 PRs»; у репозиторії C сигнал із найнижчим показником «was 0% on the repo C. Even though it was done by coding agent», і доповідач додає, що репозиторій «might have blocked it». Репозиторії не названо, сигнал не визначено, а авторство агента — це твердження доповідача. Читати разом з [оцінкою доповідей](reviewable-agent-changes-talks.uk.md): відсутність trailer не доводить, що код написала людина, і саме цю прогалину намагаються закрити ці три проєкти.

## Тут не перевірено

- Поведінку AgentNote і docket під час виконання, зокрема показники атрибуції docket і пошук транскриптів в AgentNote.
- Переживання записів docket чи нотаток AgentNote після amend, rebase або squash; висновок зроблено з коду й документації, не протестовано.
- Впровадження формату Agent Trace партнерами, названими в його README, і куди переїхав його канонічний репозиторій.

## Рішення

Використано в §3.5 «Provenance in git notes» після [тесту переписування git-ai](git-ai-provenance-notes.uk.md): форма запису Agent Trace і хеш вмісту як еталонний формат, docket як дизайн, орієнтований на рев'юера, AgentNote як застережний приклад щодо конфіденційності та переписування історії. Не рекомендувати встановлювати AgentNote в поточній конфігурації. Твердження про переживання для AgentNote і docket лишаються неперевіреними; запускали лише git-ai.

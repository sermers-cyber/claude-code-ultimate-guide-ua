## Оцінка: 3/5 (помірно, лише як кейс)

**Рішення**: інтегрувати як кейс і концепцію в `guide/core/memory-systems.md` §3.7, а не як рекомендований інструмент. Ідея, яку варто задокументувати: **агентне отримання через git-оболонку силами LLM** (LLM виконує grep і blame по репозиторію замість запитів до будь-якого індексу), точка в просторі дизайну пам'яті, якої посібник не охоплював. Не рекомендувати до впровадження: bus factor дорівнює одному, немає файлу ліцензії, ядро отримання не протестоване й переписується. Перенести один влучний навчальний пункт (узгоджуйте отримання з формою запиту) і два примітиви для повторного використання.

## Передумова перевернулася: DiffMem видалив BM25

Вихідне припущення (з огляду Perplexity) було «Markdown + Git + BM25 у пам'яті». Для коду це вже неправда. Коміт `c4fe4a3` ("git based retrieval") видалив увесь модуль `bm25_indexer/` (справжню реалізацію `rank_bm25.BM25Okapi`, 114 рядків, сам автор позначив її як «PoC minimal») і замінив його агентом, що виконує shell-команди під керуванням LLM. Поточний README каже це двічі (README:9, README:345): "No vector databases, no embeddings, no BM25, just git and an LLM." Старий BM25 можна відновити лише через `git show c4fe4a3^:src/diffmem/bm25_indexer/indexer.py`.

Для нашого контексту це важливо: DiffMem не підтверджує підходу «файли плюс BM25». Вони його спробували й відмовилися на користь отримання повністю через LLM. Для лексичної форми запиту (рядки помилок, символи) це, мабуть, хибний напрям. Див. навчальний пункт нижче.

## Що це таке (перевірено за кодом)

- **Зберігання**: файли Markdown у Git-репозиторії, справжня багатокористувацька структура. Один центральний репозиторій зберігає кожного користувача як **сирітську гілку** `user/<id>`, змонтовану через `git worktree` (`local_storage.py:83-111`). Сирітські гілки не мають спільної історії, тож ізоляція є справжньою гарантією Git, а не домовленістю щодо каталогів. Файли користувача: `<user>.md`, `memories/{people,contexts}/*.md`, `timeline/YYYY-MM.md`, автоматично згенерований `index.md`. Frontmatter у YAML розбирається чистим PyYAML, без LLM (`frontmatter.py:23-56`).
- **Отримання**: жодного алгоритму ранжування. `run_retrieval_agent()` (`retrieval_agent/agent.py:197-308`) запускає цикл викликів інструментів LLM (за замовчуванням 4 ходи) рівно з одним інструментом `run(command=...)`. Модель виконує команди з білого списку (`cat, head, tail, grep, ls, wc, git log/diff/blame/show/rev-list`) через `command_router.py`, вивід обмежено 150 рядками / 30KB, тайм-аут 10s, виконання через `subprocess.run(shell=True)` (`command_router.py:265`). Детермінована базова лінія без LLM завантажує сутність користувача плюс п'ять останніх файлів хронології (`baseline.py`, docstring: "No BM25, no embeddings, no LLM calls, pure file reads").
- **Часова / диференційна пам'ять**: підключена, але під керуванням LLM. Історія Git є даними для запитів, які агент тягне на вимогу (`git blame`, щоб знайти, коли факт востаннє змінився). `_link.py:29-56` у консолідаторі програмно аналізує спільні зміни: проходить останні коміти, будує граф спільної появи сутностей, а потім LLM пропонує wikilinks. Справжній диференційний сигнал, LLM для запису.
- **Механізми** (ядро чи необов'язкове): ядро є бібліотекою Python (`DiffMemory` в `api.py`) з **4 залежностями** (requests, openai, gitpython, python-dotenv). Навколо нього: агент запису (1276 рядків, найбільший файл), консолідатор (4 інструменти: dedupe/link/redistribute/reabsorb, ~1300 рядків), підключуваний виконавець (`inline` за замовчуванням, `hatchet` як необов'язкова надійна черга), сервер FastAPI на 890 рядків, підключувані онтології (personal/corporate). Необов'язкові шари ввімкнено через змінні середовища і `requirements-server.txt`. Поділ на ядро і сервер чесний.

## Єдиний навчальний пункт, який варто зберегти: узгоджуйте отримання з формою запиту

DiffMem збудував BM25, а потім видалив його на користь отримання повністю через LLM. Це реальний сигнал, і його причина повчальна. Запити DiffMem є **запитаннями природною мовою про людей, події і стосунки** (співрозмовник-компаньйон згадує, «що користувач казав про свою сестру в березні»). Це семантична форма запиту, де ключові слова BM25 працюють гірше, а міркування про сутності й час важливі, тож вони перейшли до LLM, яка вміє `git blame` і міркувати.

Протилежне справедливо для системи retex агента програмування: запити там є **рядками помилок, стек-трейсами і символами коду**, лексичною формою запиту, де збіг термінів високий, а BM25 не просто достатній, а часто кращий за ембединги й набагато дешевший за цикл LLM. Тож відмова DiffMem від BM25 не доводить, що BM25 хибний. Вона доводить, що **отримання має відповідати формі запиту**. Та сама основа (файли + git), протилежний вибір отримання, бо запити різні. Це найвлучніший і найпереносніший урок з усього аналізу, і йому місце в посібнику.

## Шаблони, які варто вилучити (для посібника і для системи retex)

1. **Агентне отримання через git-оболонку силами LLM** (`command_router.py`, `retrieval_agent/agent.py`). Замість DSL пошуку чи індексу дайте LLM `grep` + `git log/blame/diff` за білим списком базових команд, з обрізанням виводу і тайм-аутом. Близько 351 рядка дають дуже гнучку поверхню отримання, а «коли це востаннє було правдою» в стилі `git blame` дістається безкоштовно. Нове порівняно з посібником. Застереження, яке треба задокументувати: перевірки на рівні аргументів немає (перед `shell=True` перевіряється лише `tokens[0]`), тож `$(...)` в аргументі є реальним ризиком ін'єкції, якщо колись відкрити це для недовіреного вводу.
2. **Сирітська гілка на користувача + ізоляція через worktree** (`local_storage.py:83-111`). Справжня ізоляція файлової системи та історії між орендарями з одним спільним сховищем об'єктів, чистіша, ніж «один каталог на користувача».
3. **Frontmatter як поверхня запитів, проза як вміст** (`frontmatter.py`). Структуровані поля для запитів у YAML, розповідь у тілі. Прямо лягає на файл retex: `severity`, `tags`, `prevention_rule` у frontmatter, історія в тілі.
4. (Дрібне) **Lockfile з перевіркою живучості PID і повторним захопленням застарілого** (`lock.py`) і **коміт, відокремлений від віддаленого резервного копіювання** (`repo_manager.py:97-117`). Добрі мінімальні примітиви для файлової пам'яті, що працює як сервіс.

Явно **не** варто копіювати: відсутність режиму без LLM. Кожне читання і запис звертається до OpenRouter (`api-surface.md:9-10`), запис займає 60-600s, читання 5-30s, і кожна операція коштує грошей. Для системи retex, до якої постійно звертаються під час налагодження, саме цього податку на затримку й вартість дає змогу уникнути фільтр за ключовими словами/BM25/тегами frontmatter.

## Слабкі сторони

- **Bus factor один**: Alex / Growth Kinetics становить 78% із 60 комітів під 7 псевдонімами Git. Якщо Alex зупиниться, зупиниться проєкт.
- **Прогалина з ліцензією**: MIT заявлено лише в класифікаторі pyproject, файлу LICENSE немає, GitHub ліцензії не виявляє. Юридичний блокер для впровадження.
- **Ядро отримання не протестоване і змінюється**: компонент із найбільшим радіусом ураження (LLM, що вільно генерує shell-команди) має нульове покриття тестами, і відкрита гілка `rebuilding-retrieval`. Не будуйте на рухомій непротестованій частині.
- **Зламаний консольний скрипт**: `pyproject.toml:62` оголошує `diffmem = "diffmem.cli:main"`, але `cli.py` не існує. `pip install -e . && diffmem` падає.
- **«Продакшен» перехвалено**: продакшен для одного навантаження (Annabelle), дорожня карта визнає, що стратегію індексування з PoC ще треба зміцнити (надто вимоглива до пам'яті), «нуль зовнішніх залежностей» суперечить обов'язковому API LLM, «довговічність на 50 років» не має підтвердних даних.

## Щодо retex / smart-suggest-routing

DiffMem від супротивного підтверджує, що наявний **рушій BM25 smart-suggest-routing** є правильним інструментом для форми запитів retex (лексичні рядки помилок), а DiffMem не є конкурентом, якого варто копіювати. Ідея з DiffMem, яку можна використати повторно, це **рівень ескалації**: BM25 або фільтр за тегами frontmatter як дешевий варіант за замовчуванням, а агентний прохід через git-оболонку силами LLM лише тоді, коли лексичний збіг промахнувся. Це прагматичний гібрид, побудований на рушії, що вже працює в продакшені, а не на стеку DiffMem, який можна лише клонувати, що вимагає LLM і має одного супровідника.

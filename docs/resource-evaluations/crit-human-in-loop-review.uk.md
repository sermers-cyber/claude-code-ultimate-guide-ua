## 1. Підсумок змісту

`crit` це локальний інтерфейс рев'ю, створений, щоб стояти між розробником і ШІ-агентом. Він дає адаптивний інтерфейс для рев'ю виводу ШІ в чотирьох режимах:

- **Файли Markdown/планів**: рендеряться з inline-коментарями до рядка чи діапазону до того, як агент почне виконання
- **Git diffs**: роздільний/об'єднаний вигляд із порівнянням між раундами (різниця між ітераціями агента, а не лише між комітами)
- **Живі вебзастосунки**: проксіює запущений локальний сервер і вбудовує оверлей із прив'язкою до DOM для просторових коментарів, зіставлених із вихідним кодом
- **Статичний HTML**: прямий рендеринг із тією ж системою оверлеїв

Цикл: агент створює вивід → розробник відкриває crit → залишає inline-коментарі → агент читає ці коментарі → crit показує, що змінилося між раундами.

**Ключові функції**:
- Живі треди (безперервна розмова, прив'язана до конкретного рядка, а не одноразова)
- `crit comment src/file.go:42 'message'`: програмний CLI, через який агенти додають власні нотатки
- `POST /api/agent/request`: HTTP-ендпоінт, через який агенти надсилають людині запити на рев'ю
- Двобічна синхронізація з GitHub PR (читання/запис коментарів PR через CLI `gh`)
- `crit install claude-code`: повноцінна інтеграція з Claude Code (записує фрагменти конфігурації проєкту)
- Асинхронні URL рев'ю, якими можна поділитися, для віддаленої співпраці

**Стек**: бекенд на Go 1.26+, фронтенд на JS/TS вбудовано в бінарний файл. Без бази даних, без хмари, без телеметрії.

### Обґрунтування

**Сильні сторони**:
- Пряма інтеграція з Claude Code (`crit install claude-code` є задокументованою повноцінною командою)
- Закриває справжню прогалину: жоден наявний інструмент не показує diff між раундами в межах ШІ-сесії
- Просторові коментарі з прив'язкою до DOM для живих вебзастосунків, яким немає відповідника в стандартному інструментарії PR
- Активна підтримка: 477 зірок, v0.16.2 вийшла 9 червня 2026, загалом 665 комітів
- Ліцензія MIT, без телеметрії, без залежності від хмари
- CLAUDE.md у репозиторії є символьним посиланням на AGENTS.md, тобто супровідник розуміє конвенції Claude Code
- Розв'язує тертя, що трапляється в сесіях Claude Code: «як дати структурований відгук на план до того, як Claude його виконає?»

**Чому 4/5, а не 5/5**:
- Один супровідник (bus factor), глибина участі контриб'юторів неясна
- Режим `live` явно позначено як "feedback wanted", ще не стабільний
- Для збирання потрібен Go 1.26+ (може спричинити проблеми при збиранні з вихідного коду)
- У README не видно набору тестів
- Документація робоча, але скупа (немає окремого сайту документації)

## 3. Технічний аналіз

### Diff між раундами: унікальна цінність

Стандартні інструменти diff (GitHub PR, `git diff`, diff в IDE) показують різницю між комітами чи гілками. `crit` показує різницю між ітераціями агента в межах однієї сесії рев'ю. Такої можливості немає в жодному іншому інструменті, якщо не робити ручних закладок.

Саме для користувачів Claude Code: коли ви запускаєте Claude кілька разів на тій самій задачі й хочете зрозуміти «що він змінив між спробою 2 і спробою 3?», `crit` дає структуровану відповідь.

### Рев'ю плану перед виконанням

Режим markdown дає змогу переглядати `plan.md` чи подібні файли inline, перш ніж агент продовжить. Без `crit` для цього треба вручну відкривати файл і передавати відгук через prompt. З `crit` коментарі прив'язані до конкретних рядків, і агент може прочитати їх через API коментарів CLI.

### Синхронізація з GitHub PR

`crit` може читати й записувати коментарі рев'ю GitHub PR в обидва боки через CLI `gh`. Це замикає цикл: Claude Code відкриває PR, рецензент залишає inline-коментарі в `crit`, ці коментарі синхронізуються з PR, Claude Code читає їх через контекст PR.

## 5. Встановлення

```bash
# Homebrew (macOS/Linux)
brew install crit

# Go
go install github.com/tomasz-tomczyk/crit@latest

# Binary, Nix, Docker also available
```

**Базове використання**:
```bash
crit                          # Auto-detects uncommitted changes in repo
crit plan.md                  # Review a specific file before agent executes
crit http://localhost:3000    # Proxy and review a running web app
crit landing.html             # Review static HTML with spatial comments

# Claude Code integration setup
crit install claude-code      # Writes config snippets into the project
```

## 6. Релевантність для користувачів Claude Code

**Пряма і явна**. Інструмент створено саме для цього воркфлоу:

- `crit install claude-code` одразу налаштовує його для сесій Claude Code
- HTTP API (`/api/agent/request`) розраховано на те, що Claude Code буде агентом-отримувачем
- Diff між раундами прямо відповідає тому, як Claude Code ітерує на тій самій задачі в кількох запусках
- Синхронізація PR закриває розрив між PR, відкритими Claude Code, і структурованим людським рев'ю

Для читачів посібника: `crit` усуває тертя, що виникає в багатоітераційних сесіях Claude Code. Поточний посібник охоплює рев'ю планів і шаблони зворотного зв'язку, але не має рекомендації інструмента для структурованого inline-рев'ю з порівнянням між раундами. Цей інструмент закриває прогалину.

## 7. Тривожні сигнали

Серйозних проблем немає. Дрібні зауваження:

- **Один супровідник**: активний і залучений, але bus factor реальний при 477 зірках
- **Go 1.26+ для збирання з вихідного коду**: встановлення через Homebrew/бінарник не зачеплене; користувачі, що збирають з вихідного коду, можуть на це натрапити
- **Режим live нестабільний**: issue #557 явно позначає, що чекають на відгук спільноти
- **Один відкритий баг**: `@` в іменах файлів (#656, 2 тижні, не розв'язано, але окреслено)
- **У README не видно набору тестів**: немає бейджа CI чи задокументованої команди тестів
- **`agent_cmd` лише глобальний**: свідоме рішення з безпеки (не дає шкідливим репозиторіям перехопити вашого агента), але обмежує налаштування агента для окремого проєкту

Проблем із безпекою немає. Телеметрії немає. Видимих проблем ланцюга постачання немає.

## 8. Рішення щодо інтеграції

**ІНТЕГРУВАТИ** з оцінкою **4/5**: згадати в посібнику в розділі про людину в контурі та інструменти рев'ю.

**Куди інтегрувати**:
- Розділ про агентні воркфлоу і шаблони людського нагляду (розділ посібника про ітерацію і рев'ю)
- Розділ про екосистему сторонніх інструментів
- Можливо: виноска в розділах про мультиагентні воркфлоу / рев'ю планів

**Формат**: коротка згадка з посиланням і тим, що інструмент розв'язує унікально (diff між раундами, рев'ю плану перед виконанням, вебрев'ю з прив'язкою до DOM). Документувати весь набір функцій не потрібно, досить посилання на репозиторій GitHub. Однорядковий опис: «структурований інтерфейс inline-рев'ю між вами і Claude Code з diff між раундами ітерацій».

**Не пріоритет порівняно з основною роботою над посібником**, але акуратне доповнення під час наступного проходу по сторонніх інструментах.

## Підсумок

Бібліотека TypeScript для оркестрації ШІ-агентів програмування в ізольованих пісочницях. Надає програмний JS/TS API для запуску агентів (Claude Code, Codex, pi, opencode) у контейнерах Docker, Podman або Vercel Firecracker, із вбудованим керуванням стратегіями гілок і системою шаблонів промптів.

**Ключові можливості**:
- API `run()`, `createSandbox()`, `createWorktree()`, `interactive()` з автоматичним звільненням ресурсів (`await using`)
- Три стратегії гілок: `head` (прямий запис), `merge-to-head` (безпечна тимчасова гілка), `branch` (явна іменована гілка)
- Система промптів: підстановка `{{KEY}}` + динамічна ін'єкція контексту `` !`command` ``
- Захоплення та відновлення сесій для Claude Code (автозахоплення JSONL на хост)
- 5 шаблонів воркфлоу: blank, simple-loop, sequential-reviewer, parallel-planner, parallel-planner-with-review
- API власних провайдерів пісочниці (`createBindMountSandboxProvider`, `createIsolatedSandboxProvider`)

## Виклик від technical writer

Агент-опонент (Sonnet) рекомендував **знизити до 3/5** на підставі:

1. **Бар'єр лише TypeScript**: потребує налаштування `npx tsx`; виключає користувачів, що працюють насамперед із Python/shell; жоден інший інструмент у розділі не накладає такого обмеження
2. **Жорстка залежність від пісочниці**: має бути запущений Docker Desktop або Podman; провайдер Vercel тарифікується окремо; реальна перешкода для корпоративних/CI-середовищ
3. **Невідповідність моделі API-ключа**: використовує `ANTHROPIC_API_KEY` напряму, а не підписочну сесію Claude Code; витрати йдуть поза тарифікацією плану Max
4. **Архітектурна хибна класифікація**: це не «фреймворк оркестрації» в сенсі Ruflo; керує бінарним файлом `claude` як підпроцесом усередині контейнера (ближче до CI-запускача агентів)
5. **Активні несумісні зміни**: v0.5.x із відомим багом: шаблон Sequential Reviewer некоректно створює гілку

**Рекомендація**: лише запис Watch. Повна документація ввела б читачів в оману, коли вони оцінюють продакшен-інструменти.

**Прийнято**: оцінку встановлено на 3/5.

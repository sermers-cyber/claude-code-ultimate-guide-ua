## Вердикт

shunt — не компресор. Це делегатор: коли Claude намагається прочитати великий файл, hook блокує читання й спрямовує Claude до скрипту, який надсилає файли іншій моделі (за замовчуванням Gemini 2.5 Flash) через Spotify Portal. Claude отримує лише відповідь моделі-виконавця. Цифра 90% зі статті вимірює token, що потрапляють у контекст Claude, у трьох сценаріях читання. Вона не враховує token моделі-виконавця, точність відповідей чи додатковий хід, спричинений блокуванням.

Сам інструмент працює лише для клієнтів Portal. Portal — це керована комерційна пропозиція Backstage від Spotify: безкоштовний пробний період, далі ціни через відділ продажів, асистент AiKA включено ([Portal vs Backstage](https://info.backstage.byspotify.com/portal-vs-backstage)). Без екземпляра Portal hooks блокують читання, але делегування не спрацьовує.

Місце в посібнику заслуговує патерн, а не продукт: правило маршрутизації, яке забезпечує hook, замість рекомендаційного рядка в `CLAUDE.md`. Автор прямо про це каже: перша версія була блоком правил маршрутизації в `CLAUDE.md`, і "the rules were advisory, not enforced". Це також спростовує речення в посібнику, яке розглядало маршрутизацію моделей лише як техніку для API-конвеєрів.

## Як це працює, з джерелами

1. **Hook читання.** [`check-file-size`](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/hooks/check-file-size) запускається на кожен `Read`. Повне читання (без `offset`, без `limit`) файлу понад 350 рядків (`SHUNT_MIN_LINES`) блокується з причиною, що вказує на skill `/bulk-reader`.
2. **Bash hook.** [`check-bash-read`](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/hooks/check-bash-read) застосовує те саме правило до `cat`, `head`, `tail`, `less` і `more`, крім випадків, коли команда містить конвеєр (pipe) або `>`.
3. **Делегування.** [`bulk-read`](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/scripts/bulk-read) обгортає кожен файл тегами `<file path="...">`, додає запитання й викликає `portal-cli actions aika:invoke-chat` у режимі `bulk-reader`. [`code-write`](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/scripts/code-write) надсилає специфікацію й один еталонний файл у режим `code-writer` і може записати результат одразу на диск за допомогою `--target`.
4. **Транспорт.** [`aika.sh`](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/scripts/lib/aika.sh) передає запит через argv (стеля 400 КБ на macOS, 120 КБ на Linux), визначає режим за назвою (спершу власні режими, потім режими груп користувача, потім публічні) і відкидає будь-яку відповідь, де режим не було застосовано.

## Дефекти

Протестовано наживо через `claude --plugin-dir` на Claude Code 2.1.284 без екземпляра Portal, тож перевірено лише поведінку hooks.

| Дефект | Статус |
|---|---|
| Повний `Read` понад 350 рядків блокується; файл на 35 рядків читається нормально | Підтверджено наживо (працює за задумом) |
| PDF блокується як текст: `wc -l` нарахував 4 471 байт нового рядка в PDF, і `bulk-read` надіслав би двійковий файл моделі-виконавцю | Підтверджено наживо |
| Bash hook ігнорує будь-який шлях, що починається з `~`: `head -100 ~/…` проходить, а та сама команда з абсолютним шляхом блокується. Hook перевіряє `[ ! -f "$file_path" ]` на буквальному рядку ([рядок 33](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/hooks/check-bash-read#L33)), а `~` у лапках не розгортається | Підтверджено наживо; не покрито 51 eval репозиторію |
| `head -n 5 file` проходить, бо парсер сприймає `5` як ім'я файлу; `head -100 file` (читання 100 рядків) блокується | Задокументовано як відомий баг у власних evals репозиторію (`bash-hook-evals.json`, випадок 17) |
| `offset: 0` або `limit: 0` обходять hook читання, а саме повідомлення про блокування пропонує перечитати з `offset`/`limit` | Задокументовано в evals; hook спрямовує, а не примушує |
| Hooks виводять застаріле поле верхнього рівня `decision`. [Довідник hooks](https://code.claude.com/docs/en/hooks) зіставляє лише `"approve"` і `"block"`; `{"decision": "allow"}`, яке hooks виводять на кожному пропуску, не є задокументованим значенням | Видимої помилки в живому тесті немає. Чи воно ігнорується, чи трактується як схвалення, не перевірено |
| `code-write --target` записує через виклик Bash, тож hooks і правила дозволів, обмежені `Edit` і `Write`, не бачать файл, а Claude за задумом ніколи не читає згенерований код | Читання коду |
| Визначення режиму віддає перевагу режимам груп над публічними: режим колеги з назвою `code-writer` отримує ваші специфікації, а його вивід потрапляє у ваш репозиторій | README і `aika.sh`; не перевірялося на практиці |
| `npx --yes @spotify/portal-cli` запускає останню опубліковану версію CLI з вашими обліковими даними Portal, якщо глобального встановлення немає | Читання коду ([`aika.sh`, рядок 37](https://github.com/spotify/portal-ai-plugins/blob/3c24ca30ff63e1f5bbad1c43fe5324daff579123/plugins/shunt/scripts/lib/aika.sh#L37)) |
| Тайм-аут виклику в 180 секунд перевищує типові 120 000 мс інструмента Bash (`BASH_DEFAULT_TIMEOUT_MS`), тож довгі делегування спершу обриваються на боці Claude | Читання коду; не перевірялося на практиці |
| Без `jq` обидва hooks мовчки пропускають усе | Читання коду |

Що зроблено добре: skills робочого процесу Portal вимагають пробного запуску (dry run) і явного підтвердження перед будь-якою зміною й ніколи не просять облікові дані в чаті, `aika.sh` відокремлює stderr від JSON-обгортки й відхиляє відповіді без режиму, а README перелічує, чого plugin не делегує (налагодження, редагування, архітектурні рішення).

## Порівняння з наявним покриттям у посібнику

| Інструмент у посібнику | Рівень | Механізм | Відмінність від shunt |
|---|---|---|---|
| RTK | Вивід shell | Детерміновані локальні фільтри | Інший рівень: вивід bash — ~12% token сесії, читання файлів — ~65% |
| lean-ctx, tilth | Читання файлів | Локальне структурне стиснення (tree-sitter) | Той самий рівень. Скорочують token, не додаючи моделі й не відправляючи код за межі машини |
| Headroom | Вивід інструментів, структуровані дані | Локальне стиснення з відновленням без втрат | Оборотне; підсумки shunt — ні |
| Edgee | Шлюз між клієнтом і API | Стислість виводу, скорочення каталогу інструментів, обрізання результатів | Шлюз бачить увесь трафік; shunt бачить лише файли, які делегує |
| Субагент із `model: haiku` | Читання файлів, на вимогу | Нативне делегування в ізольованому контексті | Той самий патерн, код лишається в Anthropic, без додаткового постачальника. Не примусово, якщо hook не перенаправляє до нього |

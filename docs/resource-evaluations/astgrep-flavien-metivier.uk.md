## Короткий зміст

**Основні твердження**:

1. Claude Code використовував RAG (ембедінги Voyage), від якого відмовилися на користь grep/ripgrep
2. Причина: «агентний пошук перевершив усе інше» (не треба синхронізувати, не треба дбати про безпеку, простота)
3. Критика спільноти: «grep спалює 40% токенів на шум» (джерело: Milvus Blog)
4. ast-grep = необов'язковий плагін, потребує явного виклику
5. Коли використовувати ast-grep: міграції >100 тис. рядків, складний рефакторинг, патерни AST
6. Коли достатньо grep: «90% випадків», проєкти <50 тис. рядків
7. Філософія Anthropic: «Search, Don't Index»

## Оцінка впливу

**До інтеграції**:
- ast-grep: 0 згадок у посібнику
- Grep проти RAG: згадано «replaces RAG» без пояснення
- Критерії вибору: «коли що використовувати?» незрозуміло

**Після інтеграції**:
- ast-grep: повністю задокументовано (посібник + шаблон + довідник)
- Історія RAG→grep: пояснено з джерелами (подкаст Latent Space)
- Дерево рішень: порівняно 4 інструменти (grep/ast-grep/Serena/grepai)
- Користувачі знають, коли встановлювати ast-grep, а коли лишатися з grep

**Кому це корисно**:
- 📦 Тим, хто супроводжує великі кодові бази (>50 тис. рядків): ast-grep тепер є варіантом
- 🔧 Розробникам невеликих проєктів (<10 тис. рядків): підтверджено, що grep достатньо
- 🎯 Усім: чіткі критерії вибору замість міфів спільноти

## 📄 Підсумок змісту

Straude — соціальний дашборд для відстеження й поширення даних про власне споживання Claude Code. Інструмент надсилає локальну статистику використання (token, вартість, моделі) на спільну платформу з таблицею лідерів, серіями (streaks) і глобальним рейтингом.

**Технічний потік**:
1. Автентифікація OAuth через браузер → token зберігається в `~/.straude/config.json`
2. Збирання даних через `ccusage daily --json` (офіційний інструмент Claude Code) і `@ccusage/codex`
3. POST агрегованих даних на `https://straude.com/api/usage/submit`

**Дані, що надсилаються на сервер** (за день):
- Вартість у USD
- Token: input, output, cache creation, cache read, total
- Використані моделі (напр., `claude-sonnet-4-6`, `claude-opus-4-6`)
- Розбивка вартості за моделями
- Хеш SHA256 сирих даних ccusage
- `device_id`: випадковий UUID, згенерований під час першого використання
- `device_name`: ім'я хоста машини (напр., `prenom-macbook.local`)

**Що НЕ надсилається**: файли, вихідний код, розмови, ключі API.

## 🔍 Детальний аналіз безпеки

### Перевірка вихідного коду

Пакет перевірено безпосередньо з реєстру npm (`npm pack straude@0.1.9`), а скомпільовані файли прочитано повністю. Обфускації не виявлено.

**Архітектура** (20 файлів, 35 КБ без стиснення):

```
dist/
├── index.js              # CLI entry point
├── config.js             # DEFAULT_API_URL = "https://straude.com"
├── commands/
│   ├── login.js          # OAuth browser-based (poll + token save)
│   ├── push.js           # Collecte ccusage + POST /api/usage/submit
│   └── status.js         # GET /api/users/me/status
└── lib/
    ├── auth.js           # Lecture/écriture ~/.straude/config.json
    ├── api.js            # fetch() avec Bearer token
    ├── ccusage.js        # exec("ccusage daily --json")
    └── codex.js          # exec("npx @ccusage/codex daily --json")
```

### Позитивні моменти

- Token зберігається з правами `0600` (читання лише власником)
- Немає доступу до файлової системи поза `~/.straude/config.json`
- Немає демона чи системного закріплення (немає crontab, launchd, systemd)
- Навантаження обмежене агрегованими метриками, що узгоджується з описом
- Опція `--dry-run` для перегляду без надсилання

### Моменти, що потребують уваги

| Ризик | Рівень | Деталі |
|--------|--------|--------|
| Дуже свіжий проєкт | Середній | Створено 2026-02-18, 10 версій за 13 днів, немає зовнішнього аудиту |
| Надсилається ім'я хоста | Низький | `device_name = os.hostname()` → часто дає змогу ідентифікувати |
| Немає політики конфіденційності | Середній | На straude.com на цей момент немає жодної правової інформації |
| Дані на сторонньому сервері | Низький | Вартість і token частково публікуються (глобальний рейтинг) |
| Транзитивна залежність | Низький | Встановлює `@ccusage/codex@18` через npx без явного підтвердження |

### Вердикт щодо безпеки

**Шкідливого ПЗ чи зловмисної поведінки не виявлено.** Код читабельний, послідовний і робить те, що заявлено. Ризики — це ризики молодого інді-проєкту без історії: немає гарантій щодо тривалості існування сервісу, керування даними й конфіденційності метрик.

## 🔥 Перевірка

**Потенційні заперечення**:

1. «Чи заслуговує інструмент віком 13 днів на запис у посібнику?»

   Відповідь: так, за умови чіткого контексту щодо зрілості й ризиків — що й зроблено. Посібник уже документує свіжі інструменти (RTK). Аналіз безпеки додає цінності незалежно від самого інструмента.

2. «Чи прийнятне надсилання даних про використання третій стороні?»

   Відповідь: це вибір користувача, а не рішення посібника. Наша роль — чітко повідомити, що передається (зроблено), а не вирішувати замість користувача.

3. «Вихідний код не відкритий, лише скомпільований читабельний».

   Слушне зауваження. Зазначено як обмеження в картці. Скомпільований TypeScript без мініфікації залишається читабельним і придатним для аудиту, чого достатньо для поверхневого аналізу.

**Вердикт перевірки**: оцінку 3/5 збережено. Інтеграція обґрунтована із задокументованими запобіжниками.

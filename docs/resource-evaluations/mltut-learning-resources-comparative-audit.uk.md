# Порівняльний аудит ресурсів для вивчення Claude Code

**Дата аудиту:** 31 серпня 2026
**Прямий корпус:** 15 зовнішніх ресурсів, згаданих MLTUT
**Розширений корпус:** 34 інші навчальні ресурси з каталогу Awesome Claude Code
**Порівнювана референсна версія:** Claude Code Ultimate Guide v3.43.0

## Вердикт

Claude Code Ultimate Guide і далі лишається найкращим **загальним довідником** серед перевіреного корпусу. Жоден інший проаналізований посібник не поєднує такої глибини, такого покриття безпеки й продакшну, джерел, прикладів, machine-readable форматів і відстеження версій.

Проте це не найкращий **навчальний продукт** і не найкраще **поширюваний** посібник. Найкорисніші конкуренти сильніші в конкретних вимірах:

1. `claude-howto` значно краще знижує поріг першого знайомства. Маршрут із десяти модулів, самооцінювання, п'ять мов, діаграми та головна сторінка створюють відчуття негайного прогресу.
2. CC for Everyone і Bloom навчають зсередини Claude Code. Вони задають темп, зберігають стан прогресу й вимагають конкретних дій.
3. Курси Skilljar, Scrimba і кілька курсів Udemy розповідають про один наскрізний проєкт. Читач бачить, як застосунок проходить шлях від ідеї до розгортання, а не переглядає незалежні розділи.
4. `claude-howto` і Awesome Claude Code мають ширшу поверхню поширення: переклади, GitHub Trending, каталоги, китайські платформи, релізи, EPUB, слайди та ретрансляцію спільнотою.

Отже, головна проблема не в масовій нестачі тем. Це розрив між **чудовою енциклопедією** і **маршрутом, який легко почати, завершити й поширити**.

## Що насправді охоплює цей аудит

Аудит розрізняє чотири рівні доказів.

| Рівень | Корпус | Метод | Обмеження |
| --- | --- | --- | --- |
| A | Офіційна документація, публічні репозиторії | Читання machine-readable файлів, коду, посібників та історії Git | Знімок станом на 31 серпня 2026 |
| B | Публічні сторінки платних курсів | Читання програм, цілей і публічних розділів | Вміст відео й платних уроків не переглядався |
| C | Плейлист MLTUT | Назви, порядок і метадані 26 відео | Жодного транскрипту не отримано |
| D | 123 ненавчальні записи Awesome Claude Code | Класифікація за CSV-каталогом | Не всі 123 репозиторії прочитано окремо |

Розширений корпус містить 158 записів Awesome Claude Code. Тридцять п'ять із них віднесено до `Start Here` або `Documentation, Knowledge & Learning`. Оскільки цей посібник є одним із цих 35 записів, розглянуто 34 зовнішні навчальні ресурси.

## Аудит каталогу MLTUT

Стаття MLTUT корисна як точка для відкриття ресурсів, але не як технічне джерело.

### Виявлені проблеми

- Вона приписує `claude-howto` Constantin Shafranski, хоча репозиторій належить Luong Nguyen.
- Частина тривалостей, оцінок і обсягів курсів уже змінилася після публікації 12 квітня 2026.
- Комерційні й партнерські посилання не відокремлено від відтворюваної порівняльної методології.
- Стаття стверджує, що ресурси протестовано, але не публікує ні таблиці критеріїв, ні детальних оцінок, ні критеріїв відсіювання.
- Опис платного доступу, підписки й використання API змішує різні моделі оплати.

Висновок: MLTUT дає пристойний список, але не є аудитом. Висновки нижче ґрунтуються на доступних первинних джерелах, а не на його підсумках.

## Реальні прогалини посібника

### P0: актуальна офіційна документація

1. **Computer Use у Claude Code.** Потрібен окремий розділ про принцип роботи, обмеження, дозволи й межу довіри, відмінну від інструментів термінала й браузера.
2. **Рекомендації plugins.** Механізм `<claude-code-hint />` заслуговує на чітку документацію із зазначенням походження рекомендації та ризику непроханого впливу.
3. **Claude apps gateway.** Ця тема є лише в локальному відстеженні релізів. Тематичну сторінку слід створити, якщо офіційна документація підтвердить стабільну поверхню.

Критерій прийняття: кожне доповнення P0 має посилатися на актуальну офіційну документацію, розділяти задокументовану поведінку й припущення та бути проіндексованим у machine-readable форматах посібника.

### P1: методи, які можна перенести

1. **Best-of-N і голосування.** Згенерувати від трьох до п'яти незалежних рішень, оцінити їх за рубрикою, а потім вибрати найкраще або об'єднати. Посібник охоплює паралельність і панелі суддів, але не цей протокол як названий і повторно використовуваний метод.
2. **Журнал доказів `TESTING.md`.** Зберігати команди, результати, обмеження й неперевірені елементи в артефакті, який може прочитати людина або агент.
3. **Таксономія контексту.** Явно пов'язати poisoning, confusion, clash і застарівання з уже наявними засобами контролю. Це нестача навігації, а не чотири нові розділи.
4. **Формальна мапа runtime.** Показати на одній схемі побудову контексту, пул інструментів, hooks, субагентів, збереження стану й межі безпеки.

Критерій прийняття: метод має містити тригер, протокол, контрприклад, вартість і отриманий доказ.

### P2: обґрунтовані ніші

1. Встановлення на Android через Termux або віртуалізацію, разом із моделлю мобільних загроз.
2. Керування кількома акаунтами, лише з чіткими попередженнями щодо секретів, оплати й умов використання.
3. GitHub як приватна база знань, з обмеженнями щодо конфіденційності й пошуку.
4. Публікація artifacts у Claude.ai, лише після підтвердження в актуальному офіційному джерелі.

## Продуктові й педагогічні прогалини

Ці розриви, ймовірно, сильніше впливають на поширення, ніж чотири нові розділи.

### 1. Маршрут, що виконується в Claude Code

CC for Everyone, Bloom і RAG Learning Academy не просять читача обирати наступну сторінку. Вони зберігають стан, дають завдання, перевіряють результат і підлаштовують продовження.

Пропозиція: створити навчальний пакет, окремий від довідкового посібника.

- початкова діагностика на п'ять хвилин;
- маршрути Beginner, Practitioner, Production і Maintainer;
- вправи на реальному репозиторії;
- спостережувані критерії успіху;
- продовження після перерви;
- інтервальне повторення;
- таблиця опанування замість простого відсотка прочитаного.

### 2. Наскрізний проєкт

Курси Scrimba, Frank Kane і Maximilian Schwarzmüller виграють тому, що застосунок розвивається впродовж усього курсу.

Пропозиція: супровідний репозиторій, який починається з issue і закінчується перевіреним розгортанням, проходячи через `CLAUDE.md`, план, worktree, тести, hooks, субагентів, безпеку, CI і рев'ю.

### 3. Короткі блоки, якими легко поділитися

Основний посібник навмисно вичерпний. Йому потрібен фасад, що обіцяє завершені результати:

- «ваше перше перевірене виправлення за 15 хвилин»;
- «вибір між skill, subagent і MCP за 10 хвилин»;
- «створення й тестування hook за 20 хвилин»;
- «від розмитого запиту до доказу поставки за 30 хвилин».

### 4. Безперервна генерація маршрутів

`claude-code-docs` і RAG Learning Academy пов'язують вміст, індекс і актуальність.

Пропозиція: коли зміна в посібнику зачіпає навчальну ціль, CI має позначати уроки, тести, знімки екрана й вправи для перегляду. Вона не повинна оголошувати курс актуальним лише тому, що збірка проходить.

## Перевірка схожості та гіпотези копіювання

Гіпотезу про копіювання локального посібника доступні публічні дані не підтверджують.

1. `claude-howto` публічно з'явився приблизно на два місяці раніше за локальний посібник.
2. Сканування порівняло 106 англомовних Markdown-файлів посібника зі 109 англомовними файлами `claude-howto`.
3. Після вилучення блоків коду, сирих URL, Markdown-пунктуації та перекладів не знайдено жодного точного безперервного фрагмента завдовжки щонайменше 25 слів.
4. Із 7 053 нормалізованих заголовків посібника й 1 581 заголовка `claude-howto` точно збігаються лише 29. Вони загальні або продиктовані продуктом, наприклад `How it works`, `MCP Tool Search` чи номери версій.
5. Коефіцієнт Жаккара для заголовків становить 0,0034.

Цей метод може виявити масштабне дослівне запозичення. Він не виявляє перефразування і не доводить незалежного створення. Проте його достатньо, щоб відкинути звинувачення в масовому дослівному копіюванні в перевіреному корпусі.

Відчутна схожість, найімовірніше, має чотири причини: той самий задокументований продукт, ті самі офіційні джерела, ті самі поняття, задані Claude Code, і спільні конвенції технічних посібників.

### D. Перейняти стратегію поширення `claude-howto`, локальні матеріали реалізовано

Рекомендований порядок:

### E. Не роздувати основний посібник

Інструменти пам'яті, NotebookLM, Obsidian, альтернативні клієнти та фреймворки оркестрації мають і далі проходити процес оцінювання ресурсів. Мета не в тому, щоб поглинути весь Awesome Claude Code.

## Чого не варто імпортувати

- Загальний курс про API, RAG чи reranking в ядрі посібника з Claude Code.
- Воркфлоу для Excel, Gmail, Salesforce чи маркетингу так, ніби це прогалини посібника для розробників.
- Деталі з відтворених системних промптів як офіційні факти.

## Підсумок

Стаття стверджує, що для ефективної fullstack-розробки з Claude Code потрібні лише 3 основи (а не складні мультиагентні воркфлоу):

1. **Видимість налагодження на всьому стеку**: використовувати фонові завдання через `Ctrl+B` + Chrome DevTools MCP для автономної обробки помилок
2. **Доступ до документації, оптимізованої для LLM**: обстоює стандарт llms.txt замість MCP-серверів документації (заявлено ~10-кратне скорочення контексту)
3. **Вибір «упертого» (opinionated) фреймворку**: фреймворки з принципом convention-over-config зменшують кількість рішень, які має ухвалювати Claude (заявлено скорочення шаблонного коду на 60-80%)

Містить цитати Chris McCord (творця Phoenix), Andrej Karpathy та посилається на дослідження Chroma про context rot. Демонструє налаштування plugin для Wasp.

## Перевірка (technical-writer)

### Коригування оцінки: 3/5 (без змін)

### Пункти, пропущені в початковій оцінці

1. **Хибна дихотомія llms.txt проти MCP**: Стаття протиставляє їх, але вони доповнюють одне одного. Context7 = пошук під час виконання, llms.txt = заздалегідь оптимізована документація. Посібник має показати їхню взаємодоповнюваність.

2. **Не проведено зв'язок із CLAUDE.md**: «Convention-over-config для AI» = непрямий аргумент, що «уперті» фреймворки потребують менше промпт-інженерії в CLAUDE.md. Пов'язано з розділом 9.18 + розміром CLAUDE.md (рядок 3054).

3. **Недооцінено воркфлоу фонових завдань**: Найпрактичніша прогалина. Посібник перелічує Ctrl+B як комбінацію клавіш, але ніде не пояснює, КОЛИ й НАВІЩО її використовувати.

4. **Розділ 9.18 (фреймворк AX) уже частково охоплює тему**: Початкова оцінка вказала «нульове охоплення» для convention-over-config, але фреймворк Marmelab/AX уже охоплює концепцію. Потрібне виправлення.

### Ризики неінтеграції

**Від низьких до помірних**. Прогалини реальні, але їх можна закрити незалежно:
- llms.txt: найприкріша (у репозиторії є файл, але без пояснення)
- Воркфлоу фонових завдань: реальна UX-прогалина, але не критична
- Chrome DevTools MCP: нішево, без ризику

# Оцінка: CLI-інструменти liza-mas для економії токенів

**Джерело**: організація на GitHub [liza-mas](https://github.com/liza-mas) (Tangi Vass)
**Контекст**: згадано в коментарі в LinkedIn до серії Soufiane Keli про оптимізацію вартості токенів LLM для технічних команд
**Початково оцінено**: 2026-06-10
**Початковий оцінювач**: Claude Opus 4.8
**Переоцінено**: 2026-10-13, за публічною документацією та вибраними файлами реалізації й тестів

## Переглянуте рішення

Початкова оцінка сплутала навігацію в Markdown із генерацією змісту (TOC) і помилково прийняла npm-обгортку для розповсюдження за мову реалізації Stacklit. Вона також не врахувала цінності незалежно адресованих артефактів у паралельних worktrees. Ці помилки знецінюють початкове загальне відхилення та порівняння на основі runtime.

| Інструмент | Початкова оцінка | Переглянута оцінка | Рішення |
|------|---------------|---------------|----------|
| scip-search | 1/5 | 2/5 | Спеціалізований кандидат для навігації за символами в межах worktree |
| mdtoc | 1/5 | 3/5 | Придатний для обмеженого прикладу навігації в Markdown |
| functional-clusters | 1/5 | 2/5 | Спеціалізований дорадчий конвеєр кластеризації |
| stacklit-cli | 2/5 | 3/5 | Придатний для порівняння з upstream Stacklit з орієнтацією на CLI |

Ці оцінки визначають релевантність для посібника, а не готовність до продакшену. Це виправлення оновлює оцінки, їхній індекс і записи в списку спостереження; воно не додає нових розділів посібника. mdtoc і stacklit-cli відповідають умовам для розгляду за політикою оцінки 3. Їхню практичну користь мають визначати репрезентативні завдання агента, а не поріг кількості зірок на GitHub.

Виправлення фреймворку від 2026-09-01 досі чинне: [профілі інструментарію](https://github.com/liza-mas/liza/blob/a22c12381c5d884d2586a48aaaa517bca184f9cf/support-docs/TOOLCHAIN.md) Liza надають необов'язкові утиліти, а її [контракт інструментів агента](https://github.com/liza-mas/liza/blob/a22c12381c5d884d2586a48aaaa517bca184f9cf/contracts/AGENT_TOOLS.md) передбачає резервні варіанти. Самостійна цінність і необов'язковість — окремі питання.

## Підтримка worktree та актуальність індексу

Ці інструменти використовують файли або явно вибрані артефакти, а не вимагають одного змінного індексу для всіх робочих копій. Механізм відрізняється залежно від інструмента:

| Інструмент | Задокументований механізм | Межа |
|------|----------------------|----------|
| scip-search | Явний шлях `--index`; `reroot` копіює наявний індекс SCIP з новим коренем проєкту | Перенесення кореня підходить для робочої копії того самого дерева. Воно не переіндексовує змінені вихідні файли |
| mdtoc | Читає передані файли Markdown безпосередньо | Немає постійного індексу для синхронізації; діапазони описують прочитаний файл |
| stacklit-cli | Генерує JSON-артефакт робочої копії та приймає явні шляхи вводу/виводу | Після змін регенерація залишається потрібною. Необов'язковий рецепт post-commit пропускає шляхи під `.worktrees`, тож не оновлює ці worktrees автоматично |
| functional-clusters | Приймає явні шляхи до експорту графа SCIP та експорту архітектури Stacklit | Артефакти мають описувати потрібну робочу копію; незалежні файли не гарантують актуальності |

Джерела: [паралельні індекси SCIP і перенесення кореня](https://github.com/liza-mas/scip-search/blob/16384a7564ec9b5cf93580c26e4a76618242ee53/README.md), [поведінка mdtoc](https://github.com/liza-mas/mdtoc/blob/37712275e36b5aef9c9651e633b1896e22d917f3/README.md), [рецепт оновлення Stacklit CLI](https://github.com/liza-mas/stacklit-cli/blob/3c0e04153fe10dde2eeb4ddff72417c7621d5436/USAGE.md), [вхідні дані Functional Clusters](https://github.com/liza-mas/functional-clusters/blob/f1ac506508752660214d4a6d35fd33113177a482/README.md).

[Реалізація ключа кешу](https://github.com/MinishLab/semble/blob/0e5e02832ae0340c0feb637d2b7213fe065571fd/src/semble/cache.py) Semble хешує розв'язаний шлях проєкту. Отже, різні каталоги worktree вибирають різні кеші індексу. Спільний каталог кешу не є одним спільним індексом проєкту. Див. виправлену [оцінку Semble](./semble-code-search.uk.md).

Порівняльного огляду, який би встановив, що більшість конкурентних індексаторів потребують централізованого індексу, не проводилося. Сумісність із worktree, повторне використання індексу, актуальність і паралельний запис потребують окремих доказів.

## Аналіз за інструментами

### scip-search

**Репозиторій**: [liza-mas/scip-search](https://github.com/liza-mas/scip-search)
**Мова / ліцензія**: Go / Apache-2.0

SCIP Search виконує запити до заздалегідь побудованих артефактів SCIP щодо визначень, посилань, реалізацій і навігації на основі графа. Його [командний інтерфейс](https://github.com/liza-mas/scip-search/blob/16384a7564ec9b5cf93580c26e4a76618242ee53/README.md) підтримує незалежно вибрані індекси та перенесення кореня для worktree. Індексатори мов — окремі залежності.

Початкова оцінка надто вільно об'єднала його із семантичним пошуком і живою навігацією через LSP. Артефакт SCIP можна вибрати й скопіювати незалежно від запущеного редактора чи сервісу. Водночас індекс може бути застарілим, а статичні результати графа/впливу не встановлюють повного графа викликів під час виконання.

**Оцінка: 2/5.** Модель артефактів дає конкретний спеціалізований сценарій використання. Ширша рекомендація потребує репрезентативного порівняння зусиль на індексацію, обробки актуальності та точності навігації. Історична кількість зірок у перший день не визначає технічних переваг.

### mdtoc

**Репозиторій**: [liza-mas/mdtoc](https://github.com/liza-mas/mdtoc)
**Мова / ліцензія**: Go / Apache-2.0

mdtoc видає діапазони джерела та ієрархічні селектори `mdq` для заголовків Markdown у стилі ATX. Його [парсер](https://github.com/liza-mas/mdtoc/blob/37712275e36b5aef9c9651e633b1896e22d917f3/internal/mdtoc/toc.go) відстежує огороджені блоки, обчислює кінці розділів за рівнями заголовків, будує шляхи предків і позначає дублікати шляхів селекторів. Його [тести](https://github.com/liza-mas/mdtoc/blob/37712275e36b5aef9c9651e633b1896e22d917f3/internal/mdtoc/toc_test.go) охоплюють виключення огородженого коду, батьківські діапазони, дублікати шляхів і екранування. Ці файли переглянуто, але тут не запускали.

Простий регулярний вираз для заголовків може збігатися з коментарями shell усередині огороджених прикладів і залишає обчислення кінця розділу та відновлення батьківського шляху викликачеві. [Довідник інструментів](https://code.claude.com/docs/en/tools-reference) Claude Code документує читання файлів, пошук за шаблоном і операції мовного сервера. Ці примітиви самі по собі не забезпечують контракту розділів Markdown, який дає mdtoc. Агент може написати скрипт з еквівалентним парсингом або прочитати весь файл, але це не доводить, що утиліта не має цінності.

Той самий вивід CLI можуть споживати Claude Code, Codex чи інший агент. Його релевантність походить від цілеспрямованої навігації документами, а не від потреби в hook, специфічному для Claude. Заголовки Setext лежать поза задокументованим обсягом, а сумісність селекторів залежить від `mdq`. Економію токенів і зменшення помилок агента тут не вимірювали.

**Оцінка: 3/5.** Конкретне доповнення для агентів, що навігують довгими специфікаціями. Замінити початкове відхилення розглядом короткого прикладу, що порівнює збіги регулярного виразу, розібрані діапазони та цілеспрямоване читання.

### functional-clusters

**Репозиторій**: [liza-mas/functional-clusters](https://github.com/liza-mas/functional-clusters)
**Мова / ліцензія**: Go / Apache-2.0

[Поточний контракт](https://github.com/liza-mas/functional-clusters/blob/f1ac506508752660214d4a6d35fd33113177a482/README.md) споживає один або кілька JSON-файлів `scip.graph-export.v1` і JSON-файл `stacklit.architecture-export.v1`, а потім створює дорадчі кластери. [CLI](https://github.com/liza-mas/functional-clusters/blob/f1ac506508752660214d4a6d35fd33113177a482/internal/cli/root.go) надає `build`, `list` і `explain`.

Залежність стосується артефактів із визначеними схемами. Споживачам не потрібно, щоб upstream-інструменти працювали під час кожного запиту. Вихідний код і фікстури уможливлюють ізольовану оцінку — всупереч початковому твердженню, що його неможливо оцінити незалежно. Генерація свіжих вхідних даних залишається частиною наскрізної оцінки.

**Оцінка: 2/5.** Спеціалізований конвеєр, який можна перевірити, з більшою підготовкою, ніж прямий пошук. Переглянутий матеріал не встановлює, чи покращують його кластери навігацію агента або чи визначають функціональні межі на репрезентативних репозиторіях.

### stacklit-cli

**Репозиторій**: [liza-mas/stacklit-cli](https://github.com/liza-mas/stacklit-cli)
**Мова / ліцензія**: Go / MIT

stacklit-cli — форк [glincker/stacklit](https://github.com/glincker/stacklit), чия [реалізація вже на Go](https://github.com/glincker/stacklit/blob/master/go.mod). npm-пакет upstream розповсюджує бінарний файл. Відмінність полягає в інтерфейсі CLI та розширеннях, а не в перенесенні реалізації з Node на Go.

[Документація форку](https://github.com/liza-mas/stacklit-cli/blob/3c0e04153fe10dde2eeb4ddff72417c7621d5436/README.md) та [реєстрація команд](https://github.com/liza-mas/stacklit-cli/blob/3c0e04153fe10dde2eeb4ddff72417c7621d5436/internal/cli/root.go) підтверджують такі відмінності:

- Колишні MCP-запити стали командами CLI, як-от `find-module` і `get-dependencies`. Форк прибрав поверхню MCP/налаштування. Інтеграція з Claude Code — це ручна інструкція прочитати індекс, а не автоматична конфігурація.
- `init-insights` і `ai-summary` підтримують куровані метадані, які включає `generate-json`. `derive --ai-summary` читає збережений підсумок. Задокументований воркфлоу спершу готує чернетку свіжих insights, а потім узгоджує наявні в одній сесії агента; цей порядок задається prompt, а не бар'єром доступу.
- Парсинг використовує налаштовуваний пул воркерів зі значенням за замовчуванням 3 і можливістю перевизначення на рівні команди. [Тести рушія](https://github.com/liza-mas/stacklit-cli/blob/3c0e04153fe10dde2eeb4ddff72417c7621d5436/internal/engine/engine_test.go) порівнюють нормалізований вивід за різної кількості воркерів. Їх переглянуто, але тут не запускали. [Файл залежностей](https://github.com/liza-mas/stacklit-cli/blob/3c0e04153fe10dde2eeb4ddff72417c7621d5436/go.mod) використовує gotreesitter v0.53.0.
- `export-architecture` читає наявний індекс і записує схему, яку використовує Functional Clusters. `diff` розрізняє актуальний індекс (0), застарілі джерела (1) і збій команди (2).

[Опублікований бенчмарк воркерів](https://github.com/liza-mas/stacklit-cli/blob/3c0e04153fe10dde2eeb4ddff72417c7621d5436/specs/benchmarks/map-reduce/benchmark-report.md) документує ранішу реалізацію та приватне навантаження. Він не встановлює продуктивності індексації поточного форку після оновлення парсера. Пізніші покращення продуктивності, про які повідомляє мейнтейнер, не мають відповідного публічного бенчмарку в переглянутих матеріалах і тут незалежно не відтворювалися. Гучні твердження про скорочення токенів також залишаються неперевіреними. Налаштування воркерів і оновлення парсера не слід зводити до однієї виміряної причини.

**Оцінка: 3/5.** Інтерфейс, воркфлоу insights та експорт архітектури дають окрему цінність для обмеженого порівняння. Попередня інтеграція не звільняє upstream від того самого стандарту доказів. Повна рекомендація потребує репрезентативних навігаційних завдань і відтворюваних вимірювань, а не 50 зірок.

## Виклик і межі доказів

Початковий виклик прийняв upstream Stacklit, бо його вже було інтегровано, і відкинув форк через низьку популярність. Це було непослідовно. Ця переоцінка запитує, що дає кожна утиліта, що агентові все ще доводиться робити самому і які покращення виміряно.

Перевірка вихідного коду підтверджує виправлені інтерфейси й межі артефактів. Вона не доводить коректності паралельної роботи, прийняття агентами, придатності до продакшену чи економії токенів. У середовищі цього рев'ю не було Go, тож жодних тестів Go чи перевірок поведінки CLI не запускалося. Визначення тестів документують заплановане покриття, а не успішний результат цього рев'ю.

| Кандидат | Потрібне наступне порівняння |
|-----------|------------------------|
| mdtoc | Довгий Markdown з огородженими коментарями, вкладеними заголовками та дублікатами; порівняти коректність і загальну кількість токенів агента з регулярним виразом плюс цілеспрямованим читанням |
| stacklit-cli | Upstream і форк на тих самих публічних репозиторіях; порівняти видобування, обробку актуальності, фактичний час, пікову пам'ять і успішну навігацію агента |
| scip-search / functional-clusters | Два розбіжні worktrees з окремо регенерованими артефактами; перевірити шляхи, актуальність і корисність навігації чи кластеризації |

[Список спостереження](./watch-list.uk.md) відстежує mdtoc і stacklit-cli в очікуванні цих порівнянь. Це виправлення не передбачає нового розділу посібника чи рекомендації для продакшену.

## Що це таке

Semble — інструмент семантичного пошуку на Python з нативним MCP-сервером для Claude Code. Він шукає по коду, документації та файлах конфігурації в репозиторії. Під час першого запуску він будує локальний індекс за допомогою ембедингів Model2Vec плюс ранжування BM25, об'єднаних через RRF (Reciprocal Rank Fusion). Наступні пошуки використовують закешований індекс.

Ключові факти, перевірені за репозиторієм:

| Атрибут | Деталі |
|-----------|---------|
| **Зірки** | ~5 000 (станом на 2026-07-28 — 5 718, MIT, активна розробка) |
| **Встановлення** | `pip install semble`, потім `semble mcp` |
| **Інтеграція з MCP** | Нативний сервер, без проміжного шару-обгортки |
| **Потребує Ollama** | Ні. Model2Vec працює лише на CPU, без зовнішнього сервісу |
| **Індекс** | Будується під час першого запуску, кешується автоматично. НЕ без індексу (це виправляє поширену хибну думку в дописах спільноти). |
| **Охоплення** | Код + документація + файли конфігурації |
| **Заявлена економія** | Твердження постачальника з опису репозиторію (MinishLab/semble, прочитано 2026-09-30): "Uses 99% fewer tokens than grep+read". Знаменник: робочий процес grep + читання файлів. Тут незалежно не вимірювалося |

## Semble потребує індексу й може розділяти кеші worktree

Початкова оцінка відкинула опис «без індексу, отже сумісний із worktrees». Передумова про відсутність індексу хибна: Semble будує й кешує індекси. Висновок, що індексування робить його несумісним із worktrees, теж був хибним.

[Поточна реалізація кешу](https://github.com/MinishLab/semble/blob/0e5e02832ae0340c0feb637d2b7213fe065571fd/src/semble/cache.py) хешує розв'язаний шлях кожного локального проєкту, а потім вибирає індекс у каталозі кешу цього проєкту. Тому різні каталоги worktree отримують окремі кеші навіть тоді, коли батьківське розташування кешу спільне. Кожному каталогу потрібна власна початкова побудова; це вартість налаштування, а не несумісність. Цей огляд вихідного коду встановлює розділення за шляхом, але не є тестом під час виконання для одночасного індексування чи пошуку в розбіжних worktrees.

Корисною відмінністю від задокументованого налаштування grepai залишається відсутність сервісу Ollama, а не відсутність індексу. Тут немає підстав стверджувати, що більшість інших індексаторів вимагають одного спільного індексу для всіх worktrees.

Жоден зміст посібника не повинен описувати Semble як інструмент без індексу.

## Порівняння із задокументованими альтернативами

| Аспект | grepai | Semble |
|--------|--------|--------|
| Семантичний пошук | Так (Ollama + nomic-embed-text) | Так (Model2Vec, лише CPU) |
| Інтеграція з MCP | Через інструменти MCP (CLI grepai обгортається в MCP) | Нативний MCP-сервер |
| Потребує зовнішнього сервісу | Так (локально запущений Ollama) | Ні |
| Пошук по коду | Так | Так |
| Пошук по документації | Ні (лише код) | Так |
| Пошук по конфігурації | Ні | Так |
| Зірки | Н/д (CLI-інструмент, рахується інакше) | ~5 000 |
| Потрібен індекс | Так | Так (кешується після першого запуску) |

**Справжня відмінність**: користувачі, які не запускають Ollama локально, отримують семантичний пошук без жодних зовнішніх залежностей. Ширше охоплення (код + документація + конфігурація) — додаткова перевага над grepai.

## Перевірка прецеденту: відхилення qmd (оцінка 2/5)

Раніше посібник відхилив qmd (Simone Ruggiero) з обґрунтуванням «надлишковий порівняно з grepai, твердження неможливо перевірити». Чи застосовна та сама логіка до Semble?

Ключові відмінності:
- **Популярність**: qmd мав незначне впровадження спільнотою. Semble має ~5k зірок.
- **Перевірність тверджень**: твердження qmd неможливо було перевірити. Semble має відкритий код і конвеєр індексування, який можна протестувати.
- **Модель залежностей**: qmd був CLI-інструментом, що прямо перетинався з grepai. Semble розв'язує проблему залежності від Ollama, яка стосується ~40% користувачів CC (тих, хто не має локального GPU або не хоче запускати Ollama).
- **Охоплення**: qmd шукав лише по коду, як і grepai. Semble додає документацію та конфігурацію.

Прецедент qmd закликає до обережності, а не до відхилення. Semble знімає конкретні заперечення, через які провалився qmd.

## Оцінка перевірки

**Позиція агента-перевіряльника**: оцінку слід знизити до 2/5, бо «два інструменти семантичного пошуку на основі індексу в одному розділі створюють надлишковість і плутанину для читача».

**Контраргумент**: посібник уже документує кілька інструментів із перетином можливостей у багатьох розділах (кілька MCP-серверів, кілька інструментів стиснення). Політика полягає в тому, щоб документувати інструменти, які служать суттєво різним аудиторіям або стекам залежностей. Користувач, який не може чи не хоче запускати Ollama, сьогодні не має в посібнику шляху до семантичного пошуку. Semble і є таким шляхом. Запис має бути коротким і явно позиціонованим як «якщо ви не використовуєте Ollama», а не як заміна grepai.

**Оцінку збережено: 3/5.** Запис слід позиціонувати як доповнення, а не конкурента.

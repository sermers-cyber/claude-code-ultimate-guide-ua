## Підсумок

Addy Osmani описує зміну парадигми: від синхронної взаємодії з одним агентом до асинхронної оркестрації кількох спеціалізованих агентів. Охоплює субагентів, Agent Teams (експериментально), запобіжники циклів, патерн окремого рев'юера, бюджетування токенів, маршрутизацію між моделями та огляд ландшафту інструментів 2026 року. Побудовано навколо «фабричної моделі» для продакшен-воркфлоу з кількома агентами.

**Ключові тези**:
- Три зміни ментальної моделі: Conductor → Orchestrator, стеля одного агента (контекст, спеціалізація, координація), асинхронні команди зі спільним списком завдань і обміном повідомленнями між рівними
- Запобіжник циклу `MAX_ITERATIONS=8` + обов'язковий промпт-рефлексія перед повторними спробами
- Окремий тімейт `@reviewer`: Opus 4.6, лише читання, автоматичний запуск за TaskCompleted, 1 на 3-4 будівельників
- Дослідження ефективності AGENTS.md (Gloaguen et al., ETH Zurich, arXiv 2602.11988): згенерований LLM = -3% успішності, +20% витрат; написаний людиною = +4% покращення
- Бюджетування токенів на агента: жорсткі ліміти, автопауза на 85%, зупинка після 3+ застрявших ітерацій
- Ландшафт інструментів 2026: 3 рівні (всередині процесу, локальні оркестратори, хмарні асинхронні)
- Центральне вузьке місце: «Generation is no longer the bottleneck. Verification is.»

## Рекомендації щодо інтеграції

### 1. Статистика успішності AGENTS.md (пріоритет: високий)
**Файл**: `guide/ultimate-guide.md`, розділ AGENTS.md, біля рядка 4620
**Дія**: додати дані про успішність із Gloaguen et al., яких бракує в поточному цитуванні в UG:16924 (там згадано лише накладні витрати +20-23%):
- AGENTS.md, згенерований LLM: -3% успішності
- AGENTS.md, написаний розробником: +4% покращення успішності
**Примітка**: не додавати як новий зміст, а розширити наявне цитування Gloaguen у посібнику.

### 2. Запобіжник циклу MAX_ITERATIONS (пріоритет: високий)
**Файл**: `guide/workflows/agent-teams.md`, розділ Reliability
**Дія**: додати як іменований патерн із конкретною конфігурацією:
```bash
MAX_ITERATIONS=8  # per teammate
# Before retry: "What failed? What specific change would fix it?"
# Kill and reassign if stuck 3+ iterations
```
У посібнику цього наразі немає, хоча в продакшен-командах агентів це потрібно часто.

### 3. Окремий тімейт @reviewer (пріоритет: середній)
**Файл**: `guide/workflows/agent-teams.md`, розділ Architecture
**Дія**: додати патерн рев'юера з конкретною конфігурацією:
- Модель: Claude Opus 4.6 (лише читання)
- Інструменти: лише lint, test, security-scan
- Тригер: автоматично на кожну подію TaskCompleted
- Співвідношення: 1 рев'юер на 3-4 будівельників
Концепція агентів-рев'юерів у посібнику є; цієї конкретної конфігурації немає.

### 4. Бюджетування токенів на агента (пріоритет: середній)
**Файл**: `guide/workflows/agent-teams.md` або `guide/core/context-engineering.md`
**Дія**: додати конкретний патерн токенного бюджету:
- Призначати бюджети за доменами (наприклад, Frontend 180k, Backend 280k)
- Автопауза на 85% бюджету
- Зупинка й перепризначення після 3+ застрявших ітерацій
Наразі в посібнику це лише на концептуальному рівні; тут додається деталь реалізації.

### 5. Конфлікт назв Ralph Loop (пріоритет: середній)
**Файли**: `guide/ultimate-guide.md:1899`, `guide/core/glossary.md:106`
**Дія**: пояснити, що «Ralph Loop» у спільноті вживається для двох різних патернів:
- Geoffrey Huntley: ротація свіжого контексту через bash-цикл (керування контекстом)
- Osmani / ширша спільнота: цикл ітерації атомарних завдань (координація кількох агентів)
Додати примітку-розрізнення, щоб не плутати читачів.

### 6. Ландшафт інструментів 2026 (пріоритет: низький, лише спостереження)
**Файл**: `guide/ecosystem/third-party-tools.md`
**Дія**: відкласти інтеграцію. Conductor, Vibe Kanban, Claude Code Web, Jules, Codex Web станом на березень 2026 є передрелізними або експериментальними. Додавати з обов'язковою датою й приміткою про стабільність, коли підтвердиться стабільність. Інакше обслуговування надто обтяжливе.

## Нотатки до виклику

Рецензія-виклик (technical-writer agent) порушила такі пункти, усі підтверджено:

1. **Конфлікт назв Ralph Loop**: підтверджено через Grep. Посібник має патерн Geoffrey Huntley в UG:1899; Osmani вживає той самий термін для іншого патерну. Потрібне розрізнення.
2. **Ризик дублювання статистики AGENTS.md**: Gloaguen et al. уже цитується в посібнику (UG:16924) щодо витрат; статистики успішності (-3%/+4%) бракує. Часткова інтеграція доречна.
3. **Надлишковість 8-рівневого фреймворку**: посібник уже інтегрує 6-рівневий фреймворк зрілості агентів Martignole. 8-рівневий фреймворк Osmani концептуально перетинається. Не додавати як конкурентний фреймворк.
4. **Нестабільність ландшафту інструментів**: підтверджено: кілька наведених інструментів є передрелізними або мають невизначені плани розвитку. Позначено «лише спостереження».
5. **Прапорець конфлікту інтересів**: Osmani є керівником у Google Cloud AI. Його подання екосистеми Claude Code не є нейтральним. Зміст фактичний, але його не слід подавати як архітектуру, рекомендовану Anthropic, без підтвердження з інших джерел.

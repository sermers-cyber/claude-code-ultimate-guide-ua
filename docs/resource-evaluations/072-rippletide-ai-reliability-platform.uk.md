# Оцінка ресурсу №072: Rippletide: платформа надійності ШІ

**Джерело:** [Документація Rippletide](https://rippletide.com) / [llms-full.txt](https://rippletide.com/llms-full.txt)
**Тип:** офіційна документація — SaaS-платформа (eval, персистентна пам'ять, детерміноване міркування)
**Оцінено:** 2026-02-28

---

## 📄 Підсумок змісту

Rippletide — платформа надійності ШІ, побудована на трьох стовпах:

1. **Eval**: виявлення галюцинацій, CLI, що встановлюється через `npx rippletide`, інтеграція з CI/CD, knowledge sources (локальні файли, Pinecone, PostgreSQL)
2. **Context Graph**: персистентна пам'ять між сесіями, що надається через MCP server (7 інструментів, 4 ресурси), сумісна з Claude Code, Claude Desktop, Cursor і VS Code
3. **Decision Runtime**: детерміноване міркування через hypergraph (структуровані Q&A, теги, дії, предикати стану), внутрішнє твердження: «<1% галюцинацій»

**Точки інтеграції з Claude Code:**
- Задокументована конфігурація `.mcp.json` для підключення MCP server Rippletide
- Можливий self-hosted (Node.js >= 18, розгортання Railway в один клік)
- Інтеграція LangChain (drop-in LLM)
- Доступний конектор Amazon Bedrock

**Фінальна оцінка: 2/5**

**Обґрунтування:** Rippletide охоплює реальний сценарій (персистентна пам'ять між сесіями через MCP), але лишається сторонім SaaS-продуктом без помітного прийняття спільнотою. Посібник уже докладно документує MCP servers і перелічує патерни інтеграції. Rippletide був би щонайбільше згадкою в списку сторонніх MCP-серверів, а не окремою темою. Твердження про продуктивність неперевірювані («<1% галюцинацій», «85% → 96% resolution rate») без опублікованої методології. Ціноутворення не задокументовано. Немає зірок GitHub чи метрик Discord.

## 📍 Рекомендації

**Дія: не інтегрувати (оцінка 2 = мінімальна згадка або лише спостереження)**

1. **Чому не інтегрувати напряму**: посібник уже охоплює MCP servers і патерни інтеграції. Додавання Rippletide не дало б чистої цінності порівняно з наявним контентом — це був би список сторонніх серверів, а не концепція, якій можна навчати
2. **Можливий виняток**: якщо Rippletide здобуде прийняття й опублікує перевірювані бенчмарки, кут «eval CLI для CI/CD» (стовп 1) стане релевантним для розділу тестування/якості посібника
3. **Позитив, який варто зберегти**: `llms.txt` Rippletide — гарний приклад структурованої документації для споживання LLM, релевантний для розділу machine-readable посібника

**Чого НЕ слід робити:**
- Не цитувати твердження про продуктивність без перевірюваного джерела
- Не створювати окремий розділ про сторонні платформи надійності ШІ (надто широко, поза обсягом)

## 🔥 Виклик (technical-writer)

**Початкова запропонована оцінка:** 2/5
**Оцінка після виклику:** 2/5 (збережено)

**Аргументи за підвищення оцінки:**

1. **Нативний MCP server**: Rippletide надає справжній MCP server із 7 задокументованими інструментами, сумісний із Claude Code. Це конкретика, а не лише маркетинг
2. **Унікальний eval CLI**: `npx rippletide` для виявлення галюцинацій у CI/CD — сценарій, якого немає в посібнику. Реальна прогалина
3. **Зразковий llms.txt**: структурована документація для споживання LLM, цінність для розділу machine-readable

**Чому оцінка лишається 2/5:**

- Кут MCP охоплено: посібник документує патерни MCP, а не окремі сервери. Список Rippletide серед сторонніх серверів не дає контенту, якому можна навчати
- Кут eval CI/CD потенційно цікавий, але джерело — маркетинг комерційного продукту без зовнішньої валідації. Цитувати твердження «<1% галюцинацій» без опублікованої методології було б фактичною помилкою через асоціацію
- llms.txt можна відзначити як приклад доброї практики, але це маргінальна згадка в наявному розділі, а не новий контент

**Конструктивна критика:**
> «Кут eval CLI — єдина реальна прогалина. Але будувати розділ посібника на маркетингових твердженнях SaaS без помітної тяги було б помилкою. Якщо Rippletide опублікує бенчмарки або досягне вимірюваного прийняття, переоцінити.»

# Локальні поверхні рев'ю для змін, написаних агентами (glassbox, diffo, hunk, drift, ai-pr-review, guidedreview)

**Переглянуто**: 2026-11-08. **Оцінки**: diffo 4/5, glassbox 3/5, hunk 3/5, drift 3/5, ai-pr-review 2/5, guidedreview 2/5. Інтегровано в [Рев'ю коду з кількома провайдерами](../../guide/workflows/multi-provider-code-review.uk.md#локальні-поверхні-ревю-для-змін-написаних-агентом) і як діаграму в [Воркфлоу розробки](../../guide/diagrams/06-development-workflows.uk.md#три-місця-де-пояснюється-зміна-агента). Пов'язане: [Resisting Cognitive Surrender](knlb-cognitive-surrender.uk.md), [трейси походження агентних змін](agent-provenance-traces.uk.md).

Ці інструменти стоять між агентом і форжем: розробник запускає їх локально, щоб прочитати зміну агента до або під час рев'ю. П'ять прочитано статично з клону; guidedreview прочитано лише за README. Нічого не встановлювали й не запускали, тож уся описана нижче поведінка — це те, що кажуть код або документація, а не спостережуваний результат.

## Що робить кожен інструмент

**diffo (4/5).** Агент пише власне обґрунтування через CLI (`diffo comment`, `diffo layers`, `diffo reply`) і публікує впорядкований список шарів (заголовок, підсумок, файли, рішення). Коментарі прив'язуються до ідентифікатора hunk, що адресується за вмістом (обрізаний SHA-256 від шляху, змінених рядків і порядкового номера входження), а за потреби відкочуються до hunk, що охоплює той самий рядок, потім до файлу, потім до всієї зміни. `diffo poll` повертає агентові треди рев'юера, кожен із типом Change або Question та різним контрактом відповіді. Лише GitHub, через `gh`. Анонімна телеметрія PostHog увімкнена за замовчуванням. Сховище — одна база SQLite через експериментальний `node:sqlite` у Node. Це єдиний із прочитаних інструментів, що замикає цикл типізованим зворотним зв'язком.

**glassbox (3/5).** Агент записує нотатки через `glassbox note add`, дотримуючись інструкцій, які видає `glassbox note instructions` і які вставляє сесія-оркестратор; жоден hook цього не примушує. Нотатки мають тип (обґрунтування, доказ, припущення, розглянута альтернатива, ризик тощо) і зберігаються як SARIF 2.1.0, по одному файлу на вихідний файл у `.pr-notes/`, версіоновані разом із кодом. Прив'язка порядкова: нотатку повторно прив'язують, шукаючи перший рядок збереженого фрагмента в межах 50 рядків. Записаний хеш відбитка для повторної прив'язки не використовується. Нотатки рендеряться під прив'язаним рядком. Людські анотації експортуються у файл рев'ю, який читає агент. Інтеграції з форжем у `src/` не знайдено; `plugins/` і `scripts/` не читали.

**hunk (3/5).** Термінальний переглядач diff. Агент коментує в живій сесії (`hunk session comment add`) або через JSON-файл супроводу з `oldRange`, `newRange`, `summary`, `rationale`, `confidence`. Прив'язки м'яко розв'язуються до поточного hunk, тож нотатка ніколи не губиться; відстеження зсуву рядків немає. Агент може читати людські нотатки й відповідати на них, але не редагувати їх. Читає diff з GitHub; нічого не публікує у форж. Розширення, передані прапорцем або в конфігурації користувача, запускаються без запиту на довіру.

**drift (3/5).** Термінальний інтерфейс на Rust, що взагалі не показує пояснень від ШІ; текст поруч із diff — це обговорення з форжу. Це єдиний із прочитаних інструментів, який підтримує GitLab, через `glab api`: він відтворює `position` обговорення з `diff_refs` merge request (доданий рядок `new_line`, видалений рядок `old_line`, контекстний обидва) і позначає обговорення, чий `position.head_sha` відрізняється від поточного head, як застаріле, а не відкидає його. Він надсилає вибраний діапазон коду разом з інструкцією агентові, що працює в іншій панелі tmux, herdr або cmux.

**ai-pr-review (2/5).** Модель постфактум пише структурований огляд на основі diff, комітів, опису й коментарів; міркування агента-автора їй недоступні. Код перевіряє результат: діапазони рядків щодо diff, цитати `path:line` щодо дерева на head-коміті, до 3 раундів виправлення. На прочитаному SHA перевірка порад рев'ю запускала Codex в одноразовому worktree з `workspace-write`, `network_access=true` і політикою схвалення `never` на коді pull request, тож недовірений код міг виконатися на машині рев'юера.

**guidedreview (2/5).** За README: розширення Chrome для pull request на GitHub і локальний CLI, що на запит групують пов'язані hunks у впорядковані одиниці рев'ю з коротким коментарем від LLM. Коментарі прикріплюються до справжніх рядків diff. «Generate Prompt» будує промпт для агента програмування з нотаток рев'юера й копіює його; сам інструмент його не надсилає.

## Що спільного в усіх шести

- Жоден із п'яти, чий код прочитано, не розміщує пояснення агента в колонці поруч із diff: glassbox і hunk вставляють його під прив'язаним рядком, треди diffo розташовані під рядком, ai-pr-review вставляє рядки анотацій під кодом. README guidedreview не каже, де рендериться його коментар.
- У прочитаних версіях лише drift читає й пише обговорення merge request у GitLab; стороннє розширення `hunk-glab` для merge request у GitLab з'явилося пізніше, і його не читали. diffo, ai-pr-review і guidedreview працюють лише з GitHub; у glassbox немає шару для форжу.
- Лише diffo типізує зворотний зв'язок рев'юера, тож агент може відрізнити запитання від запиту на зміну.
- Жоден не повідомляє вимірювань якості рев'ю, часу чи знайдених дефектів.

## Тут не перевірено

- Поведінку кожного інструмента під час виконання; нічого не запускали.
- Зміни після SHA читання для diffo, hunk і ai-pr-review, а також стороннє розширення `hunk-glab`.
- Код, ліцензію й потоки даних guidedreview поза README.
- Чи досі ai-pr-review запускає Codex із доступом до мережі на `c8da8d5`.

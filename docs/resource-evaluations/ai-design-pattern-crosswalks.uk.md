# Таблиці відповідності патернів проєктування для ШІ (від класичних патернів до агентних)

**Переглянуто**: 2026-10-27. **Загальна оцінка**: 3/5. Вибіркове використання: цитувати найкращі таблиці відповідності як джерела для сторінки, що зіставляє класичні патерни програмного забезпечення з функціями harness Claude Code, і позначати кожну пару з Claude Code, яку жодне джерело не формулює, як власне тлумачення посібника.

## Метод і межі доказовості

- Кожне джерело відкривали в першоджерелі (завантажена сторінка, клонований репозиторій або прочитана сторінка arXiv), якщо в таблиці не сказано інакше.
- Два записи arXiv перевірено лише через фрагмент з результатів пошуку. Їхня оцінка попередня.
- Лише AgentPatterns.ai називає механізми Claude Code у зіставленні з класичними патернами: Observer з hooks і Facade з CLAUDE.md. Жодне з відкритих джерел не зіставляє патерни GoF чи EIP із subagents, skills або MCP, тож ці рядки є синтезом, підкріпленим лише там, де погоджуються дві або більше незалежні таблиці відповідності.
- Репозиторії на цю тему, що походять із витоків, виключено й не цитовано. Один репозиторій, що посилається на внутрішні вихідні файли Claude Code без публічного походження, вилучено з цієї таблиці 2026-10-28.
- Кількість зірок повторно не перевіряли й в оцінюванні не використовували.

## У чому таблиці відповідності погоджуються

Кожен рядок підкріплюють щонайменше два незалежні джерела. Це рядки-кандидати для посібника:

| Класичний патерн | Агентний відповідник | Джерела |
|---|---|---|
| Observer | Hooks навколо викликів інструментів | agentpatterns.ai, aicodingpatterns.com |
| Chain of Responsibility | Конвеєри hooks і дозволів | agentpatterns.ai, AHEP |
| Memento | Контрольні точки й відкат (rewind) | agentpatterns.ai, AHEP |
| Composite, Mediator | Оркестратор і subagents | agentpatterns.ai, aicodingpatterns.com |
| Factory | Породження subagents | agentpatterns.ai, aicodingpatterns.com |
| Strategy | Маршрутизація та вибір моделі | agentpatterns.ai, aicodingpatterns.com |
| Circuit Breaker | Обмеження ходів і циклів | agentpatterns.ai, aicodingpatterns.com |
| Saga | Компенсувальні дії | agentpatterns.ai, aicodingpatterns.com, arXiv 2605.20173 |
| Adapter | Адаптери інструментів і MCP | aicodingpatterns.com, arXiv 2601.19752 |

Facade → CLAUDE.md спирається на одне джерело й лишається пропозицією. Observer → hooks та інші прив'язки до Claude Code є тлумаченням цих зіставлень з боку посібника, бо жодне з відкритих джерел не формулює їх для Claude Code.

## У чому вони розходяться

Розбіжності варто показувати саме як розбіжності:

- Decorator: запобіжники (guardrails) в одному джерелі, проміжне ПЗ для ін'єкції контексту в іншому.
- Template Method: системний промпт в одному джерелі, фіксований каркас агентного циклу в іншому.
- Chain of Responsibility: конвеєр hooks в одному джерелі, ланцюжок агентів в іншому.
- Singleton: реєстр інструментів в одному джерелі, окремий власний патерн в AHEP.

## Рішення

Використовувати таблиці відповідності як джерела для цитування й не копіювати жодної картки. Побудувати таблицю посібника з наведених вище консенсусних рядків, позначити рядки з одним джерелом і рядки власного тлумачення відповідним чином і додати прив'язку до Claude Code з офіційної документації. Використовувати таблицю EIP roanbrasil і картки розподілених патернів kage-ai як найсильніші джерела для рядків EIP і стійкості. Розглядати репозиторій go4 як словник, а не як таблицю відповідності.

Прочитати статтю Barbaste et al., перш ніж цитувати будь-який з її патернів, і основний текст arXiv 2601.19752, перш ніж покладатися на його зв'язки з GoF. Загальна оцінка 3/5 відображає тему корисну, але молоду: більшість джерел датовано 2026 роком, і жодне не перевірене на поведінці Claude Code. Ця оцінка не встановлює, що будь-яка пара правильна, лише те, що джерела її пропонують.

# Оцінка ресурсу №081: Rippletide code, примусове виконання правил у runtime для Claude Code

**Джерело:** допис у LinkedIn (Patrick Joubert, CEO Rippletide) + [rippletide.com/dev](https://www.rippletide.com/dev)
**Тип:** комерційний інструмент, шар примусового виконання правил на основі hooks для Claude Code
**Оцінено:** 2026-03-17
**Примітка:** відрізняється від оцінки 072 (2026-02-28), що стосувалася SaaS Rippletide на основі MCP/eval/decision runtime. Це інший продукт: CLI-інструмент примусового виконання (`npx rippletide-code`), нативний для hooks, без накладних витрат MCP.

---

## 📄 Підсумок змісту

1. **Яку проблему розв'язує**: правила в CLAUDE.md деградують у масштабі: після ~40 правил Claude Code виконує їх непослідовно; компактація контексту призводить до втрати правил між сесіями. За Rippletide: «50% of Claude Code CLAUDE.md issues are about rules being ignored» (цитовано 18+ публічних звітів на GitHub).

2. **Основний механізм**: читає кодову базу та наявний CLAUDE.md → будує «Context Graph», що зберігається поза контекстним вікном LLM → використовує hooks Claude Code для перехоплення викликів інструментів до виконання → блокує порушення, перш ніж вони відбудуться.

3. **Архітектура**: нативна для hooks (не MCP), без накладних витрат на ін'єкцію токенів. Блокування до виконання (не логування після). Приклад виводу: `[BLOCKED] Rule: "DO NOT modify .env files"`.

4. **Встановлення**: `npx rippletide-code`: безкоштовна бета, без API-ключа та реєстрації. Граф будується «менш ніж за 5 секунд» (твердження компанії).

5. **Передісторія**: заснована в лютому 2024, SF + Париж, команда з 8 осіб. Переможець OpenAI Codex Hackathon. Співзасновники: Patrick Joubert (CEO) + Yann Bilien (Chief Scientist). Є корпоративний рівень (індивідуальне ціноутворення, «2-week validation sprint»).

**Оцінка: 3/5**

**Обґрунтування**: розв'язує реальну, задокументовану проблему спільноти (деградація правил CLAUDE.md у масштабі, втрата правил через компактацію), яку посібник визнає, але не охоплює рішеннями. Патерн примусового виконання на основі hooks справді новий в екосистемі Claude Code: жоден інший задокументований інструмент не робить блокування до виконання. Однак кілька тверджень не перевірено (стійкість Context Graph до компактації, побудова графа «менш ніж за 5 секунд», «50% проблем»), продукт перебуває в безкоштовній бета-версії без сигналів про впровадження, а компанія вже публікувала неперевірні заяви про продуктивність (оцінка 072: «<1% hallucinations» без методології).

Оцінка не перевищує 3, бо довіра до посібника вимагає застосовувати до комерційних інструментів стандарти доказовості, а цей інструмент без незалежного підтвердження цієї планки не долає.

## 📍 Рекомендації

**Оцінка 3: інтегрувати як обмежений запис із чіткими застереженнями.**

### Що інтегрувати (і як)

**Пріоритет 1: задокументувати патерн, а не лише інструмент.**

Посібник має охопити «примусове виконання правил у runtime через hooks» як концепцію в розділі про обмеження CLAUDE.md у ultimate-guide.md. Цей розділ наразі документує поведінку компактації та CLAUDE.md із областю дії за шляхом як заходи пом'якшення, але не має запису про примусове виконання до запуску. Ця прогалина існує незалежно від Rippletide. Патерн: використовувати hooks `PreToolUse` для перевірки викликів інструментів за набором правил і виходу з ненульовим кодом для блокування. Тоді Rippletide є однією комерційною реалізацією цього патерну.

НЕ створюйте в посібнику розділ, що існує лише для виправдання одного бета-продукту.

**Пріоритет 2: додати прогалину «Rule enforcement» до таблиці Known Gaps у third-party-tools.md.**

У таблиці Known Gaps немає запису про примусове виконання правил у runtime. Його слід додати першим. Потім Rippletide можна цитувати в новому розділі «Rule Enforcement» як єдину відому реалізацію, з чіткими застереженнями спостереження (бета, неперевірені заяви, немає сигналів про впровадження).

**Куди інтегрувати:**
- `guide/ultimate-guide.md`, розділ про обмеження CLAUDE.md: додати 3-4 рядки про патерн примусового виконання + посилання на Rippletide
- `guide/ecosystem/third-party-tools.md`: додати розділ «Rule Enforcement» (після Hook Utilities або після Engineering Standards Distribution) + оновити таблицю Known Gaps

**Що НЕ інтегрувати:**
- Не цитувати «50% проблем стосуються ігнорування правил» як факт: це власне формулювання Rippletide
- Не цитувати «Context Graph зберігається після компактації» як підтверджене: це не перевірено
- Не використовувати час побудови «менш ніж за 5 секунд» як статистику посібника
- Не створювати розділ лише для цього інструмента без попереднього запису в Known Gaps

## 🔥 Виклик (technical-writer)

**Оцінка після виклику: 3/5 (збережена)**

Ключові пункти, порушені під час виклику:

1. **Неперевірені заяви, вбудовані як факти**: оцінка спершу трактувала «стійкість Context Graph до компактації» як перевірену функцію. Це власна заява Rippletide. Посібник не повинен повторювати її без застережень: це та сама помилка, що тримала оцінку 072 на рівні 2/5.

2. **Поверхня безпеки не розглянута**: hook до виконання в критичному шляху кожного виклику інструмента має реальну поверхню атаки. Поведінка fail-open чи fail-closed, коли сервіс Context Graph недоступний, не специфікована. Чи запускає `npx rippletide-code` постійний фоновий процес із доступом до вхідних даних інструментів (які можуть містити секрети), не задокументовано.

3. **«Безкоштовна бета» є прапорцем ризику**: немає сторінки цін, плану після бети, заявленої політики обробки даних для сканування конвенцій. Посібник документує Straude із застереженнями про передачу даних; Rippletide заслуговує на таку саму прискіпливість.

4. **«Auto-detects implicit conventions» не досліджено**: як саме? Чи надсилає код на зовнішній сервіс? Лише локально? Це питання безпеки та приватності ще до того, як це функція.

5. **Послідовність інтеграції має значення**: не додавати розділ «Rule Enforcement» до third-party-tools.md без попереднього додавання «Rule enforcement» до таблиці Known Gaps. Спершу категорія, потім інструмент, а не інструмент, що створює категорію.

6. **Сильніша точка інтеграції це ПАТЕРН**: посібник має задокументувати примусове виконання до запуску через hooks як концепцію. Rippletide є однією з реалізацій. Мінімальний власноруч зроблений приклад (hook PreToolUse, що перевіряє список правил і завершується з ненульовим кодом) прислужиться читачам краще, ніж схвалення комерційного продукту.

**Ризики НЕінтеграції**: від низького до середнього. Проблема деградації правил реальна й недостатньо задокументована в посібнику. Її відсутність лишає прогалину, з якою практики регулярно стикаються. Але патерн можна задокументувати без Rippletide: ризик знімається висвітленням концепції, а не продукту.

## 1. Зміст

Superpowers — це повна методологія розробки ПЗ, запакована як plugin для Claude Code: набір компонованих skills, що впроваджує структуровані воркфлоу від ідеї до злитої гілки. Skills спрацьовують автоматично залежно від контексту (ручний виклик не потрібен).

**Ключовий вміст**:
- **Обов'язковий брейнштормінг на початку**: перед будь-яким кодом агент витягує специфікацію через сократівські запитання й подає її розділами, які можна переглянути
- **Планування реалізації**: розбиває роботу на завдання по 2-5 хвилин з точними шляхами до файлів, повними блоками коду й кроками перевірки
- **Розробка, керована субагентами**: для кожного завдання запускається свіжий субагент із двоетапним рев'ю (спершу відповідність специфікації, потім якість коду); розраховано на години автономної роботи
- **Обов'язковий TDD**: примусовий цикл RED → GREEN → REFACTOR; код, написаний до тесту, видаляється й пишеться заново
- **Повний життєвий цикл гілки**: `using-git-worktrees` + `finishing-a-development-branch` охоплюють увесь шлях від створення робочого простору до рішення про злиття чи PR

**Філософія**: розробка через тестування як непорушна вимога, системність замість імпровізації, зменшення складності як головна мета, докази замість тверджень.

## 5. Перевірка (агент technical-writer)

**Ключові заперечення та їх розв'язання**:

**Заперечення 1: «Перевірте кількість у 95k зірок, перш ніж ставити 5/5»**
→ Перевірено через GitHub API. 95 299 зірок, 7 546 форків, створено в жовтні 2025. Це умова для оцінки — умову виконано. Оцінка лишається 5/5.

**Заперечення 2: «Посібник уже охоплює кожен компонент окремо (TDD, spec-first, worktrees). Чи справді Superpowers щось додає?»**
→ Так: цінність у *пакеті* та *автоматичному спрацьовуванні*. Користувачі, встановивши один plugin, отримують структуровану методологію, не складаючи вручну п'ять сторінок воркфлоу. У посібнику немає жодного запису на кшталт «встановіть це, щоб автоматично закріпити хороші звички у воркфлоу». У цьому й прогалина.

**Заперечення 3: «Чи third-party-tools.md + Plugin Ecosystem — правильне місце для інтеграції?»**
→ Частково погоджуємося із запереченням. Кращий підхід: (a) оновити рядок obra на рядку 8104 в ultimate-guide.md, щоб він посилався на повний набір Superpowers, (b) додати окремий запис Notable Workflow Suites у розділ Plugin Ecosystem файлу third-party-tools.md поряд із gstack, (c) послатися з tdd-with-claude.md і spec-first.md як на «методологію спільноти, що об'єднує цей воркфлоу».

**Заперечення 4: «А як щодо воркфлоу із субагентами — чи він справді відрізняється від нативного інструмента Task?»**
→ `subagent-driven-development` у Superpowers примусово застосовує двоетапне рев'ю (спершу відповідність специфікації, потім якість коду), якого нативний інструмент Task не надає з коробки. Варто зазначити як справжню відмінність воркфлоу.

**Коригування оцінки**: перевірка підтвердила 5/5 після верифікації кількості зірок.

## Що це таке

context-evaluator аналізує файли CLAUDE.md і AGENTS.md за допомогою 17 спеціалізованих ШІ-оцінювачів (13 категорій помилок + 4 категорії пропозицій). Доступний як:

- Вебзастосунок без встановлення на context-evaluator.ai (вставте URL GitHub або завантажте файл)
- Попередньо скомпільований бінарний файл для macOS/Linux/Windows (без залежностей часу виконання)
- Встановлення з вихідного коду (Bun/TypeScript)

Оцінка займає 1-3 хвилини. На виході звіт з оцінками, рівнями серйозності (Critical/High/Medium/Low) і конкретними рекомендаціями з виправлення. Функція автоматичного виправлення створює файл `.patch` з покращеннями, згенерованими ШІ.

## Виявлені технічні шаблони (прочитано вихідний код)

### Шаблон 1: логування prompt під час виконання (`runtime-prompt-logger.ts`)

**Завжди ввімкнений блокувальний запис на диск ПЕРЕД викликом ШІ-провайдера.** Це не прапорець налагодження: кожен prompt зберігається в `prompts/debug/` з ім'ям файлу за часовою міткою ISO-8601 незалежно від стану прапорця `--debug`. Запис виконується через `await writeFile()` (блокувально). Якщо виклик провайдера впаде або завершиться за тайм-аутом, точний prompt уже на диску.

Ключові дизайнерські рішення:
- Блокувальний запис (а не «запустив і забув»): гарантує, що файл існує до початку виклику ШІ
- Ніколи не кидає винятків: збої логування записують попередження і повертають `null`, але не ламають оцінювання
- Окремо від `--debug` (який зберігає в `{workingDir}/debug-output/`): це зберігається назавжди і завжди активне

**Зараз у посібнику немає.** Посібник охоплює використання прапорця `--debug`, але не називає «запис перед викликом» дизайнерським шаблоном для skills-оцінювачів.

### Шаблон 2: адаптивний єдиний/паралельний режим (`runner.ts:764-775`)

**Перемикання між виконанням одним агентом і паралельними агентами за порогом token.** Перед запуском оцінювачів система оцінює сумарну кількість token усіх вхідних файлів. Якщо менше 100K token (`DEFAULT_MAX_UNIFIED_TOKENS`), усі файли оцінюються в одному єдиному виклику агента, що може виявити суперечності між файлами. Якщо більше, кожен файл оцінюють незалежні паралельні агенти.

```typescript
export function canUseUnifiedMode(
  context: MultiFileContext,
  maxTokens: number = DEFAULT_MAX_UNIFIED_TOKENS,
): { viable: boolean; reason?: string } {
  if (context.totalTokenEstimate > maxTokens) {
    return {
      viable: false,
      reason: `Combined file content (~${context.totalTokenEstimate} tokens) exceeds limit (${maxTokens} tokens)`,
    };
  }
  return { viable: true };
}
```

**У посібнику явно не названо.** Посібник обговорює паралельних субагентів і оцінювання кількох файлів, але не документує шаблон перемикання «перевір кількість token, обери 1 агента чи N агентів» з конкретним порогом.

### Шаблон 3: ін'єкція технічного інвентарю (`context-identifier.ts`)

Спочатку збираються CLOC + структура каталогів + аналіз `ls -la`, потім вони підставляються як структурований контекст у prompt усіх 17 оцінювачів. Схоже на Shared Ground Truth Injection (уже задокументовано у v3.39.0 `skill-design-patterns.md`). **Нова документація не потрібна**: це варіант уже охопленого шаблону.

### Шаблон 4: багаторівнева дедуплікація

Трифазний конвеєр: кластеризація за правилами (допуск розташування + схожість тексту) → семантична дедуплікація ШІ → курування за впливом. Цікаво, але специфічно для систем оцінювання. Мала цінність для звичайних користувачів CC, пропускаємо.

## Різниця порівняно з Caliber (у посібнику)

| Функція | Caliber | context-evaluator |
|---------|---------|-------------------|
| Не потребує ШІ-провайдера | Так | Ні |
| Шкала оцінювання (0-100) | Так | Ні |
| Виявлення дрейфу через Git | Так | Ні |
| Рев'ю вмісту на основі LLM | Ні | Так (17 оцінювачів) |
| Аналіз між файлами | Ні | Так |
| Автоматичне виправлення (патч) | Ні | Так |
| Без встановлення (веб) | Ні | Так |

context-evaluator і Caliber доповнюють, а не конкурують. Посібник має подавати їх як варіанти для різних потреб.

- Потребує ШІ-провайдера (Claude Code, Cursor, OpenCode, GitHub Copilot, Codex)

- Немає виявлення дрейфу на основі Git

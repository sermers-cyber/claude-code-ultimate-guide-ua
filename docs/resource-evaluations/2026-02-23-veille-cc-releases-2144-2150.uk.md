# Огляд релізів CC 2.1.44 → 2.1.50 (17-23 лютого 2026)

## Підсумок

Детальний аналіз 6 релізів Claude Code (17-21 лютого 2026), що охоплюють: нативну ізоляцію worktree, нові hooks `WorktreeCreate`/`WorktreeRemove`/`ConfigChange`, зміну клавіатурного скорочення, що ламає зворотну сумісність (`Ctrl+F` замінює подвійний ESC), масові виправлення витоків пам'яті та міграцію моделі Sonnet 4.6 на 1M контексту.

## Оцінка: 4/5

**Обґрунтування**: YAML релізів і claude-code-releases.md уже актуальні (2.1.50). Основні функції (ізоляція worktree, hooks WorktreeCreate/WorktreeRemove, CLI `claude agents`, змінні середовища 1M) є в ultimate-guide.md. Цінність цього огляду — аудит покриття, що виявляє 8+ прогалин у тематичних розділах + **1 активну критичну помилку в документації** (ESC/подвійний ESC).

## Виявлено й виправлено критичну помилку

**Файл**: `guide/ultimate-guide.md`, рядки ~5738-5741

**Проблема**: посібник вказував `ctrl+c ctrl+c` / `ESC ESC` для зупинки фонових агентів. Це хибно, починаючи з v2.1.47.

**Ризик**: користувачі вважають, що їхніх агентів зупинено, хоча вони працюють у фоні (непомітне споживання токенів, конфлікти паралельного запису).

**Застосоване виправлення**: виправлено 2026-02-23. ESC тепер скасовує лише основний потік. `Ctrl+F` = єдиний спосіб керувати фоновими агентами (overlay).

## План поступової інтеграції

### Фаза 1 — Hooks (P1, 1 сесія)

**Hook `ConfigChange`**: додати в таблицю подій hooks (поблизу наявного розділу WorktreeCreate/WorktreeRemove):

```markdown
| `ConfigChange` | When config files change during session | Enterprise: audit + block live config changes |
```

З прикладом:
```json
{
  "hooks": {
    "ConfigChange": [
      {
        "matcher": "",
        "hooks": [{ "type": "command", "command": "scripts/audit-config-change.sh" }]
      }
    ]
  }
}
```

**Керована ієрархія `disableAllHooks`**: примітка в розділі Enterprise Settings:
> `disableAllHooks` (v2.1.49+) більше не може вимикати hooks, керовані корпоративною політикою. Hooks рівня `managed` завжди перевизначають налаштування користувача.

**`last_assistant_message` у Stop/SubagentStop**: додати в розділ hooks Stop/SubagentStop:
> Поле `last_assistant_message` тепер доступне у вхідних даних подій `Stop` і `SubagentStop` (v2.1.47+). Корисне для доступу до фінальної відповіді без розбору транскриптів.

### Фаза 2 — CLI та LSP (P2, 1 сесія)

**Прапорець `--from-pr`**: у розділі воркфлоу GitHub/DevOps:
```bash
# Resume session linked to a specific PR
claude --from-pr 123
# Sessions created via gh pr create are auto-linked
```

**`startupTimeout` LSP**: у розділі конфігурації LSP:
```json
{
  "lsp": {
    "servers": {
      "tsserver": { "startupTimeout": 15000 }
    }
  }
}
```

**`enabledPlugins` через `--add-dir`**: у розділі Plugins:
> `enabledPlugins` і `extraKnownMarketplaces` можна задавати в налаштуваннях каталогу `--add-dir`, що дає змогу застосовувати політику plugins на рівні репозиторію.

### Фаза 3 — settings і keybindings (P3, пакетно)

Оновити наявні таблиці:
- **Таблиця Settings**: `spinnerTipsOverride` (власні підказки, опція `excludeDefault`)
- **Таблиця Keybindings**: `chat:newline` (налаштовуваний багаторядковий ввід)
- **JSON Statusline**: поле `added_dirs` в об'єкті `workspace`
- **SDK reference**: типи `SDKRateLimitInfo` / `SDKRateLimitEvent`

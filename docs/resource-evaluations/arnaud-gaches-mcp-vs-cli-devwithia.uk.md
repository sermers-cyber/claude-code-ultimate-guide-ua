# Оцінка: Arnaud Gaches, підсумок обговорення спільноти «MCP vs CLI»

**Джерело**: допис у LinkedIn від 20 березня 2026 року. Підсумок обговорень у спільноті Dev with IA (devw.ai). Учасників названо лише на ім'я.

---

## Короткий зміст ресурсу

- Три фази еволюції інтерфейсу: браузер (2022-23) → IDE + MCP (2024-25) → CLI-агенти (2025-26). Усі великі гравці тепер мають термінального агента.
- Оновлення щодо вартості в токенах: автор стверджує, що невикористані MCP-сервери тепер додають у контекст «0 токенів» (можна перевірити через `/context` у порожній сесії), і доводить, що головний аргумент на користь підходу «CLI насамперед» упав.
- Вибір визначають можливості моделі: передові моделі (Claude Opus/Sonnet 4.6, GPT-4o) можуть напряму керувати складними CLI; менші локальні моделі (Qwen, Llama) виграють від структурованого інтерфейсу MCP.
- Евристика практиків: детерміноване + задокументоване → CLI; дослідницьке + невідомий API → MCP.
- Корпоративні аргументи на користь MCP Remote: централізовані оновлення (без обслуговування кожної машини), нативна спостережуваність для атрибуції ROI.
- Названо антипатерн: API → MCP → CLI є «contre-productif» (марнотратним). Правильний шлях: API → CLI напряму.
- Згаданий інструмент: CLI-Anything, що автоматично генерує CLI з відкритого коду; доречний, коли готового CLI немає.
- Метатеза: суперечка MCP проти CLI стосується лише розробників з доступом до термінала. Для нетехнічних користувачів і контекстів «агент як сервіс» за замовчуванням використовується MCP.

## Оцінка: 2/5

**Обґрунтування**: окрема сторінка посібника `mcp-vs-cli.md` уже охоплює кожну суттєву тезу цього допису, з більшою технічною глибиною і кращими джерелами. Твердження про «0 токенів», подане в дописі як новина, вже задокументоване в посібнику за даними січня 2026 року, і версія посібника точніша («майже нуль», а не «0»). Можливості моделей, корпоративні аргументи, вартість у токенах, евристики практиків, переносність CLI між проєктами: усе є в наявному файлі.

Агент-рецензент підтвердив: «The resource adds zero net information to this guide.» Кожна ключова теза вже є в `mcp-vs-cli.md`, задокументована раніше й точніше. Це випадок, коли без попередньої перевірки наявного файлу джерело було б переоцінене.

Один елемент справді відсутній: історична подача через три фази (браузер 2022-23 → IDE+MCP 2024-25 → CLI-агенти 2025-26). Посібник пояснює поточні компроміси, але бракує наративної дуги для читачів, які хочуть зрозуміти, звідки взялася ця суперечка. Це варте двох речень у вступі, не більше.

- Цитати практиків: розділ «What practitioners say» уже містить рівноцінні цитати (рядки 185-197). Нового погляду немає.

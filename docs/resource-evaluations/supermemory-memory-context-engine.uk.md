## Стислий підсумок

**Оцінка**: **3/5** (Помірно — інтегрувати, коли буде час)

Supermemory — підтримуваний венчурним капіталом (посівний раунд $29M, жовтень 2025) API пам'яті та context engine з трьома окремими поверхнями інтеграції для Claude Code: безкоштовна загальна кінцева точка MCP без входу (`mcp.supermemory.ai/mcp`), платний plugin для Claude Code (`claude-supermemory`, потрібен план Pro мінімум за $19/міс) і локальний бінарник для самостійного розгортання під ліцензією MIT, який явно є однокористувацьким (single-tenant) навіть у самостійному розгортанні. Посібник не має прогалини, яку це закриває: однокористувацьку пам'ять між сесіями вже задокументовано (§3.1-3.8), а командна історія Supermemory не перевершує наявну тезу посібника в §4.7, що жоден інструмент не розв'язав проблему спільної пам'яті дешево. Найкорисніший внесок для посібника — не нова можливість, а два конкретні дані з джерелами: внутрішня суперечність у цифрах бенчмарку від того самого постачальника (95% проти 85,4% Recall@15 на тому самому бенчмарку) та інтеграція з Claude Code, платна з першого використання, тоді як кожен порівнянний однокористувацький інструмент, уже задокументований (claude-mem, doobidoo, Mem0 Cloud MCP), на цьому рівні безкоштовний.

## Підсумок змісту

**Що робить Supermemory**: хостований API пам'яті (REST + MCP), що поглинає документи, розмови й дані конекторів (Google Drive, Notion, Gmail, OneDrive, лише в хмарі) і повертає їх через семантичний пошук, обмежений «тегами контейнерів» (container tags). Під однією назвою існують три різні продукти:

1. **Supermemory MCP** (github.com/supermemoryai/supermemory-mcp): загальна кінцева точка `mcp.supermemory.ai/mcp`. Безкоштовна, без входу, вже сьогодні придатна для будь-якого MCP-клієнта, включно з Claude Code.
2. **Plugin claude-supermemory** (github.com/supermemoryai/claude-supermemory): специфічний для Claude Code plugin з інструментами `memory`/`recall`/`context` і командою `/context`. Потребує плану Supermemory Pro або вище, мінімум $19/міс, на безкоштовному рівні не працює. Останнє згадане оновлення: «Claude Supermemory V2», 2026-02-09.
3. **Supermemory local**: самостійно розгортуваний єдиний бінарник під ліцензією MIT (підтверджено читанням файлу `LICENSE` у клонованому репозиторії, copyright 2025 supermemory). Однокористувацький, один ключ API, без командного доступу кількох учасників навіть у самостійному розгортанні. Конектори доступні лише в хмарі й відсутні в цьому режимі.

**Модель багатокористувацькості**: «теги контейнерів» (жорстка межа ізоляції) плюс ролі організації та ключі API з обмеженою областю, функціонально ближче до обмеження за `user_id` у Mem0, ніж до спільних блоків пам'яті Letta чи групових гілок Memoria. Немає задокументованої семантики злиття чи розв'язання конфліктів між особистою й командною пам'яттю; це залишено логіці застосунку.

**Стан безпеки**: TLS під час передавання, шифрування класу AES-256 у стані спокою, сертифікація SOC 2 Type II, видалення відповідно до GDPR (контейнер = одиниця видалення), доступна HIPAA BAA. Усі три пункти відповідності (SOC 2, гарантії процесу GDPR, HIPAA BAA) доступні лише в планах Scale/Enterprise, а не Free/Pro. На дату дослідження відкриті й не розв'язані два issues на GitHub: «Privacy and Security Concerns for Multi-User Application» та «Is end-to-end encryption supported?». Наскрізного (E2E) шифрування сьогодні немає.

**Твердження щодо бенчмарків** (усі — самозвіт, джерела: supermemory.ai/research і supermemory.ai/docs/memorybench): №1 на LongMemEval, LoCoMo, ConvoMem; 95% Recall@15 при скороченні контексту на 99,4%; пошук менш ніж за 300 мс; у 10 разів швидше за Zep, у 25 разів швидше за Mem0; 100B token/міс у «сотень клієнтів». Жодного стороннього відтворення цих цифр не знайдено. Тестова обв'язка бенчмарку (MemoryBench) має відкритий код, але кожна опублікована цифра — це власний запуск Supermemory.

## Оцінка релевантності: 3/5

### Чому 3/5 (помірно)?

**Сильні сторони**:

1. **Реальний, профінансований продукт, що активно підтримується**: посівний раунд $29M (жовтень 2025, лідери — Browder Capital / Scientifica Venture Capital / Susa Ventures, серед бізнес-ангелів Jeff Dean і Logan Kilpatrick за стороннім профілем), ядро під MIT підтверджено прямою перевіркою файлу, справді безкоштовна точка входу MCP без входу, придатна в Claude Code вже сьогодні.
2. **Читачі про нього питатимуть**: з огляду на фінансування й маркетингову видимість мовчання в посібнику, що вже документує 15+ інструментів пам'яті, є прогалиною, хай і помірною.
3. **Конкретна цінність для перехресних посилань у двох наявних розділах**: внутрішня невідповідність бенчмарку 95%/85,4% — задокументована ілюстрація з джерелами того скептицизму, який уже рекомендує §9 посібника («numbers reported by tool vendors... should be read skeptically»). Командна модель на тегах контейнерів без семантики злиття та з однокористувацьким самостійним розгортанням — свіжий дані з джерелами для аргументів §4.7 «no team taxonomy standard» і «single-tenant DNA», а не контрприклад до них.

**Чому не вище (4–5)**:

1. **Немає нового класу можливостей**: однокористувацька поверхня Supermemory (семантична пам'ять на основі MCP) — патерн, який посібник уже документує багато разів (claude-mem, agentmemory, ICM, doobidoo, OpenMemory MCP). Він не закриває прогалину так, як це зробило автоматичне захоплення сесій у claude-mem.
2. **Його командна історія не просуває аргумент посібника, а підтверджує його**: теги контейнерів архітектурно ближчі до наявного обмеження за `user_id` у Mem0, ніж до чогось нового, а режим самостійного розгортання явно взагалі не має багатокористувацького доступу.
3. **Комерційне тертя на єдиній поверхні з назвою Claude Code**: plugin `claude-supermemory` платний з першого реального використання (мінімум $19/міс), тоді як кожен однокористувацький інструмент, який посібник уже рекомендує (claude-mem, doobidoo, безкоштовний рівень Mem0 Cloud MCP), на цьому рівні безкоштовний. Це справжня перешкода для впровадження, а не деталь.
4. **Нуль незалежно відтворених цифр бенчмарків плюс внутрішня суперечність**: кожне ключове твердження — самозвіт, а власний сайт постачальника публікує два різні значення (95% проти 85,4%) для того самого бенчмарку на двох різних сторінках. Це гірший стан перевірки, ніж у agentmemory, mem0 чи Letta, які принаймні фігурують разом у близькій до сторонньої тестовій обв'язці, наведеній у наявній таблиці Representative Results у §9 посібника.
5. **Нерозв'язані відкриті issues саме щодо того, що перевірить читач, який дбає про безпеку**: багатокористувацька конфіденційність і E2E-шифрування, обидва позначені як відкриті в трекері без виправлення на момент дослідження.

## Обмеження й міркування

1. **Цінове тертя на названій інтеграції з Claude Code**: `claude-supermemory` не працює дешевше за $19/міс. Читач, який хоче саме «plugin Supermemory для Claude Code», а не загальний MCP, натрапляє на платний бар'єр під час першого реального використання.
2. **Немає незалежної перевірки бенчмарків, плюс самостійно опублікована невідповідність**: вважайте кожну цифру продуктивності на supermemory.ai маркетингом, доки її не відтворено. Конфлікт 95%/85,4% варто цитувати дослівно як застереження, а не згладжувати в підсумку.
3. **Командна пам'ять не просунутіша за те, що посібник уже документує**: теги контейнерів — примітив обмеження області, а не модель злиття чи розв'язання конфліктів. Самостійне розгортання взагалі не має багатокористувацького сценарію.
4. **Прогалини в безпеці, важливі для функції командного типу**: немає E2E-шифрування, два нерозв'язані issues на GitHub називають саме цю прогалину, а найсильніші заяви про відповідність (SOC 2, HIPAA BAA) доступні лише за цінами Enterprise.
5. **Прогалина в повноті дослідження**: вихідний прохід дослідження не зміг дати порівняння з Mem0/Zep/Letta з джерелами й деталями, лише з Cognee. Будь-яке майбутнє оновлення, якому потрібне таке порівняння, потребує окремого проходу дослідження, а не екстраполяції з цього файлу.
6. **Немає перевіреної кількості зірок чи незалежних свідчень використання в продакшені** на момент цієї оцінки; не вказуйте цифри впровадження без свіжої датованої перевірки.

## Рішення

**Оцінка**: **3/5** (Помірно — інтегрувати, коли буде час)

**Дія**:
1. Додати Supermemory як запис у `guide/core/memory-systems.md` §3.8 (Other Notable Tools): рядок таблиці плюс короткий абзац у стилі, вже використаному для Memori та codebase-memory-mcp, що охоплює безкоштовну кінцеву точку MCP, платний plugin і однокористувацький бінарник для самостійного розгортання.
2. Додати рядок до Master Comparison Table у §3.9.
3. Додати одне-два речення до §4.7 (Why the Team Gap Is Structural), прив'язавши модель тегів контейнерів Supermemory й ціни на платний plugin до наявних пунктів «no team taxonomy standard» і «no enterprise buyer yet» як допоміжні свідчення, а не переписування.
4. Додати короткий абзац до §9 (Benchmarks and Evaluation) з посиланням на внутрішню невідповідність 95%/85,4% як конкретну ілюстрацію з джерелами наявних настанов розділу щодо скептицизму.

Точні місця вставки й поетапні плани змісту для кожного розділу див. у `claudedocs/supermemory-integration-plan.md`.

**Впевненість**: помірна. Заявлені компанією факти щодо цін, ліцензування й архітектури внутрішньо узгоджені й структурно перевірювані (файли репозиторію, сторінки документації). Факти про фінансування й засновника спираються на один сторонній профіль, а не на первинне джерело. Усі твердження про продуктивність за визначенням не перевірені (самозвіт, відтворення не знайдено), і план розглядає це як те, що варто задокументувати, а не як перешкоду.

## Підсумок

Допис у блозі Vercel порівнює чотири стратегії документації для агентів-програмістів на 19 завданнях Next.js 16 (API, яких немає в навчальних даних моделі). Виявлено, що статичний індекс документації AGENTS.md досягає 100% успішності проти skills на рівні 79% (з явними інструкціями) або 53% (без них, на рівні базового варіанту). Ключовий висновок: skills викликалися автоматично лише в 56% випадків. Стиснутий індекс на 8KB (зменшений із ~40KB) зберіг повну ефективність.

**Ключові метрики**:

| Конфігурація | Частка успіху |
|---------------|-----------|
| Базовий варіант (без документації) | 53% |
| Skills (за замовчуванням) | 53% (+0pp) |
| Skills (з інструкціями) | 79% (+26pp) |
| Індекс документації AGENTS.md | 100% (+47pp) |

**Детальна розбивка** (Build / Lint / Test):
- AGENTS.md: 100% / 100% / 100%
- Skills + інструкції: 95% / 100% / 84%
- Базовий варіант: 84% / 95% / 63%

## Виклик технічного письменника

Агент оскаржив оцінювання з погляду документації:

**Ключові аргументи**:
1. **Оцінка правильна на рівні 3, а не 4**: стаття підтверджує наявні настанови, а не вводить нові. Користувач, який читає наш посібник, уже робить правильно.
2. **56% — справжній висновок**: заголовок ховає головне. Skills провалюються, бо агенти їх не виявляють, а не тому, що зміст skills поганий. Claude Code уже вирішив це через CLAUDE.md, що завжди завантажується.
3. **Вибірка надто мала**: 19 завдань, різниця ~4 завдання між 100% і 79%. Статистично не надійно для широких висновків.
4. **Самообслуговуюча наративність**: Vercel керує skills.sh І є автором codemod для AGENTS.md. Вони знецінюють одне позиціонування й просувають інше під прикриттям прозорості.
5. **Обсяг інтеграції правильний**: 3-5 рядків, окремий розділ не потрібен.

**Коригування оцінки**: немає (3/5 підтверджено)

## Виклик системного архітектора

Агент оскаржив оцінювання з архітектурного погляду:

**Ключові аргументи**:
1. **Оцінка правильна, міркування хибні**: «Підтверджує наш вибір» — не аргумент. Оцінку 3/5 рятує бенчмарк стиснення — єдина дієва точка даних.
2. **Бракує архітектурного патерну**: стаття демонструє компроміс **eager loading проти lazy invocation**. Посібник документує його фактично (таблиця на рядку 4074-4080), але ніколи не називає патерн і не наводить емпіричних доказів.
3. **План недостатньо специфікований**: початкове «3-5 рядків, 2 розділи» — це заглушка. Правильний план: **3 рядки, 3 конкретні місця** (рядки 3527, 4082, 5641).
4. **Бракує техніки стиснення**: посібник каже «keep it concise», але ніколи не показує, *як* стискати. 5-кратне стиснення (40KB → 8KB) без втрат — практична порада, якої посібнику бракує.
5. **Прогалина в критеріях рішення**: таблиці завантаження посібника (рядок 4074) бракує **критерію критичності**: якщо інструкції критичні — використовуйте CLAUDE.md (eager, завантажується на 100%); якщо додаткові — skills достатньо (lazy, прийнятна частота виклику 56%).

**Коригування оцінки**: немає (3/5 підтверджено), але план інтеграції оновлено до 3 точних місць.

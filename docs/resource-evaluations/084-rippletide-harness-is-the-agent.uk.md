## Підсумок змісту

Стаття стверджує, що довговічним активом є не модель, а harness: навколишня система (інструменти, контекст, пам'ять, оркестрація, дозволи, hooks, skills, evals, спостережуваність, пісочниці), де накопичується організаційне ноу-хау, бо моделі стають взаємозамінними, а harness накопичує виправлення.

Аргумент структурують три діаграми:

1. **Анатомія harness**: Objective живить Orchestration (планує/маршрутизує/декомпонує, читає/пише пам'ять), яка спирається на три блоки (Context, Capabilities, Memory) і два блоки контролю (Evaluation & Feedback, Runtime Enforcement), що разом оточують окремий блок Model. Runtime Enforcement пропускає дії в блок Environment (системи/дані/інструменти, які агент змінює), що повертає результати до Evaluation & Feedback.

2. **Розподіл Capabilities і Performance**: Capabilities (інструменти, MCP-з'єднання, plugins/конектори, контекст, пам'ять, зовнішні системи, пісочниці) розширюють те, що агент може робити. Важелі Performance (оркестрація, skills, hooks, evals, цикли зворотного зв'язку, human-in-the-loop, моніторинг, обмежувачі, політики/дозволи) підвищують імовірність досягнення мети.

3. **Ітеративний цикл**: Test agent (запуск із поточним harness) → Eval agent (оцінка за якістю/релевантністю/повнотою/безпекою/ефективністю) → Modify harness (додати/покращити інструменти, скоригувати оркестрацію, додати hooks, покращити контекст/пам'ять, оновити політики) → повторювати, доки продуктивність не стане достатньою → розгорнути й моніторити.

Завершальний рядок: «the harness gets trained too. Not by changing weights, but by running evals, finding failures, and modifying the environment until the agent reliably reaches the objective.»

## Оцінка релевантності

| Оцінка | Значення |
|-------|---------|
| 5 | Критично важливо (значна прогалина в посібнику) |
| 4 | Дуже релевантно (суттєве покращення) |
| 3 | Доречно (корисне доповнення) |
| **2** | **Маргінально (інформація другорядна, уже охоплена)** |
| 1 | Поза межами теми |

**Оцінка: 2/5**

**Обґрунтування**: кожен елемент трьох діаграм уже має прямий, докладніший і краще підкріплений джерелами еквівалент у `guide/core/agent-harness.md` (arXiv 2605.18747, Fowler, телеметрія Anthropic, LangChain State of Agent Engineering, впевненість Tier 1). Відповідність майже один до одного: Orchestration відповідає While-Loop Engine (§2.1), Context відповідає Context Management (§2.2), Capabilities відповідає Tool Registry (§2.3), Memory відповідає Session Persistence (§2.6), Runtime Enforcement відповідає Permission Enforcement (§2.9) плюс Lethal Trifecta (§3), Evaluation & Feedback відповідає Observability Stack (§6), а цикл «test, eval, modify harness» відповідає Digital Twin Testing (§5) плюс eval harness рівня Tier 5 у `methodologies.md`.

У статті нуль цитат, нуль названих кейсів, нуль вимірюваних тверджень (жодної компанії, дати чи числа «до/після»). Наявна сторінка посібника цитує конкретну статтю arXiv, конкретну цифру телеметрії Anthropic (99,9-й перцентиль тривалості сесії 45 хв, січень 2026) та конкретну статистику опитування (57% організацій мають агентів у продакшені, LangChain). Це крок униз за ґрунтовністю порівняно з тим, що посібник уже документує, а не крок угору.

Оцінка не перевищує 2, бо стаття не вводить нових фактів, інструментів чи патернів, яких немає в посібнику. Вона повторює той самий патерн «відсутня незалежна перевірка тверджень», що був позначений в оцінках 072 і 081, з тією різницею, що тут немає тверджень для перевірки, а також нічого додати.

## Рекомендації

**Дія: відхилити. Не інтегрувати, не додавати до списку спостереження.**

1. Нічого з трьох діаграм не бракує в `guide/core/agent-harness.md`. Додавання цитування цієї статті означало б цитувати менш ґрунтовний переказ змісту, який посібник уже краще підкріплює джерелами.
2. Двоколонкова рамка «Capabilities vs. Performance» є єдиним трохи цікавим педагогічним прийомом (вона групує наявний зміст посібника двома способами, яких наразі немає). Сама по собі не варта правки посібника. Якщо `agent-harness.md` колись реструктуруватимуть, цей розподіл можна розглянути як табличний формат, але це «було б непогано», а не прогалина.
3. На відміну від оцінки 081, тут немає неперевіреного фактичного твердження, яке слід позначити, бо стаття їх не містить. Це не на її користь: це означає, що матеріал є чистим переказом, а не новою інформацією.

**Тригер спостереження**: не пропонується. Це третє подання від Rippletide. Патерн у всіх трьох (SaaS-реклама з неперевірними заявами, потім реклама інструмента з неперевірними заявами, потім матеріал лідерства думок без нового змісту) не дає підстав очікувати, що наступний матеріал із цього джерела подолає планку без незалежного, перевірного змісту (бенчмарків, інтересу на GitHub або технічного твердження, якого посібник ще не охоплює). До `watch-list.md` не додається, бо цей список відстежує ресурси з конкретним тригером підвищення, а тут жоден не застосовний.

## Короткий підсумок

Інженерна команда ManoMano провела «Project Aegis», внутрішній бенчмарк AI-агентів для кодування на своєму стеку розробки. Висновок: Serena MCP став обов'язковим інструментом. Стаття подає реальні дані про використання Serena в продакшені. Це MCP-сервер на основі LSP, що забезпечує навігацію кодом на рівні символів і пам'ять сесії. Посібник уже докладно описує Serena (8+ файлів, велика глибина в `ultimate-guide.md` і `search-tools-mastery.md`), але має конкретну прогалину в узгодженості: немає запису в `mcp-servers-ecosystem.md`, де GrepAI є єдиним MCP для пошуку й аналізу коду. Читач, який потрапляє на цю сторінку, отримує неповну картину.

## Зміст ресурсу

**Про що стаття** (відтворено, пряме завантаження не вдалося):

- Внутрішній бенчмарк («Project Aegis»), що порівнює кількох AI-агентів для кодування на продакшн-завданнях
- Serena MCP названо найкращим інструментом для навігації великою кодовою базою
- Обґрунтування: навігація символами на основі LSP (на відміну від embedding/векторного пошуку, як у GrepAI) дає точні, детерміновані результати з низькою затримкою
- Ефективність токенів: Serena надає цілеспрямований контекст (символ + виклики/посилання) замість читання файлів повністю
- Висновок: Serena тепер входить до стандартного AI-набору розробника ManoMano

**Що робить Serena** (перевірено через GitHub oraios/serena і Perplexity):

- Використовує Language Server Protocol (LSP) для семантичного розуміння коду: справжнє розв'язання символів на рівні компілятора, а не embeddings
- Понад 30 мов підтримуються нативно (Python, TypeScript/JS, PHP, Go, Rust, C/C++, Java одразу з коробки)
- Основні інструменти: `find_symbol`, `find_referencing_symbols`, `get_symbols_overview`, `replace_symbol_body`
- Пам'ять сесії: `write_memory` / `read_memory` / `list_memories`, зберігається в `.serena/memories/`
- Поведінкові режими: planning, editing, interactive, one-shot; контексти: desktop-app, agent, ide-assistant
- Безкоштовна, з відкритим кодом (GitHub: oraios/serena), працює локально через `uvx`
- Інтегрується з Claude Code, Claude Desktop, VSCode, Cursor, Cline

**Ключова відмінність від GrepAI**:

| Аспект | Serena | GrepAI |
|--------|--------|--------|
| Підхід | LSP (символи на рівні компілятора) | Embeddings (векторний пошук Ollama) |
| Затримка | ~100 мс | ~500 мс |
| Сценарій використання | Навігація відомими символами, рефакторинг | Пошук за наміром, незнайомий код |
| Налаштування | Language server для кожної мови | Ollama + nomic-embed-text |
| Пам'ять | Вбудована пам'ять сесії | Немає |
| Точність | Детермінована (точні символи) | Імовірнісна (оцінка схожості) |

## Оцінка релевантності: 3/5

### Чому 3/5 (доречно, інтегрувати, коли буде час)?

**✅ Сильні сторони**:

1. **Валідація в продакшені**: ManoMano є реальною e-commerce компанією, що використовує це в масштабі, а не автором туторіалів
2. **Підтверджує наявну позицію посібника**: посібник уже рекомендує Serena, а це додає зовнішню довіру
3. **Ракурс бенчмаркінгу**: реальне порівняння агентів є ракурсом, якого посібник не охоплює
4. **Сигналізує про прогалину в знаходженні інформації**: те, що продакшн-команда пише «чому Serena наш обов'язковий інструмент», свідчить, що читачі не знаходять її легко, що узгоджується з прогалиною в mcp-servers-ecosystem.md

**⚠️ Слабкі сторони**:

1. **Кейс однієї команди**: бенчмарк однієї інженерної команди, методологію не опубліковано
2. **«Must-have» це маркетингова мова**: немає відтворюваних метрик, немає контрольованого порівняння
3. **Стаття недоступна**: Medium повернув 403, зміст не вдалося перевірити безпосередньо під час оцінювання
4. **Вузька прогалина**: посібник уже добре висвітлює Serena; виправлення це точкове доповнення одного файлу, а не масштабна інтеграція

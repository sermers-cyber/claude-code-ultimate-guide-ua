## Підсумок

Вичерпний посібник із написання ефективних специфікацій для ШІ-агентів програмування (Claude Code, Gemini CLI, Cursor, GitHub Copilot). Опублікував Addy Osmani (автор «Learning JavaScript Design Patterns», O'Reilly, колишній керівник у команді Chrome) 19 днів тому.

**Ключовий внесок:**
- Шість основних сфер специфікації (команди, тестування, структура проєкту, стиль коду, Git-воркфлоу, межі)
- Трирівнева система меж (Always/Ask first/Never) для операційних рішень
- Стратегія модульних промптів, щоб уникнути перевантаження контексту
- Вбудована перевірка та самоперевірки
- Антипатерни: монолітний CLAUDE.md, розмиті інструкції

**Чому 4/5:** Закриває конкретні прогалини в нашому `guide/workflows/spec-first.md` (модульний дизайн, операційні межі, специфікації команд) патернами, що безпосередньо застосовні у воркфлоу Claude Code. Від авторитетного практика, опубліковано нещодавно, розв'язує щоденні болі користувачів.

## План інтеграції

### Основна інтеграція: guide/workflows/spec-first.md

**Додати 4 нові розділи** (після рядка 318, перед «See Also»):

1. **«Modular Spec Design»** (~50 рядків, рядки 320-369)
   - Патерн: розділити великі специфікації на кілька файлів CLAUDE.md (за функціями/доменами)
   - Коли розділяти: понад 200 рядків, проєкти з кількома доменами, командна робота
   - Приклад: `CLAUDE-auth.md`, `CLAUDE-api.md`, `CLAUDE-testing.md`
   - Послатися на принцип «сфокусованих частин» від Osmani

2. **«Operational Boundaries»** (~60 рядків, рядки 370-429)
   - Розширити MUST/MUST NOT рамкою **Always/Ask First/Never**
   - Зіставити з режимами дозволів Claude Code:
     - **Always** → режим автоприйняття (тести, форматування)
     - **Ask First** → режим за замовчуванням (зміни схеми, залежності)
     - **Never** → режим plan/заблоковано (пуш у продакшен, секрети)
   - Таблиця рішень із прикладами

3. **«Command Spec Template»** (~40 рядків, рядки 430-469)
   - Шаблон для команд тестування, CI, розгортання
   - Формат: `command → expected output → error handling`
   - Приклад: `pnpm test` → звіт про покриття → падіння при <80%

4. **«Anti-Pattern: Monolithic CLAUDE.md»** (~30 рядків, рядки 470-499)
   - Пояснити проблему когнітивного навантаження (понад 200 рядків = забруднення контексту)
   - Показати стратегії розділення (за функціями, за ролями, за воркфлоу)
   - Дати посилання на статтю Osmani для глибшого обґрунтування

## Ризики відмови від інтеграції

1. **Користувачі пишуть роздуті монолітні CLAUDE.md** → забруднення контексту → погіршення продуктивності → роздратування
2. **Немає операційної рамки для меж** → користувачам важко перекласти MUST/MUST NOT на щоденні рішення (коли довіряти, а коли перевіряти)
3. **Пропущена найкраща практика з авторитетного джерела** → посібник втрачає авторитет, коли практики цитують Osmani, але не знаходять тут посилань на нього
4. **Немає патерну специфікацій команд** → користувачі пишуть лише специфікації функцій і пропускають можливості налаштування інструментів і воркфлоу

**Вплив**: середньо-високий. Це щоденні проблеми воркфлоу, а не крайні випадки.

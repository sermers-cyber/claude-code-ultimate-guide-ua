# Опір когнітивній капітуляції (knlb.dev, листопад 2026)

**Переглянуто**: 2026-11-08. **Оцінка**: 3/5, інтегровано як короткий фрагмент у [Reviewing machine output is a third mode](../../guide/roles/learning-with-ai.uk.md#ревю-машинного-виводу-є-третім-режимом) і як діаграму в [Adoption & Learning](../../guide/diagrams/10-adoption-and-learning.uk.md#схвалюйте-лише-те-що-можете-пояснити). Пов'язана оцінка: [#077 Comprehension debt](077-comprehension-debt-ai-coding.uk.md).

Есей Kunal — це розповідь практика про роботу з coding agents без втрати розуміння системи. Його цінність для цього посібника — проста назва та одна конкретна тривожна ознака для режиму збою, який посібник уже охоплює, а також тактики рев'ю, що полегшують розуміння виводу агента. Жодних вимірювань у ньому немає.

Цитати прочитано в есеї та у двох транскриптах 2026-11-08. Kerr, 341 с–355 с: «it's not about quality control. It's about engaging with the mental model so I can see what someone has built and how it works.» Jain, 539 с–546 с: «this is now your review surface. You're not reviewing code line by line, but rather you're looking at the evidence of what was the intent».

## Ключові тези

- **Когнітивна капітуляція** (cognitive surrender): «uncritically accepting whatever agents output without actually thinking, exploring or considering alternatives» (некритичне прийняття будь-якого виводу агентів без справжнього обмірковування, дослідження чи розгляду альтернатив).
- **Розуміння — наступне вузьке місце**: «agents can drive the time to build to zero but the next bottleneck – comprehension – hasn't moved much so far» (агенти можуть звести час створення до нуля, але наступне вузьке місце, розуміння, поки що майже не зрушило).
- **Тривожна ознака**: багаторазове натискання «yes, continue» у сесії. Тоді автор або делегує повністю, з кращою пісочницею чи циклом зворотного зв'язку, або перевіряє ухвалені рішення.
- **Примусова зрозумілість**: для більших стеків змін автор доручає агентам побудувати власне представлення pull request із 4 стовпцями: 2 стовпці diff, поточний коментар агента про те, чому він зробив кожну зміну, і стовпець для коментарів і вказівок рецензента. Інші тактики: стеки змін за принципом «Make the change easy, then make the easy change», покрокове проходження реального виконання в дебагері, допоміжні утиліти командного рядка, що пояснюють маловідомі прапорці.
- **Запобіжники делегування**: спостережуваність, незалежна від бачення агента, детермінована валідація, прихована від моделі, тіньовий трафік, посібник зі стилю, швидкі розгортання та відкати.
- **Передумова**: есей цитує «The Ironies of Automation» (1983, авторка Lisanne Bainbridge, в есеї не названа): якщо ніколи не практикувати прості завдання, зі збоями важче впоратися.

## Оцінка: 3/5

Помірно. Термінологія та тривожна ознака корисні, а тактики для рецензента заповнюють прогалину, яка була в посібнику. Доказ — досвід одного практика, а академічні дані, перевірені для цієї оцінки, не показують, що пояснення поруч із кодом підвищують точність рев'ю. Есей інтегровано кількома рядками й діаграмою, а не окремим розділом.

## Тут не перевірено

- Що представлення з 4 стовпцями чи тактика стеку змін покращує результати рев'ю в будь-якій команді. Есей про це нічого не повідомляє.
- Що цитату Kerr промовляє саме Dave Kerr: опис відео й розділи приписують її Kerr, доповідача на екрані не перевірено.
- Чи повідомляє будь-яка з доповідей про вимірювання поза прочитаними фрагментами.
- Місце публікації та статус рецензування Kaufman et al. поза записом в arXiv.

## Рішення

Додати визначення, тривожну ознаку, тактики розуміння та позиції Kerr і Jain до `learning-with-ai.md`, а Kaufman et al. — як застереження, що пояснення агента є твердженням, яке треба перевірити. Додати діаграму «Approve only what you can explain» з позначкою, що це синтез цього посібника. Не подавати жодну тактику як виміряне втручання.

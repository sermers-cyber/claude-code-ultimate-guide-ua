## Підсумок

`agent-trace` (pip-пакет: `agent-strace`) — інструмент на Python (без залежностей, лише stdlib), який через hooks фіксує кожен виклик інструмента, промпт користувача та відповідь асистента в Claude Code, а потім дає змогу відтворювати сесії в терміналі або експортувати їх як спани OpenTelemetry. Створено 2026-03-15. 7 зірок на момент оцінювання (станом на 2026-07-28 вже 77).

Формулювання «strace для AI-агентів» влучне: інструмент розв'язує проблему «мій агент змінив 47 файлів, і я гадки не маю чому», даючи записаний із часовими мітками журнал кожної точки ухвалення рішення, який можна відтворити.

---

## Ключові моменти

- **Hooks Claude Code**: налаштування через `agent-strace setup`. Реєструє PreToolUse, PostToolUse, PostToolUseFailure, UserPromptSubmit, Stop, SessionStart, SessionEnd у `.claude/settings.json`
- **Відтворення сесій**: `agent-strace replay` показує повну сесію з часовими мітками, тривалостями, вхідними даними інструментів, помилками; це відсутня ланка між JSONL і розумінням
- **MCP-проксі**: обгортає будь-який MCP-сервер (stdio або HTTP/SSE). Працює з Cursor, Windsurf, будь-яким MCP-клієнтом
- **Експорт в OpenTelemetry**: вивід OTLP → Datadog, Honeycomb, New Relic, Splunk
- **API декораторів Python**: `@trace_tool`, `@trace_llm_call`, `log_decision()` для власних агентів
- **Приховування секретів**: прапорець `--redact` вилучає токени OpenAI, GitHub, AWS, Anthropic, Slack, JWT, Bearer-токени, рядки підключення

## Оцінка релевантності: 2/5

**Доречний, але надто незрілий для негайної інтеграції.**

Відтворення сесій — реальна потреба, і наявні в посібнику інструменти її не покривають. Але `claude-code-otel` уже закриває сценарій експорту в OTel, а ручні запити jq у `guide/ops/observability.md:519-550` покривають більшість сценаріїв аудиту. Унікальна перевага, інтерактивне відтворення, потребує перевірки в продакшені, перш ніж рекомендувати її читачам.

## Нотатки перевірки (рев'ю technical-writer)

**Оцінка має бути 2/5, а не 3/5.** Причини:

1. `claude-code-otel` уже експортує в Datadog/Honeycomb. Аспект OTel нічого не додає.
2. Запити jq у observability.md:519-550 уже покривають більшість сценаріїв аудиту. «Ніша відтворення» вужча, ніж здається.
3. ICM (1 зірка) додали до списку спостереження. Agent-trace із 7 зірками заслуговує такого ж підходу.

**Аспекти, пропущені в початковому аналізі**:

- **MCP-проксі = ризик MITM**: пропускати весь трафік MCP через неаудитований HTTP/SSE-проксі означає відкривати поверхню атаки. У посібнику є повний розділ про посилення захисту; додавати цей інструмент до таблиці моніторингу без попередження було б непослідовно.
- **Приховування секретів не перевірене**: токени в Base64, багаторядкові значення .env, тимчасові облікові дані AWS — граничні випадки не протестовано. Це може створити хибне відчуття захищеності.
- **API декораторів Python проти MLflow SDK**: MLflow має версіонування + відстеження експериментів + LLM-as-judge. Agent-trace простіший у запуску. Реальний компроміс не згадано.

**Щодо розміщення**: якщо інтегрувати, то не в таблицю External Monitoring Tools (там моніторинг, а не налагодження). Краще як примітку в розділі про JSONL (~observability.md:565) у формулюванні «a higher-level wrapper for session replay» (обгортка вищого рівня для відтворення сесій).

**Ризик НЕ інтегрувати**: майже нульовий. Запити jq + claude-code-otel покривають основні сценарії. Справжній ризик протилежний: додати інструмент, якому один день і який перестануть підтримувати, означає отримати мертве посилання в таблиці, на яку читачі спираються при виборі інструментів.

## Рішення

**Дія: список спостереження**
**Умова інтеграції**: 100+ зірок І принаймні один опис від практика, що показує реальне використання в продакшені.

**Якщо умову виконано**: додати як примітку в observability.md ~рядок 565 (розділ про JSONL), а не в таблицю External Monitoring Tools. Подати як «higher-level wrapper for session replay/debug» (обгортку вищого рівня для відтворення сесій і налагодження), окремо від інструментів моніторингу.

**Чому список спостереження, а не відхилення**: відтворення сесій — реальна прогалина. Python без залежностей — справжня перевага для впровадження. Інженерна якість виглядає солідно (автоматичне налаштування, приховування секретів, HTTP/SSE-проксі). Потрібен лише час, щоб довести надійність на реальних сесіях.

## Підсумок

Paul Rayner створив ContextFlow (інструмент для картування контекстів у DDD) повністю за допомогою Claude Code і проаналізував 519 комітів, щоб з'ясувати, чи робить AI рефакторинг непотрібним. Основні висновки:

- Повний розподіл комітів: 30% feat, 22% fix, 23% docs, 14% tidy (рефакторинг), 5.4% config, 2.3% test, 2.3% інше
- Лише коміти з кодом: 44% feat, 32% fix, 21% рефакторинг, 3% test; тобто кожен п'ятий коміт із кодом — суто структурна робота
- Головний аргумент: AI не скасовує рефакторинг, а знижує його вартість настільки, що його можна робити частіше, меншими порціями, до того як проблеми накопичаться
- Новий механізм: великі неузгоджені файли погіршують якість context window, а рефакторинг підтримує продуктивність AI
- Навичка проєктування, яку AI не замінить: розуміти, *коли* структура вже не відповідає задачі і як виглядає краща структура
- Містить готовий до використання промпт для git, щоб проаналізувати будь-який репозиторій із conventional commits за розподілом типів комітів

## Оцінка: 3/5

**Обґрунтування**: два окремі артефакти реальної цінності: спостереження про context window, яке варто додати до розділу про рефакторинг, і промпт для аналізу git, який варто додати до найкращих практик роботи з git. Сама історія кейсу слабша: n=1, дані зі слів автора, без зовнішнього підтвердження, опубліковано в LinkedIn. Посібник уже вимагає від кейсів вищого рівня доказовості (у Mergify є допис у блозі з джерелами; дані Airbnb підтверджено академічними дослідженнями). Крім того, відсотки комітів (44/32/21) подано без базового рівня для проєктів без AI, що обмежує можливі висновки: неможливо відрізнити «AI посилює дисципліну рефакторингу» від «Rayner особисто дисциплінований щодо рефакторингу».

## Рекомендації щодо інтеграції

**Розділити два артефакти. Розглядати їх незалежно.**

### 1. Спостереження про погіршення context window → розділ про рефакторинг (~рядок 17025)

Додати один абзац як додаткове обґрунтування в поясненні інкрементальних патернів і патернів меж. Зв'язок між зв'язністю коду та якістю контексту — окремий механізм, якого зараз у посібнику немає. Подати як спостереження практика й зазначити, що йдеться про один проєкт.

```
Example framing:
"Refactoring also protects your context window. Large, incoherent files that accumulate
without structural cleanup force Claude to process more irrelevant content per request.
Keeping modules small and well-scoped is not just a quality practice — it's a practical
token efficiency strategy."
```

### 2. Промпт для аналізу комітів git → найкращі практики роботи з git (~рядок 15564)

Додати поруч із наявними конвенціями комітів як супутній діагностичний інструмент. Його одразу може використати будь-яка команда, що працює з conventional commits, і він цінний сам по собі незалежно від історії кейсу.

```
Example placement: after the commit format section, as a "Analyze your commit distribution" sidebar.
```

### 3. Пункт про кейс → пропустити

Якість даних не дає підстав додавати його поруч із Mergify та Airbnb. Якщо Rayner опублікує повноцінний допис у блозі з методологією, переглянути.

**Пріоритет**: від низького до середнього. Промпт для git — найшвидший виграш (15 хвилин на додавання). Абзац про context window потребує більшої уваги, щоб інтегрувати його без дублювання наявного змісту.

## Перевірка (агент technical-writer)

Агент заперечив щодо оцінки (підтверджено 3/5, а не 4/5) з двох причин:

- **Походження даних**: n=1, зі слів автора в LinkedIn, без зовнішньої перевірки. Підвищення до 4 означало б якість доказів, якої ресурс не заслужив.
- **План інтеграції був невдалим**: початковий план пропонував додати матеріал до розділу кейсів. Агент слушно перенаправив обидва артефакти туди, де їм природно місце (розділ про рефакторинг + найкращі практики роботи з git), а не в пункт про кейс.

Інші позначені проблеми:
- Немає порівняння з базовим рівнем (21% комітів рефакторингу — це багато чи мало порівняно з проєктами без AI?), що послаблює тезу
- Промпту для git у початковому плані надали замало ваги, хоча це найцінніший артефакт і йому потрібне явне місце
- Ризик неінтеграції: **від низького до середнього**: зв'язок із context window варто зафіксувати, промпт для git дає читачам пряму користь, але з огляду на наявну глибину посібника нічого незамінного тут немає

# Jev / TypeSafe AI: типізовані рішення для програмного забезпечення

**Статус:** робота триває, переглянуто 21 вересня 2026 року, оновлення щодо конкурентів 28 жовтня 2026 року. **Початкова й підсумкова оцінка: 3/5**, збережена після незалежної редакційної перевірки й не змінена жовтневим оновленням. Рішення: кандидат для дослідження в робочих процесах маршрутизації та структурованих рішень; загальної рекомендації щодо продуктивності чи нативної інтеграції з Claude Code не встановлено.

## Що змінює інтерфейс

[Анонс TypeSafe від 15 вересня](https://typesafe.ai/blog/introducing-system-one-models-and-jev) представляє Jev як свою першу System One Model. [Вступ до API](https://docs.typesafe.ai/introduction) описує спільний стан і типізовані запитання замість chat completion. Його примітиви — [Choice](https://docs.typesafe.ai/primitives/choice), [Score](https://docs.typesafe.ai/primitives/score) і [Noul](https://docs.typesafe.ai/primitives/noul). Вони підтримують різні задачі: винятковий вибір, порядкову оцінку та бінарну ймовірність.

Це доречно для harness агента, якому потрібне обмежене рішення перед вибором skill, документа чи іншої моделі. Це не робить Jev заміною бекенда для розмовного циклу інструментів Claude Code.

## Незалежні звіти вже існують

[Бенчмарк фішингу anisselbd](https://github.com/anisselbd/jev-phishing-bench) повідомляє про точність 62.6% для Jev проти 81.3% для Haiku 4.5 на 2 000 листів із синтетичним текстом. Початковий протокол надсилає Jev дев'ять запитань і просить у Haiku прямий вердикт. Потім контрольоване порівняння будує регресії за тими самими п'ятьма сигналами для обох моделей. На відкладеній вибірці з 1 000 листів ці робочі процеси дають 95.0% для Jev і 93.2% для Haiku проти 91.8% для базової лінії на правилах; різниця в точності між Jev і Haiku статистично не значуща (p=0.063). Набір даних добре розділяється простими правилами. Перевірте весь робочий процес проти базової лінії без LLM, перш ніж переносити заголовну оцінку на іншу задачу.

Серед інших оригінальних звітів — [класифікаційний пілот AbdelStark](https://github.com/AbdelStark/jev-benchmarks), [вимірювання WallerChen](https://github.com/WallerChen/jev-measured) і [JevBench](https://github.com/fstandhartinger/jevbench). Їхні розміри вибірок, синтетичні дані, вибір порогів і шляхи доступу потребують окремого перегляду. Ці звіти переглянуто, але не перезапускали.

## Що виміряти перед інтеграцією

Почніть з маршрутизації skills проти лексичної базової лінії BM25, сортування тікетів або вибору фрагментів для RAG. Зафіксуйте мітки, версії моделей і промпти. Тримайте калібрування порогів окремо від фінального тесту й групуйте пов'язані перефразування в одному розбитті. Порівнюйте точність, автоматичне покриття, помилки серед прийнятих випадків, наскрізні p50/p95 і вартість одного правильного рішення з урахуванням повторних спроб і ескалації.

Для метрик калібрування використовуйте ймовірності класів. Не тлумачте статистику концентрації розподілу як імовірність правильності. [Guo et al.](https://proceedings.mlr.press/v70/guo17a.html) дає основу для калібрування; [SelectiveNet](https://proceedings.mlr.press/v97/geifman19a.html) — визначення ризику та покриття. Ці статті є тлом, а не розкриттям внутрішньої будови Jev.

## Оновлення 28 жовтня: Jev більше не єдина модель для рішень

Після Jev кілька постачальників випустили моделі для ухвалення рішень. Факти нижче перечитано на сторінці постачальника чи репозиторію 28 жовтня 2026 року; жодну з цих моделей для цієї оцінки не викликали й не запускали.

| Модель | Ваги | Ціна вводу за мільйон токенів | Інтерфейс |
|---|---|---|---|
| Jev 1.13 / [1.14](https://typesafe.ai/blog/jev-1-14) | Закриті | $0.042 | System One (`/v1/systemone`) |
| [Clef](https://huggingface.co/Cloudflare/clef), 27B | Apache 2.0, база Qwen | $0.24 на Workers AI | System One |
| [Clef-flash](https://blog.cloudflare.com/clef-faster-cheaper-multimodal/), 9B | Apache 2.0 | $0.038, розміщений контекст 24k | System One |
| [Clef-omni](https://huggingface.co/Cloudflare/clef-omni), 30B-A3B MoE | Apache 2.0 | $0.15, вхід аудіо й відео | System One |
| [Strands Decider 2B](https://huggingface.co/StrandsAgents/strands-decider-2B-qwen3.5-v1-2610) | Apache 2.0, LoRA на Qwen3.5-2B | Самостійне розміщення, `pip install strands-decider` | System One через `strands-decider serve` |
| [pplx-decider v1.1](https://huggingface.co/perplexity-ai/pplx-decider-v1.1-27b) | Apache 2.0 | Самостійне розміщення, близько 49 GiB пам'яті GPU | Власний код інференсу |
| OpenAI [Decisions API](https://developers.openai.com/api/docs/guides/decisions) | Закриті | $0.10, $0.01 з кешем | Власний формат (`/v1/decisions`) |

Для harness Claude Code важливі два наслідки. По-перше, тепер за тим самим форматом запиту існують відкриті ваги, тож hook маршрутизації можна прототипувати локально чи на Workers AI, не залежачи від одного закритого постачальника; [LiteLLM](https://docs.litellm.ai/blog/tags/typesafe) обслуговує обидва формати запитів. По-друге, запит переноситься між моделями System One, а його результати — ні: ймовірності, шкали впевненості, пороги й ефективний контекст різняться для кожної моделі, і їх треба перекалібрувати на локальних даних.

Три переглянуті сторонні оцінки не називають загального переможця. [Astronomer](https://www.astronomer.io/blog/how-to-evaluate-a-decision-model/) не виявив значущої різниці на задачі повторних спроб Airflow (McNemar p=0.15), а від 5 до 14% рішень змінювалися після перефразування. [AIMultiple](https://aimultiple.com/decision-models) оцінює Jev 1.13 у 47.9, а Clef у 51.0, зазначаючи, що під час тесту Cloudflare зчитував для Clef лише 2 048 токенів. [Leanmcp JevBench Index](https://github.com/Leanmcp/jevbench) ставить pplx-decider на 78.0, Jev 1.13 на 76.5 і Clef на 76.1. Найбільші заявлені розриви досі походять із бенчмарків постачальників.

TypeSafe також випустив Jev 1.14 (тип запитання Box, експериментальний вхід зображень через заголовок, Python SDK 0.7.5) і 9 жовтня оголосив раунд Series A на $870M. Його показники поширення різняться між [TypeSafe](https://typesafe.ai/blog/series-ai) ("a third of the Fortune 500") і [a16z](https://a16z.com/announcement/investing-in-typesafe-ai/) ("25%") і не пройшли аудиту.

Оцінка лишається 3/5: план вимірювань вище досі актуальний, і тепер він має порівнювати принаймні одну модель із відкритими вагами з Jev на тому самому розбитті.

## Редакційне рішення та приводи для перегляду

Оцінка відображає доречність для обмежених рішень у harness і наявну документацію. Вона не оцінює якість моделі. Тримайте запис попереднім, доки не буде переглянуто репрезентативний локальний бенчмарк і решту доказів від спільноти. Повернутися до нього в разі зміни моделі/API, відтворюваного незалежного результату чи формального розкриття RLCD. Будь-яке майбутнє доповнення до посібника має відрізняти запропонований маршрут від дозволу виконати дію.

Для цієї оцінки не виконувалося жодного тесту API, розгортання, перегляду політики даних для конкретного облікового запису чи рекомендації для продакшену.

## Підсумок

**nao** — це open-source фреймворк для створення й розгортання аналітичних агентів із двоетапною архітектурою: спершу контекст агента будується через CLI-інструменти, потім розгортається чат-інтерфейс, у якому кінцеві користувачі ставлять запитання до даних у формі діалогу.

**Ключові можливості**:
- Конструктор контексту з гнучкою підтримкою даних, метаданих, документації та інтеграцій інструментів
- Незалежність від СУБД (PostgreSQL, BigQuery, Snowflake, Databricks)
- Вбудований фреймворк оцінювання з можливостями модульного тестування
- Self-hosted розгортання з контейнеризацією в Docker
- Вбудована візуалізація даних у чат-інтерфейсі
- Технологічний стек: Fastify, Drizzle ORM, tRPC, React, shadcn UI (TypeScript 58.9%, Python 38.5%)

## Результати технічної перевірки

Агент technical-writer виявив кілька упереджень у початковій оцінці:

### Пропущені в початковій оцінці моменти

1. **Архітектура агентів, яку можна перенести**: патерн `context builder` з nao застосовний до агентів Claude Code
2. **Фреймворк оцінювання = критична прогалина**: у посібнику НЕМАЄ жодної згадки про оцінювання агентів (метрики, тестування, зворотний зв'язок)
3. **Патерни контексту з баз даних**: патерни впровадження контексту з баз даних не задокументовано

### Обґрунтування оцінки

**Виправлення**: 2/5 → **3/5** (помірна)

**Аргументи на користь 3/5**:
- Архітектурні патерни, які можна перенести (+1)
- Фреймворк оцінювання закриває виявлену прогалину (+1)
- Придатні до використання патерни контексту з БД (+0.5)
- Open-source, добре задокументований (+0.5)

### Прогалину «Оцінювання агентів» треба закрити

**ТАК, у посібнику МАЄ бути цей розділ**, тому що:
- Розробники створюють агентів, не знаючи, як вимірювати якість
- Документація Anthropic згадує оцінювання, але не в контексті Claude Code
- nao доводить, що це здійсненно й корисно (готово до продакшну)

### Ризики відмови від інтеграції

1. **Прогалина в оцінюванні лишається незадокументованою** → розробники не знають, як вимірювати якість агентів
2. **Патерни контексту з БД не задокументовано** → розробники заново винаходять уже перевірені патерни
3. **Втрата довіри** → якщо оцінювання стане стандартом, посібник відставатиме

### Чому початкова оцінка була упередженою

1. **Плутанина між охопленням і релевантністю**: інше охоплення ≠ нерелевантність
2. **Фокус на кінцевому продукті**: nao оцінювали як *конкурентний продукт*, а не як *джерело патернів*
3. **Недооцінка прогалин**: оцінювання агентів = критична прогалина, яку раніше не було виявлено
4. **Передчасне відхилення**: «не інтегрувати», попри виявлення 2 суттєвих прогалин

**Урок**: оцінювати ресурси на предмет *патернів, які можна перенести*, а не лише прямої інтеграції.

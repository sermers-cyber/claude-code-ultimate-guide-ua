## 📄 Короткий зміст

- **Breakthrough Method for Agile AI-Driven Development**: фреймворк, що оркеструє 19+ спеціалізованих агентів (Analyst, PM, Architect, Dev, QA...) упродовж життєвого циклу програмного забезпечення
- **Центральний принцип**: «no code until human-vetted plan» (жодного рядка коду не пишуть, доки PRD + Architecture Doc + UX spec не затвердить людина)
- **Три траєкторії планування**: Quick Flow Track (швидке виправлення), BMad Method Track (повний PRD + архітектура + UX), Enterprise Method Track (розширені вимоги відповідності)
- **Два базові компоненти**: Agentic Planning і Context-Engineered Development
- **Модульність**: пакети розширень, що встановлюються на вимогу (`bmad install expansion-packs/healthcare`)

Звідки ця оцінка: пошук альтернатив з відкритим кодом до патерну, який WeScale/Maleus представили на мітапі GenAI France (липень 2026), тобто декомпозиції PRD → задачі → збирання → бар'єри зі строгим врядуванням. BMAD-METHOD незалежно з'явився у двох окремих пошукових проходах (прямий WebSearch + перехресний пошук, наданий користувачем), що підвищує впевненість у його релевантності.

## 🔥 Перевірка на міцність

**Перевірене заперечення**: «Хіба BMAD-METHOD не просто переформулювання Plan Mode + CLAUDE.md?»

**Відповідь**: ні, структурна різниця полягає в кількості змодельованих ролей (19+ проти одного агента, що планує) і в тому, що кожна роль створює окремий версіонований артефакт (PRD, Architecture Doc, UX spec) до початку розробки. Plan Mode у Claude Code створює єдиний план; BMAD створює ланцюжок взаємозалежних документів, підписаних різними персонами. Це патерн організації роботи, а не просто довший промпт.

**Ризик у разі відмови від інтеграції**: користувачі, які шукають «як структурувати цикл PRD → архітектура → розробка з агентами», можуть натрапити на BMAD деінде, не знаючи, як поєднати його з Claude Code.

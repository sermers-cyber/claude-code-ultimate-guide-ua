# Робочий процес статусу перекладів

Репозиторій розрізняє три речі, які легко сплутати:

1. **Паритет файлів** перевіряє, чи містять обидві мови очікувані публікаційні файли.
2. **Паритет метаданих** перевіряє, чи парна французька й англійська публікації фіксують однакову базову версію посібника. Специфічна для мови `wp-version` може відрізнятися й звітується окремо.
3. **Актуальність перекладу** перевіряє, яка канонічна версія джерела та яка контрольна сума породили перекладений повний посібник.

Машинозчитуваний реєстр: [`machine-readable/translations.json`](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/machine-readable/translations.json). Публічна сторінка статусу: [`guide/core/translations.uk.md`](../../guide/core/translations.uk.md).

## Локальна перевірка

```bash
python3 scripts/check-translations.py --check
```

Ця команда перевіряє:

- канонічну англійську версію та SHA-256 за `VERSION` і `guide/ultimate-guide.md`;
- підтримувану французьку версію, хеш артефакту та записану англійську базову версію джерела;
- обов'язкові поля реєстру, унікальність мов, походження комітів джерела та зафіксоване відставання за Git;
- заявлений неофіційний статус, докази атрибуції та межі покриття кожного перекладу спільноти;
- 6 заявлених пар джерел whitepaper і відомий префікс `03`, що існує лише французькою;
- назви файлів-джерел recap-карток французькою та англійською;
- парну базову версію посібника та метадані `lang`, а також відмінності ревізій whitepaper між мовами.

Переклад, який точно позначено як `stale`, не провалює типову перевірку. Команда все одно виводить відставання. Перед публікацією підтримуваного перекладеного повного посібника використовуйте сувору форму:

```bash
python3 scripts/check-translations.py --check --require-current-maintained
```

## Після зміни англійського повного посібника

Походження перекладу має вказувати на реальний об'єкт Git. Ніколи не прив'язуйте SHA-256 незакоміченого посібника з робочого дерева до старішого коміту. Використовуйте два коміти:

1. Закомітьте канонічний посібник, довідкові індекси та пов'язану документацію, не змінюючи жодного з двох дзеркал `translations.json`.
2. Запустіть оновлення канонічного реєстру щодо цього коміту:

   ```bash
   python3 scripts/check-translations.py --update-local
   ```

3. Скопіюйте оновлений канонічний реєстр до `mcp-server/content/translations.json` і перевірте побайтову ідентичність.
4. Закомітьте лише два дзеркала реєстру перекладів.

`--update-local` відмовляється записувати, поки `guide/ultimate-guide.md` відрізняється від своєї останньої закоміченої версії. Звичайний `--check` перед першим комітом, очікувано, повідомить про розбіжність SHA канонічного робочого дерева. Ця помилка свідчить, що походження ще не зафіксовано, а не є причиною вигадувати коміт чи послаблювати перевірку.

Після першого коміту оновлення змінює локальні факти, не стверджуючи, що переклад було перегенеровано:

```bash
python3 scripts/check-translations.py --update-local
```

Це оновлює канонічну версію та контрольну суму, записує контрольну суму закоміченого `source.commit:path`, читає локальну французьку версію й перераховує її статус. Воно не змінює `translated_from` чи `last_full_refresh_at`. Валідатор перераховує байти за `source.commit:path` і вимагає, щоб цей хеш дорівнював `source.sha256`.

## Після перегенерації французького повного посібника

`scripts/translate-guide.py` записує контрольну суму вхідного кешу. Він відмовляється повторно використовувати фрагменти, створені з іншої версії джерела чи моделі. Після повного перекладу він викликає:

```bash
python3 scripts/check-translations.py --update-local --record-french-refresh
```

Ця команда прив'язує французький вивід до поточної англійської версії та контрольної суми. Перед експортом PDF або EPUB запустіть сувору перевірку.

## Рецензування перекладу спільноти

Не робіть висновок про синхронізацію лише за датою зміни репозиторію. Після перегляду віддаленого проєкту запишіть такі поля:

- заявлена версія;
- коміт upstream або базова версія джерела, якщо доступні;
- віддалений head-коміт;
- остання спостережена дата синхронізації з upstream;
- заява про покриття;
- дата рецензії.

Оновіть відповідний об'єкт у `machine-readable/translations.json`. CI репозиторію валідує заявлений стан, але під час збірки не звертається до сторонніх репозиторіїв.

Для кожної віддаленої рецензії:

1. Підтвердьте URL репозиторію, мейнтейнера, гілку за замовчуванням, HEAD, ліцензію та заявлену версію.
2. Знайдіть точний коміт англійського джерела з маніфесту чи походження Git. Якщо жодного не можна довести, збережіть порожнє (null) значення коміту джерела та порожнє числове відставання замість оцінки.
3. Перевірте атрибуцію в README, ліцензії, описі репозиторію чи повідомленні про переклад.
4. Запишіть покриття, заявлене мейнтейнером, і окреме спостереження за файловою системою.
5. Перерахуйте відставання за комітами для самого посібника та для всього репозиторію відносно `measured_at_commit`.
6. Оновлюйте `last_checked_at` лише після перевірки кожного записаного віддаленого факту.

Не виконуйте скрипти зі сховища спільноти під час аудиту. Перевіряйте лише вихідні файли та об'єкти Git.

## Парні публікації

Публічні джерела whitepaper пов'язуються за двоцифровим префіксом, а не за перекладеною назвою файлу. Публічний каталог лендингу містить 13 парних випусків, тоді як цей репозиторій містить 6 парних префіксів `.qmd`-джерел і одне заявлене джерело лише французькою. Відсутні файли-джерела не вважаються синхронізованими. Французькі документи для окремих клієнтів без нумерованого публічного префікса лишаються поза цією перевіркою паритету.

Recap-картки пов'язуються за назвою файлу-джерела. Наявність PDF стосується експорту; перевірка перекладу порівнює `.qmd`-джерела та їхній front matter.

Паритет публікацій не доводить актуальності щодо повного посібника. Whitepaper і recap-картки є тематичними адаптаціями або конспектами, тому їхнє відставання від повного посібника лишається `UNKNOWN`, доки окремий аудит вмісту не запише базову версію джерела.

## Шлюз офіційної локалі

Французька є поточним пріоритетом. Не починайте офіційне китайське чи інше видання повного посібника, доки:

- французька не проходить `--require-current-maintained`;
- людська рецензія не охопить навігацію, приклади, посилання, термінологію та неперекладені залишки;
- іменований мейнтейнер не прийме на себе постійну відповідальність;
- не задокументовано періодичність оновлень і маніфест комітів джерела;
- лендинг не зможе розмістити стабільні еквівалентні сторінки.

Незалежно підтримуваний переклад лишається виданням спільноти, навіть якщо його якість висока.

## Лендинг, sitemap, canonical і `hreflang`

Після зміни `guide/core/translations.md` зберіть лендинг на чистому worktree посібника:

```bash
GUIDE_REPO_PATH=/absolute/path/to/clean/guide-worktree pnpm build
pnpm test
```

Перевірте зібраний результат:

- `/guide/translations/` існує;
- його canonical URL вказує на себе;
- XML sitemap містить локальний маршрут рівно один раз;
- звичайні посилання показують англійську, французьку та всі зареєстровані адаптації спільноти;
- URL репозиторіїв спільноти відсутні в локальному XML sitemap;
- `hreflang` не генерується для локалі без еквівалентних сторінок і взаємних анотацій.

Після розгортання отримайте розгорнуту сторінку та sitemap. Локальна збірка, запушена гілка чи workflow, що ще виконується, не є доказом розгортання.

## Межа сторінки згадок

Атрибуція перекладів належить до сторінки статусу мов і реєстру. Якщо окрема сторінка Mentions портфоліо перелічує переклади, перевірте її незалежно та збережіть позначку «офіційний» чи «спільноти». Коміт посібника чи лендингу не доводить, що розгортання портфоліо працює.

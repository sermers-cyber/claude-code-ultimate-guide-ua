# Синхронізація лендингу

Воркфлоу для підтримання `cc.bruniaux.com` у синхронізації з посібником після суттєвих змін.

**Репозиторій лендингу**: [claude-code-ultimate-guide-landing](https://github.com/FlorianBruniaux/claude-code-ultimate-guide-landing). Команди передбачають, що робочі копії посібника й лендингу лежать поруч в одній батьківській теці.

## Елементи для синхронізації

| Елемент | Джерело (посібник) | Призначення (лендинг) |
|---------|----------------|----------------------|
| Версія | `VERSION` | Зчитується під час збірки в `src/pages/changelog/index.astro` (без захардкодженої копії) |
| Кількість шаблонів | Порахувати файли в `examples/` | Бейджі, заголовок, мета-теги |
| Рядки посібника | `wc -l guide/ultimate-guide.md` | Бейджі |
| Golden Rules | README.md | Розділ на головній сторінці лендингу |
| FAQ | README.md | FAQ лендингу |

## Тригери синхронізації

Після таких змін **не забудьте** оновити лендинг:

1. **Підвищення версії** → оновіть `VERSION` тут, потім лендинг
2. **Додано/вилучено шаблони** → перерахуйте кількість, оновіть лендинг
3. **Змінено Golden Rules або FAQ** → перенесіть зміни на лендинг
4. **Суттєва зміна посібника** (>100 рядків)

## Перебудова Guide Reader (кожен реліз)

Лендинг відкриває контент посібника за адресою `cc.bruniaux.com/guide/`. Контент генерується з цього репозиторію під час збірки — **ніколи не комітиться в лендинг**.

```bash
# From the landing repo, before each push to main:
cd ../claude-code-ultimate-guide-landing
node scripts/prepare-guide-content.mjs && pnpm build
```

**Коли це робити**: під час кожного релізу (`/release patch|minor|major`), щоб сайт відображав найновішу версію посібника.

## Команда перевірки

```bash
./scripts/check-landing-sync.sh
```

**Що перевіряє скрипт (4 перевірки):**

| Перевірка | Джерело | Порівняння |
|-------|--------|-----------|
| Версія | `VERSION` | Зчитування під час збірки в `src/pages/changelog/index.astro` |
| Шаблони | `find examples/` | Каталог `src/data/examples-data.ts` |
| Запитання вікторини | `questions.json` | Сторінки вікторини на лендингу |
| Рядки посібника | `wc -l ultimate-guide.md` | Бейджі лендингу (допуск ±500) |

**Очікуваний вивід (якщо все синхронізовано):**
```
=== Landing Site Sync Check ===

1. Version
   Guide:   3.8.1
   Landing: 3.8.1
   OK
...
=== Summary ===
All synced!
```

Якщо є розбіжності: код виходу = кількість знайдених проблем. Точні номери рядків для зміни дивіться в `landing/CLAUDE.md`.

## Пошуковий індекс (Cmd+K)

Палітра пошуку Cmd+K на лендингу містить записи посібника, згенеровані з `machine-readable/reference.yaml` (розділ `deep_dive`).

```bash
# From the landing repo, after any reference.yaml change:
cd ../claude-code-ultimate-guide-landing
pnpm build:search
```

Скрипт (`scripts/build-guide-index.mjs`) перегенеровує `src/data/guide-search-entries.ts`. Як він обробляє якорі: для файлів посібника, що віддаються локально за адресою `/guide/<slug>/`, якір відкидається, і результат пошуку веде на початок сторінки. Для всього іншого запис веде на GitHub зі збереженим якорем, тож застарілий якір там означає мертве посилання в продакшені.

**Коли перебудовувати**: після додавання, вилучення чи перейменування ключів `deep_dive` у `reference.yaml`. Зміни лише якорів у файлах посібника, що віддаються локально, не змінюють згенерованих URL, але точність YAML однаково важлива, бо це індекс, з яким працюють LLM.

Файл: `src/components/global/AnnouncementBanner.astro` (репозиторій лендингу)

**Воркфлоу оновлення**:
1. Відредагуйте текст банера в компоненті
2. Збільште `BANNER_ID` (наприклад, `banner-guide-2026-04`), щоб скинути стан «закрито» для всіх відвідувачів
3. `pnpm build` + commit + push

**Коли оновлювати**: велика нова сторінка, доданий важливий розділ, віха посібника, помітна нова функція.

## RSS-стрічка

Лендинг відкриває єдину RSS-стрічку за адресою `/rss.xml`.

**Два об'єднані джерела** (відсортовано за датою, максимум 50 записів):
1. Релізи CC: автоматично з `src/data/releases.ts`
2. Записи посібника: **вручну** в `src/data/rss-entries.ts`

**Доступні типи**: `guide_release | new_page | new_cheatcard | new_whitepaper | new_section`

**Коли додавати запис вручну**:
- На сайт додано нову сторінку (`new_page`)
- Нова серія карток (`new_cheatcard`)
- Доступний новий whitepaper (`new_whitepaper`)
- Великий новий розділ у посібнику (`new_section`)

## Карта сайту

Файл: `src/pages/sitemap/index.astro` (репозиторій лендингу)

**Правило**: додавайте кожну нову сторінку до карти сайту. Розділи містяться в масиві `sections` у frontmatter Astro.

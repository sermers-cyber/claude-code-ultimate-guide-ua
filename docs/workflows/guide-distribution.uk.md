# Поширення Claude Code Ultimate Guide

Посібник уже має потужну довідкову глибину. Робота з поширення має полегшити знаходження, проходження, переклад і атрибуцію першого корисного результату. Вона не повинна перетворювати основний посібник на рекламний текст.

## Межі

Цей воркфлоу готує матеріали та фіксує канали. Публікація, подання до маркетплейсів, аутріч, зміни ліцензії та повідомлення від імені автора потребують окремого дозволу.

Використовуйте три взаємопов'язані джерела істини:

- [`machine-readable/distribution-channels.yaml`](../../machine-readable/distribution-channels.yaml) фіксує канал, локаль, матеріал, власника, стан, URL з атрибуцією та поля 30-денного результату;
- [`machine-readable/translations.json`](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/machine-readable/translations.json) фіксує належність і актуальність перекладів;
- [воркфлоу перекладів](translations.uk.md) визначає, що означають `current`, `stale` та підтримка спільнотою.

## Запис каналу

Додавайте канал до створення його матеріалу. Використовуйте стабільний ID і тримайте канонічне призначення окремо від посилання з атрибуцією.

```json
{
  "id": "youtube-fr",
  "channel": "youtube",
  "locale": "fr",
  "owner": "Florian Bruniaux",
  "asset": "planned: quick-win video series",
  "asset_status": "planned",
  "production_brief": "docs/distribution/quick-win-video-series.md",
  "production_brief_status": "ready",
  "canonical_url": "https://www.youtube.com/",
  "tagged_url": "https://cc.bruniaux.com/?utm_source=youtube&utm_medium=video&utm_campaign=ccug-learning-path-2026",
  "status": "planned",
  "placement_status": "planned",
  "published_at": null,
  "observed_at": null,
  "submission_date": null,
  "measurement_started_at": null,
  "placement_evidence_url": null,
  "placement_verified_at": null,
  "outcome": {
    "impressions": null,
    "visits": null,
    "clones": null,
    "stars": null
  }
}
```

Реєстр `.yaml` навмисно містить YAML, сумісний із JSON. Тому валідатор використовує лише стандартну бібліотеку Python.

## Модель статусів

`asset_status` описує готовність матеріалу до виробництва. `status` і `placement_status` описують розміщення в кампанії. Тож готовий матеріал може залишатися `blocked`, поки бракує схвалення або рецензента, який вільно володіє мовою.

| Статус | Значення | Потрібна наступна дія |
| --- | --- | --- |
| `planned` | Результат і призначення визначено | Створити матеріал |
| `ready` | Матеріал існує й пройшов перевірки | Отримати схвалення на публікацію |
| `submitted` | Зовнішня платформа його отримала | Записати дату подання |
| `published` | Посилання кампанії публічно розміщене й перевірене | Записати URL доказу, дату перевірки та початок 30-денного вікна |
| `blocked` | Бракує названої залежності | Призначити власника або створити передумову |

Не змінюйте `blocked` на `ready` лише тому, що текст уже написано. Китайському матеріалу для Bilibili, наприклад, також потрібні актуальний переклад, рецензент, який читає цією мовою, мініатюра та повноваження на публікацію.

## Бар'єр перекладу

Перед створенням локалізованого матеріалу:

1. запустіть `python3 scripts/check-translations.py`;
2. перегляньте записану версію мови та хеш джерела;
3. назвіть мейнтейнера зі спільноти, якщо переклад неофіційний;
4. додайте посилання на канонічний репозиторій перекладу;
5. не надсилайте перекладених заявок, доки рецензент, який вільно володіє мовою, не перевірить текст.

Китайський переклад посібника підтримується спільнотою. Реєстр описує його спостережуване покриття та актуальність; він не містить жодного твердження про офіційну публікацію повного посібника.

## Серія «швидка перемога»

Корисна перша серія містить чотири обмежені епізоди:

1. перше перевірене виправлення за 15 хвилин;
2. вибір між skill, subagent і MCP-сервером;
3. створення й тестування одного безпечного hook;
4. порівняння кількох кандидатів на рішення та збереження пакета доказів.

Кожен епізод посилається на одну канонічну сторінку, використовує URL каналу з атрибуцією й закінчується спостережуваною перевіркою. Транскрипти з часовими мітками згодом можна індексувати через YT Insights, але успішне завантаження не доводить, що урок навчив потрібній навичці.

Готові до виробництва брифи містяться у [серії відео «швидка перемога»](../distribution/quick-win-video-series.uk.md). [Слайди навчального шляху](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/docs/distribution/claude-code-learning-path-slides.pptx) дають спільну дев'ятислайдову розповідь для доповідей, воркшопів і планування відео. Обидва матеріали лишаються неопублікованими, доки власник каналу не схвалить зовнішню дію.

## Тридцятиденні вимірювання

Записуйте ті самі чотири сирі показники для кожного каналу після `measurement_started_at`:

- покази, якщо платформа їх надає;
- відвідування URL призначення з атрибуцією;
- клони репозиторію;
- зірки.

Відсутні показники лишайте як `null`. Не перетворюйте відсутню аналітику на нуль. Порівнюйте канали лише в одному й тому ж 30-денному вікні спостереження та зберігайте дату публікації, дату спостереження, початок вимірювання, локаль, матеріал і кампанію.

Дати відповідають на різні запитання:

- `published_at`: коли сам матеріал став публічним, якщо відомо;
- `observed_at`: коли публічний матеріал було безпосередньо побачено;
- `submission_date`: коли розміщення в кампанії було подано;
- `placement_verified_at`: коли посилання кампанії з атрибуцією було перевірено на публічному каналі;
- `measurement_started_at`: коли почалося 30-денне вікно результатів.

Наявний публічний матеріал усе ще може мати статус кампанії `planned`. Публічне існування не доводить, що посилання кампанії з атрибуцією було розміщене.

Самі лише зірки не показують ні завершення навчання, ні якість посібника. Вони вимірюють одну видиму дію після контакту.

## Валідація

Запустіть:

```bash
python3 scripts/check-distribution-channels.py
python3 -m unittest scripts/test-check-distribution-channels.py
```

Валідатор перевіряє ідентифікатори, HTTPS-призначення, параметри атрибуції, узгодженість кампанії, узгодженість станів матеріалу й розміщення, порядок дат без майбутніх, докази розміщення, 30-денне вікно та невід'ємність показників результату. Він не відвідує зовнішні сторінки й не доводить, що URL доказу досі містить посилання з атрибуцією.
